# 稳定性轮次：宿主页面与 API 联调

日期：2026-10-29。基线为 `/workspace/astrbot/AstrBot` 的 v4.29.3（`abf683071`）。

本轮把阶段六“浏览器注入模拟桥”的证据推进到真实宿主资源、鉴权、桥 SDK 和插件 API：通过隔离 ASGI 服务、真实 Chromium 与临时插件运行实例完成验证。没有修改宿主源码、真实配置或聊天；没有使用真实模型 API。

## 组装边界

- 直接加载宿主 `api/plugins.py` 的 v1 与 legacy router、`AstrBotDashboard.auth_middleware`、`PluginPageService`、`PluginRequest` 和 `plugin_page_bridge.js`，不替换鉴权依赖或插件 HTTP 响应。
- `NeoMemoryPlugin` 打开临时来源、记忆、缓存和待写库；配置使用真实 `AstrBotConfig` 写入临时配置文件。样本只有两个人格的合成消息、事件和笔记。
- 测试父页面只实现 GET/POST 的 `postMessage → HTTP → postMessage` 转发，按照宿主 `PluginViewPage.vue` 的接口约定去包裹响应。它没有提供伪造业务返回。
- iframe 与 Vue 页面使用相同的 `sandbox="allow-scripts allow-forms allow-downloads"`，不启用 `allow-same-origin`。因此 ES module 加载实际经过 opaque-origin 环境下的跨域资源校验。
- 测试签名密钥与管理员 token 每次临时生成；不读取本地真实凭据，也不在报告或日志中记录 token URL。

## 已验证结果

| 路径 | 结果 |
| --- | --- |
| 未认证的记忆读取与笔记写入 | HTTP 401；没有写入笔记 |
| 无效或其他页面的路径 token | HTTP 401 |
| 带正确路径 token 的页面与资源 | 页面、6 个 JS 模块与 CSS 全部 200；`no-store` 和 `Access-Control-Allow-Origin: *` 保留 |
| 官方 bridge SDK | 使用页面 token 的请求成功，缺少鉴权失败；实际 SDK 初始化并经父页面调用真实 API |
| 相对模块路径 | `app.js` 及其 imports 继承 `/api/v1/plugins/<plugin>/views/<view>/_t/<token>/`，浏览器正常加载 |
| 四类内容所在的管理页面与来源 | 真实记忆列表可显示；原文必须点击后读取；源文本中的 HTML 被当作文本 |
| 来源空间隔离 | 同一 source ID 在原捕获空间可读，另一人格空间返回 404 |
| 模型参数保存 | 浏览器修改 batch size 后真实配置文件变化；当前运行值保持原值，重建插件实例后新值生效 |
| 设置版本冲突 | 旧 revision 保存返回 409 |
| 浏览器关闭 | queued 笔记任务在页面关闭后由服务器 worker 完成，再打开可查 |
| 插件运行实例重建 | queued 任务随数据库保留；新实例自动执行，仅产生一条笔记 |
| 幂等提交与任务详情 | 同 key 返回同 job ID；详情不暴露 lease、checkpoint、payload |
| 390 px 页面 | 五栏均无横向溢出；桌面与移动截图已目视检查 |

两项 HTTP 集成测试通过；Chromium 脚本通过，页面脚本错误为 0。外部模型请求为 0，不把本轮结果作为模型质量证据。本轮未发现需要修改生产前端的资源或桥接兼容缺陷。
