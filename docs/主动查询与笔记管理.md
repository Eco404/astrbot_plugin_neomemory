# 主动查询与笔记管理

## 查询入口

`neomemory_recall` 在当前人格和会话对应的记忆空间内查询。它接受以下参数：

| 参数 | 含义 |
| --- | --- |
| `query` | 1–4000 字符。记忆使用向量匹配；笔记使用正文中的字面子串匹配，`%`、`_` 不作为通配符 |
| `kind` | `all` 同时查询记忆和笔记；`memory` 查询记忆节点；`atomic`、`event`、`topic` 限定节点类型；`note` 仅查询笔记 |
| `limit` | 两类结果合计的返回条数上限，1–30；0 使用 `recall_max_nodes` 配置默认值。不保证一定达到该数量 |
| `event_after` / `event_before` | 事件发生时间的包含式范围；带时区的 ISO 8601 时间，或按 UTC 解释的日期。日期形式的结束范围包含当日最后时刻 |

事件时间按区间交叠判断，只有一个数值边界时视为一个时点。启用时间条件后，没有数值事件时间的记忆被排除，不临时解析自然语言时间；笔记的编辑时间不等于事件发生时间，因此笔记也被排除。类型和时间条件在已读取快照中先筛选，再进行相似度排名，最终返回前再次检查节点状态和条件。

主动记忆查询仍受当前召回快照容量约束，`recall_index_limit` 最大为 2000。这里的类型与时间筛选没有改造成全数据库的精确历史搜索，不能据此承诺找到快照以外的旧节点。抽取时分页查找旧事件的管线与该主动查询范围不同。

AstrBot 当前工具注册器使用 JSON Schema `number` 表达数值参数；工具描述明确要求 `limit` 为整数，运行时拒绝小数、布尔值和范围外输入。

## 结果与预算

返回内容使用同一个资料封套，记忆和笔记按顺序交错选择完整条目，合计遵守一个条数上限和字节预算。沿用配置名 `recall_budget_tokens`，实际估算仍按 UTF-8 字节保守计量，封套和元信息也计入；不能容纳的条目整体跳过，后续较小条目仍可被选中。

最终合流使用有界匹配候选池，并在同一读事务中重新检查当前代、节点版本、可召回状态和覆盖关系。只有在实际主动查询封套及已选笔记占用下仍能完整返回的事件，才能省略其明确完整覆盖的原子；事件放不下或已禁用时，仍可返回能容纳的原子。此过程复用同一次向量匹配结果，不重新查询模型。

每条结果显式标记 `source=memory` 或 `source=note`。记忆沿用节点正文渲染，保留类型、状态、事件时间和情绪等可用元信息，逻辑用户引用渲染为当前昵称；展示标题不替代正文。笔记保留独立身份和正文，并明确说明计划、想法不能证明事情已经发生。

仅最终实际返回的记忆节点参与召回强化；笔记和因预算未返回的节点不获得强化。笔记查询不依赖 Embedding：没有配置向量模型、向量调用异常或超时时，仍可以返回匹配笔记；`kind=note` 不进入向量管线。向量步骤使用独立的剩余截止时间，为本地笔记读取和返回留出余量。笔记在耗时步骤之后读取，避免返回等待期间已删除的内容。

## 笔记管理

新笔记由 Agent 通过 `neomemory_notes(action="create")` 创建。WebUI 用于查阅和管理已有笔记。

WebUI 和 `neomemory_notes` 工具都支持 `delete`。归档可用 `restore` 恢复；删除后条目不再出现在 active、archived、all 列表和主动查询中，不能用恢复或普通修改使其重新出现。数据库保留删除状态及删除时间，当前没有自动物理清理策略。

WebUI 删除通过条目内的确认和取消按钮完成，不依赖浏览器原生确认弹窗，以兼容 AstrBot 插件 iframe。提交失败保留编辑草稿和重试请求标识。WebUI 写入继续使用后台任务，校验所属空间与 `expected_updated_at`，同一请求标识重复提交复用同一任务；已提交后进程中断，重试从提交凭据恢复，不重复变更版本。工具直接写入仍遵守当前空间和任务占用规则。

## 验证范围

- `tests/test_active_recall.py` 验证事件时间、类型、完整条目交错、共享预算以及覆盖事件未返回时的原子回补。
- `tests/test_active_tool_contract.py` 使用真实存储和宿主工具注册器，验证无向量配置、向量故障、笔记删除并发、覆盖与节点状态变更、历史节点可查、仅返回条目强化及参数传递。
- `tests/test_note_delete.py` 验证空间隔离、版本冲突、删除不可恢复、重复提交及进程恢复；API 测试覆盖删除路由。
- `tests/ui/full_smoke.py` 在真实 Chromium 中验证笔记删除确认、失败保留草稿和重试请求。页面桥接使用合成数据，不代表实机认证或实际 Provider 测试。

这些验证覆盖功能和管线边界，不证明真实向量模型的排序质量，也不代表实机部署已经更新。
