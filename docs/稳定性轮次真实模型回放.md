# 稳定性轮次真实模型回放

日期：2026-10-29（北京时间）。环境为 Conda `astrbot`、AstrBot v4.29.3。脚本：[verify_stability_api.py](../scripts/verify_stability_api.py)。本轮扩展阶段六有限样本，使用已提供的 `gpt-6-luna` 和 Cloudflare `@cf/baai/bge-m3`，不改变生产提示词或超时默认值。

## 方法与判定边界

输入只有脚本内合成角色和消息，经过正式原始库、后台抽取任务、schema、来源校验和记忆事务。原始/派生/缓存库在临时目录创建，退出清除；不保存模型正文，不上传用户聊天或角色卡。只输出安全错误码、断言、计数和耗时。原始库正常清理策略没有因此改变。

任务最多尝试1次，SDK重试关闭；宿主内部发出的每次HTTP也计数。使用生产默认60秒抽取截止。测试消息门限降为3条，目的是以少量合成输入测试正式管线，不代表验证默认群聊频率。词法规则只针对这些固定样本，不等价于通用语义判定或总体准确率。

初始预算为总8次、LLM最多6次和Embedding最多2次。首轮4次LLM后发现评估规则需区分“旧偏好出现”与“当前明确否定”，将剩余4次分配为LLM最多3次、Embedding最多1次；本轮累计上限为LLM7次、Embedding1次、总8次，不为了全绿继续扩大预算。

## 评估器修正及有界补验

修正仅涉及评估脚本，未修改生产提示词：

- 旧词完全缺席记为 `old_absent`；每次出现均处于明确当前否定，记为 `old_only_explicit_current_negative`。
- 历史句或删除明确否定片段后仍有旧词，记为 `old_positive_or_ambiguous`，有限规则不通过。例如“以前不喝咖啡”不能充当现在不喝的证据。
- 当前偏好不允许显式否定；群聊不能仅凭两个人都含“摄影/钢琴”而通过，必须排除互斥爱好串人；假设养猫同时检查画像与生成的节点。
- 网络或结构失败始终为 `not_evaluated`；不将空产物计为“正确丢弃”。这些规则均有离线反例回归。

追加命令只运行私聊依赖链和向量，不重复已经通过的独立场景：

```bash
PYTHONPATH=/workspace/astrbot/AstrBot:/workspace/astrbot/astrbot_plugin_neomemory \
  /home/coder/apps/miniconda3/envs/astrbot/bin/python scripts/verify_stability_api.py \
  --only preference --http-budget 4
```

节点正文和查询一次批量Embedding，发送前限制去重条数不超过16、总UTF-8文本不超过16000字节。后续索引复用同空间相同文本的message缓存填入节点版本键，热召回继续复用；分别记录两步新增HTTP。此验证不代表冷启动被动召回延迟。追加运行的其他空间为空，相关断言只说明没有误用当前空间向量，不作为两个已索引空间的隔离实测。

| --- | --- | ---: | ---: |
| 初始黑咖啡偏好 | schema、当前偏好与长期节点规则通过 | 43.8282秒 | 1 |

| 第二次修正与其后向量验证 | 依赖规则未通过，未评估 | — | 0 |

修正规则后仍不能在有限判定中确认画像只含当前事实，属于**尚未解决的质量问题**；不把 `ambiguous` 当作已经证实模型记错，也不把任务写入成功等同于语义完全正确。当前脚本没有保留足够正文供事后判别具体表达，后续需在隔离合成评估中引入可审阅、短暂保留的必要片段及人工语义判断，再决定是否调整提示词。不得为通过测试而让模型机械删除所有旧饮料词，因为“不再喝咖啡”也可能是有效当前事实。

## 独立实际向量验证

偏好链累计使用6次LLM后不再重复。为避免独立向量检查被阻断，剩余2次额度改为独立场景：1次LLM生成当前偏好节点，1次Embedding同时处理生成节点与查询，不声称该独立场景补齐第二次偏好修正。

```bash
PYTHONPATH=/workspace/astrbot/AstrBot:/workspace/astrbot/astrbot_plugin_neomemory \
  /home/coder/apps/miniconda3/envs/astrbot/bin/python scripts/verify_stability_api.py \
  --only recall --http-budget 2
```

独立运行开始于18:21:40 UTC+8，脚本退出码0：

| 步骤 | 结果 | 耗时 | HTTP |
| --- | --- | ---: | ---: |
| 从合成对话抽取当前黑咖啡偏好 | 正式任务成功，生成1个长期节点，画像规则通过 | 35.6725秒 | 1 LLM |
| 实际生成节点与查询合批向量、索引与热召回 | 召回该节点，ID来自实际生成空间，预算与默认截止满足 | 0.6376秒 | 1 Embedding |

message向量转为带正文版本的node缓存键时新增HTTP为0，热召回新增HTTP为0。跨空间检查使用空的另一空间，结果为空；这是隔离的窄证据，不作为两个已索引空间或真实多用户并发的测试。0.0033秒只对应1个节点的预热本地召回，不与2000节点性能测量混为同一负载。

## 本轮结论与遗留问题

三次有界运行共 **8次实际HTTP：7次LLM、1次Embedding**。前两次脚本退出码1，独立向量脚本退出码0；不能称整套真实回放全通过。费用和token用量未采集，不推算模型成本。

已获得普通寒暄选择性丢弃、多人画像归属与轻量限制、一次偏好修正后原节点保留变化历程、真实生成节点经过真实向量召回与复用的有限证据。连续第二次偏好修正仍未评估，当前画像的旧偏好表达仍需核对。各断言是schema/来源验证加针对固定样本的词法检查，不是通用语义准确率。

下一轮首先解决评估证据不足：隔离合成场景下临时保留最小必要的画像片段供人工审阅，区分“明确当前否定”“历史描述”“错误正面事实”“规则无法识别”，审阅后清理、不提交生产聊天或密钥。确认问题后再决定提示词调整，并扩大连续修正、不同表述和群聊样本；不依据当前聚合结果擅自改变画像数据语义。
