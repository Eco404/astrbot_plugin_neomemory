# 抽取保真改进轮次参考研究

日期：2026-11-02。对应[实施计划](抽取保真改进轮次实施计划.md) F1/F3。研究范围为本地已核验的公开源码、既有独立合成诊断与评估方法；未读取用户提供的真实会话、转换/回放正文、角色卡或密钥，也未由这些内容构造案例。

本轮关注两个相邻问题：事实被选择保留后，压缩表达是否改变其成立条件；事件与原子文字不完全相同时，模型是否过早声明能够完整替代原子。已有合成诊断表明，某些遗漏在模型候选里已经存在，单纯增加存储检查不能修复。事实主体、画像当前态与关系主观视角继续作为回退维度。

本轮再次只读核对上述源码段落、检出提交及许可证；没有运行这些第三方引擎，没有复制其源码或案例到生产提示词。提交日期仅说明本地核对版本，不代表远端最新状态或质量保证。采用的是公开设计原则和本项目原创规则表述。

评估方法复用[条件保留研究](画像条件保留轮次参考研究.md)中已核验的 [QAFactEval](https://aclanthology.org/2022.naacl-main.187/) 来源问题思路和 FRANK 的分类评估动机，本轮没有重新宣称全文阅读、复现实验或指标移植。只从输出提问会漏掉已经被省略的条件，因此仍须在调用前冻结来源问题，同时检查遗漏与无依据断言。

## 2. 单一候选假设

候选 `extraction-prompt.v5` 保持 `extraction.v2` schema，围绕一个方向：**将选择性保存与不改变所保留结论的压缩分开，并用可独立替代的标准判断完整覆盖**。

这不是新的数据语义。v3已有完整覆盖定义和当前画像/长期历程边界；v5只重述两处生成规则，假设更直接的表达有助于模型执行这些既有约束。具体变化为：

1. 在选择性段落增加：可以舍弃独立事实；一旦保存结论，就保留使结论成立的范围、频率、数量、持续时间、排他性、否定和不确定性。进入历史历程也不消除旧限定；主题标签可简短，但事实标签不能扩大断言范围。
2. 将 full 的条件改写为：读者只看到事件最终正文、不再看到原子时，仍可明确得到原子的全部必要信息。需要依赖原子、来源或常识补出的细节不算已表达；表达部分内容时用 partial，不确定时不声明 full。

候选没有新增案例、字段、检查模型或生产调用；没有要求每窗必须形成画像/节点，也没有要求事件必须复制所有原子。部分事件概述仍可保留为 partial，合法 no_change 仍然有效。原有画像更新、当前否定、来源归属、关系视角及版本规则逐字保留。

与v3相比，完整系统消息及schema从10,353字符 / 15,989 UTF-8字节变为10,554字符 / 16,580字节，增加201字符 / 591字节，按字节约3.7%。这不是token测量；实际token和延迟由后续对照报告。

预期收益是减少范围扩大、频率/排他性等限定遗漏与错误full。可能代价包括正文更长、过于保守导致较少full、输出负担增加导致协议或选择回退。保守full可能增加召回文本预算，不能把“full数量下降”直接当语义改进；最终仍要逐项核对事件/原子及实际省略行为。若候选只输出空结果、漏选应保留事实或出现新增归属/条件错误，按既定门槛不升级默认。

## 3. 版本与实现边界

`core/prompts.py` 提供显式 `prompt_version` 选择，v1 schema默认仍选v1模板，v2 schema默认仍选v3，v5仅适用于v2。未知版本、已撤回v4以及不兼容schema组合直接拒绝，不静默回退。

`ExtractionService(..., prompt_version=...)` 在准备输入时固化版本到 `PreparedExtraction.prompt_version`。版本参与 `input_digest`，渲染消息与提交凭据使用该批次版本；默认服务仍为v3。相同来源对应相同批次身份，不能通过改提示词版本绕过已完成凭据后再次抽取。已保存的合法准备批次可以按其显式版本应用，不能被当前服务默认重新标记成另一版本。

本轮真实对照直接使用独立 `ExtractionService` 准备、调用和应用，未接入生产后台调度器，因而不修改维护任务的v3默认或签名。调度器重试、检查点及恢复由既有和新增模拟故障测试单独验证，不能据此声称真实v5已经跑过完整后台管线。若未来候选进入生产默认，仍须同步维护任务签名等外层版本边界，避免跨版本复用旧检查点。真实候选能否进入默认由完整F4/F5决定，不能依据本文件或单元测试先行升级。

新增 `tests/test_fidelity_prompt.py` 验证改前v1/v3系统模板散列保持不变、候选不改变数据消息与schema、非法组合拒绝、输入摘要和准备快照的版本区分，以及真实临时数据库中的候选凭据/重复提交边界。与原抽取schema和应用测试合计91项通过，所涉Python文件Ruff通过。这里的假模型/空结果用于工程不变量，不计为真实模型保真验证；本分工未调用API。

## 4. 未解决项

提示词无法强制证明语言上的等价或完整覆盖，schema也不能判定事实正确。本候选不增加结构化事实证明、不调整full持久化语义、不静默修JSON。若有界对照仍失败，保留v3和完整结果，按[后续路线](后续开发路线.md)进入独立的1B/1C实验，而不是在同一版本中连续追加规则直到已见材料通过。
