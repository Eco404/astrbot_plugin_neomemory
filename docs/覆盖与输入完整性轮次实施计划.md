# 覆盖与输入完整性轮次实施计划

日期：2026-11-02（UTC+8）。状态：本轮研究、离线对照、宿主候选及复核完成，见[执行记录](覆盖与输入完整性轮次执行记录.md)；生产默认和宿主尚未接入修复。对应[后续路线](后续开发路线.md)1B/1C；前置为[1A复核](抽取保真改进轮次执行记录.md)。

## 1. 目标与冻结边界

上一轮说明，仅加强提示词没有达到采用门槛：错误full可能让必要原子未进入上下文，画像整体更新会遗漏旧限定，宿主内容回退还可能改变已经准备好的抽取输入。本轮分别处理这些问题，不再将其合并成一个提示词候选。

生产基线为AstrBot v4.29.3（abf683071）、extraction-prompt.v3、extraction.v2、memory.db v7。本轮真实LLM、Embedding及在线裁判预算均为0；不读取用户私人会话、角色卡或凭据，不修改上一轮冻结实验，不用私人材料构造案例。复用本地公开参考代码、独立合成场景和真实宿主配合模拟HTTP。

交付是覆盖方案的离线证据、画像轻量更新的具体建议，以及可在现有接口内安全完成的宿主输入修复。覆盖默认、画像结构与新增生产调用不在本轮直接升级范围；需要改变这些语义时，形成有成本和备选项的Proposed ADR供讨论。若宿主没有可靠公开接口，不以全局补丁或修改共享Provider配置掩盖缺口，应保留隔离验证和明确后续方案。

## 3. 接口与文件安排

- `adapters/providers.py`承载宿主局部适配；如果增加错误类型，维护任务应保留失败和来源，不将输入完整性问题当成已完成抽取。需要新的恢复语义时先写明ADR。
- `core/retrieval.py`保持生产默认。离线策略优先在`scripts/coverage_policy_probe.py`中组合实际选择函数；如果必须增加测试入口，应显式可选且默认保持现状，不建立第二套生产排序器。
- `tests/`新增针对真实故障行为及输入/提交边界的测试，不通过模拟模型成功来宣称事实质量改善。
- 研究分别写入覆盖、宿主输入、画像方案文档。最终执行记录统一汇总，不把多个独立结论混成总通过率。
- 运行证据写入忽略的`data/evaluations/`；正确性所需的生产凭据继续由既有持久存储负责，不放入可清理缓存。

## 4. 对照方法与可解释性

覆盖试验使用原创合成节点和人工事前定义的事实要求，不读取真实会话；每个策略接收相同节点、分数、状态、覆盖和预算。除默认策略外，至少比较保留双方的保守基线，必要时考察精确文本证据，但不能将子串关系当作通用语义证明。紧预算下新增原子可能挤出其他节点，必须报告这类转移损失；“不因覆盖删除”不等于“保证所有事实进入上下文”。

输入验证使用真实AstrBot Context、Provider、SDK及MockTransport，无外部网络。分开观察网络重试与内容回退，不能只看SDK重试数。配置并发/截止、准备快照、候选持久化、提交凭据和来源消费的现有约束继续有效。生产全调用链的实际HTTP硬上限若未实现，应明确列为未完成，不用本轮实验预算替代。

画像方案先依据已有实现确定边界：减少未触及内容被重写与防止模型漏选是不同问题。精确定位旧文本能够防止错误应用，但不能判定新文本是否完整真实；合法no_change、低价值舍弃及群成员短画像继续保留。

## 5. 提交与完成检查

先提交计划及用户授权纳入的`.gitignore`角色卡忽略项；之后每个可独立验证的实现完成后本地提交，不推送远端。结束时检查成果和过程：是否改变默认/存储语义，是否引入额外调用，是否夸大模拟测试，是否有新产品决策被藏在代码里。

本轮完成不等于收敛阶段1全部通过，也不等于稳定发布。后续真实模型对照另行冻结材料、版本和预算；覆盖默认或画像协议变化应在本轮具体方案与证据基础上决定。
