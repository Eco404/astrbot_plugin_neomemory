# 陪伴插件输出标记与原始记录

在设置页的“文本清理”中可为所有空间配置人格输出的清理规则。修改保存后即时生效，重启后仍保留。已入库的原始记录按采集时的正文保存。

- 固定文本按字面匹配。替换内容为空会删除所有匹配，也可填写新文本。
- 正则表达式支持 Python 语法、递归子模式和可变长后顾，替换内容支持捕获组。例如匹配 `<voice>(.*?)</voice>` 并替换为 `\1`，即可保留两标签之间的单行文字。
- 启用的规则按全局执行顺序依次作用于前一条的结果。拖动条目调整其优先级，拖动分组移动整组条目。新条目追加到所选分组末尾，未选择分组时追加到一级列表末尾。编辑条目时保留原位，更换分组则追加到目标列表末尾。分组关闭会暂停组内所有条目，恢复分组后沿用各条目自己的开关。
- 默认分组“陪伴插件文本清理”使用可编辑的正则条目处理下表中的格式。每条规则都有独立的匹配内容、替换内容和开关。例如编辑“行内分段标记换行”的替换内容，就能改变两段文字之间的分隔符。默认条目跳过在 Markdown 代码示例和显式引用中出现的标记。

陪伴插件会在模型回复、消息分段及实际发送等不同环节消费这些标记。NeoMemory 可能在发送前读到回复，因此在自己的采集入口处理正文。普通回复适用于私聊和群聊，无需开启外部记忆联动。主动消息通过陪伴插件的已投递回执接入。

| 陪伴插件使用或处理的格式 | 写入 NeoMemory 的内容 |
| --- | --- |
| `<<PRIVATE_COMPANION_SPLIT>>`、分段占位符 `{{split_marker}}` | 保留两侧文字。行内边界转换为换行，单独占一行的标记移除。支持规范拼写以及分隔空白、全角和 HTML 转义形式。 |
| `<pc_reaction_expression>`、`<pc_member_safety>`、`<personality_sync>` | 移除标记和内部载荷。表情意图、成员策略与人格同步内容不作为当事人的发言。 |
| `<pc_tts>`、`<tts>` | 保留朗读文字，移除语音包装和其中的表演指令。外侧译文也保留。 |
| `&&angry&&` 等表情投递标记 | 移除格式明确的标记。Markdown 代码中的示例和普通逻辑表达式保留。 |
| 泄漏到回复中的思考、定时器、宿主上下文、记忆参考块 | 识别已知包装，如 `<think>`、`<system_reminder>`、`<core_memory>` 和 `<reference_data>`，移除完整内部块。 |
| DSML 工具调用、文本发送包装 | 移除工具调用及其参数。从文本发送包装提取要发送的正文。 |

采集时分别识别用户原话、人格自己的文字及转发作者的文字。清理也作用于人格图片附言和其中的外层文本组件。纯控制符回复不产生新的普通会话消息，主动回执同步仍能越过该条记录。

核对的陪伴插件实现为本地 `43a6dd99`（AGPL-3.0），包括 `segment_control.py`、`text_processing.py`、`voice_markup.py`、`reply_intent.py` 和 `core_reply_media_delivery.py`。NeoMemory 根据这些协议独立处理格式，无需在运行时导入陪伴插件。清理按可识别的字符和结构执行，模型自由改写成自然语言的内部意图无法可靠识别。[清理实现](../core/companion_rules.py) · [合成回归用例](../tests/test_companion_markup.py)
