# 主题组织与持续维护

> 开发期专项计划。文中的版本号、部署与验收记录对应当时的评估。正式版规范见[文档索引](README.md)。

## 目标与边界

当前事件粒度保留。不同场次、对象和独立经历分别保存；同一经历延续时更新原事件，重复新建仍需纠正。不能以减少界面条目数量为由扩大事件合并。主题负责表达多项记忆之间有持续意义的关联，既有连贯概况，也作为成员事件的检索入口。不强制所有事件拥有主题，不以topic数量或占比评优。

有效契约见[ADR-0041](adr/0041-topic-consolidation.md)。人物归属、人格自然表达、事件身份、只保留有意义内容、完整正文及来源追溯要求继续适用。私人会话只作最终评估，不用于调整提示词、规则、参数或制作专用夹具。

## 当前能力与验证边界

主题专用协议、成员集合及版本依赖、真实来源追溯、后台整理任务、低频调度、重构末尾整理、持久恢复和索引已接通；主题召回的相关成员选择及WebUI成员/所属主题浏览已实现。代码接通不等于所有主题边界都稳定，实机状态与部署证据应以对应报告为准。

独立双模型比较支持专用整理发现跨经历主题和维护成员，但在归属模糊的活动上仍有漏归类或判据歧义。当前topic-prompt.v7提供可见成员结构与逐来源观察时间，保留既有主题职责；输入依据更完整不等于语义独立性已得到可靠判断。双模型实际后台连续链验证了明确关系材料的主题创建、多重归属更新、无关经历不更新，以及不改事件、不重复消费来源或推进活动轮次。详细结果、开销、失败及范围见[主题判断与连续链评估](evaluations/topic-consolidation-20261117.md)。

另有[真实来源到召回全链](evaluations/topic-full-chain-20261117.md)，实际执行普通抽取、自动结构纠正、主题整理和真实向量召回，没有手填成员节点。该链发现省略主体被主题升级为人格亲历的问题；当前提示词提供按内容版本追溯的有限来源角色原话，[独立多主体与实际错误修订](evaluations/topic-subject-evidence-20261117.md)验证明确人格误归可纠正，真正共同参与与第三方归属可保留。部分旧文本仍省略主体，仍需后续观察。

固定两个问题的有/无topic回答对照均保留关键事实，小语料下主题增加冗余而未显示额外回答收益。不能把主题数或成功召回替代使用价值；大空间、多人、长期运行和更多自然问题仍需验证。

候选归属采用完整显式父主题与只读关联目录，避免材料中出现成员却看不到其已有组织，也避免递归加载整张图。[独立父主题上下文验证](evaluations/topic-parent-context-20261117.md)中，两模型均保留主题身份、补充成员且不改只读旁支；仍有概况遗漏新增进展的情况。工程检查见[主题工程验收](evaluations/topic-engineering-20261117.md)，实机结果见[主题整理与召回评估](evaluations/topic-live-20261117.md)。

## 交付与退出条件

| 工作 | 交付内容 | 退出条件 |
| --- | --- | --- |
| 职责与独立判据 | 原子、事件、主题边界，正反例、共同成员及更新规则 | 判据先于模型调用冻结；不靠减少事件数证明成功 |
| 模型判断 | 既有联合抽取与主题专用输入的独立比较 | 报告创建、延续、无变化、误归类、事实与人格归属，以及调用和恢复开销 |
| 成员与依赖 | 成员引用、版本依赖、原始来源追溯、原子提交 | 不伪造本批消息，不改成员正文，成员增删与主题正文一致 |
| 后台归纳 | 有界局部候选、低频自动整理、手动任务、持久检查点和恢复 | 不重复消费来源、推进活动轮次或重建事件，同空间互斥，失败可查看与继续 |
| 召回入口 | 主题及少量相关直接成员在现有预算中组织 | 无被动生成调用，不从contains推断覆盖，严格类型过滤保持 |
| 浏览 | 主题/事件/原子职责明确，成员与所属主题可查 | 用户无需猜测列表粒度，来源和版本仍在当前条目展开 |
| 实机评估 | 固定程序/配置/方法后的运行、整理及模拟召回 | 工程、模型质量和实际注入分开报告，保留失败与未验证范围 |

## 独立验证

[陪伴主题的候选发现、建档与召回](evaluations/topic-discovery-and-recall.md)覆盖逐节点邻居排序、日常相处的正反例与自然问题下的实际注入。两个模型在高密度干扰图中均利用了补回的旧事件，陪伴主题提示词的迁移收益仍有分歧。

`scripts/topic_cases.py`定义不来自私人样本的固定材料。`scripts/probe_topic_consolidation.py`冻结材料、提示词、schema、模型与请求上限后运行。普通联合抽取面对当前消息与既有事件；专用整理面对相同事实的已抽取事件和已有主题成员，是任务划分与输入组织的组合比较，不能把收益全部归因于某一句提示词。

必须覆盖持续项目跨事件归纳、同类但无持续关联的不创建、已有主题延续、无意义改写抑制、同一事件多重归属和错误成员移除。真实模型输出逐例审阅，结构合法不代表语义正确；小样本通过不代表跨模型或所有人格泛化。

## 实现约束

普通抽取材料足够时可以顺带维护主题。后台主题整理对本批待处理节点复用已有向量，在批次之外为每个节点优先选择一个达到相似度门槛的邻居。多个节点共享的邻居只占一个位置，其余位置按全局相似度补足。默认最多选择 30 个初始节点，随后展开关联主题的完整成员并附上来源摘录。主题是否成立，仍由模型依据独立经历之间的实际联系判断。

整个候选窗口超过输入预算时，先保留本批待处理节点和它们必须展开的成员，再按顺序尝试加入可选节点。放不下某个节点及其完整成员时，继续尝试后续候选。必选内容本身超出预算时缩小待处理批次，并按剩余节点重选邻居。已准备好的任务从保存的输入恢复。[生产候选与弱关联验证](evaluations/topic-neighbor-production-check.md)

成员普通进展只表示概括可能需要补充；已知错误沿用summary_stale规则。成员自然淡忘不要求同步擦除概括，人工保护不因自动整理失效。主题不自动全文覆盖成员，不改变现有event→atomic覆盖合同。

新增成员限可用active节点；更新既有主题可保留其已有historical成员，保留历史含义而不恢复旧事实的当前资格。成员状态、正文与强度不随整理改变。已有成员disabled、deleted、superseded或summary_stale时，自动更新须暂停复核，不能通过候选重生成移除成员绕过治理；准备后的状态变化仍使快照失效。topic-prompt.v6在首次输入与候选反馈中明确同一规则，协议仍为topic-consolidation.v1，无数据库迁移。

已有主题的更新须提供完整成员引用及必要正文。主题版本依赖具体成员内容版本，记录使用依据而非推断“已知事实都被重新证明”。有限原话证据用于分清行动主体，来源不足不授权模型猜测人格亲历，也不应把全部行动归给用户。重构按当前配置重新生成派生主题，不迁移人工治理历史。

普通抽取与专用整理共用成员依赖及累计来源查询的写入逻辑。普通抽取只更新明确声明的contains成员版本，以及显式版本依据中属于已有成员的部分；未触及成员保留原依赖，不因数据库已有新版便冒充本次使用了新版。包含本批新建或更新成员的显式contains使用提交后版本，显式旧节点依据使用准备时快照。专用整理依据完整最终成员集合替换依赖，并同步成员增删。

正文新建或变化时，明确使用的成员版本进入正文推导依据；普通抽取仅关联成员、同文关联或只改标题时，另记membership操作，不作为旧正文的生成依据，也不重置正文版本和强度。版本页面区分成员关联与正文来源。累计来源用于查阅，不能替代具体版本的直接引用及继承依据。

空changes没有声明新的依据，不补造缺失的历史依赖，也不改变正文或凭据。已有缺口需通过完整上下文中的显式确认，或按当前规则重构新代建立；显式确认记录的是本次评估依据，不回写原始创建历史。相关工程验证见[主题依赖一致性](evaluations/topic-dependency-consistency-20261118.md)。

## 来源与成员结构

当前可见事件与原子的contains关系传入普通抽取和专用整理，帮助识别同一经历的上下层，不扩展候选数量。新建主题至少两个不同成员的结构要求在两条写入路径一致，旧主题更新仍可保留一个成员；语义独立性由正文、时间及有限来源综合判断，不能按ID或来源不相交自动证明。来源展示UTC观察时间，未知本地时区不作推断；结构快照变化需重新准备。具体契约见[ADR-0048](adr/0048-source-observation-topic-structure.md)，固定图局限见[独立对照](evaluations/topic-organization-inputs-20261118.md)；[真实前序连续链](evaluations/topic-grounding-chain-20261118.md)仍发现事件累计、时间元信息滞后和成员语义独立性问题。现用部署与完整评估进展统一见[部署状态](evaluations/live-full-0c84538-20261119.md)，不把独立小链或旧协议终态视为当前完整实机验收。
