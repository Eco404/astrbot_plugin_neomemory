## 一致性和兼容行为

- 原始来源按捕获时的作用域校验，不要求已经成功抽取，也不随当前 generation 切换而丢失查看入口。失败窗口可从任务详情显式打开原文。
- 笔记变更是后端持久任务；浏览器关闭不影响执行。自动笔记写入也受同空间任务锁约束；人工编辑携带 `expected_updated_at`，旧页面不能覆盖新内容。笔记不随重构清除。失败的人工正文可在任务候选中查阅；重新编辑必须刷新笔记，不能绕过旧版本检查。
- 设置写入宿主配置后显示“需要重载”，运行中的不可变配置不变。插件关闭等待已接纳的保存完成。宿主其他配置入口改写同一文件时，显示外部修改并阻止继续保存，需从宿主重载；不声称能够跨进程串行化最后检查与落盘之间的竞争。
- `short_term_provider_id` 空值继承长期模型，也允许单独配置短期模型。Provider 探针使用正式适配层和共享并发，不写记忆。结果只保留成功状态、模型、耗时及向量维数。
- `models/test` 兼容路径改为 `models/probe` 的后台任务合同，要求 `idempotency_key` 并返回 `{job: ...}`；旧调用方必须适配，不能继续等待同步的 `{ok: ...}`。
- 默认人格继续跳过；导入导出、原始自动清理、退休代回切、自主活动及大型索引改造未纳入本阶段。

## 复核中发现并修复的问题

1. 设置持久化可能与插件关闭交错，使下一实例读取旧文件。新增关闭排空，测试用可控保存过程验证关闭确实等待落盘。
2. 插件关闭先解除公共组件引用时，正在执行的模型测试可能把成功结果误判成 Provider 故障。任务服务绑定稳定依赖，接纳新任务仍检查运行状态；关闭交错测试验证成功或可恢复取消均不会伪造故障。
3. 同一空间从节点 A 切到 B 时，A 的迟到原文可能仍显示在 B 旁。切换详情使原文请求失效并清空面板，浏览器加入延迟原文回归；空间和任务切换也有同类保护。
4. 维护详情原先不能方便查看失败笔记正文及未抽取原文。补充安全候选展示和按任务作用域读取来源入口。

独立复核另外验证了笔记跨数据库连接互斥、租约替换后旧 worker 拒写及原文归属，没有留下已知阻断问题。用户原有 `.gitignore` 修改保留，不随功能提交。真实 API、角色卡、运行库和参考仓库未纳入提交。

## 升级、回滚与下一轮入口

memory.db 从 v6 正向迁移至 v7，新增笔记完成凭据；source/cache/ingress 版本不变。没有自动降级。回退代码前停止插件并使用匹配版本的一致数据库备份，不只替换单个仍有 WAL 的数据库文件。前端与 API 应使用同一版本，尤其注意模型探针响应合同变化。

本轮没有新的产品或架构问题需要用户先行拍板。阶段六的功能闭环完成后，建议下一轮先进行稳定性与质量调优，再进入阶段七扩展：

1. 在实际宿主页面验证登录、桥调用、反向代理下的资源路径与页面关闭后的任务恢复；扩大真实会话回放，覆盖多人群聊、低价值内容丢弃和连续偏好更正。多模型比较等待有更多可用 LLM 时纳入。
2. 对热召回分阶段 profiling，量化 JSON 向量读取、归一化、评分和锁等待，测试低配置设备、长正文与并发；保持当前上限和截止。现有数据尚不能证明应采用哪种大型索引。
3. 观察真实失败恢复、顺序窗口阻塞及历史任务增长；只有证据支持时再设计调度、清理或存储优化。原始库清理与导入导出继续另立计划和 ADR。

这些是验证与优化范围，不影响本阶段已经交付的查阅、治理、后台任务和配置功能。
