# 抽取请求能力接入计划

## 目标与边界

阻止宿主因上下文超限删减会话后，插件仍将未完整处理的窗口记为成功。长期抽取、重构窗口和短期摘要均使用持久恢复机制，需要分别验证请求失败与检查点复用。普通聊天、模型连通性测试、采集与召回不因结构化任务的请求策略改变。

当前可供接入的公开候选能力为 `no_context_truncation.v1`，参数为 `allow_context_truncation=False`。该能力只阻止宿主的上下文超限删消息回退，不代表任意输入改写防护，也不代表 HTTP 次数硬上限。候选宿主实现位于独立副本，正式宿主没有此能力。

当前不修改宿主、不启用候选保护入口，生产保留既有兼容行为及已知输入截断问题；优先推进召回预算等独立优化。纯插件回显方案只能缓解整个数据消息丢失，不能替代此能力，也未启用。

官方最新稳定标签v4.29.4与主分支 `68acac91b` 均未提供所需能力，缺陷已在两者独立复现。仅提高最低版本不能解决问题；正式版本具备能力后可以提高最低版本要求。核查与适配器验证见[版本核查](evaluations/input-policy-adapter-20261111.md)。

## 实现范围

| 工作 | 交付和完成条件 |
| --- | --- |
| 宿主契约核对 | 在独立宿主副本检查 OpenAI Chat/Responses 的能力声明、参数转发、网络重试与取消；不改动现用宿主的其他工作 |
| 请求适配 | 识别公开能力，显式请求禁止截断；实际请求绑定已检查的 Provider 实例，不向未知 Provider 盲传参数 |
| 恢复一致性 | 任务签名包含请求策略和能力；未经该策略生成的旧候选不能直接按新策略提交；已提交回执仍正常恢复 |
| 失败与维护 | 不支持能力与普通网络失败可区分；失败不消费来源、不推进摘要覆盖；页面说明当前能力与恢复方法 |
| 调度 | 根据确认的兼容策略处理不支持的模型，避免自动反复创建相同失败任务；采集与已有记忆读取继续工作 |
| 验证与交付 | 针对性回归、独立宿主契约、全量回归和打包检查；当前说明与实际实现一致，未验证范围明确 |

## 验证矩阵

- 完整输入正常提交；上下文超限仅发生完整请求，不发送删减后的数据。
- 临时网络故障可按宿主原策略重试，每次来源文本一致；插件不增加即时重试层。
- 严格调用与普通聊天并发不互相改变；排队期间替换 Provider 不绕过能力检查。
- 未支持的 Provider、旧检查点、配置/能力变化、取消与超时均不提交不完整结果。
- 长期失败保留来源和活动轮次，短期失败保留原摘要与覆盖范围；其他空间和读取不被阻断。
- 模型连通性与禁止截断能力分别呈现；一次成功测试不代表获得输入保护。

验证优先使用真实宿主 Provider/SDK 与模拟 HTTP，不需要私人会话或真实 API。结构化事务与传输契约验证不用于宣称模型语义质量提升。
