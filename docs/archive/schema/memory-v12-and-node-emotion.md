# 节点情绪接口与 memory.db v15

规则见 [ADR-0054](../../adr/0054-independent-emotion-intensities.md)。当前`extraction.v9`与`topic-consolidation.v2`使用每标签独立强度，显式v8也保持相同情绪结构，完整生产默认见[提示词契约](../../提示词与输出协议.md)。显式旧v5～v7抽取协议仍按共享强度解析，并在进入存储时规范化。

## 字段与迁移

| 表 | 新字段 | 用途 |
| --- | --- | --- |
| `memory_nodes` | `emotion_json TEXT NULL` | 当前版本的可空情绪内容 |
| `memory_node_versions` | `emotion_json TEXT NULL` | 本内容版本保存时的情绪快照 |

SQL `NULL` 对应 API 的 `emotion: null`；非空内容序列化为如下对象：

```json
{
  "tags": [{"tag": "concern", "intensity": 0.6}, {"tag": "affection", "intensity": 0.3}],
  "description": "{{user:logical-user-id}}担心行程安排，我有些牵挂。"
}
```

标签为固定的九类枚举，1～3 项，去重且 `neutral` 独占。每个标签强度为独立的有限0～1数值，不要求总和为1。说明必须有内容，最多160个可读字符；完整用户引用按一个字符计，每个引用ID最多200字符，编码文本最多33440字符。存储规范化标签顺序，标签换序不产生新版本。

v15将旧共享强度复制到各旧标签，不重新评估情绪；原本为空的节点及版本保持为空。不改变现有标题、正文、版本号、更新时间、重要性、记忆强度或来源凭据。`null` 不是 `neutral`，也不保证历史上没有情绪，只表示没有已保存的显著情绪内容。

## 更新接口

`MemoryStore.create_node(..., emotion=...)` 接受对象或 `None`，省略则为空。`update_node_content(..., emotion=...)` 省略时保留、传 `None` 时清空；正文相同但情绪实际不同仍创建新内容版本，保存新的情绪快照并按内容更新重置强度。仅标题修改继续不推进内容版本。

抽取 `node_changes[].emotion` 对当前 `extraction.v9` 必填，可为 `null`，与标题、正文同次输出。当前支持旧协议的显式回放：不含emotion字段的v1～v4新建节点留空，更新节点保留原值；v5～v7提供的共享强度规范化为每标签独立值。提示词与输出schema必须精确匹配，不能静默接受无情绪字段的旧输出。

人工治理：

| 操作 | 字段 | 省略 / null |
| --- | --- | --- |
| `edit` | `patch.emotion` | 省略保留；null清空 |
| `split` | `parts[].emotion` | 省略或null均为空，不复制原节点情绪 |
| `merge` | `emotion` | 省略或null均为空，不推断合并后的情绪 |

治理调用继续使用 `expected_generation_id`、`expected_versions`、`expected_updated_at` 和后台任务互斥。情绪修改属于内容变更，自动形成基线引用；不额外建立情绪专用版本表或第二套乐观锁。

## 读取、展示及召回

节点列表、节点详情与版本接口返回 `emotion`。Console昵称渲染另提供 `display_emotion`，保留原始稳定引用字段；前端每个标签分别编辑强度，使用原始字段，展示使用渲染字段。历史版本只显示该版本快照。

召回 JSON 对非空情绪增加 `emotion`，其中描述进行昵称替换。渲染后的完整结构先纳入现有预算，再选择完整节点；情绪不会脱离节点单独注入。向量输入仍为正文，未增加独立情绪向量或排序参数。

情绪单改仍推进内容版本，但正文不变时可以复用同模型指纹、同空间和同正文哈希的未过期节点向量。后台索引会写入并读回确认新版本的精确缓存键；仅找到旧版本向量不代表新版本索引已持久完成。缓存过期、被清理或正文/模型变化时按普通缺项补算，不用向量缓存推断内容或任务状态。

旧覆盖证据在内容版本变化后不再参与去重。重新声明 `full` 时需要评价节点完整语义；工程层不会因为原子正文没改，就把情绪更新前的覆盖证明当成当前证明。

## 验证

- [存储与治理测试](../../../tests/test_memory_emotions.py)：空值/中性区别、字段边界、标签换序、长身份引用、三个节点层级、情绪单改和清空、旧库迁移、人工保护、拆合归属及旧协议保留。
- [抽取协议测试](../../../tests/test_emotion_extraction.py)：情绪字段、引用回译和协议约束，与持久写入对接；[独立强度测试](../../../tests/test_independent_emotion_intensities.py)覆盖v8及主题协议、旧共享强度迁移、重复标签和反馈对齐。
- [覆盖版本测试](../../../tests/test_emotion_coverage.py)：事件或原子仅改情绪时，覆盖声明必须使用更新后的版本；旧版本声明整体回滚，成功批次的旧节点上下文、版本历史与待索引节点保持一致。
- [浏览器检查](../../../tests/ui/host_smoke.py)：实际AstrBot路由与临时库进行情绪编辑、历史查看、仅标题预览及拆分表单；同时检查390像素布局。模拟Provider不会证明真实模型的情绪提取质量。

测试使用独立合成数据；没有据私人固定会话调优。旧库不需要原文即可升级。真实模型的有限证据见[v14情绪叙述检查](../../evaluations/emotion-narrative-v14-20261113.md)和[v15旧事件与情绪检查](../../evaluations/semantic-context-v15-20261113.md)；情绪标签、主体和强弱的跨模型与复杂情境稳定性仍需独立验证。
