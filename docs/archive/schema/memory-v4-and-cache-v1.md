# memory.db v4 与 cache.db v1

日期：2026-10-29。v4 在 [memory.db v3](memory-v3.md) 上追加召回所需凭据，不复制记忆正文或原始会话。

## 权威库变更

| 表 | 新增字段/约束 | 用途 |
| --- | --- | --- |
| node_coverage | event_content_version，默认0 | 与既有 atomic_content_version 共同绑定覆盖证据；旧记录没有事件版本，因此保守失效 |
| memory_nodes | last_recalled_at，可空 | 独立记录符合条件的召回时间，不修改正文更新时间；仅有效主动唤醒额外重置强度基准 |
| recall_reinforcements | node_id、content_version、generation_id、turn_id、recorded_at、increment | 24小时内按节点/正文版本/轮次防重复强化；外键随节点/代删除 |

覆盖记录只有在两端同空间、同代、类型正确、两端正文版本一致且 `coverage_kind=full` 时才可抑制原子重复注入。事件未被选中或放不进预算时，原子仍可被选中；`contains` 关系不是覆盖证明。extraction.v2 同一事务提交覆盖与正文变化，v1结果保持可解析。

`retrieval_snapshot()` 在短事务中读取当前代、节点、边和覆盖。默认只含 active，主动查询可以包含 historical；disabled/superseded/deleted 均排除。按重要性、更新时间、ID取最多2000项，超过时返回 truncated。`revalidate_recall()` 在注入前再次检查代、版本及状态，这是时点校验，不阻止返回后的未来人工操作。

仅最终交给请求或工具的节点参与强化。默认被动直接基础增益0.02、邻居倍率0.25、主动倍率2；普通请求增益再乘以 `(1-当前强度)^递减指数`，指数默认1。单轮合计最多0.12，累计最多0.2，默认300秒正增益冷却；这些参数可在高级设置热调整，额度上限不提高。主动与被动共用轮次预算，当前强度在记账事务内使用最新累计值计算。

主动实际返回有效但低于被动强度门限的 active 节点时，独立唤醒到门限加余量所需的最小基准，保留原重要性与累计普通强化。唤醒本次增益为0，复用同轮凭据，不消耗或刷新普通额度，不延长正增益冷却；同轮重复返回不重复唤醒。强化与唤醒不改变正文版本、当前代活动轮次或历史事实状态；关闭期间允许少记一次可选强化，不影响记忆内容。详见 [ADR-0030](../../adr/0030-strength-decay-reinforcement-and-awakening.md)。

## 可清理缓存库

独立 `cache.db` 使用 `PRAGMA user_version=1`，不依赖 source.db 或 memory.db 的外键。

| 表 | 内容 |
| --- | --- |
| embedding_models | fingerprint → 实际 dimension；声明维度为0的模型首次成功后也须保持一致 |
| embedding_cache | cache_key、fingerprint、namespace、kind、text_hash、node_id/content_version（节点型）、vector_json、created_at/accessed_at/expires_at |

缓存键由模型指纹、空间、类别、正文 SHA-256、可选节点ID/版本组成，不保存正文。指纹含 Provider 类/ID、模型、声明维度、去凭据 endpoint 摘要、向量模式与显式 revision。模型身份变化后旧向量不参与新查询；同名模型静默替换时需要修改 revision。

消息与节点缓存分别按条数容量和绝对TTL清理，访问更新时间只参与容量淘汰，不延长TTL。启动和显式cleanup每次最多删除500条；后台默认每30秒触发清理，积压按小批让出执行权后继续。频繁写入不执行全局清理；读取直接忽略过期项。容量是后台清理门限，两个清理周期之间可以短暂超出，不是每次写入后的硬行数上限。向量为空、非有限数、全零、数量或维度不一致会被拒绝。

默认消息上限10000、TTL7200秒；节点上限10000、TTL86400秒。容量按类型全库计算，不是每个空间各一份。消息容量可设0；运行配置中的节点容量至少1，因为在线召回依赖节点缓存。过低容量会引起反复淘汰和补建，应结合空间数量调优。模型维度元数据不会随TTL删除，防止重用相同指纹时混入不同维度；整个缓存库可关闭后清空再生成。

同模型指纹、同空间和同正文哈希的未过期节点向量可以跨内容版本复用；同空间同文消息向量也可以被节点复用。节点读取先查精确节点/版本键，再通过组合索引查同文节点，最后查消息缓存；不扫描全表。后台索引仍写入新节点/版本键并精确读回确认，旧版本向量不能替代完成凭据。查询缓存读取失败按未命中，在当前截止时间内只补需要的查询向量；节点缓存缺失交给后台索引，不在线重算全库。已校验的模型向量不因缓存I/O失败或慢写丢弃，写入有短截止并暴露错误类型；模型维度冲突仍拒绝混用。缓存不是处理进度、失败队列或人工治理凭据；后台索引中断后只重做缺失向量，不能据此推断来源已经完成抽取。

## 来源库兼容补充

source.db schema仍为v1。新的来源 metadata 可记录 `host_conversation_id`，与代表平台会话流的 stream_id 区分。历史补查若知道当前宿主conversation ID，只接受该ID的记录；旧记录缺少ID时不猜归属。无法取得宿主ID时仍按同stream、同persona、时间和条数范围查询。稳定source_id和序号保持原规则。
