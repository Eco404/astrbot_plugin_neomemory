# 私聊图片的文字依据

`source.db` 的 `source_image_evidence` 保存长期记忆抽取实际采用的图片细节。例如海报列出的地点和原定时间可以随原消息重放，聊天正文中的改期仍由独立来源表达。重构可以重新结合两者。原图缓存清理后，模型只能使用已保存的文字依据。

| 字段 | 含义 |
| --- | --- |
| `source_id` | 指向 `source_records` 的稳定来源标识，删除来源时级联删除依据 |
| `slot` | 图片在该来源中的附件编号，从 1 开始 |
| `description` | 模型实际采用的图片细节 |
| `origin` | `image` 表示直接读图，`host_caption` 表示依据宿主描述 |

来源标识和附件编号共同构成主键。某个附件已有依据时，重复提交沿用先前保存的文字。读取按调用方的来源顺序和原附件编号返回。

抽取候选通过校验时，`memory.db` 在同一事务中提交批次回执、记忆变化和 `pending_image_evidence` 的待转存文字。随后将这批文字写入 `source.db` 并清除待转存记录。进程若在两次数据库提交之间停止，可根据批次恢复。写入来源库后重复执行同一转存也能安全收尾。清理或更换派生代际后，已保存的文字仍随来源保留。

`source.db` v6 和 `memory.db` v20 的迁移创建上述表。旧来源的正文、组件和用于验证固定抽取窗口的摘要按原值保留。

升级时尚在 ingress.db 排队的记录沿用原有来源标识和去重键。带内联图片的数据在首次写入 source.db 时转换为无字节的附件占位，使用已入库文本计算内容摘要。既有 source.db 记录可能仍含旧版采集的内联媒体。
