## 1. 项目目标

NeoMemory 为 AstrBot 中的人格 Agent 提供短期连续性、长期经历记忆、用户画像、人格主观关系和自主笔记能力。系统需要支持私聊、群聊、旁听消息、多个社交账户绑定到同一逻辑用户，以及未来接入 Agent 自主活动的输入事件。

系统的基本原则是：

- 原始输入与派生记忆分离保存，原始输入是重构的唯一事实来源。
- 记忆不是所有消息的归档；无意义、重复或对当前人格没有持续价值的内容可以在抽取时丢弃。
- 记忆节点保存可独立理解的自然语言正文，来源、身份、时间、状态和关系由结构化字段维护。
- LLM 只负责受约束的语义判断和文本生成；身份、作用域、时间来源、版本、任务状态和提交由程序控制。
- 被动召回不能默认增加额外生成模型调用，以响应速度优先。
- 所有可能复用的结果优先复用，但临时数据不进入权威数据库；失败恢复所必需的检查点除外。
- 同一记忆空间的写入任务串行，不同空间的独立任务可以受限并发。

## 2. 第一版范围

### 2.1 第一版包含

1. 私聊长期记忆，作用域为“人格 × 逻辑用户”。
2. 用户社交账户到逻辑用户的显式绑定。
3. 群聊记忆和群成员轻量画像。
4. 群消息旁听，使用低频、低结构复杂度的抽取策略。
5. 原子、事件、主题三类记忆节点及关系边。
6. 用户画像、私聊人格关系、短期滚动补偿和自主笔记。
7. 选择性抽取、事件延续、相似事件区分、时间和关系邻域召回。
8. 被动召回和 Agent 主动回忆工具。
9. 记忆衰减、抽取活动衰减和有限召回强化。
10. 失败任务、重试、断点继续和维护页面。
11. 人工修改、拆分、合并、禁用、删除和节点保护。
12. 五栏 WebUI：记忆、笔记、模型、设置、维护。

### 2.2 第一版明确不包含

- 导入导出和跨实例记忆合并。
- 自动清理原始数据库。
- 默认的查询时 LLM 综合叙述。
- 外部图数据库和复杂知识图谱服务。
- Agent 自主活动的具体事件类型；只保留规范化输入接口。
- AstrBot 宿主的精确压缩前后插件 Hook；短期补偿先使用纯插件预判和滚动补偿。
- 自动推断多个账户属于同一逻辑用户；账户绑定由用户或维护页面明确操作。

## 3. 身份与记忆空间

### 3.1 基本身份

系统需要区分以下概念：

| 概念 | 含义 |
| --- | --- |
| `persona_id` | AstrBot 当前实际生效的人格标识，必须使用宿主统一解析结果 |
| `logical_user_id` | 跨平台、跨账户的逻辑用户标识 |
| `account_id` | 一个具体平台实例上的账户标识 |
| `platform_instance_id` | AstrBot 平台适配器实例 |
| `group_id` | 平台中的群组标识 |
| `conversation_id` | AstrBot 的具体会话，用于短期连续性，不作为长期记忆唯一归属 |
| `source_id` | 原始输入记录的稳定 ID |
| `memory_space_id` | 记忆读写的作用域标识 |

### 3.2 默认作用域

- 私聊长期记忆：`persona_id + logical_user_id`。
- 私聊用户画像：`persona_id + logical_user_id`。
- 私聊人格关系：`persona_id + logical_user_id`，只对私聊启用。
- 群聊长期记忆：`persona_id + platform_instance_id + group_id`。
- 群成员画像：`persona_id + platform_instance_id + group_id + logical_user_id`，内容限制为标签和短描述。
- 短期补偿：当前作用域加 `conversation_id`。
- 笔记：默认继承当前人格和场景；未来若需要人格全局笔记，再增加明确作用域。

多个账户可以共享一个私聊记忆空间，但各账户的原始对话输入流分别累计，不能把不同平台同时发生的消息直接拼成一段对话。

跨场景读取必须显式配置。即使允许读取，也要保留来源空间，不能把其他场景的记忆重新标成当前场景发生过的事实。

## 5. 数据库规划

### 5.1 `source.db`：原始事实库

原始库记录用于当前抽取、审查和未来重构的输入，不保存每一时刻的插件配置或人格全文。

核心表建议包括：

- `source_records`：原始 conversation 或未来的 `source_event`。
- `source_participants`：消息发送者、Agent、群成员和其他主体。
- `logical_users`：逻辑用户。
- `account_bindings`：平台账户到逻辑用户的明确绑定。
- `conversation_streams`：输入流、平台、群聊或私聊来源。
- `source_cursors`：各输入流的抽取游标。

每条原始记录至少保留：稳定 ID、来源类型、原始内容、角色或执行主体、`observed_at`、可选的 `event_time`、人格标识、平台和账户信息、群参与者、conversation 来源以及顺序信息。

未来 Agent 自主活动使用相同的规范化入口，但具体活动语义暂不实现。为了避免与记忆中的“事件节点”混淆，原始表中的类型统一称为 `source_event`。

原始记录暂不自动清理。清理策略待长期记忆、召回和重构稳定后单独设计。

### 5.2 `memory.db`：权威派生库

核心表建议包括：

- `memory_spaces`：人格、逻辑用户、群组和场景作用域。
- `memory_generations`：当前派生代和重构代。
- `memory_nodes`：原子、事件、主题。
- `memory_node_versions`：正文版本、更新时间和必要的人工修改信息。
- `memory_edges`：`contains`、`related`、`follows`、`supersedes` 等有限关系类型。
- `node_sources`：节点与 `source_id` 的引用关系。
- `node_participants`：节点与逻辑用户、账户或其他主体的引用关系。
- `node_coverage`：事件正文完整覆盖的原子 ID 和内容版本。
- `user_profiles`：私聊画像和群成员轻量画像。
- `relationship_states`：人格对逻辑用户的主观状态。
- `short_term_states`：短期滚动补偿及覆盖范围。
- `notes`：Agent 自主笔记。
- `operation_jobs`：后台任务状态、阶段、进度和错误。
- `operation_checkpoints`：失败后继续所需的最小检查点。
- `governance_states`：禁用、删除、人工保护和待更新标记。

正文只在实际发生内容变化时更新。来源、参与者、关系和展示名称使用引用，不在多个表复制全文。

### 5.3 `cache.db`：可清空的计算缓存

缓存库不承载记忆正确性，清空后可以重新计算。第一版只持久化明确有复用价值的内容：

- `embedding_cache`：原始消息或节点正文的向量。
- 可选的模型和编码指纹。
- 缓存创建时间、最后使用时间和过期时间。

聚类中心、当前检索候选、排序结果和最终注入文本默认只在内存保存。缓存按类型设置条数、体积和 TTL 上限，启动或维护时批量清理，不在每次请求中执行全库整理。

缓存键必须包含文本内容哈希、Embedding Provider ID、模型、维度、编码配置和版本。模型或正文发生变化时不得复用旧向量。

## 6. 记忆节点模型

### 6.1 原子节点

原子是可以脱离当前对话理解的一项完整陈述，不要求只有一句话。正文必须尽量保留主体、条件、否定、时间和来源身份。

例如：

> 我听他提到，下午喝咖啡容易影响睡眠，但上午喝通常没有这个问题。

不能只保存“喝咖啡影响睡眠”，否则会丢失条件。

### 6.2 事件节点

事件表示一次具体经历或连续过程，保存限长的连贯叙述、参与者、事件时间范围和当前状态。事件正文不是原子标题列表，也不必复制所有细节。

同一事件后续得到补充时更新原事件；不同日期的相似事件创建新事件。向量只负责找候选，归并还要参考时间、参与者和进展。

### 6.3 主题节点

主题是跨多个事件的长期组织入口，例如求职、睡眠、家庭关系。主题只保存稳定概况和关联入口，不把所有事件细节复制进去。

不是每个原子都必须有事件父节点，也不是每个事件都必须属于主题。关系图可以是多重归属，不强制严格树。

### 6.4 节点状态和版本

节点需要区分：

- `active`：参与正常召回和更新。
- `historical`：仍可被主动回忆，但默认不作为当前画像事实。
- `disabled`：人工暂时停用，可恢复。
- `superseded`：被新节点替代，保留来源和历史关系。
- `deleted`：派生节点已删除；原始来源不随之删除。

`manual_protected` 是独立布尔属性：后台抽取不得直接改写受保护正文，可与上述状态共存。保护直到人工解除；迁移与应用约束见 [ADR-0012](../../adr/0012-extraction-commit-and-protection.md)。

节点正文更新时递增 `content_version`，重新评估重要性，并将强度重置为新重要性对应的初始值。只增加来源、关系、覆盖元数据或展示名称时不重置强度。

## 7. 被动召回

被动召回默认不调用生成模型，只使用 Embedding、向量检索、关系扩展、事件时间扩展和确定性编排。

### 7.1 首版默认参数

- 补充查询时间范围：最近 `7200` 秒。
- 补充查询数量：最近 `10` 条消息。
- 历史用户消息权重：`0.45`。
- 历史 Agent 消息权重：`0.40`。
- 当前最新消息作为主查询，历史角色权重只作用于补充查询。
- 所有参数均可在高级设置中调整。

### 7.2 查询流程

1. 从当前 conversation 获取最新消息和最近 7200 秒内的最多 10 条消息。
2. 复用缓存中已存在且指纹一致的向量。
3. 对当前消息和未缓存的补充消息执行一次批量 Embedding 请求；无法批量时受 Embedding 并发上限控制。
4. 对每个查询向量取得少量候选，在本地合并和去重。
5. 当前消息候选优先，历史消息用于补足指代、上下文和遗漏主题。
6. 只在少量最终候选上扩展一层关系邻居和事件时间邻居。
7. 按 token 预算生成事件块，执行占位符替换，注入主链。
8. 只强化最终注入的节点；同一轮同一节点最多计一次。

向量服务延迟过高时，在被动召回截止时间内使用当前消息结果，不等待历史补充完成。没有任何可靠候选时不注入空洞的“无记忆”文本。

### 7.3 注入组织

- 原子命中：直接注入完整原子，必要时附事件定位。
- 事件和原子同时命中：事件正文作为主段落，只补充事件正文未完整覆盖的原子。
- 只有事件命中：只注入事件正文，不自动展开全部子节点。
- 主题命中：注入主题概况，并选择少量相关事件。
- 时间邻居：明确标记为同期经历，不暗示因果关系。

注入是选择、分组、排序和格式化，不默认重新调用 LLM 生成一篇新叙事。节点正文在抽取时生成，主链模型负责结合这些材料回答。

采用节点级衰减：具体原子变得不活跃后，事件概括仍可能被召回；召回事件概括不自动强化或展开全部子节点。

## 8. 抽取管线

### 8.1 私聊消息窗口

首版沿用大纲示例作为候选默认：`a=5`、`b=20`、`c=40`，空闲时间 `t` 暂定为 900 秒，均可调。

- `n < a`：继续累计，不触发长期抽取。
- `a ≤ n < b`：空闲达到 `t` 后抽取。
- `b ≤ n < c`：空闲达到 `t` 或可信话题切换时抽取。
- `n ≥ c`：强制收束当前窗口。
- 另有字符或 token 上限，防止单条超长消息突破预算。

抽取窗口是处理批次，不是事件边界。同一事件可以跨批次延续，一批也可以生成多个事件。低于 `a` 的尾部永久待处理是允许的，近期原文和短期补偿负责连续性。

### 8.2 向量和聚类复用

消息在被动召回阶段已生成的向量，可以在抽取前复用。抽取窗口暂时保留当前消息向量和少量聚类状态，允许产生多个聚类中心。短句使用相邻有效语境判断，不用孤立短句决定话题切换。

窗口结束后释放聚类中心、候选结果等临时数据。低于 `a` 的原始消息继续保存，但不长期保留对应的临时聚类缓存。

### 8.3 单次抽取输出

在上下文规模允许时，一次 LLM 请求同时输出：

- 新增或更新的原子；
- 事件延续、新事件和事件正文变化；
- 必要的主题变化；
- 用户画像变化；
- 私聊人格关系变化；
- 每项的来源 ID、已有节点 ID、操作类型和“无变化”状态。

群聊内容复杂或候选过多时允许拆分任务。短期摘要不强行合并到长期抽取。

### 8.4 选择性记忆

提示词必须明确允许整个批次不产生长期节点。优先保留：稳定认识、明确修正、重要经历、后续约定、选择和结果、对当前人格有意义的互动，以及已有事件的重要补充。普通寒暄、重复表达、没有持续意义的琐碎内容可以丢弃。

人格影响“什么值得记”和叙述语气，但不能改变消息归属，也不能把主观推测写成用户事实。

## 9. 衰减、强化和活动轮次

强度由以下因素共同决定：

```text
当前强度 = 基准强度 - 有上限的时间损失 - 活动轮次损失 + 有上限的召回强化
```

- 时间衰减使用非线性、缓慢增长的损失，并设置累计上限。
- 活动轮次只在同一记忆空间的一次成功抽取批次完成后推进。
- 重试同一个批次不重复推进活动轮次。
- 节点正文更新后重评重要性并重置强度。
- 普通查询只懒计算强度，不把衰减结果写回并重置时间起点。
- 直接命中强化高于关系邻居；主动回忆强化高于被动注入。
- 过时偏好使用 `supersedes` 或 `historical` 表示，强度恢复不能把旧偏好变回当前画像。

## 10. 群聊旁听

旁听纳入第一版，但不按私聊标准处理。群消息 listener 只入库和提交低频后台任务，不发送回复、不调用主链。由于宿主 listener 位于过滤和预处理之后，第一版明确记录“到达插件阶段的旁听消息”，不宣称覆盖所有未经宿主处理的入站消息。

群聊候选默认值，作为后续调优起点：

- `group_a=40` 条消息后才允许后台整理。
- `group_b=100` 条时允许可信话题切换触发收束。
- `group_c=200` 条时强制收束。
- 空闲时间暂定 1800 秒。
- 暂不为每条旁听消息单独生成向量；达到批次后再批量处理。
- 群成员画像最多 12 个标签，描述最多 300 个中文字符。
- 群聊不启用人格主观关系。

直接与 Agent 交互的群消息可以进入更细致的群聊处理队列；普通旁听消息只保留重要群事件和简短主题概述。所有旁听原文仍进入 `source.db`，不会因为低资源策略丢失原始输入。

## 11. LLM、Embedding 与提示词

### 11.1 调用原则

- 相关任务共享同一批输入和候选，但只有判断依据相近时才合并。
- 需要前一阶段结果才能确定输入的任务保留阶段边界。
- 可并行的不同空间任务受 LLM 和 Embedding 两个独立信号量控制。
- LLM、Embedding、数据库提交和页面请求全部使用异步接口；数据库事务中不等待网络模型。
- 插件保存任务级尝试次数和总截止时间；Provider 内部重试不被误报为插件任务次数。
- 任务失败后保留最小检查点，不让单个空间失败拖垮整个插件。

### 11.2 提示词结构

每类任务使用版本化模板，基本结构固定为：

1. 任务目标和本次启用的输出部分。
2. 来源、身份、人格、时间和叙述视角规则。
3. 当前待处理消息。
4. 仅用于解指代的上下文。
5. 相关已有节点、画像和关系状态。
6. 同一事件、新事件、矛盾、画像变化和无变化的判断标准。
7. 容易误判的反例。
8. JSON schema 和字段长度限制。

程序校验空间、节点 ID、来源引用、枚举、长度、关系端点和版本。结构合法不等于事实准确，真实 API 测试和回放评估负责验证语义质量。

用户后续提供多个真实 LLM 和 Embedding API 后，使用同一测试样本比较模型，不把单一模型的输出行为写成固定规则。

## 12. 任务、重试与断点恢复

### 12.1 任务阶段

通用后台任务采用：

```text
固定输入范围
→ 模型输出生成并校验
→ Embedding 生成
→ 派生数据事务提交
→ 索引或代切换
```

每个成功阶段保存最小检查点。模型成功但向量失败时只重试向量阶段；数据库提交失败时只重试提交，不重新抽取。

### 12.2 操作锁

- 原始消息收集始终可用。
- 同一空间的抽取、人工治理、向量重建和重构互斥。
- 不同空间可以并发。
- 全局配置迁移、数据库迁移和全量重构使用全局锁。
- WebUI 点击前显示可用性，后端创建任务时再次检查。
- 同一操作重复提交返回已有任务或明确冲突，不创建重复任务。

任务状态包括 `queued`、`running`、`retrying`、`paused`、`failed`、`completed`、`cancelled`。进程恢复时，将无法确认状态的运行中任务转为可恢复状态。

### 12.3 重构

重构从 `source.db` 固定范围回放，使用当前配置和当前人格，不恢复历史配置快照。回放速度不能替代原始空闲时间；需要依据原始时间间隔模拟窗口。

重构在新 generation 中执行，成功后原子切换。人工治理记录不迁移，可以随旧 generation 清理；原始来源、账户绑定、自主笔记和任务日志不受影响。页面必须明确提醒用户这一行为。

## 13. 人工治理

### 13.1 默认语义

- **修改**：编辑正文、时间、参与者、重要性或关系；正文修改生成新版本并重建向量。
- **拆分**：创建多个新节点，重新分配原子和来源；原节点标记为 `superseded`。
- **合并**：选择保留节点，迁移可合并的来源和关系；被合并节点标记为 `superseded`。
- **禁用**：保留内容但不参与召回和自动更新，可恢复。
- **删除**：删除派生节点、向量和关系；原始来源仍保留。
- **人工保护**：正文保护默认一直有效，必须人工解除；自动抽取发现新进展时创建待审核候选，不覆盖受保护正文。

删除和重构可能再次产生相似记忆，维护页面必须说明：删除派生记忆不等于删除原始输入，重构还会清空治理结果。

### 13.2 摘要和向量一致性

正文更新后旧向量立即标记失效。新向量未生成时，该节点可以在维护页查看，但不作为正常向量召回候选。父摘要没有同步更新时标记为 `stale`，必要时暂不注入，避免新旧结论并列。

## 14. WebUI 规划

页面采用五个侧边栏入口：

### 14.1 记忆

顶部选择记忆空间，内容分为四段：长期记忆、用户画像、人格关系、短期记忆。

### 14.2 笔记

独立显示活跃和归档笔记，支持查看、编辑、搜索、归档和恢复。搜索结果必须标记 `source=note`。

### 14.3 模型

从 AstrBot 已加载 Provider 获取文本和 Embedding 模型列表，保存 Provider ID，不复制 API Key。支持默认模型、任务覆盖、并发、批大小和连通性测试。

### 14.4 设置

分为功能设置和高级参数。每项显示默认值、单位、说明和恢复默认按钮。恢复参数时校验 `a < b < c` 等约束。

### 14.5 维护

显示失败任务、阶段、进度、错误详情和重试入口；提供节点治理、向量重建和重构入口。重构、批量治理等耗时操作由后端执行，页面刷新或关闭不影响任务。

任务进度显示当前步骤、已完成数量、总量、重试状态、已用时间和可选的剩余时间。总量未知时只显示阶段和计数，不生成虚假的百分比。

使用 AstrBot 插件视图、`register_web_api` 和 SSE 或轮询，不另起 Web 服务。

## 15. 测试计划

### 15.1 单元测试

- 作用域和账户绑定。
- 人格最终解析结果的保存。
- 抽取窗口 `a/b/c/t` 边界。
- 多聚类中心和向量复用。
- 节点版本、覆盖关系和强度重置。
- 时间衰减上限和活动轮次。
- 关系、时间邻居和注入去重。
- 任务锁、重复提交和进程恢复。
- 人工拆分、合并、禁用、删除和保护。
- generation 切换和失败回退。

### 15.2 回放测试

使用固定的 source 数据和假的模型响应，验证：

- 同一事件跨批次延续。
- 相似但不同日期的事件不误合并。
- 明确纠正更新画像，旧经历仍保留历史含义。
- 助手推测不进入用户事实。
- 私聊、群聊和跨账户作用域不串用。
- 召回不会因邻居扩展突破预算。
- 重构不读取旧派生记忆和人工治理结果。

### 15.3 真实模型验证

用户提供真实 LLM 和 Embedding API 后，建立多 Provider 回放矩阵，记录结构化成功率、来源引用准确率、事件归并、画像误写、延迟、token 和向量成本。模型分数不能替代人工抽样审查。

## 16. 实施阶段与退出条件

退出条件：重启后原始消息可继续写入；人格、逻辑用户、群和 conversation 归属可回放验证。

### 阶段二：节点和派生库

完成节点、关系、来源引用、画像、关系状态、笔记、版本和状态。

退出条件：固定回放数据能稳定通过事件延续、冲突和无变化案例。

### 阶段四：被动召回和主动工具

完成批量向量、缓存复用、关系和时间邻居、预算编排、主链注入和主动回忆工具。

实施状态：已完成，见[阶段四执行记录](../../阶段四执行记录.md)。运行时边界拆分为 `adapters/providers.py`（宿主Provider适配）、`adapters/runtime.py`（宿主生命周期/作用域/注入）、`core/embeddings.py`、`core/retrieval.py`、`storage/cache_store.py` 和 `storage/recall_store.py`，入口只负责装配、hook和API。

退出条件：正常对话路径不增加默认生成模型调用；超时可降级；注入内容能保留条件和否定。

### 阶段五：任务和维护

完成后台任务、锁、重试、断点恢复、人工治理、向量重建和 generation 重构。

退出条件：重复点击不会产生冲突任务；任务中断后可恢复；重构失败不影响旧派生代。

### 阶段六：完整 WebUI 与调优

完成五栏页面、SSE/轮询进度、模型测试、高级参数、错误审查和真实模型回放。

## 17. 后续计划

阶段六之后的近期工作按[后续开发路线](../../后续开发路线.md)执行，不直接进入阶段七扩展：

1. 抽取可信度：先进行限定保真与事件覆盖的最小候选对照，核对实际请求和恢复边界，再逐项收敛来源归属、画像选择及关系视角。
2. 召回与注入：使用真实 Embedding 检查来源到最终临时上下文的完整链路，验证缓存复用、覆盖、版本、预算和短期连续性。
3. 宿主与恢复：完整 Dashboard 操作、平台接入、进程中断、重构切代和人工维护；可与抽取实验独立推进。
4. 性能与容量：低配、并发、持续负载、内存与候选上限的有界测量，按证据优化。
5. 受控试用与 v1 验收：明确支持版本、模型和运行规模，形成安装升级、故障处理及发布候选记录。
