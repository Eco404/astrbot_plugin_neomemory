# 补齐轮次真实模型回放

2026-10-29 在 Conda `astrbot` 环境、AstrBot v4.29.3 源码下，使用宿主真实 `ProviderOpenAIOfficial` 和现有 `ecoapi` 配置中的 `gpt-6-luna` 进行小规模回放。凭据仅从本地已忽略的 `docs/api_key.md` 读取。

本次只发送脚本内的合成角色说明与合成消息。原始库、记忆库与缓存均使用临时目录，结束即删除；不读取真实聊天或角色卡，不保留模型原文、端点、账户信息或异常正文。结果属于管线和有限语义检查，不是长期陪伴效果评估。

## 可复现入口

```bash
PYTHONPATH=/workspace/astrbot/AstrBot:/workspace/astrbot/astrbot_plugin_neomemory \
  /home/coder/apps/miniconda3/envs/astrbot/bin/python scripts/verify_context_api.py
```

脚本最多安排三次长期抽取与两次滚动摘要；默认 HTTP 总量上限为 6，任务最多尝试 1 次，SDK 重试显式关闭。宿主内部仍可能发出额外请求，HTTP hook 对实际请求数量执行上限。`--only extraction` / `--only short_term` 可以只重跑相关部分；`--http-budget 1..6` 可进一步限制请求。

所有摘要与抽取均经过持久任务执行器、正式提示词、schema 校验、来源校验和数据库事务，不将手写记忆冒充模型产物。最后使用实际产生的记忆运行 `MemoryRuntime.passive`，检查临时注入和预算，前台不调用生成模型。

## 执行过程中的修正

首次运行的长期任务在调用模型前失败，错误类型为 `TypeError`、HTTP 数为 0：验证脚本向 `MaintenanceEngine` 传入同步的人格读取函数，而该接口要求异步函数。已将脚本改为异步桥接；生产实现未因此修改。摘要的两项已通过检查没有重新请求模型，只对未完成的长期部分使用剩余 3 次 HTTP 预算继续验证。

## 长期回放的实际结果

修正脚本后，使用 `--only extraction --http-budget 3` 追加验证。首次长期窗口在 90 秒插件截止后失败；安全错误类型为 `RetryableJobError`，错误码为 `provider_temporary_failure`，实际发出 2 次 HTTP，耗时 90.0593 秒。该配置最多尝试一次，因此任务保留为 `failed`，没有写入派生节点或画像。

| 计划场景 | 本轮结论 |
| --- | --- |
| 首次咖啡偏好与摄影课程抽取 | Provider 阶段未取得可提交结果；无法判断结构与语义质量 |
| 当前画像从咖啡改为乌龙茶，长期节点保留变化历程 | 前置窗口失败，未继续执行 |
| 同一摄影课程结业后更新原事件身份 | 前置窗口失败，未继续执行 |
| 实际长期画像进入前台 | 没有真实产物，未获得该项实测证据 |

两轮合计 **5 次实际 HTTP**：摘要 3 次，长期 2 次；没有为了得到全绿结果继续扩大模型调用量。首次脚本桥接错误未发出请求，不计入调用量。已通过的真实摘要前台验证仍有效。

脚本将无有效模型结果的语义状态记为 `not_evaluated`，不把缺少产物导致的匹配失败解释成“模型记错事实”。首次脚本运行及首次长期运行整体退出码均为 1，不能称为完整真实回放通过。长期三窗口应在服务稳定时用同一脚本补测；目前仍属于后续质量评估缺口。

追加核对本地 API 配置的模型元信息及已有 API 验证报告，只存在这一项已提供、已验证的 LLM；另一项服务是 Cloudflare Embedding。没有已知可用的替代 LLM，因此本轮不再尝试未验证模型或扩展调用范围。

## 评估边界

- 中文词汇、否定式与节点身份断言用于检查预先明确的合成事实，不构成通用语义判分器。通过这些断言不代表模型不会在其他措辞下遗漏或产生错误。
- 当前仅一个模型、一个私聊用户、少量窗口，没有覆盖多人群聊、长时间跨度的大规模资料、多模型差异或持续使用成本。
- 本次未重复测试向量 API；向量连通性与宿主 Provider 行为沿用既有阶段验证。本轮聚焦画像修正、事件延续和短期连续性。
