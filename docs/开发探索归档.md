# 开发探索归档

| 探索 | 尝试与取舍 |
| --- | --- |
| 经历与主题 | 尝试通过放宽合并减少列表中的碎片。回查原文和事件后，保留了单次经历的粒度，另以主题整理相关事件，并保存成员与版本依据。 |
| 画像与人格关系 | 对照轻量画像、逐窗改写和带权历史背景。画像聚焦本人且可复用的特征。参考 LivingMemory 的主观记忆表达，将人格关系分为长期理解和近期余韵，让短期摘要承接近况。 |
| 人格视角与来源 | 对照客观摘要与人格直接叙述。群聊和转发暴露出发言者、提及对象与原作者混淆的问题，抽取输入逐一标明角色。观察时间及直接、继承来源用于核对正文。 |
| 图片 | 在私聊合成对话中比较不同分辨率、张数和输入顺序。相似图片逆序时观察到归属错位。正式版按消息顺序附图并标明发送者，抽取后保留文字依据供重构。 |
| 召回 | 对照扩大候选、调整门限、补充近期查询和整条预算分配。有依据的问题可能漏召，无依据的问题也可能返回弱相关结果，因此分别评估候选覆盖和最终注入的支持程度。 |
| 恢复 | 实机回放暴露出格式错误、超时和人工重新生成的成本。采用固定输入、有界自动纠正、持久检查点与事务回执。宿主截断输入的问题完成了隔离探索，宿主改动留待单独决策。 |

## 多轮召回评估

QuReTeC 研究从对话历史中选择与当前问题有关的词。NeoMemory 借鉴其区分独立查询与承接上文查询的思路，以可在本地识别的追问及最近有效上文验证。LivingMemory 的回放工具提供了固定查询向量、分开记录候选与交付结果的评估方式。[QuReTeC，SIGIR 2020](https://doi.org/10.1145/3397271.3401130)

评估使用仓库的 `tests/fixtures/recall-selection.json`，开发集和留出集各 18 问，每集有据 12 问。采用本地量化 BGE-small-zh-v1.5 的归一化 CLS 向量，两版排序共用一份向量。开发集有据首条命中从 8/12 升至 9/12，留出集从 10/12 升至 12/12。两集合计四个追问从 0/4 升至 3/4。主题接近、所问事实缺少依据的八问中，两版都误返五问。宽泛问题标注的 18 个相关条目中，两版都返回 6 个。实机所用模型、多人群聊与连续多轮交付的效果需单独验证。[评估用向量模型](https://huggingface.co/Xenova/bge-small-zh-v1.5/tree/75c43b069aac4d136ba6bc1122f995fedcfd2781)

开发中使用过独立合成案例、模型对照、故障注入和受限实机会话回放。固定用户和人格的私聊样本只支持该场景的观察。当前验收事项见[开发路线](后续开发路线.md)。
