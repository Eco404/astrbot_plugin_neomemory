# 阶段三实施计划：抽取与强度

状态：已完成离线实现与阶段复核。前置基线为阶段 1/2，宿主 AstrBot v4.29.3（abf683071），Python 使用 Conda astrbot。阶段完成后必须复核实现、验证结果和遗留问题，再进入阶段 4。

## 目标与边界

建立一条可以注入假模型、从真实 source.db 记录到 memory.db 派生结果的抽取闭环。判断什么值得记由版本化提示词约束，程序负责范围、身份、版本、事务和幂等，不用规则冒充模型的语义判断。本阶段不让线上每条消息自动调用模型；真实 Provider 调度、Embedding、召回、后台 jobs、维护页面及重构在后续阶段接入。

用户已确认：人工保护独立于节点状态；主插件接入 memory.db，强制注入 SourceStore.has_source；补齐版本查询。群聊旁听采用低资源策略，短期补偿、笔记工具仍按既定阶段推进。

## 窗口规则

私聊默认 a=5、b=20、c=40、空闲 t=7200 秒；群聊 a=40、b=100、c=200、t=1800 秒。n<a 持续累计；a≤n<b 空闲达标抽取；b≤n<c 空闲或可信话题切换抽取；n≥c 强制收束。字符/估算 token 预算是第二边界，不改变 n<a 不抽取。单条超预算不得丢弃正文或假装已处理，返回明确的超长状态供未来分段任务处理。窗口固定来源顺序，不把窗口边界当成事件边界；可信话题切换由后续复用向量的聚类层提供，本阶段不猜测。

## 输入和输出契约

输入包含空间、活动 generation、固定来源列表及身份、人格文本、有限的已有节点和画像/关系版本。来源来自 SourceStore 公开接口，不接受模型自称存在的来源。Agent 发言不可无依据变为用户事实，群消息必须保留发言者归属。

输出使用严格 JSON，明确 create/update、完整可独立阅读正文、重要性、来源、事件时间、局部引用与已知节点引用。更新保留节点身份；另一时间的相似经历新建。长期偏好变化生成“原来……现在……”的完整叙述，画像使用当前完整快照替换。主题只在真实持续关联时产生，不强制凑齐三层。节点正文更新必须携带重要性重评。情绪仅少量标签、强度和短描述。

内容长度、数量和重要性尺度必须写入 schema/prompt，程序验证前不应用。所有节点正文由抽取阶段生成，后续召回直接组织数段连贯内容；暂不增加在线润色调用。协议细节见《提示词与输出协议》。

## 一致性和失败边界

网络/假模型调用发生在事务外。应用时再次校验活动 generation、已有节点版本、人工保护和状态，拒绝过期上下文。一个批次的节点、边、画像、关系、来源引用、成功凭据和活动轮次在 memory.db 同一事务提交。凭据只保存恢复幂等所需的范围、版本和结果引用，不保存无复用价值的临时模型输出。

本阶段先支持顺序回放和显式调用，不开放自动调度。失败保留 source.db 原始记录，抛出校验或执行异常，调用方用已有 batch_id 关联错误并修正后重试；持久化失败队列、任务状态、人工待审候选在阶段 5统一落地。命中保护节点的自动修改整批拒绝，不静默丢弃；已有记录的来源、关系也不绕过保护追加。其他空间可继续显式处理。

## 强度与活动轮次

同一空间、同一 generation 中成功应用批次后推进一轮，无变化批次也是一次成功抽取；重复提交不推进。generation 独立保存轮次，避免未来重构污染在线旧代。节点基准保存重置时间、重置轮次与有限强化量，查询纯计算，不全库扫描。新建/正文或重要性更新重置基准。时间损失有累计上限，活动损失也有边界；召回强化的具体写入和冷却留到阶段 4。

## 验证与退出

- 旧 v1→新版本：保护、正文版本、来源/关系/coverage 引用完整；重开不重复迁移。
- 假模型固定回放：空批次、一次经历跨窗口延续、不同时间相似事件、偏好变化及画像替换、低资源群画像。
- 异常：非法 JSON、未知来源、身份不匹配、跨空间和跨代节点、陈旧版本、受保护/禁用节点、事务中途失败、并发同批次和重启重试。
- 强度：长期停用损失上限、仅本空间推进、内容更新重置、重复批次不重复衰减。
- 全量 pytest、ruff 和 compileall；宿主加载/卸载和初始化失败探针。真实模型质量不作为离线测试已证明的结论。

## 回滚与后续

提交按功能分组。迁移不提供破坏性降级；回退旧代码前保留数据库副本并使用匹配版本，不直接删除 source.db。本阶段没有自动抽取入口，因此抽取故障不会启动线上模型风暴；可停用插件保留两个数据库。阶段 4接入 Provider、向量及召回前再次确认调度、候选范围和模型输出质量。
