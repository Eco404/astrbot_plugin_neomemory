# 抽取候选与增量索引参考研究

## 范围

本文研究后台抽取如何发现旧事件，以及成功提交后如何准备可复用向量。被动召回仍使用自己的截止时间与强度筛选；抽取候选不调用被动召回，也不产生召回强化。所有验证输入均为独立合成数据，不读取私人会话样本。

## 当前候选管线

1. 对抽取窗口均匀选取最多 10 段非空原文，覆盖首尾与中间；每段最多 4000 字符。查询保持独立，避免把多话题平均成单个向量。完全相同的文本复用同一空间、同一模型指纹下的消息向量。
2. 当前空间和当前构建代内，按稳定节点 ID 每页最多 128 条扫描全部有效、摘要未失效的 active 节点。该读取不受被动召回的节点上限、强度阈值或近期节点数限制。
3. 已存在的正文版本向量直接复用，缺项按配置的 batch size 补算。分页只保留有界的最佳候选，评分为各查询相似度的最大值。近期间隔保留约三分之一候选名额，其余名额由语义候选补充。
4. 模型仍负责决定补充同一事件、建立不同事件或不改变内容。向量相似度不触发自动合并。展示标题不进入向量正文。
5. 候选准备与抽取模型调用共用抽取截止时间。未配置向量模型时使用近期候选；已配置模型的调用失败成为可恢复或需检查的任务错误，不伪装成成功的近期候选回退。

候选总量受 `extraction_context_nodes` 控制。扫描覆盖全部有效节点不等于所有节点都进入提示词，也不保证均匀采样能识别每个小话题。冷缓存的大空间可能超时；向量缓存容量显著小于空间规模时还可能反复补算，应通过维护任务和实际规模测试评估开销，不能承诺任意规模下固定耗时。

## 话题切点与窗口消费

话题检测只读取最近有界样本中的消息向量缓存，不补算向量、不调用 LLM。在这些样本里，从后向前找出相互相近的连续长句尾部；至少两条长句构成新话题证据。该尾部整体与前面的多个旧中心比较，返回任何一个旧话题都不构成可信切换。短回复跟随前一长句归属，不能单独触发切换；尾部长句缺失向量时等待其他触发条件。

切点返回相对完整待处理记录的索引。仅话题触发时消费达到最低条数的旧话题前缀，新话题尾部继续待处理；数量、长度、空闲触发遵守各自规则。MemoryOS 的会话聚合可提供多条内容归属于同一主题的参考，但它的相似度合并不提供本插件需要的原始记录消费切点，因此这里只采用本地有界判定和显式索引，不照搬合并机制。

`tests/test_topic_windows.py` 覆盖连续多条新话题、多个旧中心、短回复、缓存缺失和样本偏移；`tests/test_extraction_window.py` 检查切点与其他触发优先级；`tests/test_topic_window_consumption.py` 经真实原始库和维护任务验证只消费旧前缀、新尾部仍可继续处理。该判定是缓存向量上的保守近似，不能证明真实会话中任意指代和话题交织都可准确识别。

## 提交后的增量索引与恢复

每个窗口成功提交后，根据批次推导记录选择该批次创建或修改的当前正文版本，准备对应的节点版本向量。仅改标题、再次确认同一正文、已被后续正文替代的旧版本不触发此索引。重构也在进入下一窗口之前完成当前窗口的向量准备。

成功的抽取凭据是恢复依据。缓存失败不会撤回记忆、重复推进活动轮次或再次请求已提交窗口的 LLM。断点记录批次 ID、已完成数量和总量；已提交的模型输出不继续复制在断点中。重试读取批次结果及现有版本缓存，仅补缺项。缓存被清空时允许重新计算向量，仍不重新抽取。

在线候选排名可以使用本次已计算但缓存写入失败的向量；离线索引则必须读回对应节点版本键，才能报告完成。同一正文的消息向量可以直接提升到节点版本键，避免网络重复计算。进度、任务生命周期和批次提交不依赖浏览器保持打开。

## 独立验证及限制

- `tests/test_extraction_context.py` 使用 2105 个合成节点，检查最旧两个相似事件仍可进入候选、分页大小、冷热缓存、模型批次、空间/构建代/状态隔离，以及无召回强化和活动轮次副作用。
- `tests/test_window_indexing.py` 使用真实 SQLite 存储及确定性模型替身，检查缓存写入失败、分批网络失败、取消发生在缓存写入之后但进度保存之前、冷缓存恢复、消息向量提升、每窗口索引，以及标题和确认操作不重建正文向量。
- 确定性向量用于验证选择机制和调用边界，不证明真实模型能区分同一事件与重复事件。真实 Embedding 排序质量、真实 LLM 更新判断和大规模耗时仍需独立合成语料评估。
