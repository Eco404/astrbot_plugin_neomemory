# 维护与故障处理

本指南说明当前NeoMemory管理页面与后台任务的操作语义。记忆归属以页面选择的空间为准；普通私聊空间对应人格与逻辑用户，群聊空间对应人格、平台实例与群。先核对空间，再操作任务或节点。

空间选择器的私聊标签显示「人格 · 逻辑用户名」，群聊标签显示「人格 · 群 群名」。群名取自适配器提供的消息。尚未收到群名时显示群 ID。已知群名会保留，收到更新名称后再替换。

## 查阅标题、版本与来源

记忆页的长期原子、事件、主题显示持久标题，可按标题、正文或最新昵称搜索。标题、正文可在维护页编辑，新建拆分部分和合并结果需填写标题。

“查阅版本和来源”在当前节点、画像或关系卡片内展开，多个条目互不覆盖。继承基线在同一区域打开并可返回；来源原文紧随对应入口，显式点击才读取，读取失败可原地重试。折叠再展开可复用当前页面结果；切空间、分类、分页或刷新会丢弃该页状态，旧请求不会写入新卡片。短期只显示已有的覆盖信息。人格关系当前正文及历史按长期理解、近期余韵分段显示，空段明确标示。余韵即使已超过注入期限也仍可查阅，不代表它仍在回答上下文中。

正文版本显示生成该版本时的标题快照。旧快照为null时显示“未记录标题”，即使当前已补标题也不回填历史。独立修改标题以“修改标题”操作显示前后值；它不能证明旧正文的来源已经记录。“本次直接引用”“同窗上下文”“继承基线”和“累计来源”保持区分。

查询按钮紧邻记忆搜索框，类型及状态选择后立即应用并回到第一页。记忆和笔记的分页控件悬浮在底部；笔记编辑区位于列表上方。

## 逻辑用户与账号

维护页的“逻辑用户与账号”随上方记忆空间筛选。私聊显示该空间的逻辑用户，群聊显示该人格在该群已记录的发言者。账号归属和人工名称在各人格间共用。可按名称、逻辑ID、平台实例或账号搜索，选择用户后修改名称、查看账号以及添加或移除关联。人工名称优先用于页面和记忆渲染，不会被后续账号昵称覆盖。

OneBot 的 QQ 号、Telegram 和 Discord 的用户 ID 可在各自平台的机器人之间识别。同一社交账号在用户管理中只计一次，可以有多个消息入口。QQ 官方 OpenID 和无法确认跨实例身份的适配器按实例识别。同一人在不同平台使用的账号可以显式绑定到一个逻辑用户。其他空间的账号可通过手动填写平台实例和账号ID转移。确认框列出原归属、目标用户和涉及的各人格私聊空间，二次确认后提交后台任务。

- 账号原用户仅有这一个账号：删除原用户跨人格的私聊长期记忆、画像、关系、短期、笔记及版本、任务和向量，再将账号绑定到目标用户。确认框列出实际删除数量；群聊共享记忆与原始记录保留。
- 账号原用户还有其他账号：仅转移账号关联，原用户及全部既有共享记忆保留；不合并历史记忆。
- 从用户移除账号：该用户必须至少关联两个账号。移除后为该账号建立独立身份，原有记忆继续归属原用户，不重构或迁移；该账号后续会话不再为原用户提供记忆。

账号变更与其他后台任务全局互斥；预览后归属或待删除数量变化时需要重新预览确认。关闭浏览器不会停止后台操作，任务在“查看所有空间”中可见。跨库处理中断后使用“从断点重试”；已经完成的删除不会自动还原，不应使用取消任务代替回滚。原用户在原始库保留删除标记以维持历史引用，正常列表隐藏，旧私聊原文不再重新构建该身份。

## 同步陪伴插件主动消息

在功能设置开启「接入陪伴插件外部记忆接口」，使用支持送达回执的陪伴插件，并让 NeoMemory 成为当前写入提供方。`supplement` 模式即可接收。文字分段按平台确认送达的时间入库。开启联动后的临时中断由后台按游标追赶。

若「维护 → 插件状态」提示回执接口与注册接口版本不一致，NeoMemory 会尝试通过基础接口维持外部记忆读写，保留回执同步进度。重启 AstrBot 可让已安装的陪伴插件模块一起重新加载。连接恢复后，NeoMemory 自动追赶中断期间的回执。

## 查看运行状态

从AstrBot插件View打开NeoMemory，在“维护”页查看任务、自动更新状态和持久待写队列。耗时工作在后端执行，关闭浏览器不取消任务。重新打开页面可继续查看相同任务ID、当前步骤、完成数量、总量和总用时。总用时从任务创建开始计算，包含排队、重试及人工恢复等待；成功、失败或取消时停止，恢复后继续计算。页面每秒更新计时，每3秒读取后台进度。

右上角“已连接”仅表示页面与AstrBot插件桥接已建立，不作为任务成功、失败或操作通知使用。操作反馈显示为独立通知气泡，可点击关闭；未悬停且没有键盘焦点时累计6秒后自动关闭，悬停或聚焦期间暂停计时。

等待自动重试的任务以中性状态显示恢复提示和等待倒计时，不将上次错误作为当前失败突出显示。重新领取任务或成功保存检查点时清除旧错误字段；最终失败仍保留错误信息与人工处理入口。历史拒绝候选作为诊断证据保留，不等于当前任务仍然失败。

| 状态 | 含义 | 常见处理 |
| --- | --- | --- |
| `queued` | 已持久入队，等待后台领取 | 等待或取消；不要重复创建同一任务 |
| `running` | 已领取并持有租约，正在执行 | 查看步骤及进度；不需要浏览器保持连接 |
| `retry_wait` | 被判定为临时故障，等待下一次自动尝试 | 通常无需操作，倒计时结束后由后台领取；可取消 |
| `failed` | 自动尝试已结束，或需要人工判断 | 打开详情，按下文选择重试方式 |
| `cancelled` | 当前任务已取消 | 已提交结果和检查点仍保留，可显式恢复 |
| `succeeded` | 任务完成 | 查看结果及实际处理范围，不只看进度条 |

“当前空间可以启动任务”与“自动记忆更新已暂停”可以同时出现：

- **运行互斥**：同空间的 `queued`、`running`、`retry_wait` 任务占用操作资格；服务端在事务内检查，重复点击或另一浏览器不能绕过。全局作用域任务会与所有空间互斥。其他空间通常可以继续工作。
- **失败阻塞**：当前空间、当前活动代的 `extract`、`rebuild` 或 `reject` 失败，会暂停该空间后续自动长期抽取。失败任务本身不占用上述运行锁，因此仍可进入人工治理、重试或重新准备。已保存原文和既有记忆不会因这个状态被清空。
- **主题整理暂停**：当前活动代存在失败的 `topic_consolidate` 任务时，自动主题整理暂停，维护页显示关联任务；普通消息抽取仍可继续。已经成功处理的前几批不会使剩余失败内容自动获得新的纠正额度。显式重试或重新准备可恢复整理，删除失败任务也会移除这项暂停依据。
- **其他任务失败**：短期摘要等任务失败不属于上述长期失败阻塞条件；它们运行时仍可能受同空间互斥约束。短期失败或取消的窗口需要显式恢复。

维护页面自动为每次提交生成标识。网络超时后，可先查看后台任务。在同一次页面会话内重试相同操作时，页面会沿用原标识，后台可返回已受理的任务。

## 超时与运行时长

主动与被动召回默认截止15秒。单个长期抽取窗口默认180秒，候选检索、向量准备、Provider排队和模型生成共享该时限；提交后的逐窗向量补齐及完整索引步骤分别使用默认300秒的索引时限。短期摘要与模型连通性测试也使用180秒的抽取调用配置。

全量重构没有固定总时长上限，按窗口推进并持续续租。默认30秒任务租约是故障恢复凭据，不是构建运行上限。超时后的恢复仍按任务类型、错误类别和已有检查点处理，不因放宽时限增加重试次数。

这些参数可在WebUI高级设置中调整，新值用于后续工作，已开始任务保留执行配置。可逐项恢复默认或直接填写新值。宿主Provider、SDK或上游服务自身的超时独立生效，插件放宽外层截止不保证上游等待同样长。

## 候选纠错与输出模式

长期抽取、主题整理和短期摘要默认在首次生成之外最多自动纠正3次，可在高级设置调整为1—10次或关闭自动纠正。范围包括各自协议的JSON语法、重复键、枚举、模式、字段缺失/多余、长度、数量、数值范围，以及固定输入中的引用种类、候选版本和证据归属等明确错误。人格关系两段的op/body不匹配也属于可自动纠正的候选错误：replace必须提供非空完整正文，keep或clear必须使用空字符串；反馈指出具体段、操作和实际正文长度，仍受相同次数与窗口期限限制。首次请求、程序检查和纠正反馈使用相同标准，具体约束见[模型协议](提示词与输出协议.md)。重新生成的候选仍须通过全部校验，不由程序修补事实或猜测来源。

拒绝候选、次数和窗口额度持久保存，重启与显式重新生成不补回额度，新设置用于新准备窗口。纠正与原调用共用窗口截止，时间不足时不会保证用满3次。宿主网络重试和任务临时故障重试不重置候选额度。仍失败时暂停并保留进度；窗口准备时已经标为只读的节点会在候选选错时给出字段级反馈。实际来源/上下文变化（包括生成期间新增的保护）、配置变化、输出不完整、整体容量及未分类语义冲突继续人工处理。

维护详情提供当前窗口自动纠正次数及上限、Provider 响应状态、结束原因、token 用量和调用耗时（宿主未返回的字段可缺省），以及重生成是否返回完全相同候选。格式合法不代表事实、主体或时间条件正确。

WebUI 的“抽取输出格式”默认使用 JSON Schema。原生 OpenAI Responses Provider 通过独立客户端发送结构化请求。缺少该接口或模型明确拒绝该格式时，插件在同一窗口的剩余时间内使用同一模型和提示词生成文本，继续按原协议校验。显式选择 json_object 需要 Provider 和服务端支持。短期摘要的结构化请求限定字段、协议版本和窗口内可引用的来源，入库前再校验字数、身份、证据和完整 JSON。短期任务在准备窗口时固定输出格式，重新准备可使用当前设置。切换模式会改变任务请求合同，已有检查点需按配置变化规则处理。

## 按板块重构

在“维护 → 人工维护 → 空间维护”展开“重构记忆”。在上方的“按板块重构”中勾选主题、用户画像、人格关系，然后点击“启动板块重构”并确认空间。群聊支持主题和成员画像。整库回放使用下方的“全量重构”。

主题重构确认框显示可用成员数、受保护成员数及现有主题数。可用成员不足两个时，确认框提示清空现有主题。主题分支根据当前有效的事件与原子生成主题，成功时替换该空间的所有旧主题，包括人工保护的主题。画像和人格关系按已有原始记录回放，同一窗口内合并所选内容调用模型，按新版本序列保存。低于抽取门限的尾部消息保留待处理。每个分支成功后单独发布并替换所选内容，结果为空时对应板块也为空。主题和会话回放并行时，后台任务分别显示当前步骤、进度条和完成数。临时故障按分支独立退避，各分支分别使用任务尝试次数上限。维护页显示该分支的下次重试倒计时，其他分支继续执行和发布。重启后沿用各自的检查点、尝试次数和重试时间。某个分支用尽额度后显示失败原因，其他分支结束后可手动从断点重试，已发布的结果按回执复用。主题模型调用超时时，任务详情显示等待模型并发名额的用时，以及取得名额后的调用耗时。窗口期限同时覆盖排队、宿主请求及其重试。

长期记忆节点、用户画像、人格关系分别按实体保留最近的正文版本，默认各 10 个（含当前）。设置页的高级参数可分别设为 1–100。调低上限会清理超额旧版本及其专属来源操作，已清理的基线在保留版本中标注为未保留。查阅按最新在上显示。调高上限用于之后产生的版本。

## 整理主题

维护页“整理主题”按当前规则重新审阅当前空间有效事件/原子及其主题，不重新抽取原文；自动任务只处理尚未审阅或正文发生变化的节点。手动任务冻结节点更新时间及审阅时间范围，已审阅的节点可以重新判断，任务本身不会反复处理同一范围；新产生的记忆留给下一次，没有有效内容时直接完成。归纳输入补充节点具体版本的有限来源原话与发言者，区分用户自述、人格行动和第三方转述；省略主语不授权补成人格亲历。来源片段有明确截断标记，不宣称覆盖全部事实。主题成员可以交叉归属，事件正文、版本、来源消费与活动轮次不因整理改变。

自动整理要求自动抽取和自动主题开关同时开启：私聊默认8项变化或最早待审阅项等待3600秒，群聊分别为16项和7200秒。阈值与候选数可在高级设置修改。自动抽取关闭时仍可手动整理；关闭主题自动开关也不取消已提交的手动任务。长期重构在主题功能开启时先完成新代主题归纳再切代，不会发布未完成主题步骤的新代。

进度包含准备候选、模型归纳、校验、向量索引。归纳使用长期LLM、180秒默认抽取截止与3次候选纠正额度；向量索引沿用300秒默认步骤期限。正文及成员提交后的索引失败只需断点重试，不应重新生成已提交结果。候选输入会补齐已有主题的完整成员，超提示词预算时明确失败，不静默截断后删除未提供的成员。

主题失败候选可在原任务中“重新生成当前窗口”，包括重构中的主题窗口；此前事件和归纳凭据继续保留，已用自动纠正额度不重置。显式重新生成会使用归档草稿、原冻结输入及其目标schema重新计算诊断，提供create/update所需身份、版本与允许引用等精确反馈；不会替换原输入、扩大候选范围或重置纠正额度。普通自动恢复继续使用既有保存反馈，不触发这项显式诊断刷新。输入不再匹配时仍须重新准备，不能靠刷新诊断绕过。纯格式合法不代表归类准确。归纳任务失败不撤销已保存事件；普通抽取的来源顺序保障仍按下述规则执行。

人工纠错产生的summary_stale主题需要明确人工修订，自动整理不能恢复；人工保护也不能通过另建同义主题绕过。仅因新增细节或自然淡忘，不将所有上层概括一律隐藏。

主题请求按最终UTF-8字节预算装配，包含人格、完整节点与成员关系、来源身份和版本元数据、原话及协议。来源证据可按剩余预算缩短或省略，保留片段明确标记不完整；不会截断必要成员正文。必要时减少可选语义候选，再缩小本批审阅条数，未处理节点留给后续批次。单个种子及其完整主题成员仍超预算时明确暂停，需要检查配置或人工整理主题。候选纠正保留有限反馈空间，调用前再次检查完整请求大小。维护详情显示提示词字节、来源片段保留数量及本批实际节点规模。

主题纠正请求超过预算时，会尝试对完整合法JSON消息做等价的传输压缩：仅移除字符串之外的JSON空白，保持正文、引用、字段顺序、重复键和数值写法。混合文本提示及非法JSON候选原样保留，避免改变解析位置诊断。冻结输入、规范请求摘要和归档候选不变；检查点另存压缩前后字节数及传输摘要。预算内请求不改变；压缩后仍超限则继续暂停，不删除来源、缩短正文或扩大预算。有限预留不保证所有纠正请求均可容纳。

显式候选会补齐所属主题和完整成员；展开后其他关联主题进入只读概况目录，帮助模型识别既有主题，不递归加载整个关联图。目录内容与归属关系也参与预算及提交检查。只读主题不在本批直接更新，后续完整进入候选后才能更新。

## 三种重试方式

以下区别主要适用于长期抽取和重构。三种入口不能同时使用。

| 页面入口 | 保留和重新执行的内容 | 何时会调用模型 |
| --- | --- | --- |
| **从断点重试** | 恢复原任务和检查点；保留原输入范围、版本条件、已保存候选及已提交窗口 | 当前窗口已有候选时复用它；没有候选且后续步骤需要生成时才调用。临时网络失败可能尚未保存候选 |
| **重新生成当前窗口** | 适用于有已保存候选且尚未提交的失败或取消的抽取/主题整理/重构/短期摘要任务；归档原候选与诊断，保留当前窗口输入和已完成进度，清除当前候选后重新生成 | 在配置、输入等检查通过后，重新调用当前窗口模型；附最后一份被拒候选和明确校验反馈；已耗尽的自动纠错额度不重置 |
| **重新准备后重试** | 按当前状态创建新任务，成功入队后将旧任务标为取消；不沿用旧候选 | 按新任务需要调用。重构会重新固定来源范围、建立另一新代，从头回放，不接续旧重构的已完成窗口 |

有已提交批次回执时，恢复优先使用回执，不重复提交内容、来源消费或活动轮次。它只保护已确认提交的工作，不能把“普通重试”理解为任何情况下都不会调用模型。

后台必要向量缓存写入及读回使用已有步骤的剩余总期限，在线缓存短写限时不用于后台必须落库的步骤。逐窗索引在内容提交后执行；window_index失败时断点重试只补缺失的变化节点向量，不重新生成已提交窗口。context:N表示正在分页查找关联旧记忆，已扫描N条；任务卡显示来源处理进度，向量索引显示为当前步骤。

自动抽取、主题整理、短期摘要以及召回触发的索引补建，在全自动完成后退出任务列表。失败或取消的任务可在列表中处理。人工启动、断点重试、重新生成或重新准备的任务在成功后保留。后台保留执行凭据以支持去重和诊断。历史索引补建仅在符合自动任务标识、首次成功且没有重新排队时隐藏。

输入、人格、模型绑定或相关抽取配置发生变化时，原检查点可能不再适用。`configuration_changed`、`context_changed` 等错误不能通过反复点击“重新生成当前窗口”绕过；应核对变化后重新准备任务。手工治理的操作载荷还含节点版本条件，“重新准备”不会自动替换成最新节点版本，发生冲突时应回到节点页面刷新后重新编辑。

同一个重构任务的显式窗口重新生成保留此前已提交的新代内容；“重新准备后重试”会重新开始重构。这两者的时间和模型开销可能相差很大。

普通抽取会补齐已有主题的成员与包含关系。尚未提交的旧检查点若没有这些图关系，而当前输入包含主题或其成员，重新准备时输入摘要可能改变，需要显式重新准备任务；不能忽略摘要差异直接提交旧候选。没有相关主题的旧输入和已有提交回执不受这项输入扩展影响。重构的重新准备会重新回放整代，操作前应查看当前检查点。

## 删除后台任务

后台任务区域的“清空已完成任务”在二次确认后批量清理 `succeeded` 任务，范围跟随“查看所有空间”：未勾选时清理当前空间，勾选或没有当前空间时清理所有空间。该操作覆盖全部分页，保留失败、已取消、排队、运行和等待重试任务。确认框明确显示范围；提交期间不能重复提交或关闭，失败后可以重试。后端在同一事务中执行清理，失败时回滚任务删除。

除 running 外的任务均可在维护列表删除，服务端在事务中与领取任务互斥。正在运行的任务先取消，再删除；本机尚未退出的取消工作器会先被终止。删除清除任务行、候选、检查点和相关任务执行凭据。重构任务专属的未发布 building/failed 代及其节点、画像、关系、来源引用、消费记录和向量一并清理。

成功任务已启用的记忆代与旧有效代不删除；原始消息、已提交记忆和笔记也不因删除任务丢失。任务删除不等于“放弃窗口”：来源未消费且自动抽取开启时，后续扫描可重新调度。需要阻止处理应关闭自动抽取；需要明确消费而不生成记忆应使用放弃窗口操作。

## 取消与放弃窗口

**取消任务**会撤销任务的有效租约，阻止之后依赖该租约的提交，但不会回滚已经完成的事务，也不会删除检查点、原始记录或此前已提交窗口。正在进行的网络请求未必立即停止；它能否在取消生效前完成提交取决于事务先后顺序，因此取消后应刷新任务和记忆结果。

取消不等于丢弃来源，也不是持久关闭自动抽取的开关。需要持续暂停新的自动长期工作时，在“设置”中关闭自动抽取；已经排队或运行的任务另行处理。取消后的任务需显式恢复，未消费来源仍属于待处理内容，不应靠反复取消来解决无效候选。

**放弃失败批次**只支持当前空间、当前活动代中失败的普通 `extract` 任务，不支持直接跳过重构中的失败窗口，也不能放弃已经正常提交的批次。

放弃前需在页面确认并填写原因。该操作不调用生成模型，而是提交一个明确的 `no_change` 回执：保留原文，记录这些来源已消费，推进相应游标与活动轮次，不创建该窗口的节点、画像或关系；随后将原失败任务标为取消。它会影响后续自动处理，不能把它当作无副作用的“清除报错”。

## 如何读错误详情

详情中的 `error_code` 表示任务为何停止，`validation_errors` 定位候选字段。原文和候选需要在相应入口主动查阅；字段诊断本身不附异常正文或原文片段。

| 诊断 | 当前含义 | 建议操作 |
| --- | --- | --- |
| `output_incomplete` | Provider 明确报告输出未完成或达到长度限制 | 检查模型输出限制及响应诊断；按需调整配置后重新准备，或显式重新生成当前窗口 |
| `provider_temporary_failure` | 网络、限流、超时或部分服务端临时错误 | 先看是否仍在 `retry_wait`；最终失败后检查服务，再从断点重试 |
| `model_required` | 窗口缺少可调用的对话模型，或主题的来源涉及多个模型 | 在维护页重新准备任务，确认窗口和主题分别使用的模型 |
| `provider_unavailable` | 当前Provider不能完成请求，未被归类为可自动重试的临时错误 | 在模型页核对选择并测试；测试其他模型不会自动保存选择 |
| `invalid_output` + `json_invalid` | 候选解析或顶层协议不合法 | 查看位置及候选；新发起的重新生成会向模型提供解析坐标和固定语法提示，输入配置仍须匹配 |
| `invalid_output` + 字段路径/类型 | 候选不满足schema，包括稳定引用还原后的字段限制 | 按具体字段审阅；显式重新生成会带入对应反馈 |
| `relationship_slot_body` | 关系某段op与body不匹配：replace为空，或keep/clear仍带正文 | 程序可在剩余额度与期限内自动纠正；最终失败后查阅具体段和字段反馈 |
| `unknown_reference` | 使用了当前窗口不认识或种类不匹配的引用 | 不手工猜测ID；核对候选后重新生成 |
| `expected_*_version_mismatch`、覆盖或归属诊断 | 候选的节点/画像/关系版本、覆盖端点或证据归属不符合当前契约 | 依据具体字段审阅；输入已变化时重新准备 |
| `readonly_node` | 普通抽取候选尝试修改只读节点、关联或覆盖 | 查看字段诊断和自动纠正结果 |
| `task_write_not_permitted` | 任务无权向目标写入 | 检查任务类型及目标记忆代 |
| `protected_candidate`（1.0 已保存的任务） | 候选未通过当时的写入权限检查 | 查看保护原因，使用“重新准备后重试”按当前候选规则重新处理 |
| `context_or_evidence_invalid`、`context_changed`、`configuration_changed` | 原输入、来源、版本或执行配置不能继续用于当前操作 | 核对实际变化，重新准备；不要把它直接认定为模型语法错误 |
| `prompt_budget_exceeded`、`oversized_source`、`output_budget_exceeded` | 提示词、单条来源或输出超过当前处理上限 | 查看来源规模与配置；原样重试通常不能消除同一限制 |

### JSON位置

标准JSON语法错误可以提供 `lineno`、`colno`、`pos`：行、列从1开始，全文偏移从0开始，均按字符而非UTF-8字节计数。重复键、NaN/Infinity等解析回调拒绝没有标准位置，不会编造行列。`json_invalid`也涵盖不支持的顶层协议格式，不能仅凭这个分类断言一定是缺标点。

### 稳定引用与长度

模型看到的 `{{user:u1}}` 会还原为 `{{user:逻辑用户ID}}` 后再校验。当前协议分别限制可读长度和编码容量：合法完整用户引用计一个可读字符，其余Unicode码点逐个计；引用ID最长200字符，引用还原仍需满足编码容量。事件正文最多3000、画像描述600、关系长期理解500、近期余韵150、画像标签24、标题60、节点emotion.description160可读字符。更换显示昵称不改变存储校验，最终注入预算另按昵称展开后的UTF-8字节计算。

`string_too_long`等长度诊断会指出字段；候选重新生成使用该固定协议的可读上限或编码容量反馈，保留主体、否定、条件和引用归属。系统不会自动删除文字或截断正文来使候选通过。调低注入单项上限会使超限整段省略，不能达到缩写正文的效果。

已有失败检查点可能没有完整字段诊断。输入和配置仍匹配时，可先“从断点重试”保存候选，重新校验并保存诊断，再“重新生成当前窗口”。有保存候选的这次校验不需要再次调用模型；如果候选尚未保存、配置已变化或失败来自其他步骤，不能套用这个保证。

## 人工治理节点

维护页的修改、拆分、合并和状态操作针对长期记忆节点。用户画像、人格关系、短期摘要可在记忆页查阅；不要据此假定它们拥有同一套节点拆合操作。笔记在独立笔记页管理。

| 操作 | 当前后果 |
| --- | --- |
| 仅修改标题 | 保存展示标题与title_update操作，不改正文版本、updated_at、强度、原有人工保护、覆盖或向量；旧版本快照不变 |
| 修改正文、情绪或重要性 | 正文或情绪实际变化产生新内容版本并保存标题/情绪快照；内容或重要性变化重置强度，节点默认人工保护。情绪标签换序不算内容变化 |
| 拆分 | 创建2–20个部分，分别指定标题、完整正文、重要性、情绪及原节点已有来源；不自动复制原节点情绪，原节点标记已替代，新节点人工保护 |
| 合并 | 选择2–20个同类型、同状态节点，指定保留节点、标题、完整正文及合并后情绪；不推断继承某一节点情绪，其他节点标记已替代，结果人工保护 |
| 人工保护 | 设置独立的 `manual_protected` 标记，阻止自动抽取改写该节点；不改变节点状态，没有自动到期时间 |
| 解除保护 | 解除保护的事件或原子重新进入主题审阅范围；解除保护的主题会重新审阅其成员。禁用状态需另行恢复 |
| 禁用 | 将活跃或历史节点设为disabled并保护，排除正常召回；保留正文、版本和来源 |
| 恢复 | 仅把disabled节点恢复为active；仍保持人工保护 |
| 删除 | 写入deleted派生墓碑并移除关联关系/覆盖，不擦除原始来源和历史正文；当前恢复入口不能撤销deleted或superseded状态 |

标题编辑沿用同空间后台互斥，同时检查generation、正文版本、updated_at和expected_titles中的原始title（可为null）。页面只提交实际改变的字段；仅改标题不会附带未变正文和重要性。遇到冲突时刷新节点后重新编辑，不把正文版本没变当成原标题仍有效。高级JSON中edit.patch含title、merge含title时必须提供目标节点的expected_titles；split.parts[].title为新节点字段。

情绪表单使用启用开关、少量标签、各标签独立的0～1强度与短说明，不要求分数之和为1；未启用即为null，不补成neutral。编辑中省略patch.emotion保留、显式null清空；拆分/合并省略情绪时为空。内容版本查阅显示当时快照，旧版本没有值就显示未记录，不借当前值回填。

人工保护不等于永久保鲜、强制召回或预算优先，也不能阻止重构产生新的记忆代。解除保护后，状态、强度、候选上限、相似度及最终预算仍决定节点能否参与召回。

治理子节点或改变包含关系可能使上层事件/主题摘要标记为过时，暂停其正常召回。系统不会在一次手工拆合后自动调用模型改写全部上层叙述；应查看任务结果中的受影响父节点，审阅并补全父节点正文，或选择重构。纯保护/解除保护不会因自身操作使上层事实文本过时。

节点删除不是全库内容擦除。同一内容可能仍在原文、版本、其他节点或上层叙述中；今后从原文重构也可能重新生成相关记忆。

## 重构、索引与短期记忆

**整理抽取**处理当前代符合规则的待处理窗口；最低条数不足时仍不强制抽取。可信话题切换只消费旧话题前缀，新话题尾部继续待处理。**重建索引**为当前记忆正文计算或读取向量，不重新生成正文。**重构记忆**从本地原始库重新推导长期记忆、画像和人格关系，两者不可互相替代。

重构使用当前插件配置和人格，开始时固定来源范围，在新代后台回放；旧的派生记忆不作为重构依据。新代成功完成回放及配置的索引步骤后才切换为活动代，失败时继续保留旧代作为活动代。期间新消息仍可写入原始库，超出固定范围的输入留待后续处理。

重构不会迁移旧节点的手工修订、保护、拆分或合并结果。成功切代时，同一事务删除该空间全部退休代的节点、版本历史、画像及关系历史、短期摘要、抽取/主题/治理凭据和处理游标，同时清理旧节点向量；不影响其他空间。新记录从v1开始，回放中多次更新仍正常递增，不把本次新生成的版本压成一个v1。原始记录与独立笔记保留。任务记录、切换回执和代标识仅用于运行追踪与恢复，不含可回切的旧记忆备份。原始记录如果已被外部清理，重构不能恢复缺失来源，也不保存每个历史时刻的人格和配置快照。

进度条达到完成不代表每条原始记录都生成了记忆，甚至不代表全部来源已达到消费条件。结果中的 `source_count` 与 `pending_source_count` 才说明实际处理和待处理范围；不足最低窗口条数的尾部可以继续等待，无意义内容也可在抽取时产生 `no_change`。

**长期重构不会自动生成短期摘要。**短期摘要需要实际会话触发后台滚动任务，且受近期原文保留量、最低数量、当前流和宿主conversation等条件约束。重构切代后旧代短期摘要不会混入新代；需要后续合适的会话触发重建。短期空白不能单独作为长期重构失败的证据。

新准备的短期摘要使用 `short-term.v2-dev.1` 提示词，输出协议为 `short-term.v1`。已有短期检查点按记录的提示词版本续跑。摘要按模型输出正文计量字符，每个 {{user:u1}} 占 11 字符。存储时还原稳定用户引用，注入和界面按当前昵称渲染，明确约定称呼保留。纯插件滚动预判看到宿主明确摘要时可跳过重复补偿，不能保证精准覆盖宿主每次实际裁掉的全部消息。

## 笔记和主动查询

笔记页与neomemory_notes支持delete。归档可以restore，删除后不出现在active/archived/all列表及主动查询中，不能由普通修改或恢复撤销；数据库保留删除状态，不自动物理清理。WebUI在条目内确认，后台任务继续检查空间、读取版本和重复请求标识，失败保留草稿便于重试。

主动查询支持类型、数量及事件时间范围，并合流source=memory/note。笔记字面搜索不依赖向量，Embedding故障可保留笔记结果；事件时间条件排除未知数值时间的记忆与笔记，不把笔记更新时间当经历时间。两类完整条目共享条数与字节上限；只有实际返回的记忆强化，笔记不会获得记忆强度。

低强度active节点在主动工具实际返回后可独立唤醒到被动资格门限上方，仍受后续正常衰减；这不恢复historical事实，不解除禁用或人工保护。强度参数在高级设置即时应用，工具边界见[主动查询与笔记管理](主动查询与笔记管理.md)。

## 原始待写与磁盘数据

运行数据位置由 `StarTools.get_data_dir("astrbot_plugin_neomemory")` 决定，通常与插件代码目录不同。维护健康信息会给出实际路径。

| 文件 | 用途 | 清理影响 |
| --- | --- | --- |
| `ingress.db` | 尚未成功进入原始库的持久待写内容 | 不是缓存；删除会丢失尚未确认的输入 |
| `source.db` | 原始conversation/event及归属信息 | 当前不自动清理；删除会失去重构依据 |
| `memory.db` | 记忆代、正文版本、直接来源、任务、回执、治理及笔记 | 删除不是普通修复步骤，会丢失上述状态和断点 |
| `cache.db` | 可再生向量等计算缓存 | 重建需要时间和向量调用；正在打开的SQLite文件不能仅删主文件而忽略WAL |

待写队列的条数与有效载荷上限同时生效。成功持久入队后才有对应恢复保障；队列满或磁盘不可写时，维护页显示内存应急数量及溢出，尚未落盘的内容可能在重启时丢失。先处理容量或磁盘故障，再使用单条或全部待写重试。同一来源流保持顺序，不能越过前项失败。

cache.db按类型执行数量和TTL约束，有界清理在后台运行；缓存读取异常按未命中，写入异常不丢弃已算出的有效结果。冷索引仍可能使在线查询降级，不在线重算全空间。当前没有独立缓存体积硬上限，文件大小和持续负载需另行观察。

不应通过清空运行库来解决普通候选错误。需要完整重置测试数据时，应先停止插件并明确清理范围；这与重构派生记忆是不同操作。当前没有WebUI通用导入导出、全库一键重构或自动原始库清理功能。

## 首次安装与确认生效

在 AstrBot 插件管理上传对应版本的插件安装包并启用，通过插件 WebUI 的「维护 → 插件状态」确认存储就绪，检查模型页已选 Provider 的连通性。插件首次启动会创建四个数据库。数据目录和每个文件的职责见[数据库结构](schema/README.md)。

从 1.0.0 正式版升级时，首次加载自动将 memory.db 从 v1 迁移到 v2。使用过 1.1.0 预发布版数据库的测试实例，需要在安装正式版前单独转换开发格式及其任务检查点。

健康接口的 `ready` 表示插件已就绪。`memory.schema_version`、`memory.expected_schema_version` 均为整数 2，维护工作器的默认 `extraction_prompt_version` 为 `extraction-prompt.v3-dev.1`。新准备的长期窗口按此提示词生成，回执的 `schema_version` 为 `extraction.v1`。旧长期任务从检查点恢复时若提示配置已变化，使用“重新准备后重试”按当前配置运行。

安装后首次触发抽取前，空间可以没有派生内容。先检查已入库待抽取来源条数，再到模型页核对长期模型和向量模型。需要验证某条记忆时，可在记忆条目下展开来源，然后在维护页模拟召回。

在「维护 → 召回测试」输入查询后，可以看到本次快照中实际可检索的向量数、候选总数和最近一次本空间索引任务的结果。已完成的索引任务区分扫描的条目数与实际补齐的版本向量数。同一模型和空间下可复用的相同正文也计入可检索数。空间忙时，补建请求留待后台扫描。最近召回记录分别显示各入口实际交付的内容、查询向量复用数和模型调用次数。

## 当前边界

工程校验通过只表示结构、来源引用和提交条件符合规则，不证明事实归因、否定条件、画像取舍、情绪归属或模型覆盖声明都正确。关系承接已有明确规则和有限对照，仍有时间对象歧义及称呼限定漂移；当前真实主动查询也出现弱相关噪声。人工治理和来源查阅仍然有必要。

WebUI「设置 → 高级参数 → 召回策略」默认选中「自适应召回」。已经保存的「向量排序」或「相关性筛选」继续生效，可在此切换。WebUI「模型选择」可指定 AstrBot 的 Rerank 提供商，留空时普通查询直接使用本地筛选。重排模型按标准化得分 0.50 准入，使用原始 logits 的 TEI 提供商按 0 准入。不同提供商的得分分布可能不同，可在维护页预览。

多事件回顾优先使用空间记忆模型设置，继承插件配置时使用「记忆 LLM」。按对话模型选择时，可使用本轮读取的近期回复中记录的模型，聊天入口也可按当前会话配置选择。无可用模型或模型超时会使用剩余时间完成候选筛选。「维护 → 召回测试」的结果中可以查看是否结合上文、候选条数、实际选择方式及回退状态。单条预览没有真实对话上文。

被动召回使用有界候选、截止时间和完整条目共享预算。主动/被动召回快照上限为2000，超出部分不在该次候选中；后台抽取旧事件采用全空间分页匹配，不等于主动工具也能越过快照范围。正文放不下时整项省略，人工保护不会绕过这些规则。网络超时、冷缓存或宿主负载可能导致降级，已有本地上下文也必须通过最终有效性和预算检查才会注入。

宿主输入超限回退可能截掉抽取输入，当前尚未启用可靠的逐请求禁止截断保证；不要把格式合法的输出或 `no_change` 回执直接当作输入完整的证明。确定边界的进程恢复测试也不能替代整机断电、磁盘损坏或所有宿主环境的可靠性保证。
