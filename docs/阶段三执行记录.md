## 目标完成后的复核与修正

| 复核发现 | 修正与证据 |
| --- | --- |
| 自动抽取写入路径可能绕过 source_exists | 应用入口强制存在性校验，无校验器拒绝；false checker 测试通过 |
| 已完成批次快捷返回忽略人格变化或退休 generation | run 校验完整输入摘要和活动代；相同 Prepared 才复用凭据，直接 apply 同样拒绝退休代 |
| 先写新窗口再补旧窗口会恢复旧画像 | 持久化每流 sequence 上限，乱序旧范围拒绝；原始来源仍保留供未来新代回放 |
| 用户首次写入失败，Agent 先入库导致无法确定归属 | Agent 保存 trigger_message_id，以同流同人格的原请求用户记录解析；迟到用户补写后可抽取 |
| CapturedSource 去重使用 identity.message_id，但保存时未使用同样 fallback | 保存使用一致的 fallback，延迟来源测试通过 |
| BEGIN/COMMIT 等待期间取消，可能释放锁但遗留事务 | 取消/失败先排队回滚再释放锁；测试覆盖提交前/后的真实不同结果 |
| PRAGMA 初始化失败，尚未登记的连接可能泄漏 | open 异常关闭局部连接，失败/取消后可重开 |
| 提示词 supersedes 与应用层状态效果不一致 | 统一为同类型显式替代、旧目标 historical，禁止循环；循环整批回滚 |
| no_change 也可能依赖已被人工修改的上下文 | 无变化提交同样检查输入节点、画像、关系快照；陈旧上下文不消费来源 |

这些属于实现一致性修正，没有引入需要用户重新选择的产品分歧。已确认的独立保护和插件装配决策见 [ADR-0012](adr/0012-extraction-commit-and-protection.md)。

## 当前限制与下一阶段准备项

1. 抽取是显式调用的离线服务；宿主当前只采集来源并初始化两库。自动调度、Provider 重试/超时组合和可配置并发尚未接入。
2. 原始窗口、已有节点候选由调用方提供，尚无 Embedding 聚类/候选检索。超长单条来源保留待处理，未来分段任务要实现后才能自动推进。
3. 第一版输出未设置 coverage 字段，contains 不意味着 full coverage。阶段四注入去重前需补充显式覆盖协议，禁止用程序猜测正文已完整覆盖某原子。
4. 失败不消费原始来源，但模型失败输出和完整 Prepared 上下文不持久化；后台失败队列、重试面板、进度与待审候选在阶段五实现。重启后查成功凭据或从未处理原文重新准备。
5. source.db 的 last_derived_sequence 本阶段保持不变；派生处理进度以 memory.db 原子完成凭据为准。未来调度不能只读取旧 source 游标判断是否已处理。
6. 旧 Agent 记录缺少请求关联且没有可靠前序用户时，保留原文并拒绝猜测身份；未来维护应显示此类不可解析范围。
7. 真实模型语义质量仍需评估：schema遵循、来源准确率、重要性量表、事件误合并、完整叙述长度和提示词成本。提示词现为离线候选，不默认启动自动抽取。

下一阶段先细化 Provider/Embedding、候选范围、覆盖与注入预算，再开始阶段四；本次不自动扩展目标到完整召回和 WebUI。
