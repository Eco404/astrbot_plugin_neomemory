# 来源时间与主题组织：独立连续链评估

本评估使用独立合成对话，检验普通抽取的实际滚动结果经过主题整理后是否保留主体、时间、状态和事件粒度。**任务都能完成，主题也能生成；但本轮没有证明 v32/v6 已解决事件过度累计、时间元数据滞后或主题成员语义独立性。** 干净对照中，两个模型的候选分支都把四次不同活动累计到同一个 event。不能把结构校验通过或最终主题数量当成质量通过。

## 方法与材料

- 脚本：`scripts/probe_topic_grounding_chain.py`。
- 材料：`tests/fixtures/topic_organization_independent.json` 的 `windows`、`persona` 和 `chain_review`；本连续链不读取其中的 `fixed_cases`。
- 四个窗口分别描述 2032 年 10 月 2 日需求访谈、10 月 9 日排练试验、10 月 16 日志愿者说明会、10 月 30 日说明交付。原文另外包含无关私人出游、11 月 3 日由第三方负责但尚未进行的观众测试，以及人格只在线帮助整理文字的边界。
- 两个模型：`gpt-6-luna`、`gpt-5.6-luna`。每个模型分别运行旧协议 `extraction-prompt.v31/topic-prompt.v5` 和候选 `v32/v6`，均从独立空库开始。
- 每窗运行普通联合抽取；第 2、4 窗之后运行主题整理。下一窗只能使用该分支实际提交的前序图，不插入理想节点，不进行人工语义重生成。
- 使用 AstrBot v4.29.3 provider，`json_schema`，每个窗口 120 秒，自动纠正最多 3 次。并发 2，每轮最多 24 次首次生成、40 次实际 HTTP；provider 内部重试关闭，单次调用最多一次 HTTP。
- 此小图实验不配置向量服务；普通抽取 16 份可见性记录均显示全部可用节点进入候选且无分页遗漏。因此不能用“候选节点没召回到”解释本轮的事件合并，也不能据此评价生产向量召回质量。
- 审阅范围包括全部已提交窗口、全部主题整理输出及所有被拒候选/纠正反馈。未使用私人会话，未按私人样本修改提示词或材料。

这里的候选明确为 v32/v6；不自动代表后续其他提示词版本。每模型每臂只有一条链，输出具有随机性，不能据此报告总体准确率。

## 主题专门管线与上游问题的区分

1. **主题任务确实执行。** clean 的八个主题窗口均实际调用模型；产生路径包括普通抽取提前创建/更新以及专门整理创建/更新。不能再用“页面有一个主题”推断只有专门管线在工作。
2. **新建两成员是结构规则。** 本轮候选可以拿复合 event 加目标 atomic 达到下限；多节点仍可能高度重复。验证器没有声称已验证语义独立性。
3. **专门整理不能修复已合并的事件身份。** 它按契约只组织现有节点，不拆分或重抽 event。持续把四次活动写入同一个 event 发生在普通抽取阶段；增加主题频率不能直接修复。
4. **无变化输出已观察到，但没有保证。** clean 的 `gpt-5.6 baseline/W4`、`gpt-6 grounded/W4` 正确返回空 changes；`gpt-6 baseline/W4` 在成员未变且前序 topic 已覆盖当前进展时仍再次改写。纯成员变化保留正文的能力需要单独材料，不从这两次 no-change 推断。
5. **时间锚信息能提供依据，不能代替更新判断。** 这轮没有观察到候选把说明会明确改写成交付当天，但新增来源 UTC 和版本观察范围仍未让模型稳定同步 `event_time` 或消除“今天”。元信息缺少后续活动不等同于模型编造精确日期，应分别记录。
6. **中间主题状态存在异步滞后，不据此认定工程回归。** gpt-6 grounded 第 3 窗的模型没有提交 topic 正文更新，只更新 event、创建说明会 atomic，并添加 topic→新 atomic 的边。存储给 topic v1 记录的是 `membership`，只关联新 atomic v1；原 event 的依据仍为 v2，没有把最新 event v3 冒充旧主题的已审阅依据。主题仍为 active，已存正文保留待做的说明会表达，第 4 窗才改正。ADR0041 第 7 条允许普通新增细节等待低频补充，`summary_stale` 暂停规则用于已知纠错；当前召回新鲜度条件检查该标记，不自动把成员版本差异当成禁止召回。本轮没有模拟召回或最终回答，不能宣称已经发生回答错误，也不据此新增立即一致或一律禁用父主题的规则。

## 自动纠正与未解决质量问题

clean 全部四份拒绝候选均由插件既有自动纠正恢复，每个相关窗口只追加一次模型调用，没有测试脚本或人工重试。

| 模型/分支/窗口 | 拒绝标准 | 结果 |
| --- | --- | --- |
| gpt-5.6 baseline / W1 | `unknown_reference`：`base_node_ids` 使用本批 local 引用 | 依照固定输入重新生成后通过 |
| gpt-5.6 baseline / W2 | `create_identity_invalid`：新建身份字段不符 | 重新生成后通过 |
| gpt-6 grounded / W1 | `unknown_reference`：`base_node_ids` 使用本批 local 引用 | 重新生成后通过 |
| gpt-5.6 grounded / W4 | `unknown_local_reference`：边指向未声明 local 节点 | 重新生成后通过 |

第一轮的四次纠正也全部恢复，分别为 `node_type_mismatch`、`unknown_local_reference`、`unknown_event_time`、`topic_update_identity`。这些证明结构错误的有限自动恢复在本材料上可工作，**没有把事件过度累计、旧计划时间残留等语义错误自动纠正**。

第一轮另保留了这些不利现象：gpt-6 baseline 把说明会的“今天”放入后续交付窗口的事件时间；gpt-6 grounded 的已完成 atomic 仍保留计划时间；gpt-5.6 grounded 将排练、说明会、交付累计在一个 event，时间仍为排练日期。第一轮 gpt-6 grounded 恰好生成四个 event，而 clean 同分支只生成一个，直接说明单次较好样本不能充当稳定性结论。

## 下一步验证边界

- 优先隔离普通抽取的事件身份判断：持续项目可共享主题，日期、参与者或具体活动改变时是否仍将其当成同一 event。沿用独立材料，不能根据私人会话设合并关键词或特例。
- 独立验证计划→完成及同一事件补充时 `event_time` 的更新语义，同时区分相对时间未锚定、旧标签残留和捏造精确时间；不以无条件替换为当前来源时间解决。
- 专门评估同一 event 及其 atomic 的重复、真正独立 atomic 的持续关联、只增加成员且旧概况成立、完全无新变化四类情况。应分别使用完整图和有限来源摘录，比较成员变化与正文变化，不强制目标主题数量。
- 当前不增加模型裁判或生产语义重试，也不以结构校验、节点数或本轮整链完成率代替上述质量验收。本报告不涵盖实机全量重构、向量检索、模拟召回或最终聊天回答效果。
