# 节点内容时间与迁移验证

## 对象与方法

验证 [ADR-0050](../adr/0050-content-observation-clock.md) 和 `memory.db v14`：更新时间取原始观察时间，保留独立系统修改时钟，读取不依赖原始库。工程基线为 Conda `astrbot` 与 AstrBot v4.29.3 测试宿主。

合成测试使用独立来源、不同观察/抽取时间、乱序来源及版本依据，不使用私人会话内容编写规则或夹具。实际数据只复制既有实机终态快照进行隔离迁移，不修改运行实机，不调用模型。

## 结果

- 完整pytest回归2610项通过；唯一警告为宿主依赖的 `audioop` 弃用提示。
- 13项内容时间专项测试通过：新建、原始epoch为0、未知来源、旧确认不后退、新确认推进、正文与标题更新、治理锁、拆分合并、主题确认与仅关联成员的区别、基线冻结、同批父节点先输出、旧schema迁移、原文清理与重开读取。
- Console/API/维护API相关101项通过；Chromium `full_smoke`、`topic_smoke`通过。浏览展示使用内容时间，治理提交仍使用系统修改时间；未知值不回退、稳定排序与分页正常。
- 旧库回填按派生时间约束同版本确认范围。旧主题只继承形成时已经存在的成员来源，不能受成员后续确认影响；在线主题确认也不会从旧依赖间接吸收后来来源。

隔离输入为 `data/evaluations/grounded-topics-full-20261118/snapshot-terminal` 的SQLite备份副本，范围包含多个保留代，不等同于当前活动代：

## 限制

原文或版本凭据缺失时无法完整还原旧内容时间，只保存可确认的最新已知时间或未知值。此次验证证明元数据行为，不证明记忆正文的主体、事实或时间表达正确，也不代替新的实机部署或模型质量评估。
