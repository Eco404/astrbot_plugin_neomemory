# 多查询候选覆盖对照

## 结论

当前生产仍使用 `extraction-context.v1`。新增的 `extraction-context.v2` 仅用于显式隔离实验，没有切换默认，也没有修改抽取提示词、近期配额或被动召回路径。

固定向量场景证明v1的全局最大相似度排序会让一个话题挤掉另一话题的最佳候选；v2可消除该构造中的遗漏。但冻结的真实Embedding对照没有显示新增目标覆盖，且引入一例弱相关候选，因此本轮不支持默认采用。不能仅凭程序边界测试通过宣称语义检索改善。

## 参考与方案

先核对[新建与更新研究](../research/event-create-update-balance.md)，再阅读本地Graphiti提交 `5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`（Apache-2.0）的 `graphiti_core/search/search_utils.py::rrf` 及 `search_config_recipes.py`：它保留多路候选后融合排名，提示不能过早只保留一路得分。其RRF是多检索方式的排序融合，不提供逐话题覆盖保证；多个相似查询还可能放大同一话题，不能直接移植。没有复制第三方代码，也未声称核对最新上游状态。

v2为最小覆盖候选：

- 每页仅做一次节点×查询矩阵运算，同时保留全局top-limit与每个查询的最佳节点。
- 最多10个查询；每查询只保留一个代表，多个查询共享同一最佳节点时去重，不继续索取下一节点。
- 近期 `ceil(limit/3)` 名额不变，先安排各查询达到0.35相似度的代表，再用原有全局排名补足。
- 总limit不变，不增加LLM、向量请求或额外聚类；0.35是实验前冻结的候选门限，不是经过跨模型校准的相关性保证。
- 小预算无法保证所有查询都覆盖；代表按分数及节点ID稳定排序。分页保留O(limit+查询数)项，加上当前页矩阵，不保留全库向量副本。

入口为 `select_context_ids(..., context_policy="extraction-context.v2")`。默认不传参数时仍使用v1，当前维护任务请求签名也仍为v1。实验方案不能因存在入口就当作生产已采用。

## 冻结真实Embedding评估

脚本 `scripts/probe_context_coverage.py` 在请求之前写入全部节点、查询、目标与两种策略的manifest，SHA-256为 `14e27e44a32011dd6b42aa332bcb93410a933f2491520a40c2c24833001ad9a5`。

材料独立编写，没有读取私人会话：43个合成旧节点，其中31个属于相近的天文活动话题，2个分别为琴弓维修及图书角书架，另有10个近期背景；8种查询组合覆盖单/双/三话题、重复消息、简短闲聊、无关问题、近期重合及小预算。两种算法使用完全相同的已返回向量，无择优重跑或按结果调门限。

模型 `@cf/baai/bge-m3`，1024维。48个去重文本分3次真实HTTP，SDK无重试，总Embedding耗时约2.96秒，0次生成模型调用。证据保存在忽略目录 `data/evaluations/context-coverage-20261117/`。这是候选选择器与真实向量的对照，不是原始采集、模型抽取或事务链验收。

| 查询组合 | v1与v2结果 | 解释 |
| --- | --- | --- |
| 双话题 | 集合一致，琴弓目标均入选 | 未显示新增覆盖 |
| 三话题 | 集合一致，两个少数话题目标均入选 | 未显示新增覆盖 |
| 单话题 | 集合一致 | 未改变单查询排名 |
| 重复主话题消息 | 集合一致 | 原文去重，不额外占名额 |
| 简短闲聊 | 集合一致 | 闲聊最佳结果已在近期名额，不能证明阈值识别了闲聊 |
| 无关问题 | v2新增旅行公交节点，替换1个天文节点 | 无关问题与旅行节点余弦约0.440，高于0.35；实际引入弱相关噪声 |
| 近期重合 | 集合一致 | 已有近期项不重复占位 |
| 小预算limit=3 | 集合一致，两个目标均入选 | 此例未遇代表争抢，不能外推任意小预算覆盖 |

所有分支总数、唯一性及近期份额均符合限制。这里的目标是预先指定的具体旧节点，不是完整相关性金标准。内容字节数有记录，但本次没有测试模型对这些内容的实际利用；相同节点数也不保证相同提示词字节数。

## 工程验证

固定正交向量构造中，31个A节点最高分1.0、B最佳0.8、10个近期无关节点，limit=30：v1选20个A加10近期，v2选19个A、B及10近期，规模不变。新测试还覆盖重复查询与近期重合、不足门限的分数、limit=0/1/2/3/4/10/30/50、按1/7/128个节点分页和相同分数的ID顺序。低分测试只验证门限机制，不将低分等同无关。

既有超过2000节点分页、冷热缓存、范围隔离、向量失败、节点版本与后台必要写入测试继续运行，确保候选实验不改变生产v1路径和持久索引职责。测试结果以最终工程回归为准。

## 后续边界

保留v1生产默认。继续区分“正确旧节点未进入模型输入”与“已经看见但错误判断新建/更新”，不强制提高更新比例。若研究新的分配方案，应另行冻结独立材料，检查弱相关噪声、重复话题、短句指代、近期必要背景、总字节容量及连续抽取结果；不能通过修改本轮案例或调高门限来宣称已解决。
