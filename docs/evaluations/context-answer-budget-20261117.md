# 真实记忆产物的回答预算对照

## 结论

对[后台连续链](background-profile-chain-20261117.md)的v27真实产物，用同一问题、人格及固定候选比较2048与4096字节装配后的回答。8次真实LLM调用均完成，无重试；4096在两题补回了2048缺失的关键回答信息，其余两题核心内容保持正确，没有观察到明显错归属或凭空补全。

该结果支持把4096作为更宽松的使用默认进行验证，保留已有用户配置覆盖值。它不代表所有问题都更准确，也没有证明6144值得采用；更大预算仍会带入弱相关节点，检索质量需要单独优化。

## 方法

脚本`scripts/probe_recall_answer_budgets.py`读取已经保存的v27最终装配文本，不重新抽取、检索或Embedding。四个自然问题与所需信息来自已冻结长链清单；每题分别使用2048/4096的实际渲染上下文，共8次HTTP，不重试、不纠正、不择优重跑。

输入只有合成人格、统一当前日期、实际补充上下文及用户问题，评估所需事实只保存在离线清单，未发送给模型。模型为AstrBot原生Responses Provider上的`gpt-6-luna`，text模式，SDK/宿主重试关闭，单次120秒。每个调用保存请求、回答、usage及耗时。

源材料是独立合成长链的真实生成产物，未读取私人会话；这仍是同一个人格和单条链，不能称为新的未见材料或真实平台连续对话。实验检验模型能否利用已注入信息，不覆盖前端hook、工具选择或实机运行。

冻结清单SHA-256为`4300d5e33bc0f5dd6e8c90f98fccddcdf08c7bcb87eaef0dce41d2c0586f16f5`。本地证据位于忽略目录`data/evaluations/recall-answer-budgets-20261117/`，未向Git提交凭据或运行数据库。

## 逐题审阅

| 问题 | 2048字节 | 4096字节 |
| --- | --- | --- |
| 两处设备分别搬好了吗 | 回答北广场延期未搬，但明确找不到湖畔状态 | 回答湖畔已搬入门厅、试听通过且无损坏，北广场延期未搬 |
| 当前与十二月排练的区别 | 正确回答11月隔周二、12月1日起每周三及不参加商业演出 | 同样正确 |
| 职业、年限与抄谱习惯 | 回答自行车技师、2020年起六年，乐谱频率/公版/图书馆/不外借完整 | 给出2020年起而未直说六年，其他习惯完整；属于可接受的表达省略 |
| 是否曾谈过北广场协调的疲惫 | 明确表示找不到相关感受记录，并询问当前最累的部分 | 回答曾谈过烦躁、疲惫、延期以及愿意继续倾诉、不想独自硬撑 |

2048缺失的两题没有瞎猜答案，这是良好的不确定性处理，但仍是已有记忆未能服务回答。4096修复的是这些问题的核心信息可达与利用，不是“完整复述每个限定”：例如最后一题未主动复述“不是生人格的气”，双项目题没有逐项罗列所有设备前提。按用户接受少量瑕疵的标准，这些省略不抵消本次核心回答改善。

没有把回答中的“我记得”按存储正文规则判错；这里是用户问及过去时的实际对话回答，长期记忆正文的叙述要求另行验收。

## 成本与范围

8次HTTP总耗时约31.35秒，单次2.89—6.14秒。预算2048各题实际上下文为1783—2045字节，4096为3943字节；调用耗时受顺序和网络影响，不能把4096的个别更快回答当作速度收益。

交付默认变更发生在长链与回答对照之后；长链执行的是context.v1/2048基线，本项是同候选显式2048/4096比较，不是最终默认context.v2的完整运行验收。

Provider回报2048各题input_tokens为4984—5060，4096为5597—5603；output_tokens分别为56—137和49—78。四题合计：2048为20073输入/340输出token，4096为22403输入/267输出token，共42476输入/607输出token。这里保留供应商实际回报，不把本地UTF-8字节数当token数，也不据此假设宿主或服务端没有附加开销。

本次没有给6144生成回答，因为同一产物下它与4096的上下文完全相同，没有新增装配收益。默认调整后仍需持续观察更多人格、长关系、大空间及弱相关噪声；结果不授权截断正文，也不需要新增被动召回的润色调用。
