# 独立结构约束纠正验证

日期：2026-11-16（Asia/Shanghai）。本地AstrBot v4.29.4源码、Conda astrbot，隔离来源库与派生库。分别验证提示词v17与当前v20，均使用schema v6、短引用reference.v2、纠错反馈candidate-regeneration.v3。

## 方法

`scripts/probe_regeneration_constraints.py` 在调用前冻结独立温室传感器检查计划、必要条件、未完成状态及三份人工构造的无效候选：非法情绪枚举、全空事件时间对象、非法local_ref字符。没有读取私人会话，也没有从其摘录改写测试。

通过真实AstrBot Context和Provider，gpt-6-luna与gpt-5.6-luna分别每类调用一次，共6次HTTP。每份候选只有一次纠正请求；SDK网络重试关闭，宿主普通请求重试设为一次尝试；没有触发内容重试。模型结果经短引用解码、schema与真实事务校验后提交，再阅读存储正文。manifest、精确请求、原候选、纠正候选、receipt及最终节点位于忽略目录 `data/evaluations/schema-correction-20261116/`。

## 结果

6/6通过校验并实际提交，单次5.38～6.52秒。人工逐项阅读6个最终节点，均保留用户主体、周三前收到校准件才开始的条件、否则延期及尚未开始状态；未将用户计划写成人格行动，情绪归属正确。表述细微变化未改变上述必要内容。

这是人为故障注入的可纠正性验证，没有随机生成首轮候选，所以不能计算自然失败率、自动恢复率或提示词提升比例；没有旧反馈v2对照，不能宣称v3一定提高模型成功率。6次成功也不能推导连续长任务无人值守可靠。

## 当前默认v20验证

另用当前v20精确请求执行同样的三类人工故障、双模型各一次，共6次HTTP、6/6实际提交，单次5.23～7.68秒。证据保存在 `data/evaluations/schema-correction-current-20261116/`；两组均有单独的 `manual_review.json`，没有重写已冻结的来源和判定条件。两组合计12次纠正调用，不是12个独立场景。

当前6例均保留用户主体、周三前收到校准件才开始、否则延期，没有把计划写成已完成。但gpt-6-luna的空时间对象纠正结果在正文和事件时间中均遗漏“下周”。这是补充审阅发现的时间覆盖缺口，不冒充预注册指标，也不能算语义完整通过。gpt-5.6-luna的两例不再显式写“检查尚未开始”，仍以未来条件计划表述，没有完成断言。

该结果说明结构纠正成功不能等同于语义无损；不能用6/6入库成功支持默认自动恢复。本轮没有根据这条合成输入追加专用提示词或关键词规则。v17与v20调用数量很小，也不构成版本优劣的统计结论。

## 运行方式取舍

精确反馈可直接用于现有显式重新生成。自动纠正仍保留为待决定行为：若启用，建议每个固定窗口至多一次内容纠正，拒绝候选与尝试次数持久化，网络重试不增加内容纠正额度，输入/版本/租约变化停止并重新准备；失败后保留人工入口，不跳过窗口。

当前没有足够自然失败和语义保持证据支持把这些结果当成自动纠正默认上线依据，因此没有新增默认LLM调用或自动纠正循环。简洁召回表达也未作为本项输出要求，保留完整正文。
