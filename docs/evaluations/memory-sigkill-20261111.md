# 记忆提交与重构切代的进程强杀验证

日期：2026-11-11（Asia/Shanghai）。三个确定的提交后边界各执行三次真实 `SIGKILL`，共 **9/9 通过**。恢复时三类正文及版本、直接来源、累计节点来源、批次消费和游标均未重复变化；活动轮次保持1。重构窗口已提交但未切代时默认节点查询仍只返回旧代；切代已提交后恢复任务直接使用切代回执。

这组证据使用隔离合成输入、实际 `MaintenanceEngine`、`JobRunner`、`ExtractionService` 和 SQLite 存储。Provider由确定性内存响应代替，不调用模型、向量或网络，不操作实机数据库。

## 边界与方法

依据 [ADR-0015](../adr/0015-durable-maintenance-and-replay.md) 的租约、同事务提交回执及原子切代契约，以及 [ADR-0026](../adr/0026-version-provenance.md) 的逐版本来源契约。既有维护引擎测试使用 `CancelledError`，会运行取消后的释放逻辑；本探针补充没有机会执行该清理的进程强杀。

| 场景 | 确定屏障 | 强杀时应有的状态 |
| --- | --- | --- |
| `extraction_committed` | 真实 `extraction.apply` 已返回；外围 `_window` 尚未收到结果 | 抽取事务已提交，任务仍为 running / validate，进度0 |
| `rebuild_window_committed` | 新代窗口的真实 `extraction.apply` 已返回；重构循环尚未更新完成进度 | 新代为 building，已提交一个窗口；旧代仍为 active，进度0 |
| `rebuild_activated` | 真实 `activate_rebuild` 已提交切代及回执；调用方尚未收到结果 | 新代为 active，旧代为 retired，任务仍为 running / switch，进度2 |

每个写进程录入两条合成会话，使用正式维护入队、领取和执行流程。合成Provider只产生一次响应，包含一个事件、一个画像和一个人格关系，各直接引用两条来源。重构场景另建一个旧代节点用于验证可见性。响应经过实际 reference.v2 解码、extraction.v2 校验、来源检查和 v9 提交。

父进程收到屏障信号并确认非空 memory WAL 后发送 `SIGKILL`，要求退出码为 `-9`，再启动不同PID的恢复进程。恢复首先确认任务仍为running，未到期租约不能领取；使用真实时钟等待三秒测试租约到期后，经正式 `claim` 和 `runner._execute` 继续执行。没有使用随机睡眠寻找提交边界，也没有模拟推进时钟。生产默认三十秒租约未改动。

恢复Provider禁止生成，任何调用都会使验证失败。完成前后对以下十二张表的完整行集合计算规范化SHA256并比较：节点、节点版本、累计节点来源、画像、画像版本、人格关系、关系版本、派生操作、派生直接来源、抽取回执、批次来源消费和派生游标。任务状态与代状态单独检查，允许其完成正常恢复转换。

未切代场景恢复前没有重构回执，新代为building、轮次1；恢复后同一新代变为active并产生匹配的回执。已切代场景在新进程尚未执行工作时即有目标代匹配的回执，完成后目标代与轮次保持不变。九个任务完成后检查点均清空，无法再次领取已完成任务。

memory.db处于WAL、synchronous NORMAL（1）；首轮三个场景的强杀前WAL大小分别为655,112、758,112和786,952字节。这些数字仅用于确认未关闭连接时仍有WAL，不是吞吐指标或断电保证。

## 结论与未覆盖范围

本次验证的是提交完成、调用方尚未观察结果这一确定窗口中的进程恢复；未发现需要生产修复的问题。结合[待写恢复验证](ingress-sigkill-20261111.md)，五处边界合计15次实际SIGKILL恢复通过。工程恢复成功不代表模型语义质量。

尚未覆盖完整AstrBot进程或实机的强杀、整机断电、SQLite事务内部任意故障点、硬件损坏、多实例竞争及长期负载。memory使用NORMAL同步，不能据进程强杀结果声称断电持久性。当前合成输出只新建条目，没有在强杀探针中覆盖多轮正文更新或所有治理操作；短期摘要回执也没有对应的真实SIGKILL验证。

重构索引服务在本探针中未配置，切代可见性只通过真实存储默认节点查询验证，没有实际召回、注入、浏览器或向量服务参与。旧代种子只有一个节点，未覆盖旧代画像、人格关系和治理清理的所有组合。三个边界各三次、每次两条输入，不能推导总体故障概率或性能上限。宿主输入截断问题继续按用户决定暂不处理。
