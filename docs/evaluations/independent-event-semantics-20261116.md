# 独立事件同一性与表达评估

## 方法与边界

使用独立编写的八组合成输入，不读取或改写用户提供的真实会话、人格及回放节点。四组开发案例用于诊断，四组留出案例在候选方案冻结后才审阅。每组使用 `gpt-6-luna`、`gpt-5.6-luna` 各运行两次；模型均经 ecoapi，因此这是跨模型而非跨供应商测试。

`python -m scripts.probe_event_semantics --directory <本地结果目录> --prepare-only --version <提示词版本>` 在任何请求发生前保存精确消息、案例、判定标准、模型、重复次数和摘要。省略 `--prepare-only` 才执行冻结请求。运行不随当前提示词文件变化重建请求，SDK重试为零、宿主一次尝试，无内容纠正；并发为二。所有候选，包括失败候选，保留在本地忽略目录。HTTP计数、模型报告的token用量和耗时单独保存；未取得定价信息，不估算货币费用。

此探针使用真实 AstrBot Provider、Context 和 NeoMemory ProviderAdapter；验证输出schema，并人工检查语义。直接提供固定候选节点以隔离模型的事件同一性判断，不验证向量候选选择、短引用回译、数据库提交或召回。因此schema通过不能写成完整管线通过，也不能写成事实正确。

开发案例覆盖跨日同一工程的进展、同日不同场次、不同日期重复活动，以及有条件承诺与专有标题。留出案例覆盖较长间隔的结果、重复活动不同结果、交换主体的条件及无法确定事件同一性的情况。所有判定允许选择性记忆，但保留的结论不得丢失必要条件；有充分同一性依据才要求更新旧节点。人工审阅分别记录事件身份、事实条件、人格主体和文风，不使用禁词命中率替代语义审阅。

## 参考依据

检查了 Graphiti 本地快照 `5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`，Apache-2.0，快照提交日期2026-10-25；不声称已核查当前上游状态。[dedupe_edges.py](https://github.com/getzep/graphiti/blob/5c27edfa8d3e0f49b2571bcebb4261bcc89ee037/graphiti_core/prompts/dedupe_edges.py#L54) 明确日期、数字和限定条件有关键差异时不判重复，新增进展和较新日期本身不构成矛盾。其对象是事实边，NeoMemory的对象是可持续更新的事件正文，不能照搬成“跨日期必定新建”。本评估借鉴其区分同一性、补充和矛盾的原则，没有复制第三方代码。

合计96次真实HTTP、780,871个模型报告token，零SDK重试、零内容纠正。事件同一性分母排除没有旧事件候选的纯承诺和主体用例。均由实际候选人工审阅，不是仅按create/update字段自动打分。

v16的明确失败出现在开发集同日不同场次：`gpt-5.6-luna / same_day_distinct / 2` 将上午单次事件更新成“当天两场培训”的合集。正文保留了两个场次的大部分事实，但旧节点的事件身份被扩大，违反冻结的独立创建标准。这支持检查“单次事件不能被日期或主题合集替换”的通用问题，而不支持“同一天一定合并”或“不同日期一定拆分”的规则。

v17的明确失败出现在原留出：`gpt-5.6-luna / uncertain_identity / 2` 在来源明确不确定是否同一场的情况下，更新旧节点为已取得证明，并以“日期想不起来”替换已知旧日期。另一轮相同模型及两轮另一模型保留了不确定的新记录。因此v17仍存在同一性判断的随机错误，不能称为事件误合并已解决。

v18仅替换通用事件同一性说明，不针对原留出的不确定性结果追加规则。额外冻结全新“同日不同听证会”和“跨日同一运输理赔”两案，分别在v17/v18上进行双模型各两次验证；两版均8/8。v18在开发集也与v17同为12/12，未证明相对v17有质量收益。保留为候选，不能以v16的单次失败未再出现就宣称优化已验证。

表达方面，审阅范围内未见人格主体互换或多余的“我记得/我听说”等记忆包装；这不是所有节点都包含人格行为，也不是普适人称准确率。部分候选省略了独立人格承诺或只将其放入关系中，属于抽取覆盖与存储层选择差异，不能混同于错误事实。原留出的“计划、不表示已完成”被部分候选写成“尚未完成”，有推断强度风险；本轮未据此修改提示词，亦未把缺少严格判据的表达一律判正确。

另观察到少量情绪描述从“终于获批但部分未获资助”推断欣慰与遗憾，以及一个开发候选将单次活动发布条件写入画像。这些不属于冻结的事件身份主指标，须单独检查情绪证据强度及任务条件与稳定画像的边界，不能用本轮身份通过率替代这些质量结论。

## 限制与后续方向

每模型每案仅两次，模型由同一供应商提供，短窗口仅有零或一个旧事件候选，多数输入有明确的时间与身份线索。当前结果能揭示机制问题，不能估计实机长会话的总体错误率，也不能证明新提示词在多候选、代词密集、跨多窗口输入中更优。

下一步应先冻结多候选干扰、间接同一性证据和不确定性保持的独立评估方法，再研究是否需要更明确的事件身份依据。不得从真实样本摘取或改写失败句子，不得把“允许选择性抽取”改成“必须保存所有事实”。保持被动召回零新增生成调用；事件判断仍在已有后台抽取内完成。

## 输出合同一致性版本的有限回归

`extraction-prompt.v19 / extraction.v6` 基于v17消除经历情绪段落的“仅v5”限定，并说明整份候选120,000编码字符容量；未采用v18事件同一性候选规则。使用原八案、每模型一次，共16次调用进行有限回归。案例与判定未变，这些结果已被审阅过，不再称为新留出，不能用于宣称新的泛化收益。

精确请求目录为 `data/evaluations/event-semantics-20261116-v19/`，manifest SHA256为`312c16200588c76df6c97dadcbfe8a9ba872a4781a999368637f2afddf6de01b`。

16/16候选通过schema，零重试；合计132,079个模型报告token，运行耗时72.133秒。`gpt-6-luna`和`gpt-5.6-luna`单次中位耗时分别7.55秒、9.13秒。包含本次有限回归的全部探针合计112次HTTP、912,950个模型报告token。

事件身份人工检查为10/12：`gpt-6-luna`为6/6，`gpt-5.6-luna`为4/6。后者在`same_day_distinct`再次把上午事件扩为当天两场合集，在`uncertain_identity`再次将不确定的新经历作为旧事件更新，并覆盖其已知日期。两项均属于实际质量失败，不因schema通过而关闭，也不能认为输出合同修正应自动解决这些语义问题。

审阅范围未发现人格主体互换或冗余记忆包装。两个模型在主体交换案例中均将“计划、不表示已完成”写成“尚未完成”，继续保留推断强度风险。当前默认版本的选择以代码与有效配置为准；这里分别保留各精确模板的评估证据，不把实验版本结果冒称另一个默认版本的效果。

当前默认`extraction-prompt.v20`在v19基础上仅去除人格主体规则标题的“仅 extraction-prompt.v16”限定，未采用v18事件规则。上面的v19结果是与v20仅差该标题的相邻对照；本探针没有对v20重新执行完整语义回归，不能把v19的16次结果标成v20实测，更不能宣称v20已消除两项事件身份错误。后续验证须保留这一范围差异。
