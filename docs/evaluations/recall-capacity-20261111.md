## 工作负载与测量口径

两个私聊空间共 4,200 节点，每个空间只有一个当前活动代，每代 1,575 个 active、525 个 historical。节点 ID 固定，重要性按编号唯一递增，快照顺序不依赖随机 UUID 或更新时间的微小差异。所有节点强度初值为 0.6；不执行召回强化。没有边、覆盖关系或短期摘要；每空间各有一段固定短画像与人格关系。

离线 Provider 复用既有容量脚本的文本哈希随机向量；768 维、batch size 16、向量并发配置 2。查询是本空间最后一个 active 节点原文，历史为此前 10 个 active 节点原文，交替 user/agent，权重 0.45/0.4，均在 7,200 秒内。使用原文查询使候选与装配可重复，不能代表自然语言问题的命中率。预热后测量热缓存，不重复旧证据已覆盖的冷缓存前台和控制台分页实验。

使用生产 `MemoryStore`、`CacheStore`、`ProviderAdapter`、`EmbeddingService`、`RecallService`、`ContextStore` 和 `assemble_context`。按 `MemoryRuntime._passive` 的调度方式并行读取本地上下文与长期召回，保留 25 ms 给最终复核；召回超时可保留已完成的本地上下文。最终复核使用剩余时间与至少 25 ms 的宽限，随后同步装配，实际墙钟可能超过配置截止。没有用硬性的整体 5 秒超时替换该语义。

本探针未调用 AstrBot 真实事件 hook，不包含身份路由、源库历史查询、昵称查询、请求对象注入和强化的成本。计时从并行上下文加载之前开始，到最终共享装配结束；单独保留最终复核和装配耗时。

分位数为 nearest-rank。单请求与并发组各 10 个样本，P95 等于最大值；并发场景每请求有 20 个样本，其 P95 是第 19 个有序样本。事件循环每 10 ms 测量一次定时器超出预期的延迟。资源采样线程每 20 ms 读取 `/proc/self/status` 和数据库目录；采样峰值可能漏掉更短暂的峰值。Linux `ru_maxrss` 另行报告整个进程的生命周期峰值，包括依赖导入、建库、索引、预热和全部场景。

环境：AMD Eng Sample `100-000000954-50_Y`，16 个可见逻辑 CPU；普通亲和允许 16 个 CPU，受限子进程只允许其中一个 CPU。容器 `cpu.max=max 100000`、`memory.max=max`，可见主机总内存 57,420,888 KiB；Linux `6.18.18.c1186-trim`、Python 3.12.13、NumPy 2.5.2。未设置 `OPENBLAS_NUM_THREADS`、`OMP_NUM_THREADS`、`MKL_NUM_THREADS`。允许的 CPU 并非独占资源；单核亲和不等于低配实机或受限 CPU 时间配额，也未施加内存、慢磁盘或网络限制。

每请求均得到 11 个排好序的候选，最终保留 4 个完整长期节点、画像与关系，合计 1,950 / 2,048 UTF-8 字节；本地画像和关系没有被省略。其余 7 个候选明确记为共享预算省略，没有裁断正文。该结果只证明这份固定长度夹具的完整条目装配。所有场景完成后，每空间再次请求均恢复正常，仍得到 4 个节点。

单核亲和本次更快，不构成优化收益。两个环境顺序执行，线程调度、数值库执行与共享硬件负载不同；本次没有修改生产实现，也没有做随机交错或多次独立进程统计。与旧 1.5 秒截止实验的夹具、空间数和最终装配路径也不同，不作直接提升比例比较。

## 候选上限与资源边界

每个空间从当前活动代的 2,100 个 active/historical 节点中固定取 2,000 个。上限排除 100 / 2,100，即 4.7619%；其中排除 active 75 / 1,575，同为 4.7619%。被动召回随后从上限内剔除 500 个 historical，实际读取 1,500 个 active 候选。其他空间没有进入分母，也没有将退休代数据计入遗漏比例。

这是本夹具的候选数量排除比例，不是查询相关性、语义漏召回率或任意规模下的遗漏上限。数据继续增长而候选上限固定时，被排除的比例也会增长；本次没有调整此有效契约。

RSS 单位 MiB（2^20 字节）；每个子进程依次执行表中场景，因此后续值可能包含分配器与线程池保留的内存。

| --- | ---: | ---: | ---: | ---: |
| 16 CPU | 241.77 | 400.38 | 541.63 | 540.67 |
| 1 CPU | 225.92 | 372.98 | 393.00 | 392.67 |

## 验证范围

脚本完成两种 CPU 亲和实验，校验了候选 ID 集合、上限、active 数量、索引数量、热查询零新增向量调用、最终跨空间隔离和共享字节预算。Ruff 与 Python 编译检查通过。没有增加或修改生产测试、默认值或实现。

本证据补充了跨空间并发、CPU 亲和限制、RSS、数据库/WAL 和最终共享装配指标。尚未覆盖真实网络推理、AstrBot 全链路成本、实际低内存设备、稠密图、长正文组合、长期持续负载、同时写入或多进程竞争。当前数据支持这份有界离线工作负载可完成，不能作为线上 SLO、真实召回质量或一般部署容量保证。
