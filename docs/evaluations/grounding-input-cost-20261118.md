## 范围与方法

复核代码为 `e79a801`。仅使用独立合成实验 `data/evaluations/topic-grounding-clean-20261118/` 的 grounded 臂八份 `prepared.json`，未读取私人会话、访问实机或新增模型调用。只读 SQLite 使用 `mode=ro`；未修改生产代码或数据库。

对每份同一准备快照分别渲染 extraction v31、v32、v33，沿用真实 reference 协议。v31 过滤新增的 event→atomic 结构边，仅保留原协议可见的 topic 成员边；观察锚点及可读时间也按版本隐藏。三者使用同一份正文、画像、关系、人格和来源，排除不同模型产出带来的文本量差异。八份 v32 重建的基础请求均与原实验所有相应调用的前两条消息逐字一致，包括带纠正反馈的调用。

计量是程序 `message_bytes()` 使用的两条消息 `content` 的 UTF-8 字节和，包含提示词内 schema；不包含 SDK 请求封装、单独传输的 structured-output schema 等其他 HTTP 内容，也不是 tokenizer 计数。v33 是离线重渲染的成本，不是该实验实际调用过的版本。

本地复核脚本及指标：`data/evaluations/grounding-input-cost-20261118/analyze.py`、`result.json`、`request_identity.json`。

## SQL 与临时内存边界

本组每个快照有 0～6 个已知实体。实际调用观察锚点 helper 产生 0～6 次来源链查询，加 0～1 次原始时间查询；读取直接来源链行数最多 22，唯一原始来源最多 11。查询计划显示节点版本使用 `idx_memory_versions_node`，直接推导使用 `idx_derivation_node`，来源关联使用既有主键索引；版本选择分别取首个和末两个，不递归遍历所有祖先正文。SQL 中的小结果排序存在临时 B-tree，不能描述为完全无临时分配。

SQL 复核使用实验结束后的合成数据库，并按准备快照的版本上限读取；同一版本后续的确认可能已增加来源，所以这些数量不是原调用当时的 SQL 日志。字节比较始终使用原先冻结的锚点，未用重查结果修改请求。

每个实体的模型可见锚点最多三个；画像、人格关系也使用已有版本/来源链，不增加新表。原始时间按唯一来源 ID 每批最多 200 条读取，只取 ID 和观察时间，不加载会话正文。

需要区别三个版本上限与内存硬上限：同一版本可能被多次确认，每次确认的直接来源仍需纳入观察范围。该部分没有固定来源条数上限；一个窗口要同时持有选中版本的来源关联、唯一 ID 集合、时间映射和输出锚点，临时内存随这些直接证据增长。每批 200 条仅限制单次查询，不限制总集合。普通抽取的初始候选数还可能因主题成员闭包扩展，不能把初始候选限制当作锚点实体总数硬上限。

本次只读同步包装器复用实际 helper，`tracemalloc` 观察到的 Python 分配峰值约 1.1～14.6 KB；这不包含 SQLite 原生分配、真实异步连接、完整请求对象或生产长历史，不能当成插件的内存上限或性能 benchmark。就该组实际规模而言，查询量与分配很小；大量重复确认的长期状态尚未做压力验证，应保留这一限制。

中间 ID 集合、查询行和时间映射只在 helper 执行时存在，用完释放；进入 prepared/checkpoint 的精简锚点属于重试恢复所需的固定输入，不能为了节省缓存把它改成重试时重新查询。没有新增持久临时数据池。

## 缺失原文与语义边界

原始记录不存在时，查询不会用数据库 `created_at`/`updated_at` 填日期；锚点保留直接来源数量与实际可用数量，无可用时间返回 `null`。这个行为已由独立存储测试覆盖，本次不通过删除数据库记录重新测试。

锚点表示所选版本直接证据的观察范围，不代表所有继承事实发生在该范围，更不保证最新确认给旧事实更新日期。UTC 仅为展示时区，不冒充说话者本地时区。明确这些边界会增加输入体积，但没有制造新的事实日期或将处理时刻变成原始观察时刻。
