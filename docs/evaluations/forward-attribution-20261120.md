# 群聊转发内容的抽取归属

## 实验范围

NeoMemory a65f763，AstrBot v4.29.4。已核对本地与实机的 QQ 官方、OneBot 适配器以及 NeoMemory 来源采集模块的文件摘要。实验全部使用本地隔离 SQLite 数据库，事件和人物均为合成材料。每个模型、每个用例使用独立的空库。

原作者小澄说自己对芝麻过敏，以后订工作餐需要避开芝麻，周五会交登记表。转发者阿岚自己的附言是周四负责把菜单发到群里。以过敏事实的归属、两人的待办、阿岚的画像是否写入过敏信息为判断依据。直接自述对照组中，同一段话确实出自阿岚。

每组显式准备一个单消息群聊窗口，分别调用 gpt-6-luna 和 gpt-5.6-luna。每次使用运行版本的长期或短期提示词，直接提交给 Responses API。长期候选经短代号还原、正常校验和数据库事务提交后读取节点和画像，短期输出经正常解析和身份还原。共 12 次长期抽取和 12 次短期摘要，每格每模型一次。未覆盖自动触发、模型纠正、多轮对话及实机 QQ 客户端发包。

## 结果

| 交付形态 | 模型实际能看到什么 | 两款模型的结果 |
| --- | --- | --- |
| OneBot 原生 forward 卡片，仅有转发 ID | 发送者与空正文 | 均无节点、无画像，摘要为空 |
| 同一卡片加阿岚的文字附言 | 阿岚自己的附言 | 均只记录周四发菜单，画像为空 |
| 宿主 Node 组件含小澄姓名、账号、原文，另附阿岚评论 | 原始组件 JSON 有姓名和原文，模型输入仅有附言 | 两款模型都漏掉小澄的原话，正确记录阿岚的待办 |
| QQ 官方文本明确写“转发自小澄的原话”，随后标明“我的补充” | 原作者和附言边界在正文内可见 | 过敏和周五交表归小澄，周四发菜单归阿岚，均未为阿岚建立过敏画像 |
| QQ 官方普通文本模拟转发标记已丢失，只剩“我对芝麻过敏……” | 发送者阿岚和第一人称正文 | 两款模型均在实际入库的长期节点、阿岚的画像以及短期输出中误归给阿岚 |
| 阿岚直接发送同一句自述 | 与上一组相同 | 两款模型均按阿岚自己的情况记录 |

OneBot 卡片用真实适配器转换合成协议事件。Node 组直接装配真实宿主组件，检验内部原文已经送到采集层的情况。QQ 官方三组用真实适配器解析合成普通文本；无标记组检验一种输入条件，不能据此断言官方 QQ 转发操作一定以这种格式送达。

无标记组和直接自述组，短期请求完全相同，长期请求去掉各实验独立生成的空间 ID 后也完全相同。对结构化 Node 组和仅带附言的卡片组做同样比较，结果也相同。转发关系能否保留到模型输入，直接决定了这两种情况是否具备可用的区分依据。

## 结构化转发输入的复测

长期使用 extraction-prompt.v41，短期使用 short-term.v7。沿用上述两款模型、六个合成用例及隔离数据库，另加入三人嵌套转发和带文字预览的 QQ 合并转发卡片。16 次长期请求、16 次短期请求，每格每模型一次，另有一次长期候选纠正。主题整理和单独画像、关系重构通过集成测试核对输入，本次真实模型调用覆盖联合长期抽取和短期摘要。

| 用例 | 长期节点、画像及短期输出 |
| --- | --- |
| 仅 ID 的卡片，有无附言各一组 | 两款模型都未补写不可见原话。有附言时只记录转发者周四发菜单的安排。 |
| 原作者署名的宿主 Node 加附言 | 两款模型都将过敏和周五交表归给小澄，周四发菜单归给阿岚。两条长期节点分别记录两人的事项，两份短期摘要保留两人的归属，阿岚的画像均为空。 |
| 两层嵌套 | 两份短期摘要均区分了阿岚发菜单、小柳联系食堂、小澄回避芝麻及交表。gpt-5.6-luna 的长期候选首次提交成功。gpt-6-luna 首份候选用了不合格式的局部引用，脚本对同一输入显式调用插件的校验反馈后重新生成并提交。此次没有运行后台自动纠正调度。 |
| QQ 合并转发 JSON 卡片预览 | 两款模型在短期摘要中都正确区分转发者和预览文字中的小澄。长期抽取中，一款同时保留两人事项，另一款只保留发送者的附言。两款均未为阿岚写入过敏画像。 |
| QQ 官方普通文本三组 | 明确标出转发及附言的组均正确区分两人。丢失转发标记的组与真正自述的组一样，均把过敏写进阿岚的画像。 |

案例中的署名与事实均为合成数据。可读结构的收益在本组实验中是把之前被丢弃的引文及作者传到了模型端。卡片预览的完整性、模型最终保留哪些细节，以及实际客户端对不同转发操作提供的组件，仍受交付形态和模型选材影响。
