# 旧事件候选、增量向量与节点情绪的真实模型检查

测试对象为 `extraction-prompt.v14 / extraction.v5` 候选、memory.db v12，宿主源码AstrBot v4.29.3。输入是预先固定的独立合成材料，没有读取私人会话或据其调参。运行脚本为 `scripts/verify_semantic_context_api.py`，本地证据位于 `data/evaluations/semantic-context-20261113/`。

## 方法

空间中预置一条一月陶艺课事件及随后12条其他经历，候选上限设为6。第一个窗口明确补充旧杯子烧制完成且已取回；第二个窗口描述另一天的同类课程，新碗尚未烧制。运行前固定审阅要求：正确续写旧事件、不同经历分开、未完成状态不反转、情绪归属明确、无依据允许null。预置节点仅是测试前提，不算模型成功抽取的产物。

每个窗口使用真实向量模型准备候选，随后再用相同输入读取热缓存；同次LLM抽取生成正文、标题和情绪，事务提交后准备变化版本的节点向量。最后对旧杯子提出主动语义查询。没有自动或人工重试、重新生成、输出清洗或回填。

## 结果

模型为gpt-6-luna，实际LLM HTTP 2次、Embedding HTTP 6次。两个窗口均通过协议、引用、事务提交及向量读回检查。

| 检查 | 第一个窗口 | 第二个窗口 |
| --- | --- | --- |
| 旧事件进入6条候选 | 是 | 是 |
| 冷/新增查询准备耗时 | 1.3456秒 | 0.4770秒 |
| 重复热查询准备耗时 | 0.0078秒 | 0.0073秒 |
| 热查询新增HTTP | 0 | 0 |
| 提交后需准备的变化节点 | 1 | 1 |

逐项人工审阅完整输出：第一个窗口更新了原有杯子事件，保留一月课程及十一月取回的时间范围，标题正确表述烧制完成；高兴归属于明确表达该感受的成员，情绪为joy/0.5，描述正确使用稳定身份引用。第二个窗口新建另一条课程事件，未把小碗写成已烧制，也没有反转旧杯子状态；无额外情绪依据时为null。两个正文均没有“我记得”包装，也没有把对方动作写成人格亲自做过。旧版本和新版本保留独立来源与标题/情绪快照。

主动查询将旧杯子事件排在首位，完整返回了成员昵称和情绪，向量无缺项。共返回6条，其中另一次陶艺课相关，其余4条是较弱相关的日常经历；默认相似度门限下存在噪声，不能将“有结果”当成高精度召回。没有据这一小样本调整门限。

## 证据限制

这是一个空间、一个LLM、13个预置节点和两个新窗口的检查，不能证明大空间冷缓存耗时、多模型事件同一性、自然指代或完整关系连续性。全空间分页的2105节点边界与索引失败恢复由独立工程测试覆盖，工程测试不证明真实语义准确率。热查询时间是本环境的两次观测，不是延迟保证，也不能代表持续负载性能。

工具查询的默认2000节点快照与后台抽取分页候选是不同边界；本实验没有证明规模外节点能被主动工具找到。情绪是否被错误full覆盖隐藏仍依赖模型声明的真实性，当前结构和版本检查不能证明自然语言覆盖充分。
