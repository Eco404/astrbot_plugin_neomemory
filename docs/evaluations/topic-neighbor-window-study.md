# 主题整理中逐条选择相关旧节点的输入对照

在三个话题争夺同一批名额的合成场景中，现行排序选入 0/2 个预先指定的旧事件。先从邻居排名中排除本批已入选节点后，2/2 个旧事件进入最终模型输入。在没有额外关联的场景中，这种选择也会换入语义无关的旧节点。

## 材料与方法

合成图包含 39 项旧事件。31 份不同城镇的新闻摘录叙述不同志愿者为各自的闭幕活动校对字幕，形成密集的近义干扰。另有两项陪伴约定和六项日常背景。每个场景另加入该批新事件，在真实 source.db 和 memory.db 中各自创建有来源的节点。公开的材料、判据及两种预算在获取向量前固定，清单 SHA-256 为 `d2bf06fcec383d594fbcd306047b6ee5cf8eccf470005d3aa7ff1d53d921bb6b`。所有场景均来自独立编写的合成材料。

Cloudflare `@cf/baai/bge-m3` 为 44 段不同文本提供向量，共 3 次 HTTP。两种排序复用同一份归一化向量。现行路径通过 MaintenanceEngine 的主题准备方法选取初始候选、在 SQLite 中固定成员及来源、裁剪证据并生成 v7 请求。实验路径只在排名每一页前排除已经固定的待整理节点 ID。每个待整理节点沿用现有相似度门槛保留一个代表，重复代表只占一位，其余名额按全局排序补齐。两边都保留本批全部待整理节点。候选上限均为 30，预算为默认 256000 字节或独立固定的 18000 字节。

命中按最终序列化请求中出现的预标注旧事件计算，已入选种子不重复计分。四种场景使用同一个基础图，两个预算使用同一组内容。统计不能折算成独立用户的召回率。本实验只比较模型可见内容。

## 最终进入请求的内容

| 场景 | 默认预算，现行 → 排除已选 | 紧预算，现行 → 排除已选 | 其他变化 |
| --- | --- | --- | --- |
| 新发生的字幕新闻、倾听约定的践行和轮流选书同时进入一批 | 目标 0/2 → 2/2 | 目标 0/2 → 2/2 | 两个旧约定替换了两项其他城镇的字幕新闻 |
| 两条新经历均承接同一个倾听约定 | 目标 1/1 → 1/1 | 目标 1/1 → 1/1 | 两侧候选集合相同、约定只出现一次 |
| 字幕新闻与临时借伞，各自缺少跨事件关联 | 无目标 | 无目标 | 新排序在两个预算下均将另一项字幕新闻换成归还字典的旧经历，仅凭归还物件不足以建立持续关联 |
| 倾听约定及其践行都已进入种子 | 已有一对，无额外目标 | 已有一对，无额外目标 | 新排序将另一项字幕新闻换成无关的共读约定，两条已有种子均保留 |

在三话题场景中，两边在默认预算下都包含 30 个节点及 30 份来源摘录，请求为 42125 → 42177 字节。紧预算下均保留 11 个完整节点和一份摘录，请求为 15984 → 16011 字节。裁剪保住了两个新增目标的节点正文，来源说话者的原话证据变少，紧预算下的主体表述仍需独立核验。

本次 16 份请求均完成准备，候选比较本身使用 0 次生成调用。未触发种子减半，图中也没有需整体展开的大型旧主题。缩小种子批次后如何重新排序，以及在多页大库、不同向量模型下的成本和弱邻居噪声，仍需分别验证。已有相关经历本来就在当批时，观察到的换入项提示应把“本批是否已有足够证据”纳入后续对照。此次不按合成材料调整相似度门槛。

早先对普通抽取的 Graphiti RRF 对照显示纯名次融合也会引入无关项。这里复用现有逐查询代表选择及全局补足，以相同名额比较自身命中的影响。[既有多话题向量融合评估](context-fusion-20261117.md)

## 来源说话者复核

首次实验使用节点文字填充合成原话，遇到人格视角叙述时来源作者会有歧义。为检验真实模型如何归纳主题，另行冻结对应的用户发言和人格回应，分别进入来源库。覆盖倾听约定、共读约定及后续践行，节点正文、目标成员和全部向量沿用前一组。原输入单列保留。本组清单 SHA-256 为 `6d10955861430e1511d83348a358a55352a9a613f7a07ea6cc321c648bdffb88`。16 份请求均完成准备。三话题场景在两种预算下依然为 0/2 → 2/2。默认预算下，现行输入包含 32 条原话、43021 字节，实验输入包含 34 条原话、43894 字节。紧预算下两边都只容纳了一条摘录。各任务生成的正文与成员选择应使用另行记录的真实模型证据评价。

## 复跑

在插件根目录和 conda astrbot 环境执行。脚本会在新目录写入清单、每次准备后得到的完整模型输入和诊断报告。

```bash
PYTHONPATH=.:../AstrBot python scripts/probe_topic_neighbors.py \
  --output data/evaluations/topic-neighbor-window-repeat \
  --vectors data/evaluations/topic-neighbor-window-20261119/vectors.json
```

加上 `--attributed-sources` 可复核分说话者版本。省略 `--vectors` 使用本地已配置的真实 Embedding API 重新获取向量。线上模型修订可能改变复跑结果。
