# WebUI治理闭环与加载可用性验证

## 范围与原有缺口

本次使用Chromium、真实NeoMemory前端资源、AstrBot认证/资源/插件扩展路由和临时插件运行实例。宿主源码为 `v4.29.4-45-gbb2e46773`，工作区无宿主修改；插件以 `578a30e` 为基线，加上本次治理加载修复。所有写入均落在独立合成数据的临时数据库和临时配置，未操作实机现用插件、原始库、人格或配置，也没有外部模型请求。

原有 `host_smoke.py` 已覆盖标题/情绪治理提交、条目内版本来源、热配置，以及关闭浏览器和重载后的任务继续执行。但拆分只检查表单载荷，完整拆分/合并/状态治理主要依赖mock bridge或存储层测试，尚缺少浏览器表单经真实宿主任务路由到数据库的联合验证。本次只补足这一闭环及验证中发现的加载交互问题。

实机Vue Dashboard的只读证据仍见[Dashboard查阅验证](dashboard-recovery-20261118.md)。本次父页面是最小GET/POST桥接契约实现，不是完整Vue应用；不能将两者拼接成“实机Vue治理写操作已通过”。

## 实际治理闭环

扩展 `tests/ui/host_smoke.py`，让同一合成节点通过正常表单完成8个后台治理任务。逐项核对任务终态和数据库内容，不只检查“任务已提交”的提示。

| 操作 | 已核对结果 |
| --- | --- |
| 编辑正文与标题 | 原节点版本1→2，正文更新，人工保护启用 |
| 拆成两条 | 原节点成为已替代；两条新节点均为版本1、受保护，并保留显式选择的来源 |
| 合并两条 | 保留指定节点身份，正文含两部分内容，版本1→2；另一节点成为已替代，来源仍完整 |
| 禁用、恢复 | 状态依次为disabled、active；人工保护仍为true，正文版本未变化 |
| 解除保护、开启保护 | 保护依次为false、true；状态保持active，正文版本未变化 |
| 删除 | 确认前不能提交；确认后生成deleted墓碑，保留两个正文版本、来源关联和原始记录 |

8个提交标识各不相同、对应8个成功任务。最终三个相关节点分别为：原节点superseded/版本2、合并保留节点deleted/版本2、另一拆分节点superseded/版本1，人工保护均为true。外键检查无错误。

以上证明治理表单、接口、任务和存储语义接通，不等于测试了所有拆合关系图或所有自动抽取保护冲突。更复杂的回滚、环路、过期版本和自动覆盖限制仍由已有治理层测试承担。

## 互斥、进度与已有功能回归

仅在隔离运行实例中暂停worker，浏览器提交正文治理后，任务进入queued，治理及整理按钮禁用。另用同一浏览器的请求上下文提交不同请求标识、相同空间的冲突任务，真实接口返回409，队列仍只有一个任务。

恢复worker后，在实际治理提交入口加一个测试用等待门，使运行状态可被稳定观察。生产管线已经写入的步骤为“应用人工治理”、进度0/1，浏览器显示执行中，且没有运行中任务的删除入口；释放等待门后真实治理提交，终态显示完成、1/1和100%。该等待门仅控制观测时机，没有模拟成功回执或数据库结果，不用它评价耗时性能。

完整host smoke同时重新通过原有检查：

- 节点、画像、人格关系的版本与来源在条目内展开，历史基线可导航。
- 标题独立修改不误增正文版本；情绪修改形成可查阅版本。
- 模型及高级参数热应用时插件与存储实例保持不变，单项恢复默认不覆盖其他配置，重载后配置保留。
- 关闭页面后队列继续执行；隔离插件重载后未完成任务继续，笔记结果可查。
- 五个页面在桌面及390像素视口可用，未发现页面异常或横向溢出。

`full_smoke.py`、`topic_smoke.py`也通过，分别覆盖更广表单交互和主题成员查阅。它们使用mock bridge，承担前端交互回归，不作为真实存储提交或实机写入证据。

## 发现并修复的实际问题

新增测试最初在节点刷新尚未返回时切换动作并填写拆分表单，晚响应重新建立表单，造成输入丢失。随后使用独立、单次有界延迟复现：真实节点列表GET处于等待时，标题输入仍启用；正常输入新标题后释放请求，标题被旧节点值覆盖。没有创建任务或写数据库，因此不是后台治理回滚，也不能只归为测试速度过快。

修复将治理编辑区域设为可禁用fieldset：节点列表加载期间暂停治理输入、节点选择和刷新；完成或失败后恢复。列表只接受最新请求，并继续检查空间及页面上下文，旧请求不能覆盖新空间表单。未改变记忆、保护或任务互斥的业务规则。

浏览器回归通过三种有界场景：

1. 延迟真实读取时，标题、正文、动作、提交等控件不可编辑；响应结束后恢复。
2. 人为中断该读取，页面显示错误并恢复控件，不永久锁住编辑区。
3. 旧空间读取被延迟时切换空间，成功载入新空间并填写标题；旧响应实际返回后，新空间和输入仍保留。

这些测试只延迟或中断网络读取，不替换成功响应内容。当前修复不承诺草稿跨刷新或跨空间保存；它解决的是点击刷新之后仍允许编辑、再由晚响应覆盖输入的问题。

## 测试过程与证据

原失败日志保留在忽略目录 `data/evaluations/governance-host-ui-20261118/`。新增探针最初误用了英文/“已完成”状态标签，实际界面为“执行中/完成”，已修正断言。随后记录了真实刷新覆盖问题，正常治理链先独立通过，再增加产品修复和延迟回归，没有通过等待来隐去该缺陷。

另一次结果全部通过，但当前Playwright的 `Response.finished()` 遗留关闭页面监听任务并产生 `Target closed` 清理告警。探针改用读取响应body等待接收完成，保留原日志；这不是插件页面异常，也没有修改产品来规避工具告警。

最终检查为host、full、topic三个浏览器脚本及 `git diff --check`。临时数据库在测试结束时清理，断言和聚合输出保留来源、版本、任务及终态验证结果。全程没有用私人会话生成夹具，没有外部模型请求，也没有执行实机治理写入。

另外在独立检出的最低支持宿主AstrBot v4.29.3（`f61a7f42696da6df25dc7a249ec9b8d54ed9da18`）重跑完整host smoke，8个治理任务、迟到响应、真实宿主路由、热配置和重载续跑全部通过。该运行的工作树还包含同名身份渲染改动，未切换主宿主仓库或实机。记录见同一证据目录的`host-v4.29.3.log`及`minimum-host-verification.json`；它仍是隔离宿主路由验证，不是实机Vue写入。
