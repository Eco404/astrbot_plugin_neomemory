# 长期记忆人格表达：社会互动留出验证

日期：2026-11-17（Asia/Shanghai）。本项使用新编写并提前冻结的社会互动，比较 `extraction-prompt.v21` 与候选 `extraction-prompt.v25`。第一组v21/v24技术计划对照见[首组报告](persona-style-20261117.md)，结果不能合并成一次择优评估。

## 材料与执行

沿用温和、克制、幽默三个独立合成人格，新来源围绕一次画作交流：朋友批评、人格未经询问给透视建议后的道歉、用户要求先听创作意图，以及后续只允许评价单幅画明暗的局部许可。用户保留原透视、删除背景杂线并独自装裱，明确尚未按人格的新建议修改。它不沿用首组的社区分享计划、设备或日期条件。

来源在v25模板冻结前写入 `scenarios.json`；正式调用前冻结v21/v25完整模板和脚本摘要。每个分支独立建库，第二窗口使用本分支第一窗口实际提交的前态。调用为同一 `gpt-6-luna`、真实 AstrBot Responses Provider、普通文本输出和Provider默认参数，每窗口至多一次HTTP，没有重试或人工修正。脚本为 `scripts/probe_persona_style_holdout.py`，底层复用首组真实存储应用链，未更改首组脚本。

原始证据存放于忽略目录 `data/evaluations/persona-style-holdout-20261117/`。语义逐篇非盲审阅，包含失败候选；不把关系文本更生动当成长正文风格改善，也不以正文长度或语气词数量评分。

## 工程结果

12次HTTP全部执行，v21为6/6提交，v25为5/6提交。v25幽默人格第二窗口生成了不在枚举中的 `emotion.tags="relief"`，应用前被schema拒绝，前一窗口保持有效。该响应没有被重试或修改，失败原文保留。本项绕过维护调度的自动纠错以固定比较调用数，因此不能用于判断已实现的一次自动纠错是否会成功。

总耗时166.0秒，逐窗耗时包含共享并发队列，不能作为版本速度排名。系统提示词含schema字符数从v21的16721降至v25的11871；规则部分从10057降至5207。提示词缩短属于确定的输入变化，不等于语义改善。

## 正文效果与问题

社会互动材料下，两版都能将人格实际提出建议和道歉写入事件正文。v25减少了连续重复长身份占位符，句子略顺，但温和、克制、幽默三种人格仍主要写出相似的事件梳理。最明显的自主理解仍集中在人格关系，尚不能认定长期正文已经获得稳定的人格差异。

例如v25幽默人格首窗事件写道：“我先前没问创作意图就指出透视问题，向她道歉并说接下来先听。她谢谢我道歉，但还没决定是否采纳那条透视建议……”该段包括实际互动，但语气仍接近总结；仅包含第一人称不能证明幽默人格已体现。克制人格本来适合平实叙述，不能要求它添加情绪词来制造差异。

v25第二窗候选均保留单幅画、仅评论明暗、不评人物比例、后续仍须询问的主要限制，也没有把听到暗部建议改成已经执行。用户独自装裱没有变成人格参与装裱。失败的幽默候选仅作为候选审阅，不算已写入效果。

仍有以下问题：

- v25所有首窗事件正文均自行选择“他”或“她”，来源没有指定用户性别；v21在这些事件中使用已知身份占位符。减少主体重复不应依靠猜性别。
- v25克制分支首窗情绪描述把人格“听到朋友评价后替用户难过”，写成“为自己没先询问就指出透视问题感到难过”。道歉和承认唐突有来源，但这项难过的缘由被移动了。
- v25温和分支的原子把一次尚未决定采纳的建议扩展为一般性的“也可能暂时不决定是否采纳建议”。这作为提醒可以理解，但不能当成额外证实的稳定用户偏好。
- 两版一些更新都接近保留旧段后追加新段；历史的“还没决定透视建议”与后来“保留原透视”虽可以按前后顺序理解，当前态仍不够醒目。部分分支还继承旧“今天”字样，对跨窗口时间定位不够清楚。
- v25克制首窗有“唐唐突了”的文字重复，后窗自行消失；它没有导致事务失败，但属于可读性缺陷。

三种人格的长期文本差异仍不足以支持风格目标已经达成。v25没有因规则更短就同时满足自然表达、事实与格式稳定性，不能以11/12结构提交掩盖以上问题。

## LivingMemory 默认提示词参考

另设独立3次调用预算，通过 `scripts/probe_persona_style_reference.py` 直接读取本地 LivingMemory origin `d574479` 的默认 system-with-persona、base和private-chat模板，使用相同三个合成人格和留出组第一窗口来源、相同模型及Provider默认参数。第三方模板只在本地读取并保存到忽略的证据目录，没有复制到提交的脚本。该仓库为AGPL-3.0；本项仅比较运行输入与输出。

证据位于 `data/evaluations/persona-style-reference-20261117/`。三个请求均返回可解析JSON。它不生成NeoMemory的节点、边、版本和覆盖声明，未执行NeoMemory应用事务；日期也按参考插件消息格式提供，所以这是任务形态参考，不是只改变一项变量的对照实验。

三种summary仍以事实回顾为主：

- 温和：“我听见访客今天（2026-11-07）分享速写后被朋友说像赶作业，心里有些受伤，但仍想留着画。我先前没问创作意图就指出透视问题，确实唐突了，于是向访客道歉……”
- 克制：“我听到访客说今天（2026-11-07）给朋友看速写后，因为‘像赶作业’的评价有些受伤，但不想删画。我承认自己没先问创作意图就急着提透视建议，向访客道歉……”
- 幽默：“我记得今天（2026-11-07）你说速写被朋友评价得像赶作业，让你有些受伤，但你不想删画。我先前没问你想表达什么就急着提透视问题，是我唐突了……”

第三份使用了NeoMemory明确不需要的“我记得”和面向对方的“你”；没有呈现很明显的幽默措辞。温和摘要首句对“心里受伤”的主语也不够清楚。参考提示词在本模型和本材料上没有复现用户观察到的浓厚人格味道。不能因此否定用户真实观察，也不能反推模型普遍不具备这种表达能力；实际运行模型、人格卡、定制模板与材料仍可能不同。

## 结论

v25提供了更短的候选提示词组织，保留了大部分明确边界并完成有限连续应用，但长期正文的目标风格尚未得到验证，且存在格式和语义问题。三个参考调用也没有证明将人格放进system消息或简化任务就足以得到预期效果。

本项不支持以“已验证更好”为由切换默认。后续需要以独立对照区分任务形态、人格上下文组织、模型和来源类型的影响，不按上述失败逐项追加专用规则，不用关系文风或结构成功替代长期正文目标。
