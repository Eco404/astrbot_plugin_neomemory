# 稳定引用展开后的长度校验与诊断

日期：2026-11-11（Asia/Shanghai）。评估只使用独立合成候选和现有schema边界；未读取实机会话、人格或失败候选，没有真实模型调用，也未依据实机候选的长度或引用数量设计夹具。

## 当前契约

模型输出中的短引用通过 `reference.v2` 还原为稳定逻辑用户ID，正式提交前再按完整canonical正文校验schema。因此短引用文本合法，并不保证还原后的完整文本合法。事件正文3000字符、画像描述600字符、关系正文1000字符、标签24字符等既有限额继续生效；没有按显示昵称长度重新计量、增加引用豁免、放宽上限或自动截断。

维护任务在提交阶段遇到Pydantic `ValidationError` 时，保存最多20条仅含字段路径和错误类型的诊断，以 `ReviewRequired / invalid_output` 停止并等待人工处理。来源快照或真实上下文变化的普通 `ValueError` 仍保留 `context_or_evidence_invalid` 分类。原短引用候选和还原后的候选继续保存在检查点，不因拒绝而修改正文或派生数据。

显式重新生成先检查原短引用候选；原候选本身合法时，使用已保存的canonical字段诊断。`string_too_long` 的标准反馈说明长度按还原稳定用户引用后的完整表述检查，要求缩短完整表述并保留主体、否定、条件和引用归属。反馈不附带canonical原文、稳定用户ID或异常文本，不自动删字，也不启动自动重新生成。

## 独立合成证据

新增 [test_canonical_length_diagnostics.py](../../tests/test_canonical_length_diagnostics.py)，每个正文只放一个短用户引用，以固定合成句和重复填充字符构造现有上限的精确边界。输入与受限会话无关，也没有依赖任何真实模型风格。

| 检查 | 结果 |
| --- | --- |
| canonical事件正文恰好3000字符、画像600字符、关系1000字符 | 三例均完整保存，正文与还原结果逐字一致，没有裁断 |
| 对应三类canonical文本分别超出1字符；原短引用文本仍低于上限 | 三例均拒绝，保存准确字段路径及 `string_too_long`；没有节点、画像、关系、派生操作或抽取回执，活动轮次为0 |
| 三类失败后显式重新生成 | 旧候选及canonical诊断完整归档；发送正确字段反馈；合成修正保留主体、仅在安静时练琴的条件及不在夜间打扰的否定；仅显式重生新增一次Provider调用，最终轮次1 |
| 一个标签仅为 `{{user:u1}}` | 短引用为11字符且可通过wire校验；还原测试逻辑用户ID后超过24字符，继续拒绝，诊断定位到 `$.profile_changes[0].tags[0]` |
| 旧失败检查点缺少canonical诊断 | 以保存候选从断点重试即可补齐字段诊断；不重新调用Provider、不改候选、不产生记忆或推进轮次 |

最初十项边界及重新生成测试在补丁前为 **7 failed / 3 passed**：三项恰好上限通过；其余七项因原有错误分类和缺失诊断失败。修复后，与JSON诊断、抽取诊断、引用协议、重新生成、维护引擎/API、schema及抽取提交相关的十个套件共 **224 passed，8.68秒**。另补旧检查点重试场景后，新增文件共11项全部通过。最终补丁的全量回归为 **1384 passed，35.46秒**，没有测试失败。相关文件通过Ruff E/F/I/UP检查（忽略E501）及空白检查。

## 设计限制与操作边界

单个稳定用户引用可能独自超过标签24字符上限，这已经由独立合成输入确认。当前处理保持严格canonical上限，并使失败可见；它不解决“标记开销是否应占正文和标签长度预算”的产品语义问题。是否按其他长度单位计量、对引用单独分配预算，或限制标签中的引用，需要专门讨论，不能由错误诊断补丁自行改变。

已有失败检查点若没有字段诊断，升级不会自动回填。可以先从断点重试保存候选，获得准确诊断后再显式重新生成；上述无新增Provider调用的检查只适用于输入、人格和配置仍匹配原检查点的情况。发生真实上下文变化时继续遵守原有重新准备要求。

本验证使用合成Provider，证明的是拒绝边界、失败持久化及明确的恢复反馈，不证明真实模型收到反馈后一定一次修正成功。原子和主题的类型专属长度校验仍受既有契约约束，本次未为所有字段和跨字段校验建立逐项真实模型评估。宿主输入截断问题仍按用户决定暂不处理。
