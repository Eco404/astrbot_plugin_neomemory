# 候选自动纠正与后台索引稳定性验证

## 证据范围与结论

独立合成的6类错误候选均通过生产后台任务的自动纠正路径，在一次真实模型调用后完成事务提交，没有人工重新生成。该结果支持扩大明确可恢复错误的适用范围；不等于自然构建成功率，也不能保证私人样本曾出现的26个窗口今后全部无需人工。

本次没有读取或改写私人会话，没有据其内容调整模型。初始错误候选是人工注入的夹具，其余信息预先给定，模型只需依照固定输入重新生成，因此任务难度不等同自然首次抽取。默认最多3次候选纠正的预算边界由工程测试核实，本轮模型样例全部首次纠正成功，未触达额度上限。

## 参考实现与采用边界

参考本地 Graphiti，提交 `5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`，Apache-2.0，文件 `graphiti_core/llm_client/openai_base_client.py` 的应用错误重试：附上错误反馈，限制次数；网络超时、连接和服务器错误交SDK处理，避免与应用纠正混合。来源：<https://github.com/getzep/graphiti/blob/5c27edfa8d3e0f49b2571bcebb4261bcc89ee037/graphiti_core/llm_client/openai_base_client.py>。该版本是本地固定参考，不代表上游当前状态。

采用的是区分错误类别、精确反馈及有界纠正的设计。未复制其广泛捕获异常、直接转发异常字符串和仅内存计数方式。NeoMemory仍使用固定来源与候选上下文、持久额度、严格提交校验，不绕过来源、版本或人工保护，也不自动跳过失败窗口。

## 真实模型方法

脚本：`scripts/probe_candidate_recovery.py`。使用真实 `SourceStore / MemoryStore / MaintenanceEngine / JobRunner`；仅适配器第一次返回错误夹具，后续由 AstrBot 原生 `openai_responses` Provider 调用 `gpt-6-luna`，采用text输出。错误判定、候选归档、额度预留、纠正反馈、引用还原和事务提交均使用生产路径，没有在测试脚本中手动调用重新生成入口。

固定来源为独立合成的条件性维修准备：已有事件，后续完成资源预约，但工具未到、工作尚未开始；另一条人格回应表达愿意陪伴。六例分别改变错误字段，不能当成六种独立复杂场景。语义判据在调用前冻结：同一事件更新不重复新建、完成与计划区分、必要条件、主体、来源和未知时间保留。

SDK与宿主请求重试关闭，单并发，每例最多3次真实请求，首轮总HTTP上限18；注入首次草稿不产生HTTP。插件任务网络重试次数设为1次执行，不用外层重试掩盖失败。未使用向量服务，也不涉及任何实机数据写入。

首轮证据：`data/evaluations/candidate-recovery-20261117/`，清单SHA-256：`2d7d498d87236e3c8cd095de3bbb96b03b824a4b30d2cabe17d4ae6df6f20127`。请求、响应、来源、数据库、任务和候选归档保留于忽略目录。

首轮运行期间，v5反馈中的人物来源字段名从错误的`speaker_role`修正为实际`actor_kind`。首轮进程使用已载入的旧反馈，证据不覆盖重写。修正后另执行同一固定关系证据例，1次HTTP自动纠正并提交成功，仍返回关系null；该定向确认单独记录，不合并成新增场景或扩大成功率。追加证据：`data/evaluations/candidate-recovery-20261117-actor-field/`。

## 语义审阅

六例保留了用户主体、已预约但尚未维修、取得工具才开始及否则等待；未新建重复事件、补造时间或关系边。涉及人格实际回应时，输出仍有对应Agent来源支持。

`create_fields`一例情绪描述加入“因此”，将担忧与等待串成原因，而来源明确解释等待是因为工具未到。主体、事实状态和前提仍然保留，但因果表达存在风险，不能宣称语义全部通过。未为此修改夹具或继续择优生成。

关系证据例选择不更新关系，属于允许的有效输出，不是通过添加无关用户引证凑数；然而它没有证明复杂非空关系内容的引证修复能力。其他例也不能外推跨模型、长窗口及多人物的修复效果。

## 后台向量写入

独立排查确认，在线可再生缓存的100毫秒写入余量原先也作用于后台必要索引。合成180毫秒慢写、2秒总期限下，旧策略复现`IndexCacheUnavailable`，缓存错误为`TimeoutError`，模型仅调用一次。该机制可能导致不必要的重试，但不能反向断言它就是上一轮实机瞬态失败的具体根因。

后台必要缓存写入改为遵循已有索引调用期限，在线缓存仍及时返回已算向量；索引保留当前节点/版本读回检查，未持久化不报告完成。缓存读取、计算、写入及读回共用同一截止时间，不增设重试循环或存储池。

新独立测试覆盖180毫秒慢写、数据库锁等待、同文缓存提升无需重复Embedding、在线慢写及时返回、后台超时/取消和读回超时后的已保存向量复用。与已有向量、缓存恢复、窗口索引及抽取候选检查合计60项通过；已提交抽取只补索引、不重复抽取或消费的边界沿用真实存储验证。

## 工程验收

完整产品测试1843项通过，宿主有1项既有audioop弃用警告。覆盖默认首次生成加3次纠正、最后一次额度成功提交、耗尽后保留失败、重启/配置变化不补额度、旧检查点按原额度处理、真实保护及上下文变化仍拒绝、旧v4反馈兼容，以及后台索引的慢写、锁等待和取消。WebUI任务步骤与纠正上限显示已同步，JavaScript语法和文档链接检查通过。独立代码复核未发现阻塞问题；额外将旧提交的schema与v4反馈模块同当前兼容入口对照，12类历史候选的反馈对象完全一致，覆盖JSON位置、重复键、create/update、时间、自环、局部边/覆盖引用、枚举及长度。

现有离线画像证据工具也能识别有固定输入与重生成凭据的引用拒绝链；引用失败不能被计为成功提交，证据不完整仍独立标记。新默认带来的调用数变化已同步对应工程测试，没有弱化提交或来源判据。

## 限制

本轮不部署、不重新构建实机，不提供自然无人值守长链成功率。人工注入故障的自动恢复、schema通过、数据库原子提交与语义正确分别解释。后续需要在独立多窗口材料和更多Provider下验证自然错误、自动纠正开销、重复候选及连续语义保持。
