# 正常叙述生产接入与人格关系连续性诊断

日期：2026-11-12。代码提交 `b363eed`。用户要求采用新版叙述规则、弃用旧生产默认，同时核对人格关系是否偏离最初的连续性规划。

## 正文措辞的原因与处理

检查时实机75个安装文件与既有部署清单一致。249个构建批次全部记录 `extraction-prompt.v7` / `extraction.v2`；92个当前节点中88个以“我记得”开头。生产v7本身提供“应写我记得……”的正面示例，因此不是前端新增前缀或清库未生效。正常叙述要求此前仅落实为v9隔离候选，未进入生产入口，这是要求落地不完整。

切换回归还发现，v9替换整个人物叙述块时遗漏了“保留明确约定的昵称、专属称呼与引用原话”的规则。为保持既有模板可复现，v9内容不改写；v10在v9正常叙述规则上补齐身份引用、约定称呼和简短标签要求，作为生产默认。未依据私人样本改写规则或构造夹具。

自动抽取、新建任务、重构及默认v2提示词构建均选择v10。旧版本只供显式历史回放、隔离对照及旧记录解释，没有生产默认回退。schema保持extraction.v2，窗口引用保持reference.v2；已有已提交正文不自动改写，旧未完成检查点因提示词签名不同需要重新准备。

health增加 `maintenance.extraction_prompt_version`，值来自实际维护实例的抽取服务，用于区分磁盘文件更新和运行实例更新。当前文档及ADR描述当前默认，原有评估报告保留各自测试版本与结论，不将旧证据重标为v10结果。

## 人格关系的原规划与实现缺口

原大纲3.4要求人格的主观感受与心理活动保持连续性，存储为一段自然语言；3.5允许累积互动后判断是否需要更新。它没有要求把每次互动变成独立感想，也没有要求无限追加原文。

当前路径是“本窗口来源、人格、已有节点和画像、上一版关系正文 → 模型输出完整关系正文 → 更新当前状态并保存历史版本”。`ExtractionService.prepare`读取上一版关系，`PreparedExtraction.messages`将其放入 `known_relationship`；存储层整体写入新的 `state_text`，同时记录基线版本。

保存完整新正文可以实现连续更新，但必须由新正文承接仍成立的主观状态。当前节点和画像提示词明确要求保留仍成立旧内容；人格关系规则主要要求第一人称、主观自由及事实边界，缺少同等明确的持续感受保留与变化融合要求。旧版本作为来源凭据存在，不等于旧感受已经出现在当前正文；聊天注入和记忆页主卡片只使用当前版。

固定实机构建的诊断结果：

| 项目 | 观察 |
| --- | --- |
| 构建窗口 | 249窗，5～31条，平均8.98条，中位8条；关系复用长期抽取窗口，没有独立的关系累积门限 |
| 关系版本 | 116版；从第2版开始，每版都记录前一版为继承基线，没有发现版本链断裂 |
| 正文长度 | 存储文本83～486字符，中位142，当前107；远低于抽取schema的1000字符上限 |
| 最新版输入与引文 | 对应6条来源窗口，直接引用2条，并继承第115版；直接引用数量不等于全部历史影响范围 |
| 固定语义抽样 | 查看第1、24、47、70、93、112～116版；这些版本主要围绕当次或近期互动形成感想，末尾版本随新互动换题，较少呈现累积关系基调 |
| 渲染 | 前端显示当前完整正文，没有截短成107字符；注入单项上限为1200字符，共享预算可能整项省略，但不改写数据库正文 |

这支持“连续更新语义不足、近期互动容易替代长期关系状态”的判断。小窗口与频繁更新可能加重这一现象，但没有做窗口大小的控制实验，不能断言扩大窗口就能解决。上一版关系确实传入程序准备的请求，也不能因此宣称模型已正确保留全部历史。宿主超长输入回退仍是独立已知限制，本次没有它触发并导致关系短小的直接证据。

v10只处理正常叙述及既定称呼规则，没有补上关系长期延续规则。因此关系连续性仍是待修复的实现缺口；该现状不作为新的业务契约。

## 修正方向与独立验证

先按原规划明确完整更新的语义：保留仍成立的关系感受与重要心理变化，在新互动确有影响时融合或修正；近期心情可以存在，但不因新话题出现就自动清空无关的长期感受。人格继续自由表达，不强制关系等级、固定段落或每轮更新。

使用与私人样本无关的连续合成窗口，分别验证：无关新话题、普通寒暄、明确关系转变、短暂负面情绪、未解决的矛盾以及长期感受仍成立时的保留。再比较共用窗口和独立累积机制的质量、调用成本及延迟，避免先增大窗口或长度上限而不检验语义。实现仍可保存完整正文；是否需要局部修改应由这些实验决定。

参考本地公开实现：MemoryOS `587ed77` 的 `memoryos-pypi/prompts.py` 明确要求在融合新观察时维持已有画像洞见；Hermes `d0509566` 的 `tools/memory_tool.py` 提供对既有条目的patch操作。前者说明保留规则需要明确，后者可用于评估局部编辑，但两者都不是人格主观关系的直接实现，不能据此引入90维画像或断言局部修改必然更优。未复制第三方代码。
