# 陪伴主题的双模型提示词对照

在11个独立合成场景上，当前 v7 与增加一段陪伴主题判据的候选各有 18/22 次符合预定操作和成员。候选能补回一次含蓄的实践，也漏掉了原来识别出的重要例外。现有结果支持继续使用 v7。

## 实验范围

两组均使用 AstrBot OpenAI Responses Provider、JSON Schema 和插件的主题提示词构建器，模型为 `gpt-6-luna` 与 `gpt-5.6-luna`。两个分支收到相同的人格、手写事件/原子、已有主题、成员边和有限本人原话。候选只在系统消息中增加以下一段。

> 日常相处也会形成跨经历的关联。后一次互动以言语或实际行动承接、实践、修正或重新理解了先前的约定或相处方式，把这些经历放在一起能帮助日后理解它的来由和变化时，可以形成或延续具体主题。概况写出成员实际支持的联系，对方的动机与关系亲疏仍以本人表达为依据。

每个案例在该组请求前固定预期操作、完整成员、自然问题及人工内容判据。第一组含七个案例。观察到其中一些关联由约定暗号联结后，另编四个无暗号案例，在读取第二组任何模型输出前冻结，候选措辞相同。每个组合运行一次，协议错误最多纠正一次，语义失误不重抽。第一组28份最终输出用了29次HTTP，用时约130秒。第二组16份输出用了16次HTTP，用时约65秒。唯一一次纠正在 `gpt-5.6-luna` 的候选更新，首次输出未满足主题更新的身份/版本契约，纠正后身份和成员均正确。

这里的分数要求创建/更新/保持空结果符合预期、全部成员没有多选或遗漏，更新还要求沿用指定主题及版本。另逐条审阅实际标题和正文。图很小，模型直接获得完整候选，向量发现、数据库原子提交和实机运行属于其他验证范围。历史资料中，同一成员被两项独立主题共享和归属模糊的处理已有单独实验。[主题判断与连续链](topic-consolidation-20261117.md) [主题输入研究](../research/topic-organization-inputs.md)

## 按场景结果

每格左侧为 v7，右侧为候选。“符合”指符合上述结构判据，包括应返回空结果的反例。

| 两次沉默的起因和对象不同，应跳过 | 符合 / 符合 | 符合 / 符合 |

| 邀约下次再念道别卡，后来回访并补写感谢，应创建 | 符合 / 符合 | 符合 / 符合 |

七例主对照两模型合计由 12/14 变为 13/14，无暗号组由 6/8 变为 5/8。应建或应更新的共12个模型判定中，两臂各完成10个。应跳过的10个判定中，两臂各正确跳过8个。两种提示都支持明确的约定实践，跨模型的收益方向在同一条旧主题更新上也有反转。

正文审阅发现，主对照里 `gpt-6-luna` 的 v7 正确选择了两个暂停信号成员，仍在主题正文写了一句关于被排除的灯箱事件。候选在该例省去了无关事件。无暗号组中，同一模型的候选把仅旁听的口述史写成了一贯交流方式。另一个模型在饮品协助上，两臂都把临时分工联系成主题，候选还在正文中自称“不是固定流程”。结构校验能接受这些输出，成员选择和能直接注入的文字仍需分别检查。猜字也说明日常新建和已有主题补充可能受到不同影响。一次给出正确结果的成员不能直接证明模型在后续更新中会稳定保留它。

## 复核

两组可分别用 `scripts.probe_companion_topics` 和 `scripts.probe_companion_topic_transfer` 执行。运行前用 `--directory <新目录> --freeze` 固定材料，再去掉 `--freeze` 运行。需要使用 Conda astrbot 环境，并设置 `PYTHONPATH=.:../AstrBot`。每份清单保存输入、规则、逐案例预期、模型、开销上限及哈希。模型返回位于输出目录的 `<模型>/<案例>/<baseline或companion>/output.json`。
