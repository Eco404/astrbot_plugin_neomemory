# 用户画像主体与旧资料取舍实验

基于 33f71ec。采用本地 AstrBot 的 OpenAI Responses Provider、gpt-6-luna 和 JSON Schema，在独立临时数据库中执行日常联合抽取和用户画像专项重构，审阅实际提交后的标签、描述和版本。材料为独立编写的合成私聊。共 18 组，84 个逻辑窗口，全部任务完成。共 90 次抽取调用，另有 6 次仅使用最终画像的问答调用。候选提示仅在实验进程中生效。

## 材料与方法

每种提示跑一条十窗合成对话的日常抽取和专项回放，各一次。第 2、5、7、9 窗分别引入稳定身份与逐字稿要求、带例外的录音格式、新人练习安排和局部修正。其余六窗涉及机构规则、第三方和一次性经历，预期跳过。另将同一份含两个无关旧条目的画像独立初始化三次，各跑两窗日常抽取。再用一组含本人借阅限制及替代做法的两窗材料检查误删。主序列判断标准在运行前固定。借阅材料在首轮存量结果出现后编写，先固定预期再调用。重写方案是在审阅前两组方案后设计的探索方案，借阅材料对其属于已见案例。

- 现行方案使用 v37。
- 追加方案在 v37 画像职责末尾增加主体、相处用途和旧资料筛选要求。
- 重写方案整体替换画像职责，明确选择旧标签和旧正文时应保留的个人限制、例外与允许的替代方式。三种方案共享来源证据、模型、合并抽取、提交和版本逻辑。[主序列与预设标准](fixtures/profile-subject-selection.json) · [借阅材料](fixtures/profile-subject-selection-holdout.json) · [重写规则全文](fixtures/profile-subject-rule-rewrite.txt)

重写规则的三次存量更新里，一次完全清理，一次只清掉标签而正文照旧，一次跳过更新。把规则写得更明确未能稳定解决旧正文沿袭。只看标签数量或整项任务成功都会高估改善。借阅留出的重写组第二窗经历了额外模型调用才完成提交。

## 从空库重构的选型

以画像专项重构从原始会话生成的标签、正文和内容版本评价构建质量。另用事先固定的五窗修表对话，每种规则从空数据库独立运行两次，合计六次重构、30 个窗口。逐版检查用户属性归属、机构和第三方信息误收、条件与例外保留，以及新安排对旧安排的替换。[补测材料及判据](fixtures/profile-clean-rebuild.json)

| 规则 | 两次构建的最终标签数 | 实际画像表现 |
|---|---|---|
| v37 | 7、6 | 两次均排除了工具盒规则和他人偏好。一次把人格名写成左撇子用户的姓名。 |
| 追加规则 | 4、7 | 两次均以用户为主体，保留左手操作示意、原厂图例外、隔周周日上午的安排和工作台替代选项。一次把预留可升降位表述为优先安排，且正文只说教初学者，标签补明修表。 |
| 重写规则 | 4、4 | 两次保留具体条件与替代选项，标签较集中。一次整段使用用户第一人称，读者容易把“我”理解成人格。 |

六次均只在第 2、3、5 窗写入，历版均未收录外部盒子规则、第三方偏好或一次性清点。结合十窗对照，追加规则更适合作为构建候选。它在两组材料的三次专项回放中都保持了主体归属与变化时机。标签精简度和个别条件的措辞仍有波动。重写版的精简度更一致，叙述人称需要改善。结论基于单模型、两组私聊合成材料。

## v38 默认入口验收

使用同一组五窗合成私聊，从两个独立空库分别运行日常联合抽取和画像专项重构。两条路径均使用默认提示词和 gpt-6-luna，每条各调用五次，全部完成。按实际入库版本核对，两条路径都只在第 2、3、5 窗写入，标签和描述均排除了工具盒规则、他人的表带偏好和一次性清点。两份末版画像均保留左手操作示意、原厂零件图例外、修正后的隔周周日上午安排，以及普通桌配高脚凳的替代条件。

日常抽取最终有五个标签，把“要提前预留”写成了“优先预留”，略微弱化要求。专项重构有四个标签，正文保留了该要求。此次运行复用了选型材料，用于核对默认模型请求和实际提交结果。跨模型、群聊和长期使用的泛化效果仍待验证。本机逐窗结果在 `data/evaluations/profile-subject-v38-acceptance/`。
