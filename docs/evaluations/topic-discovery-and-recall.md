# 陪伴主题的候选发现、建档与召回

多话题竞争时，候选选择决定模型能否一起看到一项约定及其后来的实践。独立合成对照支持优先改善逐项选择旧事件，再评估对日常回答的帮助。陪伴主题提示词两臂在首组和迁移组的结构判断合计均为 18/22。当前建议使用生产 v7，并保留至少两项独立成员的条件。

## 候选能否改变模型的实际判断

选用候选实验中预定的三话题竞争场景。在新闻密集的图中，后来的倾听方式和轮流选书都各有一条早先约定。判据要求各建一个主题，分别包含其约定和实践，并审阅额外主题、成员和无依据的心理推断。主题输入由生产准备函数生成，两个排序分支使用相同的 v7 系统提示、256000 字节预算和最多 30 个初始候选。较紧预算的可见性单独见[窗口对照](topic-neighbor-window-study.md)。

用 gpt-6-luna、gpt-5.6-luna 分别执行两种排序。先使用逐节点保存的合成摘录。发现摘录与节点的第一人称表述相同，原始记录却统一标为用户，容易混淆动作主体。随后保持相同节点、判据和向量，单独用明确区分用户与人格发言的来源重做四个请求。两次都在模型调用前冻结输入。相同场景的来源复验不能作为第二个独立语料。

| 输入与模型 | 现行排序下的主题 | 排除已选节点的邻居排序下的主题 |
| --- | --- | --- |
| 逐节点摘录，gpt-6-luna | 无 | 倾听、共读各建一项，成员均正确 |
| 逐节点摘录，gpt-5.6-luna | 合成一项笼统约定，仅含两条新经历 | 两项，成员均正确 |
| 按说话者分别提供原话，gpt-6-luna | 合成一项笼统约定，仅含两条新经历 | 两项，成员均正确 |
| 按说话者分别提供原话，gpt-5.6-luna | 合成一项笼统约定，仅含两条新经历 | 两项，成员均正确 |

8 次 HTTP 均在首次生成后通过主题 schema。所有返回的成员都在其对应输入里。换入两条旧约定后，两模型都能说出每个约定的由来与后续实践。gpt-5.6-luna 有一处标题「先听完，再一起商量」省略了先询问对方是否愿意的条件，其正文保留了这一点。这里审阅模型提案和可见成员，没有测量长期多次更新的稳定性。该场景刻意安排了高密度近义干扰，不能据此估算日常漏建率。

## 提示词与实际注入

双模型在相同可见图上比较了现行 v7 与加入陪伴关系正面判据的候选。候选补回一例含蓄承接，也曾把对第三方的行动归入双方的相处。首组现行和候选分别符合 12/14、13/14 项结构预期，四例迁移材料中分别符合 6/8、5/8 项。成员判对之外，主题正文还需审阅事实、条件和人称。[提示词与迁移对照](topic-companion-prompt-study.md)

另用七个自然问题和实际被动注入入口比较四组模型输出及无主题事件库。事件库已带回全部 10 组必要成员。两组候选主题也达到 10/10，但注入字节增加。这个小库里，组织出可用主题与改善回答所需材料的覆盖是两个不同结果。问题覆盖、注入成本及效力边界见[自然问题召回对照](topic-companion-recall-study.md)。

优先把已固定节点排除出邻居排名的方案带入大空间验证。应检查既有主题成员展开、多页候选、批次缩小后的重新排序，以及错误邻居会不会挤占跨事件问题所需的成员。候选数、整理频率和主题入选门槛在本实验中都没有作为调优变量。实机私人会话只适合在方案固定后作外部评估。
