# 画像更新、人格关系深度与容量优化评估

日期：2026-11-16（Asia/Shanghai）。本报告汇总独立材料上的候选实现、真实模型对照、采用判断及工程复核。私人会话没有用于提示词、参数或规则调优。生产插件和现用数据库未改动，宿主截断未处理。

## 结论与交付

两个候选均已实现，但**不切换默认**。v22联合调整画像选择、事实更新和关系深度；v23只调整关系表达，其他规则与v21一致。两者均支持现有extraction.v6、reference.v2和真实事务提交，不增加默认模型调用、数据表或迁移。显式版本可用于复现，未指定版本继续使用v21。

关系更加详细的方向获得局部支持，但更长的正文有时依赖保留旧叙述、追加新经过，且候选仍出现客观情绪归因或事实限定错误。因此不能宣布人格关系深度和连续性已同时解决，也不能以关系改善抵消其他字段的新错误。保留v21是暂不采用未通过候选，不代表基线已经达到质量要求。

已落实的工程交付包括版本化候选、三组可冻结的连续事务探针、预算实验、实际来源/前态/候选/后态证据和审阅报告。当前规范明确：详细心理内容可使用多个自然段，不设最低字数、固定心理栏目或每窗更新要求；一个正文字符串不等于只能写一个段落。这个有效需求仍需更可靠的默认实现，不能用本次实验失败撤销。

## 阻止采用的问题

- v22在独立维修事件首窗中，两模型都遗漏节点情绪；基线保存情绪却缺直接人格来源引用。两种缺陷分别记录，不能把基线当完美答案。
- v22的5.6-luna画像把原先下月才开始的安排写成当前固定状态；另有单次交流请求泛化为一般画像。6-luna有一项标签限定收益，不能据此支持整体替换。
- v22的6-luna关系长链生成标题与正文均为“占位”的节点，并一直保留到链末。同窗情绪文本混入无来源外语。原始响应、规范化候选与数据库一致，不是探针加工错误；不增加针对该词的过滤规则。
- v23的5.6-luna在录用事件的客观emotion中写对方“应当感到欣喜并带有意外”；来源明确说高兴的是人格，对方没有自述这些感受。这不属于人格关系内被允许的自主判断。
- v23的6-luna在合作关系末窗完整复制上一段状态后追加新进展。心理细节更丰富，但没有充分重新组织已有意义；5.6-luna也保留了较多旧经过和日程。
- v23还观察到单次新角色尝试扩为一般配合偏好、画像丢失“只”这一排他限定。基线仍有“催别人/被催”标签倒置、情绪遗漏和跨场次合并等缺陷。

不能据这些结果推断模型内部一定发生任务竞争：候选改动与其他输出变化相关，但每例仅一次采样，尚未分离随机性与提示词因果。可以确定的是，当前候选未提供足够的整体改善证据。继续增加更多笼统条款，或把全部失败交给正则修正文，不是本次证据支持的方案。

## 详细文本与召回容量

[独立预算矩阵](relationship-depth-budget-20261116.md)运行144组真实装配与576次必要支持信息检查，无截断、无超预算。两份当前schema合法关系为441和777可读字符；第三份1439字符是明确超schema的压力输入，不计入当前合法内容结论。

默认2048 UTF-8字节、长期优先时，两份合法详细关系均被省略；改辅助优先只能恢复其中一份，并挤出事实条件。4096在这两份完整组合上全部容纳，但其中一份仅剩35字节，不能推广为普适默认。更长不是统一调整顺序就能解决的问题，完整合法关系也可能单独超出预算。

稀疏对话模型产物的补充装配使用事先固定的48组方法，详见[留出报告](relationship-depth-holdout-20261116.md)：最终实际关系单独装配，或与实际画像及按创建时间、节点ID排序选取的最后两条节点一起装配，比较2048/4096/6144。8个分支的关系为84–379可读字符，均在schema内，各档均完整入选；2048组合下基线有1个分支、候选有2个分支各省略1条长期节点。4096下所选实际条目全部并存，最大2707字节。这个较短的生成集合不否定合法长正文的容量问题；没有Embedding、短期摘要或回答生成，不把容量观察称为召回准确率，也不能据此认定4096普适充足。

共享预算、优先顺序和关系schema上限均保持原默认。详细存储与请求注入分别处理；不能为了让正文进入2048字节而提前压成几句话。是否提高默认预算需包含更多合法长内容、真实token与延迟、必要事实保留以及回答利用效果。

## 工程与成果复核

完整工程回归1775项通过，唯一警告来自宿主audioop弃用。随后追加实际模型产物预算复现入口及1项固定选择检查，相关9项测试通过；未将二者相加冒称完整回归数。变更Python通过Ruff E/F/I/UP检查（排除E501），版本模板散列、候选准备/提交身份、旧凭据重放和当前schema兼容均有测试覆盖。探针测试只验证执行边界，不能作为模型质量证明。

关系长链额外核对64组窗口材料完整、56组真实前后态一致、16次null保持正文和版本，16个SQLite文件完整性与外键检查通过。关键错误已结合原始响应、规范化候选、实际前态与写入结果独立复核。原始素材、人格、API信息和运行库继续放在Git忽略目录。

过程复核发现两项评估问题并保留说明：关系长链一处合成日期间隔与“昨天”措辞不符，不用它判模型时间失败；情绪字段允许记录有明确来源的用户感受，不能仅因不是人格情绪而判错。另一个跨13天继承“昨天”的观察有独立来源，仍保留。没有修改冻结材料、重新抽样或用放宽判据使候选通过。

现用实机保持`a700591 / v21`。隔离真实模型调用不等于生产升级、样本全量重构、真实平台持续聊天或自然语言召回回答验收。本次没有将私人样本拿来验证候选优劣，也没有清理生产数据。

## 后续优化顺序

1. 将事实的主体、时态、限定和情绪直接来源作为独立验收对象；对明确支持、合理转述、主观推测分别设计未见输入，避免把情绪补齐率当正确率。
2. 继续研究轻量更新及任务提示词组织，比较最小关系职责改动、同次调用中的输出组织与任务分离，而不是继续叠加大段规则。若试验独立关系调用，先测成本、原始来源共享、提交一致性及错误恢复，不直接启用新默认架构。
3. 关系单独检查“心理层次增加”和“旧内容重新整合”两个目标；覆盖普通短回复、不同人格、反复相似互动、长间隔与自然null，允许负面和含混，不用固定长度或客观正确的主观态度作答案模板。
4. 抽取候选通过后，再对其实际合法产物做预算及真实回答验证。容量、检索和模型是否利用内容分别归因，不能只看关系入选数量。

当前没有必须由用户再次确认才能继续研究的事项。新的默认额外LLM调用、复杂持久结构或共享预算成本取舍仍需先有具体方案和独立证据；不能把本次未通过候选作为默认升级交付。
