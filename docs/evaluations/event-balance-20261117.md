# 独立新建与更新平衡评估

## 结论

当前v26并非在所有情况下都倾向新建。给定正确旧候选时，两个独立延续案例均正确更新；同时仍出现同日不同场次错误合并。添加一段通用身份决策规则可以修正本次场次合并，但也引入了一次无新信息的冗余更新，未证明整体收益，不替换生产默认。

独立固定向量检查还复现了当前候选排序的多话题覆盖风险：某话题高分节点可以占满名额，使另一话题最佳旧候选不可见。这是候选算法的能力边界，不是已查明的实机样本条目增多根因。

## 方法与参考

先核对当前提示词、候选准备及既有独立事件研究，再参考固定版本的Mem0与Graphiti，来源、版本、许可证及适用差异见[研究说明](../research/event-create-update-balance.md)。没有读取或改写私人会话作为案例，没有基于私人样本调参。

新增 `scripts/probe_event_balance.py`：两分支均基于精确v26系统提示词；候选只替换原有的一段新建/更新说明，加入判断信息增量、具体事件延续、独立场次、不确定性和不操作的顺序。其余persona、schema、来源及已知节点保持一致。候选不是新的生产提示词版本。

八案、判据及两个版本的完整请求在任何请求前冻结。全部为独立新编合成材料，每案每分支仅调用一次 `gpt-6-luna`，ecoapi的Chat Completions路径，单分支并发1。使用真实AstrBot Provider与NeoMemory适配器，SDK零重试、宿主一次尝试，无内容自动纠正；与实机原生Responses/结构化输出模式不同。

直接提供1—2个旧节点，隔离模型的身份判断，不测试真实向量语义、短引用回译、数据库提交或连续增量状态。schema通过与人工语义审阅分开；原始候选即使schema失败也保留，不手改成可提交结果。

## 模型结果

| 指标 | v26基线 | 身份决策候选 |
| --- | ---: | ---: |
| 实际HTTP | 8 | 8 |
| schema通过 | 7 | 7 |
| 模型报告token | 45,663 | 47,129 |
| 分支总耗时 | 93.068秒 | 65.133秒 |

合计16次HTTP、92,792个模型报告token。分支顺序执行且每案仅一次，耗时差异不能解释为候选必然更快。

| 独立案例 | 基线 | 候选 |
| --- | --- | --- |
| 隐式同一项目后续，含另一项目干扰 | 正确更新原项目并保留未完成条件 | 正确更新原项目并保留未完成条件 |
| 同一组装互动跨窗口完成一个步骤 | 原始候选正确更新；情绪使用非法`relief`，schema拒绝 | 同样正确更新但非法`relief`，schema拒绝 |
| 同日不同对象的两场面试 | **错误更新**上午节点为全天合集 | 正确新建下午节点，保留两人不同状态 |
| 跨日再次进行同类实验 | 正确新建，不覆盖前次结果 | 正确新建，不覆盖前次结果 |
| 跑步场景偏好变化，通勤场景明确未变 | 更新跑步原子，通勤节点不动 | 更新跑步原子，但**冗余改写**未变的通勤原子 |
| 同主题但具体项目不同 | 新建事件及有独立意义的偏好原子，不吞并旧项目 | 同样保留独立项目和偏好 |
| 已知安排的重复释义 | no_change | no_change |
| 多候选、来源不确定属于哪一次 | 保留不确定新信息，不武断更新旧节点 | 同样保留不确定性，选择atomic粒度 |

两分支都没有在这两种“正确旧候选已提供”的延续用例中错误新建，不能用本次结果证明提示词缺乏更新能力，也不能排除长链、复杂指代或候选缺失时过度新建。候选修复一个事件身份错误，但额外产生无新信息的内容更新；该更新可能推进内容版本、重置强度及使覆盖失效，不只是文字偏好。

两分支的身份判据结果不等于完整语义通过。部分正文省略主体，仅靠周围上下文理解，独立注入时有歧义；未在本次计算综合准确率。主题案例的事件与偏好分别有独立意义，不能单纯因为生成两个节点就判重复。两个分支在偏好变化和新增兴趣案例中均未输出画像，此为旁项观察，不是画像初建专用控制试验。

## 候选分配的独立程序检查

使用当前生产 `select_context_ids`，提供42个合成节点及两个正交查询，向量直接固定，无模型和网络：

- 31个话题A节点对查询A相似度1.0；话题B最佳节点对查询B为0.8。
- 最近10个节点与两个查询均无关。
- 默认上限30先保留最近10个，再用所有查询最大相似度的全局排名填剩余20个。

结果为10个近期节点加20个A节点，B的最佳候选被排除。运行 `python -m scripts.probe_event_balance --directory <结果目录> --candidate-allocation-only` 可复现，结果为 `retrieval-limit.json`。这证明当前算法没有逐查询覆盖保证，但不证明真实Embedding会给出相同排序，也未量化现用样本受到影响的比例。

若下一步研究候选分配，可以复用同一批查询和节点向量，比较逐查询有限候选并集、去重与全局补位；同时核对噪声、近期上下文和总长度。不能按这个人工构造直接认定新算法更优。

## 决策与后续

保持生产默认。优先将“原节点是否进入模型输入”与“模型如何选择操作”分开定位，不统一要求更积极合并，也不设新建/更新比例。

后续用独立多话题、多个相似旧节点、短指代和连续窗口补足检索与事务链验证。身份决策候选还须在更多模型和重复次数下同时保住事件分离、无信息不操作、旧事实和情绪。改善必须减少无意义碎片，同时不以误合并、冗余更新或事实损失换取条目更少。

当前研究不自动整理既有记忆，不改变来源、保护、覆盖或遗忘语义，不增加被动召回LLM调用。
