# 集成边界核查

核查日期：2026-11-13。核查依据为当前有效 ADR、接口契约及实际实现；测试结果仅证明对应执行路径，不替代业务决策。

## 核查范围

- 强度的普通强化额度、主动唤醒、同轮去重及热配置下的策略一致性。
- 节点情绪的内容版本、覆盖关系、完整条目预算及候选修复反馈。
- 主动记忆与笔记合流、最终返回内容强化、历史状态和筛选条件。
- 可丢弃向量缓存与已提交抽取窗口的恢复边界。
- 默认 `extraction-prompt.v15` / `extraction.v5` 与显式旧候选兼容性。

## 发现与处置

### 主动封套变大后，已被初选事件覆盖的原子无法回补

合成例子中，事件在 687 字节的普通记忆封套内恰好可返回，初选因此省略完整覆盖的原子。主动查询使用更长封套后，事件不能完整返回；原实现仅对初选结果再次限额，导致返回空内容，尽管原子仍可完整容纳。笔记占用共享预算时也存在同类缺口。

已修复：主动查询保留一次向量匹配产生的有界候选池；最终合流前，在同一事务内重新校验当前代、节点版本、可召回状态及覆盖关系。选择器以真实主动封套和已选笔记的字节、条数占用判定事件能否替代原子。未返回事件不能省略原子；最终仅实际返回的记忆参与强化。此过程不增加向量请求。

实现涉及 `core/active_recall.py`、`adapters/runtime.py`、`core/retrieval.py` 和 `storage/context_store.py`。最后一项新增的历史状态参数默认为关闭，被动召回仍只接受 active 节点。

证据：`test_active_recall.py` 覆盖上述预算复现、笔记占用、事件提升与最终条数；`test_active_tool_contract.py` 使用真实存储验证原子回补、仅一次向量请求、仅返回内容强化、事件禁用及覆盖撤销竞态，并验证历史记忆仍可主动查询。

### 情绪单独变化时，候选重生成反馈给出错误覆盖版本公式

存储将正文或情绪的实际变化计入 `content_version`，但覆盖版本失败反馈仍要求“正文不变时保持旧版本”，与情绪单改后的真实版本不一致。错误路径白名单也缺少节点 `emotion` 和 `intensity`，会丢失精确定位。

已修复：覆盖反馈按正文或情绪变化计算最终版本，字段定位补齐情绪字段。对应候选重生成及情绪覆盖测试通过，合计 18 项。

### 新提示词继承的覆盖版本公式与情绪版本不一致

核查时 `EXTRACTION_RULES_V14` 已要求保存情绪和完整语义覆盖，但仍继承旧 `COVERAGE_RULES` 的明确公式：“正文完全相同或不更新时仍是原 content_version”。这会在正文不变、情绪变化时产生相互矛盾的指令；旧“事件正文更新后覆盖失效”表述也未包含情绪变化。

已修复：默认升级为v15，仅替换覆盖版本公式及失效条件，明确正文或规范化情绪实际改变时版本加一，标签换序不算内容变化。v14及更早显式模板保持原样。`test_production_coverage_rule_counts_emotion_and_retains_historical_templates` 验证新规则及历史模板边界，情绪单改的覆盖事务测试验证实际版本；最终全量回归1672项通过。另有[v15两窗真实模型检查](semantic-context-v15-20261113.md)，但该样例没有覆盖声明，不把它算作模型覆盖判断的证明。

## 其余核查结论

- 普通强化与唤醒在存储事务中使用不同路径；唤醒保留已用普通强化额度，不消耗新的普通强化增量，历史节点不被恢复为当前事实。去重按节点、内容版本和轮次执行。
- 请求入口保存运行时引用快照，热配置发布新的召回服务；在途请求的排序与强化使用同一强度策略引用。
- 情绪变化推进内容版本，版本绑定的旧覆盖不能继续省略原子；情绪结构参与最终完整字节预算。正文不变时按相同模型指纹、空间及文本复用向量，后台索引仍需读回当前节点版本键确认持久化。
- 已提交抽取窗口通过提交凭据恢复，后续向量失败不应重新调用抽取模型或再次增加活动轮次；缓存不承担提交凭据或失败恢复数据的职责。
- 默认提示词与标题协议旧提示词使用独立常量，显式 v11/v12/v13 仍绑定 extraction.v4，v14及默认v15绑定 extraction.v5；不能用移动默认常量隐式改变旧候选的协议解释。
