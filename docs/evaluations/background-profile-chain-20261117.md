# 画像职责与节点更新的后台连续链评估

## 结论

v27与v28各8个连续抽取窗口均完成，合计16窗、80条来源、18次LLM HTTP和34次Embedding HTTP，耗时约441.10秒。没有人工重新生成、编辑候选或跳过窗口。v27的8窗均首次通过；v28两窗首次被拒绝，分别经生产管线自动纠正一次后提交。

v27在本链中完成画像初建、新增习惯、职业年限更正与未来生效安排保留；两个项目正确分开，两个重复窗口均返回no_change。结合既有双模型证据及用户接受少量瑕疵的标准，支持v27进入使用验证，不要求其所有概括完全无损。

v28的重复窗口也正确，但没有显示相对v27减少无增量更新的额外收益；最后一窗的显著情绪只进入关系，事件emotion为空。这里不以单项瑕疵否决所有进展，但没有理由把规则增加本身当成已验证收益，建议保持v28显式候选。

## 固定方法

脚本为`scripts/probe_background_profile_chain.py`。两个分支独立来源库、记忆库、缓存库，从空库开始，只承接本分支真实提交前态。材料新编，未读取私人会话或按私人样本改题；涉及职业、业余活动与两个独立社区项目。每窗5条来源，8个窗口覆盖初建、新增、纯重复、未来安排、项目完成、纠正、再次重复及有意义情绪变化。

使用AstrBot v4.29.3源码中的Responses Provider与真实`gpt-6-luna`，text输出；Embedding为配置的Cloudflare模型。经`SourceStore.capture → MaintenanceEngine.enqueue → JobStore.claim → JobRunner._execute → 候选检索/短引用/生成/校验/事务 → 必要向量索引`执行，保留租约心跳和持久任务凭据。`ExtractionService`只用于显式指定各臂版本，不绕过后台应用。

长链实际使用context.v1、当时默认召回预算2048字节及30个候选、首次生成外最多3次自动纠正、抽取窗口120秒、后台索引300秒。没有提高超时救场。SDK/宿主网络重试关闭，任务max_attempts设1，网络失败与模型纠正分开；内容纠正由生产管线决定。每窗明确enqueue只控制合成输入边界，未验证自动扫描触发、真实平台采集、完整插件装配、实机部署或中途进程崩溃恢复。

运行前冻结来源、规则、模板、源码哈希、配置、语义判据及64次LLM/80次Embedding上限。首次失败不替换为理想前态；如果纠正耗尽，该臂即停止。材料和规则运行后未修改或择优重跑。

## 语义审阅

- **画像初建与更新**：两版均记录职业、合唱及后续乐谱习惯，未把人格的硬币爱好归给用户。新爱好没有抹去无关职业或合唱资料；职业年限更正为六年/2020年起。11月原安排与12月1日后的新安排同时保留，商业演出、公版作品、图书馆与不外借等限定保留。
- **节点选择**：v27初窗另存职业、合唱原子；v28初窗仅画像保存这些稳定资料，后续合唱改变时才建立原子。选择性记忆不要求每条画像事实都另存原子，因此不把两版节点数差异直接计为质量优劣。
- **事件身份与状态**：两版均沿原ID更新已有项目，新项目另建，没有把一处许可或完成状态挪给另一处。湖畔完成及试听通过、北广场延期且未搬均正确。
- **无增量更新**：两个明确重复窗口，两版均返回no_change，未新建或改写节点、画像或关系。其他窗口检查到的节点变化均有对应进展、纠正、范围或真实互动补充；本链未复现既有实验的无意义旧习惯重写，不能声称v28修复了它。
- **情绪与关系**：v27后期仍偏事实复述，关系混入较多项目细节；v28关系较聚焦心理，但较短且主要追加旧状态，详细整合尚未解决。v28第五窗纠正后emotion标签为concern，描述却已是担忧消退/释然，标签不够贴切；第八窗事件emotion为空，显著烦躁、疲惫只留在关系。上述作为质量损失保留，不把人格自主判断的确定性视为错误。
