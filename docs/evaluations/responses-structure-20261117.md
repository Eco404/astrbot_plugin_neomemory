# Responses 结构化输出兼容性验证

日期：2026-11-17（Asia/Shanghai）。使用本地 AstrBot 的 `ProviderOpenAIResponses`、实际 `ecoapi/gpt-6-luna` 服务与独立合成输入。没有读取真实会话、修改实机插件配置或提交派生记忆。

## 方法与边界

`scripts/probe_responses_structure.py` 通过宿主 Responses Provider 请求模型。每种模式创建独立客户端并复制配置，在 `custom_extra_body.text.format` 指定格式；不修改共享 Provider，不修改宿主源码。结构化请求使用完整 `extraction.v6` schema；请求钩子记录实际 HTTP 请求的格式、strict 参数和消息角色。SDK 重试关闭，宿主请求尝试数为1，每种模式最多1个 HTTP 请求。

第一组使用一条独立的、有日期与前置条件的植物标本整理计划，分别请求普通文本、JSON 对象、严格 JSON Schema，共3次。扩展组加入16个独立旧事件和另外两条新来源，对普通文本与严格 schema 各调用一次；纠错组再加入含非法 `local_ref` 的合成草稿和通用反馈，同样各调用一次。合计7次，不重试失败候选，不按结果调整来源或参数。输入、请求、候选及报告存放在忽略目录 `data/evaluations/responses-structure{,-long,-repair}-20261117/`。

## 结果

| 输入 | 模式 | 请求数 | 状态 | Schema与引用解码 | 耗时 |
| --- | --- | --- | --- | --- | --- |
| 单条条件计划 | text | 1 | completed | 通过 | 8.44秒 |
| 单条条件计划 | json_object | 1 | completed | 通过 | 5.84秒 |
| 单条条件计划 | json_schema / strict | 1 | completed | 通过 | 7.85秒 |
| 16个旧节点与3条新来源 | text | 1 | completed | 通过 | 11.80秒 |
| 16个旧节点与3条新来源 | json_schema / strict | 1 | completed | 通过 | 11.70秒 |
| 上述扩展输入与非法引用草稿 | text | 1 | completed | 通过 | 11.83秒 |
| 上述扩展输入与非法引用草稿 | json_schema / strict | 1 | completed | 通过 | 11.83秒 |

逐项审阅显示：单条输入的三份候选均保留用户主体、下周、周三前借到设备才开始、否则延期、尚未开始及担忧。JSON对象模式把担忧仅写在情绪描述中。扩展输入的普通文本结果保留了计划与志愿登记，未选择自行车经历；其余三份扩展候选保留三项独立经历，没有修改旧地图节点、把计划写成完成或把登记写成已经值班。两份纠错候选均使用合法的 `local_1` 等引用。没有生成关系边，本次不能据此声称已覆盖边更新或复杂关联质量。

7/7通过仅说明这些具体请求得到合法结果。一次小样本不能证明网关实际启用了受约束解码，也不能估计自然错误率、纠错成功率或比较模式优劣。没有执行抽取应用事务，本项只核对候选结构、引用和有限语义。普通文本也全部通过，不能据此宣称严格模式降低了实际故障率。

## 当前适配与后续验证

结构化模式仅对原生 OpenAI Responses Provider 提供明确支持，普通文本保持默认。不支持的 Provider 返回明确错误，不悄悄退回文本。每次调用的独立客户端在完成、异常和取消时关闭，宿主仍负责网络重试；响应诊断仅记录状态、结束原因、token数量及耗时等元信息。

MockTransport 经真实宿主和SDK验证了两种结构化格式的HTTP载荷、并发调用隔离和超时关闭客户端。实际网关的严格约束执行、长链更新、多模型、跨节点关系和自然错误率仍需独立验证。`json_object`不保证字段schema；`json_schema`不替代来源、主体、条件与事件同一性的判断。

参考了本地 Graphiti `5c27edf` 的结构化输出与应用级错误反馈分层，以及 Mem0 `26cdefb` 的 SDK 结构化解析入口；未复制其代码。两项目均为 Apache-2.0。该设计仍通过 AstrBot 的 Provider 执行，不能直接把第三方SDK调用示例视为宿主参数透传已生效的证据。
