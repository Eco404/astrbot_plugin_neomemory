## 检查结果

完整pytest回归通过1952项，仅有宿主既有`audioop`弃用警告。真实Chromium主题页面检查通过，覆盖主题与事件区分、条目内成员及来源、所属主题、分页、切空间迟到响应、移动布局、后台任务提交与独立主题暂停提示。

| 合同 | 已验证行为 |
| --- | --- |
| 成员和版本 | 完整成员集合原子提交；版本依据与来源可追溯；多重归属、成员移除、无变化及重复提交均有覆盖 |
| 现有事件 | 主题任务不改成员正文、不重复消费来源、不推进活动轮次；普通抽取补齐已有主题及成员，包含关系进入请求摘要和提交检查 |
| 来源主体 | 有限原话来自具体内容版本及继承基线；有界截断、来源缺失不冒充完整依据 |
| 候选归属 | 所有显式候选补齐父主题和完整成员；共享成员其他父主题以只读目录呈现，不递归整图；目录变更使旧快照失效 |
| 请求预算 | 最终序列化字节包含非ASCII、身份与版本元数据；证据先裁、可选候选再减、必要时缩批；完整成员不截断；完整纠正请求另行检查 |
| 并发和治理 | 同空间任务互斥及租约有效；人工保护、已知错误摘要和版本冲突不能被自动整理绕过 |
| 失败与重构 | 模型失败、无效候选、提交后索引失败和切代前失败可断点处理；嵌套主题重新生成保留已完成事件；已提交回执不能被当作待生成候选 |
| 自动预算 | 首批成功、后批耗尽3次纠正后，同代失败主题任务阻止自动另建任务刷新额度；普通抽取继续；显式删除失败任务后可重新调度 |
| 清理 | 删除未发布重构时，目标节点、主题依赖、审阅记录、回执和拒绝候选随所属任务/代清理；已发布记忆保留 |
| 召回 | 主题带出预算内相关直接成员；不从contains推断全文覆盖，不新增被动生成调用，严格类型过滤保持 |

自动预算问题通过独立16节点案例复现并修复：首8项审阅成功，后8项输出持续非法；不能因剩余dirty集合改变而获得新任务和新纠正额度。对应回归还验证维护状态与普通抽取继续工作。

## 升级及适用边界

已有未提交的普通抽取检查点若形成于主题关系输入接入前，且当前候选包含主题或成员，准备后的输入摘要会改变，安全暂停为`context_changed`，需要重新准备。独立探针确认没有额外模型调用或误提交；无主题输入和已提交回执不受该输入扩展影响。不保留绕过关系快照的旧提交路径。

上述测试验证工程合同，不证明模型归类和正文始终正确。真实模型结果见[主题归纳](topic-consolidation-20261117.md)、[来源到回答全链](topic-full-chain-20261117.md)和[来源角色证据](topic-subject-evidence-20261117.md)。大型主题的完整成员输入仍受提示词预算限制；被动召回仍使用最多2000节点快照，群聊、多用户及长期负载不在本次完整验收范围内。
