# 缓存故障与后台清理验证

缓存读取I/O故障或损坏按未命中处理。查询可以在原截止内补向量，节点索引缺失继续后台处理。模型结果已校验后，缓存I/O失败或慢写不会让本次结果丢失；维度冲突和调用取消仍按原规则处理。

清理每个事务最多删除500项，启动先执行一批，随后每30秒后台清理；积压批次之间让出执行权。容量是清理门限，瞬时行数可能超过门限。TTL在读取时立即生效，不等后台删除。关闭缓存会取消清理任务，清理错误只保存错误类型。

## 工程验证

`test_cache_store`、`test_cache_recovery`、`test_embeddings`、`test_retrieval`共75项通过，覆盖读取不可用、损坏向量、写入失败、慢写超时、查询恢复、节点缺失不在线建库、维度冲突、任务取消、清理事务回滚和后台关闭。

与当前事件索引联调时仍须核验缓存实际写入；成功计算并不等于已经持久缓存，不能仅凭embed返回就报告索引完成。

## 独立I/O微测量

同一环境比较标题提交`ede8c8a`的缓存实现和新实现，各运行3次。每次写1536项256维合成向量，12批，容量512；没有模型网络调用。

| 指标 | 旧实现 | 新实现 |
| --- | --- | --- |
| 写入总耗时范围 | 0.0995～0.1170秒 | 0.0925～0.0988秒 |
| 单批中位范围 | 0.0077～0.0090秒 | 0.0078～0.0084秒 |
| 写完尚未后台清理的行数 | 512 | 1536 |
| 集中显式清理耗时 | 0.0004～0.0009秒 | 0.0143～0.0219秒 |
| 清理后行数 | 512 | 512 |

这些数据说明清理成本从频繁写路径移到了后台，并没有消失。包含后台清理的总成本没有稳定显著下降；不能宣称整体性能大幅提高。微测量不包含真实网络、生产规模、长时间并行写或低配机器。原始统计保留于本地`data/evaluations/cache-maintenance-20261113/report.json`。
