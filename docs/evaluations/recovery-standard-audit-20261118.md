# 首次生成与候选纠正标准审计

## 范围与依据

审计覆盖抽取、主题整理、滚动短期摘要三条管线的结构与硬业务约束：字段类型和容量、引用与作用域、内容版本、创建/更新、成员集合、来源、保护及运行快照。判断依据是实际校验器、首次请求、拒绝候选反馈及提交事务；提示词出现某项要求或测试通过，不能代替行为契约。

本报告不把自然语言事实正确、情绪深度、事件同一性或主题价值变成新的硬拒绝规则，不增加语义评分或模型核验。本文所说“来源有效”仅表示合法范围及结构归属，不能证明一句原文实际支持候选中的每句话。

首次提示使用抽取 `extraction-prompt.v31`（输出仍为 `extraction.v7`）、主题 `topic-prompt.v5`（输出仍为 `topic-consolidation.v1`）、短期 `short-term.v3`。抽取 v31 只补输出计量说明；主题 v5 补整体容量和固定允许身份全集；短期 v3 补整体字节容量及摘要字符计量说明。三者不改变既有文风、成员粒度或事实判断标准。显式旧抽取 v30、主题 v4、短期 v2 的完整请求有字节摘要回归覆盖，不把历史准备输入重标为新版。

动态反馈使用 `candidate-regeneration.v8`、`topic-regeneration.v2`、`short-term-regeneration.v2`。公共字段约束读取固定目标schema，跨字段规则读取已接受的限额，身份与版本读取本次原始输入；拒绝候选只提供待修正值，不决定目标版本或合法身份集合。此处是代码及本地验证范围，不代表实机已经部署该组合或已用完整私人数据验收。

## 主题身份输入缺口与生效范围

主题提交允许身份原本从三个已有来源取得：known节点正文、当前空间logical_user_id、node_participants。旧首次提示只显式展示节点引用，没有给出后两项组成的完整允许集合。因此即使首次提示已说明“不要编造身份”，模型也不能直接知道完整结构允许范围；不能将这一缺口误记为自然语言主体判断错误。

主题 v5 的准备快照增加 `allowed_user_ids`，纳入input_digest，首次请求与纠正均复用该集合；提交校验仍按同一已有来源计算，集合变化要求重新准备。没有新身份表，也不按昵称推断账户绑定。旧prepared没有该字段时仍沿既有派生行为；旧topic v4请求不注入该字段，不改其历史系统文字。缺口对新v5输入已补，不能据此宣称过去v4输出的语义已重新验证。

## 证据与限制

`test_prompt_standard_alignment.py` 的7项针对性检查通过：默认提示容量单位、显式旧请求逐字一致、主题允许集合完整且冻结、身份字段计入实际预算、允许集合变化拒绝提交。测试采用独立合成数据和真实本地存储，不使用私人会话，不调用外部模型。

连同 `test_topic_schema.py`、`test_topic_store.py`、`test_topic_budget.py`、`test_short_term_identity.py` 的相关检查，共47项通过。预算测试的手工请求使用与生产相同的固定身份集合，比较实际序列化字节与记录值，不以扩大额度消除差异。

恢复标准的定向测试组合591项通过，其中 `test_candidate_standard_metrics.py` 的115项覆盖各对象必需字段、额外字段、数值实际值、条件最小项、重复/neutral、固定身份与版本、覆盖最终版本及命名规则分类。既有共享字段矩阵继续覆盖schema字段限制；主题真实任务恢复检查同一输入、归档拒绝草稿与只提交一次。测试组合有重叠，不能将各组数字累加为独立案例总数。

`test_feedback_identity_metrics.py` 的5项独立检查通过：节点和人格关系使用不同情绪字段时，neutral与重复项均有正确计量；旧v7反馈不追加新版指标；主题纠错建议的可用成员集合不包含不可新增的受保护节点，真实提交也拒绝该关联。该测试不改变人工保护必须停止的规则。

`test_saved_recovery_protocol.py` 的2项真实任务重启检查通过：取消后从数据库恢复v1 descriptor及其保存的errors，实际请求沿用原协议和原反馈，并各自只提交一次。这隔离验证反馈descriptor兼容，首次输入保持不变；不证明旧prompt跨升级能自动绕过签名。旧准备任务若执行签名或请求digest改变，仍停止并要求重新准备。旧v7反馈另有冻结字节fixture验证，旧v6显式协议继续保留。

`extraction.v3` 的event_identity、profile_evidence、interaction_confirmation属于显式历史/实验协议，不能写成当前 `extraction.v7` 已实施的硬字段约束。当前来源结构检查同样不等于已证明主体、接受/完成或本人自述的自然语言含义。

独立审阅另外覆盖组合错误字段：节点类型为列表/对象且正文为数字时，反馈仍返回各自字段错误，不因动态限额查表崩溃。覆盖版本按真实提交层规则计算：正文精确比较，情绪按既有规范化比较；正文仅增加首尾空白也会改变当前存储版本。测试同时调用实际存储层版本判断核对反馈，避免另写一套看似合理的计量规则。

最终最低支持宿主AstrBot v4.29.3完整回归为2560项通过，只有宿主audioop弃用警告。新增标准矩阵最终为117项，必需字段与可空性直接从首次schema独立解析，避免由生产反馈helper同时生成测试预期而掩盖遗漏。首轮完整回归有一项旧测试仍精确期待不含`const:null`的未知时间反馈；按当前新协议补齐预期后重新执行完整回归通过，未为通过测试删去新指标。原有提示词字节与旧反馈兼容检查仍通过。

完整日志位于忽略目录`data/evaluations/recovery-standard-audit-20261118/full-minimum-host.log`。本次工程检查不包含真实模型质量通过的结论；完整实机构建使用哪组协议，须以其冻结包和终态报告为准。
