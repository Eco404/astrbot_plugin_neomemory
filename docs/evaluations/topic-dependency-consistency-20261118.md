# 普通抽取与专用主题任务的成员依赖一致性

## 结论与边界

普通抽取和专用主题整理已共用成员版本依赖、累计来源及参与者的提交逻辑。普通抽取不再仅写contains边而漏写相应成员依据；明确更新主题正文时记录实际成员版本，单独关联成员不冒充正文重新生成。本项是生产存储路径的独立合成验证，不包含模型语义质量或实机完整重构通过的结论。

## 设计依据

有效要求来自ADR-0041：普通抽取保留主题能力，专用任务维护完整成员集合，成员关系与版本依据一致提交；仅成员变化不制造正文版本和强度重置。

参考Graphiti固定源码`5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`的`graphiti_core/utils/maintenance/community_operations.py`（Apache-2.0）。其`build_community`从成员概括生成社区，再独立建立成员边，支持区分概括内容与成员关系的职责。它没有NeoMemory所需的成员具体内容版本、历史派生凭据和断点重放合同，不能直接作为版本来源修复方案。本项仅借鉴职责划分，没有复制第三方代码；固定快照不代表最新上游维护状态。

## 实现语义

- `storage/topic_dependencies.py`只接收调用方已确定的成员版本，不自行从数据库当前版本推断旧主题依据。普通路径局部更新，专用路径依据完整成员集合替换。
- 普通抽取显式contains关联本批新建/更新成员时记录其提交后版本；显式旧节点依据使用准备快照。未涉及的旧成员依赖保持原版本，即使其正文已独立更新。
- 普通主题正文create/update的派生凭据包含明确成员版本；仅关联、同文关联及标题操作另记membership，成员版本放在关联操作中，不作为正文base_versions。来源浏览区分这类操作，主题证据收集也不会把关联原文当成正文事实证据。
- `node_sources`继续保留主题累计来源的浏览语义，具体正文的直接与继承依据仍由版本派生记录表达，不混为逐版本证据。
- 专用任务的显式同文确认可以建立本次成员依据而不增加正文版本；空changes则保持原样。已有缺失不被静默回填，需显式重新确认或新代重构。
- 显式确认记录可以与已有跨类型派生记录形成版本关系回路。它表达不同时间的评估关系，不能当作事实自证；现有有界追溯使用visited终止循环，关联操作不参与正文证据收集。本项没有增加新的全图拒绝规则。

## 验证

执行主题测试集合、来源追溯、版本查阅API、标题抽取及显式旧节点依据测试，共145项通过。`node --check views/neomemory/memory.js`通过；没有据此声明浏览器交互已经验收。

新增独立用例覆盖普通主题创建、部分更新保留旧成员版本、edge-only关联与缺失正文凭据、同批成员更新、旧缺口的空changes/显式确认区别、事务回滚、显式旧节点依据引用受保护成员，以及同批更新后仍使用准备快照的情况。额外验证跨类型确认回路能够终止且不把成员关联原文混入正文证据。

复用原有独立合成探针调用实际ExtractionService和TopicStore，结果如下：

| 操作 | 成员数 | 依赖数 |
| --- | ---: | ---: |
| 普通抽取创建 | 2 | 2 |
| 专用任务无变化 | 2 | 2 |
| 专用任务显式同文确认 | 2 | 2 |
| 普通抽取更新并追加成员 | 3 | 3 |
| 再次专用任务无变化 | 3 | 3 |

对应合成输出保存于忽略目录`data/evaluations/topic-dependency-consistency-20261118/ordinary-topic.json`。探针仅使用独立合成内容，没有读取私人会话或据其内容调整实现。

## 尚未证明的事项

依赖与事务一致不证明主题正文忠实、不证明成员语义关联正确，也不能保证普通抽取完整引用了所有真实使用的旧事实。历史缺失保持原貌；显式旧节点依据协议的模型输出质量、实机升级与完整重构、最终召回均需各自证据，不能合并本报告测试数作为全面通过。
