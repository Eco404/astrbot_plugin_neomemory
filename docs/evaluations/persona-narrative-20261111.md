# 人格叙述、称呼引用与短期范围评估

日期：2026-11-11，时间按 Asia/Shanghai。评估使用独立合成材料，没有读取或改写受限真实会话来调优提示词、规则或测试夹具；实机部署和旧重构结果没有改动。

## 目标与方法

验收长期记忆的人格第一人称、逻辑用户占位符在输出/存储/展示间的稳定映射、画像主体、人格关系的主观内心表达。工程测试同时检查跨窗口身份、多人引用、当前账号昵称优先、展开后的预算、约定称呼原文、原始记录及治理版本不变。

`scripts/verify_narrative_api.py` 在请求前固定两份合成窗口、人格与人工判读问题：私聊包含对方偏好、明确称呼约定、对方亲身经历与双方交流；群聊包含两个成员各自的偏好与经历。通过本地 AstrBot 4.29.3 的真实 ProviderAdapter、ExtractionService、引用协议及孤立数据库完成生成、精确解码和提交。判读问题只存本地，不附加给模型。

每版每例只允许一次 HTTP 请求，总计每版两次；SDK 重试关闭，宿主最多一次尝试，单例时限 180 秒。不使用 Embedding。所有候选和失败保留，不选择性重试。

## 观察与调整依据

第一版叙述提示词 `extraction-prompt.v6` 在私聊中产生两条主体错误：对方的偏好、对方完成的一次分享被写成人格自己的偏好和亲历。虽然规则已禁止这种转移，仅给负向禁止仍未使该例正确。画像、人格关系及称呼约定节点正常；群聊两条事件的主体正确。

## 真实模型结果

模型为 `gpt-6-luna`，引用协议为 `reference.v2`，两版总计 **4 HTTP**。四次候选均通过 schema、精确引用解析及真实提交；这不等于四次语义正确。

| 提示词 | 私聊 | 群聊 |
| --- | --- | --- |
| v6 | 60.015 秒；3 节点、1 画像、1 关系。2 个节点主体错归属；明确称呼保留并正确渲染；画像与关系未见此类错误 | 36.582 秒；2 事件、2 画像，成员主体正确，关系为 null |
| v7 | 13.980 秒；2 节点、1 画像、1 关系。返回内容的主体和视角正确；明确称呼约定未被保存 | 6.950 秒；2 原子，成员主体正确；0 画像，关系为 null |

v7 的四个实际返回节点均从人格视角回忆，同时将对方偏好与行为归给对应成员；画像及关系中的身份引用也能正确渲染。私聊关系表达自身的高兴、期待与担心，没有要求对方确认这些感受。

**仍有未解决的内容选择问题：** v7 没有保留私聊中的明确称呼约定，群聊也没有生成画像。因此不能声称它已稳定记住约定称呼或已验证群画像表达。程序能保持已经写入正文的约定称呼，不等于模型总会将称呼抽取出来。单次两窗口对照不能估计质量提升比例，耗时差异也不能当作性能结论。

未执行基于用户真实会话的新重构，未验证旧记忆逐步更新的风格一致性；没有证明昵称本身的自然问题召回率。默认短期提示词仍独立，不能据这些长期结果判断短期质量。
