# 群回答身份消歧独立审阅

本补充核对[六问实际回答验证](group-short-answers-20261118.md)的冻结请求、原始稳定身份正文、回答及独立合成来源。没有额外模型调用，没有修改产品、提示词、数据库或原始结果。逐问结论和请求/答案摘要位于忽略目录 `data/evaluations/group-short-answers-20261118/semantic-review-independent.json`。

## 主要定位

山坡/澄的原始事件将“没有接手观察灯”明确归给维护树木编号的逻辑用户。另一逻辑用户负责昆虫观察并提出迁灯，二者占位符不同。最终呈现却把两个占位符均替换成“小同”，最后一句成为“观察灯由另一位负责，小同没有接手”。回答将未接手者错误解释为昆虫观察负责人。原始节点没有这项主体反转；身份区分在渲染时丢失，随后回答发生错误解析。这证明信息损失及错误传播路径，但尚未通过控制实验证明仅修复渲染就必然消除模型错误。

港湾/凛在相同名字折叠下仍正确按岗位区分两人；不能把所有同名输出都判错，也不能据此证明当前身份呈现充分。山坡/凛的画像称两项条件均未到位，事件称防雨罩已到；本次回答采用事件而答对，冲突仍存在。港湾/澄则忠实复述旧原子中的“许可未到”，与最新合成来源冲突；既有抽取审阅已经确认旧节点在 known_nodes 中却未获得更新。此错误不能靠消歧或扩大预算修复。

两个短期回答正确沿用取消渡船、改去展馆的安排，第二问也接受当前用户新告知的订票完成状态；开放时间和寄存柜仍列为待确认。额外入馆和交通建议没有冒充已知事实。摘要把共同讨论压成共同出行的措辞风险仍在，这两次回答没有明确放大它，不等于摘要问题已经修复。

## 可复用的现有实现

本地 AstrBot 源码 revision `bb2e467739c0a0466802da49c62280fc8becf256` 的 `astrbot/core/astr_agent_runtime/tools/message_tools.py` 第459–470、529–531行，在群历史工具中按不同 sender_id 检测同名，再呈现为“昵称 [sender_id前8位]”。`MessageMember.__str__` 同时保留 User ID 与 Nickname。这是具体工具/成员表达的参考，不能推断所有宿主聊天上下文都已消歧。

NeoMemory 当前 `core/memory_text.py:23` 直接将逻辑用户引用映射为昵称；`SourceStore.get_user_display_names` 返回现有逻辑身份与昵称，不做身份合并。最小改进可留在呈现层：同一相关作用域存在不同逻辑用户同名时，为占位符展开结果附加既有身份标识。存储占位符、账户绑定、来源、显式专属称呼和引用原话均保持原语义；不需要新身份表或额外模型/向量请求。

这符合 ADR-0001“不按昵称推断同一人”及 ADR-0028“单独注入正文须能明确主体”的要求。昵称加现有ID是消歧，不是变更身份。完整逻辑ID最直接；若使用短ID，必须确保同组可区分，不能直接照搬固定前8位而忽略内部ID公共前缀。所有消费路径须使用一致标识，包含长期节点、画像/关系、短期摘要、主动工具及WebUI；当前发言人与相关身份也应能对应。相关作用域中的同名检测不能仅看一个条目的引用，否则两个分别只含一人的条目仍可能各自渲染成相同昵称。

## 成本与验证范围

仅对这四问已注入长期正文，将每个同名占位符展开为“昵称 [完整logical_user_id]”，离线计算分别增加190、152、76、152 UTF-8字节，原上下文分别为1375、1246、1101、860字节。这是正文增量估计，不是已执行的产品装配，也不包含可能新增的当前发言人说明。实际实现仍须在最终渲染后执行既有预算与整项省略，不增加隐含额度。

通用验证应覆盖跨条目同名、同名但不同账户、同一逻辑用户多个账户、缺失昵称、唯一昵称不变、显式称呼不被误替换、短标识碰撞及预算边界。可再用独立合成材料比较原呈现和消歧呈现的回答主体正确性。不能对本组六问加入活动或岗位专用规则，也不能用消歧成功代替变化覆盖、画像时效及事实更新验证。
