# 群聊记忆中的未发言成员

## 对照方法

独立合成一个三人群，两位发言成员与一位此前已建立账号归属的成员同名。先单独采集该成员的报到消息，随后分别抽取三个窗口。前两个窗口涉及同一个口述史项目，第三个涉及独立的教室搬迁。三条检查分别关注谁保管原件、谁收到核对授权书的请求、陌生账号会不会被认作群内已知成员或人格。第二个窗口还包含人格本人对前言及发布时间的承诺。

使用 gpt-6-luna 和 gpt-5.6-luna，各自从空的本地 SQLite 库独立采集和抽取。对照采用长期 v39、主题 v8、短期 v5，新版采用长期 v40、主题 v9、短期 v6。每个长期窗口一次生成，解码、校验并写入实际存储。主题请求使用各自已入库的事件、原子和有限来源，校验其输出。短期摘要以六条新增发言作一次完整输入。此次比较覆盖模型输出与数据契约，实机整库重构、自动任务调度、向量召回和最终对话质量不在这组实验内。

## 观察

| 检查 | 对照 | 新版 |
| --- | --- | --- |
| 已建立身份但当窗未发言的保管人、核对请求对象 | 4 个窗口结果均省略具体身份或称对象未知 | 4 个均正确使用该成员的稳定引用 |
| 身份未知的领钥匙对象 | 两款模型均保留不确定性 | 两款模型均保留不确定性，领取保持待办 |
| 项目主题 | 两款模型均整理出项目，并保留人格对前言的参与 | 两款模型均保留保管人和核对对象，教室搬迁没有混进主题 |
| 短期摘要 | 两款模型都把成员交接原件写成了交给人格自己 | 两款模型最终均正确引用保管人，陌生领钥匙者也保持未知 |

两个版本的六个长期抽取窗口各自全部入库，没有为未发言者生成画像。新版有一次同时生成概括事件及内容接近的原子。摘要中“请对方核对”仍可能写成“对方负责核对”或“对方尚未核完”，扩大了对方已接受任务的证据。中间的短期表达实验还出现过把“核对后再发布”扩大成“核对后才撰写”。更换表述多次生成的结果存在波动，表中计数反映本次小组对照。

## 证据来源

适配器提供的账号和消息组件是身份解析的入口。QQ 官方群消息使用群成员标识，显式提及与发送者是不同字段。核对了本地 AstrBot v4.29.3 参考源码的 qqofficial_platform_adapter.py，复用了 NeoMemory 已有的账号归属时间记录与窗口代号。模型调用只使用合成材料。旧群消息缺少身份快照时，重构能恢复到什么程度，取决于其保留的原文及同窗身份依据。
