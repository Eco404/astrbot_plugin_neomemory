# 稀疏对话下的人格关系深度对照

日期：2026-11-16（Asia/Shanghai）。范围：独立合成输入、真实连续提交协议，比较`extraction-prompt.v21`与仅调整关系表达的`extraction-prompt.v23`；schema均为`extraction.v6`。不使用私人会话或其改写，不修改实机生产配置或数据。

## 方法与验收

详细心理自述能够检验承接和整理，但不能单独证明模型在普通短回复中也能形成有层次的心理表达。因此本对照使用诗歌交流与合作游戏两条独立四窗口链，agent主要通过短回应、玩笑或意愿表达参与，不直接列出所期待的全部心理层次。两种人格分别寡言而有审美、跳脱而好胜，初态仅给一句已有关系基调，不计为模型成绩。

每链含一个普通事务窗口；其他窗口保留人格自主理解空间，不指定必须出现的情绪或成长结论。首窗同时包含已发生事实、明确人格事件情绪、稳定用户习惯和带多个条件的未来安排，以检查关系表达调整是否影响长期节点、画像、标题和情绪。各窗完整审阅所有输出，不能只评价关系后宣布整体通过。

两个模型`ecoapi/gpt-6-luna`与`ecoapi/gpt-5.6-luna`、两版本、两链、四窗口，共最多32次HTTP请求，总并发2。复用实际`ExtractionService`、引用解析、schema和来源校验及隔离SQLite提交；后续窗使用各臂自己的实际已提交前态。每窗口一次请求，失败停止该链，无内容重抽或理想前态替换。SDK重试关闭；与其他模型实验串行运行以保持总并发限制。

审阅标准是心理内容是否具体、人格化、有连续性，同时尊重来源主体、事实条件、时态和客观画像边界。关系允许偏见、坚定看法、误解和负面感受；不能把其评价直接当成客观用户事实。普通事务应不改关系；有关系意义的互动可更新，但不要求每窗都更新或达到固定字数。更长不能自动算更好，更短也不自动判失败。

脚本为`scripts/probe_relationship_depth_holdout.py`。输入先通过`--freeze-scenarios`固定，SHA256为`947d24705885a200ef02811704463f1f6d6f605cd95833faad6c65968e5708f9`，保存在`data/evaluations/relationship-depth-holdout-20261116/scenarios.json`；实际调用前`--prepare-only`固定提示词全文和源码摘要。逐窗保留请求、真实前态、原候选、规范化候选、提交后关系和节点，末尾另存实际最终画像与节点；中间画像变化可由候选、下一窗输入及数据库核对。3项工程测试核实实际画像跨窗承接、失败停止和32请求边界，不把假模型测试作为语义效果证据。

## 实际结果

两模型、两版本共32次真实HTTP请求、32个窗口事务提交，耗时293.829秒，无重试或人工补状态。8个普通事务窗口均返回关系null并保留之前关系正文与版本。全部窗口的长期节点、画像、标题、情绪及关系均逐条审阅。

v23在诗歌链中更常保留“直接批评”“尊重条件”和继续交流的心理含义，单次正文通常比v21详细；但合作链的后段仍把上一长段关系正文整体复制后追加新内容，未稳定实现心理重组。详细内容增加不构成质量通过。

客观输出仍有阻止采用的问题：5.6-luna/v23诗歌首窗把明确属于人格的高兴写成用户“应当感到欣喜并带有意外”；6-luna/v23合作第三窗把本次尝试新角色扩大成一般配合偏好，并在后窗情绪因果中混入不严谨归因。基线也有5.6-luna/v21把“不喜欢催别人”写成“不喜欢被催”，两版本均出现部分事件情绪遗漏和跨场次合并。主观关系中的坚定判断、用户明确表达的不服气或不着急，不因不是客观事实而判错。

## 证据边界

该设计是两条四窗口链、两模型、非盲定性对照，不支持统计显著性、长链平滑淡出、从空白建立关系或真实平台聊天结论。采用关系分支需要分别确认关系收益与其他输出没有新增严重错误；若事实或情绪仍有缺陷，应明确保留，不能用关系改善抵消。

该结果仍是两条四窗口链、两模型、非盲定性对照，不支持统计显著性、长链平滑淡出、从空白建立关系或真实平台聊天结论。它支持继续研究“详细表达与旧状态重组同时成立”的方向，但不支持v23替代v21默认。
