# 画像覆盖变化：代码核对与独立对照

## 结论

从v21到v26，确实改变了画像所处的联合提示词，不能说“只改长期正文，画像完全没动”。但现有证据不能把实机画像从8个版本减少到1个版本，全部归因为这个改动；输入样本、输出模式、连续前态和生成随机性同时变化。

本次新增独立小对照没有复现“v26或结构化输出必然漏建画像”：四个首窗候选都提取了三类明确稳定自述，三个执行到后窗的分支都新增另一项稳定爱好并保留职业、阅读信息。仍有两版共同存在的限定和当前安排遗漏，另有一窗因为人格关系来源不合规导致完整事务拒绝。需要分开评价画像生成、整窗提交与连续更新，不能只数最终画像版本。

## 代码核对

核对范围为实机v21代码`a700591`至v26代码`7d2197a`：

- `core/prompts.py` 将默认从 `RELATIONSHIP_AFFECT_PROMPT_VERSION` 改为 `NATURAL_PERSONA_PROMPT_VERSION`；v26从 `core/persona_memory_prompt.py` 引入整份模板，并非只给v21追加风格段落。
- v21的规则正文9990字符，v26为5607字符；这里只是Python字符数，不是token量或注意力份额。画像和关系合并段中、关系规则之前的文字约795字符变为373字符。
- v21分别强调逐项比较、描述与标签复核、保留无关旧事实，并提供迁居更新示意；v26将其压成一个轻量画像段，删去了该示意和部分独立复核措辞。新模板最前面突出人格自己的互动与表达，画像职责位于后续。**任务显著性是否因此下降，是合理假设，尚非已证实因果。**
- `core/persona_memory_prompt.py` 的画像规则仍要求当前事实、本人自述、保留有效限定、标签与描述一致，不存在“只保存一项偏好”的新业务规则。“缺少新稳定信息不改写”与v21“未出现新稳定信息不更新”语义接近，不能把这一门限误称为v26才引入。
- 画像存储、准备和事务应用路径没有这段版本范围内的行为改动。`core/extraction_apply.py::prepare` 仍读取当前代画像，并按本批用户发言者选择；`PreparedExtraction.messages` 仍传入 `known_profiles`。没有新画像条数门限或自动清除逻辑。
- schema仍为 `extraction.v6`，`ProfileChange` 未改；该范围的schema变更只有重复JSON字段异常类型。Provider层新增结构化输出路由，会影响模型生成约束，但不在程序内删除 `profile_changes`。

v26采用前的[人格表达对照](persona-style-final-20261117.md)主要验证日常互动正文、事实和事件身份，没有覆盖完整的画像选择与更新矩阵。这是验收覆盖不足，不能用风格样例通过推断画像不会回归。

## 现有实机证据的混杂因素

[v21实机报告](live-rebuild-v21-20261116.md)为2237条来源、249个窗口、文本输出，产生8个画像版本；[v26实机报告](live-rebuild-v26-20261117.md)为2353条来源、265个窗口，成功完整运行使用 `json_schema`，产生1个画像版本。不能直接进行逐窗因果对照。

旧画像较丰富，但有已确认的人格偏好误归用户、当前状态过期；新画像较窄却有覆盖遗漏。因此“旧版更多”不等于“旧版完全正确”，“新版更少”也不自动证明更准确。轻量画像不需要全量记录，但明确有持续用途的自述漏选仍应改善。

## 独立模型对照

没有读取私人会话来构造题目，也没有依据返回结果改变材料、提示词或参数。调用前冻结新合成场景、两窗、同一合成人格、提示词模板和评价范围。清晰稳定信息包括职业背景、阅读偏好、带频率与范围限定的运动习惯；后窗新增持续收藏爱好，并修改未来才生效的运动安排。人格有独立兴趣，普通晚饭等暂态信息用于核对选择边界。

设计为v21/v26 × text/json_schema × 两个连续窗口，预算最多8次HTTP，`gpt-6-luna`、AstrBot Responses Provider默认采样参数，并发2，无网络或内容重试。每个分支使用独立数据库和自己的真实提交前态；失败立即停止该分支，不手改前态、不补跑。既有生产schema、引用解码及应用事务均实际调用，不将模板模拟当模型效果。

冻结SHA-256：`9754113e5f005457ab68c6fb9dbbd107b87e9f26a277347dd390a65a6ef75555`。本地证据与执行脚本位于忽略目录 `data/evaluations/profile-regression-20261117/`，不包含私人样本。实际7次HTTP、6窗提交、约116.16秒；耗时包含排队，不能按此比较版本速度。

| 分支 | 首窗画像候选 | 后窗 | 限制与缺陷 |
| --- | --- | --- | --- |
| v21/text | 覆盖职业、阅读、运动三类 | 新增收藏，保留职业/阅读与运动持续时长 | 首窗画像没有明确保留仅室内的排他限定；后窗遗漏未来调整生效前仍成立的原安排 |
| v21/json_schema | 覆盖三类且保留首窗排他限定 | 新增收藏，保留目前与下月安排区别 | 后窗画像不再明确保留仅室内的排他限定 |
| v26/text | 覆盖三类且保留首窗限定 | 未执行 | 同批关系只引用Agent发言，违反本人来源要求，整窗拒绝；不能把正确画像候选记为已保存 |
| v26/json_schema | 覆盖三类 | 新增收藏，保留职业/阅读与持续时长 | 画像未明确保留仅室内的排他限定；后窗遗漏变更生效前的原安排 |

三个执行到第二窗的分支都保留“下个月”这一未来生效范围，没有把新安排直接断言为目前已执行；遗漏旧安排与提前生效是不同问题。此处按来源逐项审阅，未以关键词命中代替语义判定。

另外，v26/json_schema首窗只产生画像、没有长期节点，后窗再为运动变化创建节点。这是首次创建该节点，不能仅因 `create` 数量推断它拒绝更新旧节点。画像与长期节点是不同存储职责，抽取统计必须先检查候选上下文是否有对应旧节点。

样本只有一条独立双窗链，每单元一次生成。结果不能证明v26画像不回归，也不能证明结构化输出改善或损害画像；它排除了“这条路径已完全失去画像生成能力”的过强说法，支持继续定位选择与连续更新质量。

## 建议的最小优化边界

1. **把画像职责单独说清楚，保留联合调用。** 在同次抽取中分别判断：首次明确自述、新增独立资料、已有事实或状态修正；长期节点已经保存不等于画像已表达。人格语气只控制长期正文与关系，不把画像选择服从于事件是否值得叙述。没有新适合画像的信息仍不更新，不设每窗强制画像。
2. **保留轻量结构与当前事实约束。** 继续标签加短描述，不新建事实槽位或把原子机械复制为画像。修正只影响相应部分；未来才生效的变更不能抹去生效前当前事实；同一事实的范围与限定需要完整保留。
3. **先独立对照再采用。** 当前证据支持提出上述最小职责候选，不支持立即整体回退v21、整体采用v22，或把“画像更多”设为唯一成功标准。候选需覆盖首次选择、低价值不存、画像独立于节点、无关事实保留、未来变更、本人/人格归因及多窗稀疏表达，并保留结构失败。
4. **将风格与任务契约拆成可复用提示词段。** 以后更新长期文风时复用画像、引用和版本规则，避免再次整份改写时顺带缩减其他任务要求；这属于提示词组织，不额外调用模型。保留显式版本与独立行为验证，不靠字符串存在就宣称质量稳定。

重新核对的参考包括本地Mem0 `26cdefb46600c0fa5953c4b5ee5003c125539fc4`（Apache-2.0）关于用户/Agent信息的职责分离，以及Hermes `d05095663342556788cf2a198bfa7844cc7968ab`（MIT）的user-profile目标和局部patch设计。它们提供任务边界与编辑范围参考，不证明NeoMemory中文画像质量。Mem0当前自动路径不是旧式原位UPDATE算法；Hermes局部patch也不能解决首次漏选，且后台修改存在审批边界。更完整比较见[画像轻量更新研究](../画像轻量更新方案研究.md)。不因此引入额外模型调用、复杂持久画像结构或未获采用的patch协议。

本项未修改产品、现用数据库或实机配置；只新增独立证据与本报告。
