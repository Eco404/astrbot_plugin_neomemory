# 事实元信息与15000字节预算核查

## 抽取确实收到什么

生产v31/v7的`PreparedExtraction.messages()`在`core/extraction_apply.py`中逐条提供source_id、actor_kind、actor_logical_user_id、conversation_logical_user_id、content_text、observed_at、event_time_*、stream_id和sequence_no。`core/prompts.py`序列化这些字段为同一user消息里的JSON数组；`reference.v2`只缩短身份与引用，不移除角色或时间。

因此“没有将发送者和时间传给模型”不成立。当前人格记忆提示也明确说明Agent即人格、用户自述的第一人称归属用户，区分转述、建议、接受和实际完成；事件发生时间不同于消息提及时间。

## 确认的薄弱点与尚待验证的因果

1. **时间表示薄弱。** observed_at以Unix数值原样传入，没有额外可读日期、逐条时区或日期边界。模型需要自己解释数字和原文中的相对时间。窗口按条数、空闲和话题选择，不保证不跨日；同批不意味着同一天。
2. **旧状态缺少来源时间锚点。** 已有画像仅含身份、标签、描述、版本和状态；关系仅含身份、正文、状态及版本。旧节点有事件时间，但当次输入通常不展开旧原文。完整追溯链保存在数据库，不等于每次模型看见它。旧“今天”或相对持续时长可能被当作当前状态继续继承。
3. **说话者不等于动作主体。** 发送者元信息说明谁发送原文，不能单独解决转述、称呼、主语省略及视角转换。最终要输出人格第一人称自然正文，仍需要语义判断；已有直接反转证据说明提示规则没有被稳定遵守。
4. **结构校验不验证句意。** 合法引用、版本、类型及本人来源检查，不能证明每个结论是原文确认的，或问句已经获得回答。当前v7不会运行旧实验v3的事件身份/确认字段检查；即使让模型声明状态，也不自动证明其声明正确。结构合法的事实错不会触发标准纠正。
5. **旧错继承与联合任务负担。** 旧正文作为生成基线，可以把旧错传播到新正文、主题和回答；同次抽取负责多种对象，可能增加任务干扰。传播路径有实现依据，但各因素对错误的贡献大小需要独立对照，不能声称已测出唯一根因。

实时采集另有时间语义区别：`main.py`调用`normalize_event`没有传平台发送时间，`core/source_ingest.py`默认使用插件观察时刻。导入转换`convert_legacy_evidence.py`则保留原记录timestamp。因此实时接收时间差异不是本次导入重构跨日错误的解释。本次只分析，没有改采集或抽取行为。

## 参考与建议验证顺序

已查本地Graphiti提交`5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`，Apache-2.0：`graphiti_core/utils/maintenance/edge_operations.py`为多episode组织各自时间与reference_time，`prompts/extract_edges.py`要求优先按具体episode解析相对时间，并展示ISO时间。适合参考逐来源可读时间和清晰参考锚点，不照搬其事实边valid_at语义，也不据本地快照判断上游当前维护状态。

Mem0提交`26cdefb46600c0fa5953c4b5ee5003c125539fc4`，Apache-2.0，`mem0/configs/prompts.py`区分Observation Date与Current Date。这里只参考区分观察与处理时间的输入组织；默认日期回填不能原样用于历史重构，更不能用构建时间代替来源发生时间。未复制第三方代码。

优先用独立材料对照：逐条可读时间与可靠时区、旧状态的来源观察锚点、清晰的说话者/动作主体表示，再检验同次调用内先判事实后写自然正文。未知时区不假定用户所在地；发送时间不直接当事件时间；跨日不强制拆开持续事件。任务拆分的额外模型成本仍需明确取舍，不把每条加一次审核模型作为默认方案。元信息改善也不承诺纠正所有语义错误。

## 预算实施与验证

用户确认保留字节计量，将总预算设为15000字节，约5000个常用汉字容量；配置schema、运行配置及RecallPolicy缺省已一致。现有保存值仍保留，指定实机使用设置API更新：持久值与运行值均为15000、applied=true，运行配置变化仅recall_budget_tokens，无重载、无清库、无重新构建。实机生成代码仍为0870f01，本地默认变更没有重新部署包。

最低支持宿主AstrBot v4.29.3下，配置/共享装配/检索/主动召回/设置/运行热应用/同名身份预算的已有测试258项通过。

使用最终完整构建已冻结的六个自然问题候选进行离线核验：先重建2048字节文本，六问均与原始注入逐字相同，再仅修改容量重做15000字节装配。六问全部带入画像与关系，长期节点均为6个；实际占用7795—9078字节，剩余候选因节点数量上限省略。该过程不重新检索、不调用模型或向量、不强化或更改来源，结果不解释为答案质量提高。证据位于忽略目录`data/evaluations/budget-15000-20261118/`。

固定私人样本仅用于变更后装配检查，不用于选择容量、改提示词、参数搜索或生成专用测试。历史完整构建与12次回答报告仍保持原2048/4096预算，不能重标为15000预算验收。
