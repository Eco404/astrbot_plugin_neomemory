# 阶段一执行记录：身份与原始事实库

## 状态

阶段一已完成实现和退出验证，基线为 AstrBot `v4.29.3`，提交 `abf683071`。本阶段只保存可重放的原始输入，不调用 LLM、Embedding，也不创建 `memory.db`。

## 已交付内容

- `core/identity.py`：平台、会话、群组、账户、人格快照解析；默认逻辑用户 ID；私聊和群聊空间 ID 辅助函数。
- `core/source_ingest.py`：私聊/群聊输入和 Agent 响应规范化、组件 JSON、长度截断标记、稳定去重键和 `identity_pending`。
- `storage/migrations.py`：`source.db` v1 迁移。
- `storage/source_store.py`：WAL、外键、事务、幂等写入、stream sequence、账户绑定、游标和分页查询。
- `main.py`：AstrBot 自定义过滤器、`on_llm_response` 接入、后台写入、失败源的有上限进程内暂存与重试入口、健康和查看 API。
- `views/neomemory/index.html`：最小原始记录查看页。
- `tests/`：身份、规范化、数据库幂等/绑定/并发、AstrBot 宿主和真实插件目录加载测试。

人格解析遵循“有明确来源才保存”的规则：事件 extra 或宿主会话管理器能给出 `persona_id` 时写入记录；无法可靠解析时保留 `NULL` 并将 `identity_pending` 置为 1。账户绑定首次使用确定性单账户映射，显式绑定可以替换自动映射，已有显式绑定发生冲突时拒绝静默覆盖。

```bash
  /home/coder/apps/miniconda3/envs/astrbot/bin/python -m py_compile \
  main.py core/*.py storage/*.py tests/*.py
```

宿主测试覆盖：

1. 使用真实 AstrBot API 导入插件，注册 4 个 Web API，并初始化 `source.db`。
2. 私聊和群聊旁听过滤器均返回 `False`，不会唤醒 Agent；用户和 Agent 记录均能写入。
3. 人格快照、逻辑用户、来源流和 sequence 可查询；重复事件不增加记录或 sequence。
4. 模拟写入失败后，规范化对象进入失败队列，恢复数据库后可以重试成功。
5. 终止后重新初始化，原始记录和迁移版本保持不变。
6. 将插件复制到真实 `data/plugins/<name>` 布局后，通过 AstrBot `PluginManager.load()` 加载，再调用终止流程，结果为成功。
