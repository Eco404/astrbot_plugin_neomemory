# NeoMemory 1.0 数据库结构

正式版直接建立下列四个 SQLite 数据库的完整 v1 结构。数据目录由 AstrBot 的 `StarTools.get_data_dir("astrbot_plugin_neomemory")` 提供。每个文件独立记录 schema 版本。数据库结构版本用于识别文件格式，节点、画像和关系的内容版本则用于记录某个实体在使用过程中的修订。

| 数据库 | 持久内容 | 写入与清理 |
| --- | --- | --- |
| `ingress.db` | 尚待送入原始库的输入、重试与失败状态 | 原始记录确认写入后清除相应待写项 |
| `source.db` | 带序号和观察时间的原始消息、外部来源、参与者、会话流、逻辑用户及账号归属、图片文字依据 | 原始记录供重放，插件不自动清理 |
| `memory.db` | 空间与记忆代、节点及成员、强度、版本来源、画像、关系、短期摘要、笔记、任务和恢复凭据 | 派生变化与其提交凭据通过事务写入，重构成功后才发布 |
| `cache.db` | 按模型、文本或节点版本区分的查询与节点向量 | 可重新计算，按配置清理 |

## 版本与时间

- 新实体的内容版本从 1 开始。标题独立编辑，正文或情绪的有效修改会生成内容版本。默认每个长期节点、画像及关系分别保留最近 10 个版本（含当前版本）。
- 节点记录其直接来源和继承版本所含的最新观察时间。原始消息移除后仍可读取已保存的内容时间。事件发生时间可以未知，更新任务运行的系统时间另行保存。
- 成员与覆盖依据绑定具体版本。只有仍有效的成员、来源和版本条件才能提交到当前记忆代。
- 全量重构按固定范围重放来源，成功后切换记忆代并清理该空间旧代的派生内容。新实体从 1 重新计数。原文、独立笔记和属于其他空间的数据保留。
- 按板块重构分别发布选中板块的结果。主题使用现有事件和原子；画像和人格关系回放原始会话。这些操作从维护页发起。

工程依据见[存储代码](../../storage/)和[模型协议](../提示词与输出协议.md)。
