# 画像轻量更新方案研究

日期：2026-11-02（UTC+8）。状态：研究与候选设计；尚未实现、未进行真实模型验证，生产默认继续 `extraction-prompt.v3` / `extraction.v2`。本文只读取代码、公开参考材料和独立合成评估记录，没有读取私人会话、人格卡或凭据。

## 结论与问题边界

建议下一轮评估**精确旧片段更新**：数据库仍保存 `tags + description`，模型在原有一次抽取中提出局部修改，程序保留未修改文本。它能把“模型重写整段时意外漏掉无关旧事实”的部分风险转为可检查的操作边界；不能保证修改片段内部不漏限定，也不能保证模型选中所有值得进入画像的事实。

画像漏建应另外评估一个很小的**明确选择结果**，先限于私聊的固定逻辑用户：在同次抽取中明确选择更新、已经表达、没有适合画像的新信息或证据不足。选择不等于必须保存；不得要求每个长期节点都有画像、不得把所有 `atomic` 自动复制进画像。两项机制分开比较，避免把改进归因混在一起。

当前代码 `core/extraction_schema.py::ProfileChange` 返回完整标签和描述，`storage/extraction_store.py::_write_profile` 直接完整替换。已有作用域、用户本人来源、版本与状态校验，能够拒绝过期或非法应用，却不能判定旧描述中哪些条件被模型漏写。[上一轮独立合成记录](抽取保真改进轮次执行记录.md)已经分别观察到：首窗缺限定、更新丢未被纠正的限定、完整事实进入节点但未进入画像。它们不是同一种错误，局部编辑只直接针对第二种。

## 推荐候选A：精确片段更新，不增加持久画像层级

### 候选协议

为实验定义新的 schema 与 prompt 版本；不得把新字段塞进现有 `extraction.v2`，也不改写旧候选含义。建议保留每用户一项变化和现有 `logical_user_id / expected_version / source_ids`，将完整 `tags/description` 输出改成：

- `description_edits`：少量 `{old_text, new_text}`；`old_text` 非空且必须在准备时的旧描述中精确出现一次。`new_text` 可为空，表示明确删除该片段。
- `description_append`：一段完整的新事实表达或空字符串；程序在修改后的非空描述后用单个换行连接，现有文本不改写。用换行避免程序猜测中文句末标点，不要求按句切分已有描述。
- `tags_add / tags_remove`：精确标签；删除目标必须在旧标签中，新增目标不得已经存在；列表内部不得重复，新增与删除不得相交。

初始候选可限制每用户最多8个描述编辑，标签继续使用当前上限。次数是输出预算，不是把画像拆成8条永久事实。新增画像使用 `expected_version=0`、空编辑/空删除、完整新增描述与标签；不得从无节点的场景强制补节点。新协议的具体名称与长度在实施计划冻结，本文不预占版本号。

局部新增仍需要模型生成完整句子，不能从原子直接机械摘取：原子可能是历史、转述、第三人、主观关系或只保留一次经历。画像保留当前事实；长期节点是否同时创建仍按已有选择规则。

### 定位、冲突与最终状态

1. **同批所有编辑定位于同一旧版本。** 程序先在原始 `description` 中解析全部位置，包括相互重叠的重复出现；不允许前一编辑生成后再供后一编辑匹配。目标不存在、多处命中、编辑区间相交、重复编辑都拒绝。
2. 校验完成后从后往前拼接替换，再追加新增段落。对未命中的原始片段作逐字保留，不做模糊匹配、Unicode/标点归一化、自动摘要或全局去重。需要修改重复的短词时，模型必须给出足够长的唯一上下文。
3. 标签先按旧序保留未删条目，再按输出顺序加入新标签；不能把缺席 `tags_add` 的旧标签当作删除。标签与描述同一最终状态提交。程序不擅自用标签推断对应描述、也不能证明两者语义一致。
4. 对最终文本和标签统一验限，允许同批“明确删除旧内容并新增”后仍在限内。超过现有私聊600字/12标签或群聊240字/8标签的抽取上限则拒绝，**不静默截尾、按长度删事实或自动增加一次压缩调用**。不改当前群聊限额；历史规划中的其他数值不在本轮顺带调整。
5. 所有编辑为空或结果完全不变不能伪报变化。当前批次如果只有“不值得保存”等选择结果，仍可合法 `no_change`；失败不等于 `no_change`。
6. 不禁止模型给出覆盖整段的唯一 `old_text`，因为复杂修正可能需要它，但审阅必须把它视为整段重写风险。不能通过“使用了patch字段”宣称已经保护整段限定。若实验表明模型频繁整段修改而无收益，应拒绝候选，而不是加任意字符比例门槛伪装语义检查。

独立思考示例：旧描述为“在晴天的周日上午观察野鸟，已坚持五年。照片只用于个人记录，不公开发布。”新来源明确只把时间改到周六上午。将唯一片段“周日上午”改成“周六上午”，程序会原样保留晴天、五年和照片用途；若模型选中整句并重写时漏掉五年，精确定位检查仍会通过。这说明实际保证是**编辑范围外逐字保留**，不是“所有事实不丢失”。此例未发送模型，也不是既有质量结果的复现。

### 版本、恢复与治理

- `expected_version`、准备时画像快照、generation、scope、状态及现有 `updated_at` 检查保持；不要仅凭旧片段仍存在就接受过期候选。模型输出新协议、准备摘要、prompt/schema版本和提交凭据必须一一绑定。
- 在事务外生成、解析及计算候选最终值；事务内重新验证快照/版本并与节点、覆盖、画像、来源消费、完成凭据同批提交。任一操作失败，整个抽取批次不提交，沿用当前空间顺序阻塞与维护恢复，不偷偷只丢掉画像操作。
- 不调用通用 `upsert_profile` 绕过抽取事务，不把原始操作转换成旧schema后冒充旧输出凭据。可复用内部最终值校验/写入函数，但新schema必须有自己的合法解析与凭据路径。
- 已保存合法候选且未提交时，重试优先使用候选；已有提交凭据时直接恢复；旧版本已经改变则要求重新准备。新操作执行失败不触发无限模型修复。维护页显示失败原因、原候选及旧值/拟更新值差异，仍使用现有后台任务与检查点。
- 临时编辑位置、拼接中间值不进入数据库；恢复必需的原候选继续放任务检查点，不能塞可清理缓存。数据库仍是一行标签与描述，**无新增画像事实表、句子ID或语义槽位**。
- 当前 `user_profiles` 有状态与版本，但没有独立 `manual_protected` 字段；`memory_nodes` 的保护标志不能误称为已经覆盖画像。候选必须保留画像 inactive 拒写、人工修改引发的快照失效，并且不能弱化既有节点人工保护。若要求画像在人工修正后永久自动锁定，这是另一个需要显式设计的产品能力，不应借本候选暗中增加或宣称已完成。
- 重构按当前规则在新generation生成，可清空旧治理；不迁移旧片段操作到新画像。当前画像表也不是历史版本表，不能凭新增patch协议宣称用户已能回看所有历次画像正文。

## 可分开评估的候选B：明确私聊画像选择

在同一次抽取输出中，为当前私聊逻辑用户增加一项选择结果，枚举为 `change / already_represented / not_profile_worthy / insufficient_evidence`。枚举表达的是决策结果，不存新的画像事实；无需自由形式思维链。

- `change` 必须有该用户对应的有效画像变化；其余三项必须没有该用户画像操作。模型无法以空列表掩盖协议上未作选择，但仍可能选择错误。
- 有本人来源才要求该选择；只有Agent来源时仍不能据Agent猜测建立用户事实。已有画像为空也允许 `not_profile_worthy`、`insufficient_evidence`；一次心情、暂态任务、寒暄不必建画像。
- `already_represented` 表示适合画像的信息已经在画像表达；仅存在长期节点不能自动等同已经表达。是否真被表达仍是语义检查，不靠文本包含硬判。
- 选择不是独立“变化”：没有其他变化时允许全批 `no_change`。不要因为结构字段必填而创建空画像或推进画像内容版本。
- 群聊第一轮不要求每个旁听成员都返回一项判断；人数增长会增加输出与失败面。群聊兼容性仍要测试，若将来扩展，应使用有界目标集合并保持低成本。

候选B能够提高“模型作出了什么选择”的可观察性，但不保证降低漏建率；模型完全可能自信输出错误的 `not_profile_worthy`。在没有真实对照之前，不应默认增加生产字段或宣称修复。

## 备选与不采用项

| 方案 | 能得到的保证 | 主要代价/不足 | 建议 |
| --- | --- | --- | --- |
| 继续完整替换，追加更强保留提示 | 不增加协议复杂度 | 已多轮出现语义遗漏，仍无程序保留边界 | 保持生产基线用于对照，不作为新的最终修复方案 |
| 精确旧片段操作A | 未选区域逐字保留、版本/定位可验证 | 片段内部仍会丢事实；定位失败会增加维护任务 | 优先做隔离候选 |
| A加明确选择B | 能区分漏填协议与有意不存 | 选择可错，输出字段增加；与A同时改不易归因 | A独立对照后，或预先固定独立实验组 |
| 短句列表加永久ID | 稳定定位至一句，未选句可原样保留 | 旧画像迁移、人工编辑、拆句/合句语义都增复杂度；仍不能保护句内限定 | 暂不采用 |
| 完整结果与旧值做程序diff后补回缺失文本 | 可看到字符级删除 | 无法区分纠正、精简和遗漏；补回会复活已失效偏好、制造矛盾 | 不采用 |
| 画像改成节点引用/检索视图 | 能复用节点正文 | 节点包含历程、转述和低层细节；破坏画像当前态及低成本固定注入 | 不采用 |
| 额外模型审查/画像专用调用 | 任务分离或可改善审阅 | 额外延迟费用、模型仍可能共同出错，尚无有界证据 | 本轮不采用；若要默认新增调用，再提出成本与效果对照 |

## 下一轮冻结验证与采用条件

下一轮先实现最小协议候选A与确定性补丁函数，在隔离路径使用；生产默认先不变。无需现在向用户索取开放式设计答案。候选B单列可选实验，不把它混入A后仍称“单变量对照”。

工程验证重点：重复旧片段（包括重叠出现）、多个不相交修改、区间交叠、空删除与新增、精确标签存在性、最终长度、完整事务回滚、过期画像/人工变化拒绝、候选恢复不重发、完成凭据幂等、新旧schema隔离。使用临时库，不为纯文档或实现镜像另建测试引擎。

真实评估在调用前冻结样例、问题、人格、模型、版本、请求预算和判定规则。至少包含：新增无关稳定事实、局部修正且旧时长/条件仍有效、撤销当前偏好但长期历程保留、需要跨句重写、重复片段、容量接近上限、明确稳定事实首次出现、允许不存的暂态/寒暄、群聊来源隔离。新材料独立构造，不参照私人会话，也不让被测模型看到预期问题。

分开报告：画像选择正确性、修改范围内事实准确性、修改范围外字符保留、当前态/历程边界、标签一致性、协议失败/维护次数、输出token与耗时；拒绝应用但留下正确旧状态不能算语义成功，成功写入也不能抵消新错误。既有合成失败可作回归，但不能替代新样例；新旧方案按同一来源和各自连续前态对照，不手工修正前窗后再比较。

采用至少需要看到：无关旧事实保留有稳定收益，新增定位拒绝与维护负担可接受，当前事实修正与选择不明显退化；单模型小样本只支持有限结论。若不达门槛，保留v3，记录失败而不追加预算测到通过。

## 需要明确的决策

本轮研究不需要用户立即决定，也不修改现有Accepted ADR。后续正式采用时由主计划给出具体Proposed ADR：是否把自动画像更新默认切换为精确片段协议；接受“无法唯一定位/超长时保留旧状态并让当前空间窗口待维护”的工程代价，还是保留完整替换。前者沿用现有失败恢复机制，但可能提高发生频率，需实验量化后决定。

明确选择B是否默认启用应按独立对照决定；不要求每节点建画像和允许低价值不存是既定约束，不重新交用户投票。额外默认LLM调用、句子/事实表、永久画像人工锁定都不属于推荐候选，只有决定引入时才需要另行审议，不能作为推进当前隔离研究的前置条件。
