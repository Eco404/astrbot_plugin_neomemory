# 阶段五补齐：可靠采集与完整上下文

日期：2026-10-29。状态：功能交付与复核完成；长期三窗口真实质量验证受Provider超时限制，补测进入阶段六。基线561项测试，最终687项通过，AstrBot v4.29.3、Conda astrbot。用户已确认补持久待写，保留失败窗口顺序阻塞，默认人格直接跳过。详见[执行复核](阶段五补齐执行记录.md)。

## 范围和实施顺序

| 批次 | 完成内容 | 验收目标 |
| --- | --- | --- |
| A | 独立ingress.db和有界待写服务；源库提交后删除待写条目；错误查看/人工重试 | 队列重开、写源库后中断不重复；同流前失败不被后续越过；容量满不静默淘汰 |
| B | 默认人格统一跳过；维护页显示自动抽取暂停原因 | 不采集/注入/调用模型/创建任务；旧默认空间不继续自动推导；失败窗口可定位处理 |
| C | 纯插件后台滚动短期摘要，来源覆盖及持久任务检查点 | 前台零生成等待；会话/流/人格/代隔离；失败恢复复用候选；宿主摘要避免重复 |
| D | 画像、私聊关系、短期摘要和笔记提示进入统一临时上下文 | 无向量模型仍可用；完整条目和总预算；当前代重校验；临时注入不保存到宿主历史 |
| E | 合成场景多轮真实模型回放、故障/宿主/浏览器验证，文档/ADR和复核 | 不将连通性烟测冒充质量结论；记录样本与结果；分功能commit |

默认人格跳过包括宿主普通default、ChatUI特殊_chatui_default_及明确无角色[%None]；不自动映射为其他人格。未知身份的既有原文记录机制保留用于诊断，无法归属时不抽取/召回。

失败抽取继续按顺序阻塞当前空间后续推导；原始采集、其他空间及已完成记忆的召回继续可用。明确把“任务锁空闲”与“自动推导暂停”分别展示。乱序推进策略等整体功能完成后再讨论。

## 接口与目录

- storage/ingress_store.py、core/ingress.py：独立队列、容量、状态、原始入库重试；main负责生命周期。
- core/persona_policy.py：统一支持范围，入口和后台双重检查。
- core/short_term.py、short_term_prompts.py：独立短期后台任务，当前人格与明确输出协议。
- storage/short_term_store.py、short_term_schema.py：摘要提交/覆盖/receipt，memory.db v6。
- storage/context_store.py、core/context_bundle.py：一致快照、预算与数据包；adapters/runtime.py负责临时注入。
- adapters/ingress_api.py：待写错误、详情及重试；现有维护页增加待写队列和暂停状态。

短期使用人格×空间×来源流×host_conversation_id，预留最新10条原文，对更旧消息每累计6条触发，单次最多40条/16000字符，摘要默认最多400字符。参数可调。前台只调度后台任务和读取已完成摘要，不能保证与宿主实际截断边界完全重合。

画像仅当前用户的当前空间；群聊不注入人格关系。笔记默认查询active，提供显式archived/all筛选。总注入预算沿用recall_budget_tokens的保守估算，完整条目无法放入则省略并记录诊断；有向量召回时为长期记忆保留预算。

## 既定边界

完整五栏UI、可视化拆合、导入导出、原始库自动清理和大型索引升级继续留后续。当前最多2000节点的检索限制继续如实报告，不以调大数值代替索引设计。待写容量是有效载荷容量，实际SQLite文件/WAL大小另有开销；持久介质完全不可写时无法声称消息已经可靠保存。

## 验证重点

source提交后未清队列的重启、源库不可写/队列满、同流失败排序、用户/Agent入口与默认人格、short_term候选保存后恢复、超长来源、人格配置变化、会话切换、generation切换、宿主摘要、总注入预算、无Embedding模式、注入不进入永久历史、人工重试按钮及自动更新暂停提示。
