# 画像漏建诊断与稳定事实选择边界

日期：2026-10-30。承接画像条件保留轮次，默认仍为 `extraction-prompt.v3` / `extraction.v2`，不改变数据库版本。

状态：D1–D5已完成；交付、8次实际调用、失败/不确定证据及下一步见[执行与复核](画像漏建诊断轮次执行记录.md)。没有将本轮结束视为语义质量已修复。

## 问题与边界

上一轮 v4 候选首窗口写入了长期节点，却没有画像；旧证据没有模型候选，不能区分未提出与未写入，更不能证明由提示词版本引起。本轮补诊断、少提示自然措辞回放及证据审阅，不预设必须修改生产提示词。

用户要求画像轻量、选择性保留，并非每轮必须更新。因此不能建立“每个长期节点必须对应画像”的规则。测试应分开评估：

- 选择：本用例明确持续多年的习惯、稳定偏好，应进入当前画像；这不是对任何单条信息的全局强制。
- 保真：决定保留的事实必须保留范围、频率、否定和不确定性，不能补造未说明属性。
- 可选：一次琐事、尚未决定的临时计划可省略；若保留，不得当成已发生或稳定偏好。
- 更新：新增不互斥事实不能清除原有事实；当前画像不承载变化史。

旧用例及旧失败结论不改写。新自然措辞用例的预期在调用前冻结，评估问题不发送给模型。

## 调用预算与变更门槛

本轮最多 **8 次实际 LLM HTTP、0 次 Embedding**。首先自然措辞3窗、已知条件2窗，共最多5次；余下最多3次仅用于依据前述证据的定位复测或现有连续偏好修正回归。不得因为失败而扩张预算。每任务1次尝试、SDK重试0、60秒抽取截止；无在线裁判，离线由代理阅读证据。网络失败也计入预算。

只使用已授权API和合成输入，临时运行库退出清理；最小证据放忽略的 `data/evaluations/`。合法候选用严格schema规范化并限定数量，非法输出仅保存长度/散列/错误类别，不保留原始输出；不增加生产日志或持久库字段。

若 v3 出现漏建，先用候选及完成凭据定位；证据不足不追加未经验证的强制规则。若提出生产修改，需另有明确依据与足够验证；本轮预算不够时保留默认并明确后续实验。历史 v4 漏建不可用本轮新结果倒推定论。

## 验证和剩余范围

运行候选诊断、质量脚本及抽取应用相关测试，再跑全量 pytest、Ruff、compileall、diff 检查。工程回归不等于模型质量；单模型、有限合成样本不证明普遍稳定。

本轮不引入画像事实表、额外生产模型调用、自动修复、第三方记忆引擎、导入导出或原始库清理。保持现有失败窗口和恢复语义。
