# 召回候选回补与实机重构验证

## 目标与边界

恢复既有覆盖合同：只有最终完整注入的有效事件才能抑制原子。使用当前候选排名及已有向量结果，在最终共享预算内重新选择；不增加Embedding或生成模型调用，不改变full声明的信任策略，不处理宿主输入截断问题。

## 数据流

- 被动召回按需保留本次有界排名候选。它们是请求生命周期内的数据，不写数据库或长期缓存；主动工具保持完整返回的接口。
- 在辅助资料的最终校验事务内，检查候选所属空间、活动代、正文版本、状态和摘要新鲜度，并重新读取这些候选之间的当前覆盖关系。不能使用已变为partial或已删除的旧full声明。
- 最终装配复用已经渲染的节点文本，按共享字节预算和节点上限选择。长期优先仍预留首个可容纳命中，辅助资料优先仍先安排摘要、画像和关系。
- 覆盖事件放不下或已失效时，原子仍可按原排名参与选择；补回项继续接受完整正文、节点上限和剩余预算限制。只有实际注入项强化。

## 验证与交付

1. 用独立合成来源复现画像挤出事件后细节丢失，并覆盖两种优先级、紧预算、节点上限及昵称展开。
2. 通过真实存储和请求hook验证禁用、修改、切代、full改partial及删除覆盖后的行为，不让陈旧候选回补。
3. 运行相关与全量回归、固定预算矩阵；记录额外本地校验开销及未改变的语义质量边界，完成文档和本地提交。
4. 按用户授权更新实机NeoMemory，卸载插件后清理其运行数据，保留插件配置与宿主人格，重新导入指定会话并进行全量重构、索引、结构及有限召回评估。
5. 实机样本仅用于评估，评估方法在读取结果前固定。失败保留证据；通用修复用独立材料验证，不针对该单用户会话修改提示词或参数。

完成条件是候选回补符合现有覆盖及预算合同，实机完整构建达到可审阅终态且问题分层记录。该交付不代替来源归因、条件保留、多模型、平台联调或容量等其余计划的验收。
