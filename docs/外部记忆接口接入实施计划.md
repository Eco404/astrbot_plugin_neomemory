# 外部记忆接口接入实施计划

日期：2026-11-06。范围是 NeoMemory 对 `companion.external-memory.v1` 的第一轮适配，
不包含陪伴插件内部代码修改和真实发布。

## 目标

- 通过公开 extension API 注册 NeoMemory Provider。
- 严格使用陪伴接口传入的作用域和认证主体，映射到 NeoMemory 记忆空间。
- 让读取、写入、统计都具备明确的预算、幂等和失败边界。
- 保留 `source_event` 原始输入能力，为未来自主活动抽取预留入口。

## 交付内容

1. 适配层负责 Provider 发现、注册、注销和活动状态。
2. 设置增加启用开关、归属模式、优先级和回调超时；默认关闭。
3. `read` 仅服务私聊，复用现有召回服务，返回完整节点正文。
4. `write` 将陪伴插件允许的自主记录写入持久 ingress 和 `source.db`，不直接改写 `memory.db`。
5. `summary` 返回画像、关系和派生节点的有限计数。
6. 新增 ADR、契约测试和执行记录。

## 非目标

- 不读取陪伴插件私有数据库或导入其内部模型。
- 不为外部回调增加第二套网络重试。
- 不在当前轮定义 `source_event` 的长期抽取语义。
- 不自动启用 `owner` 模式，不宣称已完成陪伴插件所有回复管线的端到端接管。

## 验证矩阵

- 错误 schema、缺少角色、跨安装作用域和群聊读取必须拒绝。
- Provider 只注册一次，停用和终止时能注销，注册失败不影响 NeoMemory 主功能。
- 同一外部记录重放返回同一 ID；内容、人格、平台或群作用域冲突必须拒绝。
- 陪伴插件延后加载或重载后，Provider 能重新注册，旧注册不会继续接收调用。
- 外部记录按宿主作用域保持稳定原始流；标签、元数据和可选字段不能绕过 JSON 校验进入持久队列。
- 外部写入进入 `source_event/external`，不会直接进入会话抽取。
- 读取遵守节点条数和字符预算，不调用生成模型。
- 统计不返回正文或敏感字段。
- 现有全量测试和静态检查保持通过。

## 后续宿主联调

需要在 AstrBot 实机和陪伴插件启用后另行验证：Provider 实际发现、普通回复与 V2 回复路径、
补充模式下是否重复注入、接管模式下 NeoMemory 的注入是否覆盖全部目标管线，以及超时和
注销后的降级行为。完成这些验证前，相关设置保持关闭。
