# 画像条件保留轮次实施计划

日期：2026-10-30。承接画像质量轮次：v3解决了已观察到的历史混入，但一次修正将“每天只喝乌龙茶”缩为“每天喝乌龙茶”。本轮目标是区分事实正确与必要条件完整，先研究已有实现与事实一致性评估方法，再按证据调整。

状态：C1–C5的研究、工具、实验与复核已完成。9次HTTP用尽，v4候选存在漏建画像等失败，已撤回默认升级，继续使用v3；限定语质量问题仍未解决，详见[执行记录](画像条件保留轮次执行记录.md)。

## 范围与语义

保持人格×逻辑用户归属、轻量tags/description、长期节点保留历程、当前画像只含当前事实的架构。描述中被选中保留的事实，不应丢失影响回答的否定、排他范围、条件、时间状态或频率。允许同义改写，不强制逐字保留“只”；例如“非周末不喝茶”与“仅周末喝茶”可等价。标签允许是中性主题（如“通勤方式”），不能用“每天骑车”标签扩大“仅晴天骑车”的适用范围，也不要求每个标签重复完整描述。

明确偏好变更才替换旧事实；新增一个不互斥的爱好不删除原爱好。“尚未决定”不等于“确定不做”，“除非下雨，否则骑车”不能推断“下雨就一定乘公交”。排他词的作用对象必须正确：“只在周末喝茶”不是“周末只喝茶”。

原始库/schema/生产任务接口不改；不引入第三方完整记忆引擎、语义正则过滤器或被动LLM裁判。选择性丢弃原则不变。本轮fixture明确指定值得保留的长期事实，不能把“什么都不写”当完整性通过。

## 逐条件验收与产物

固定fixture保留原文、前后画像/标签/节点和来源ID，增加`review_requirements`：每项为field、question、expected_answer和稳定id。离线review中的`assessments`须覆盖全部问题，写observed、verdict和reason。问题不提供给抽取模型，避免把标准答案提示给被测模型。结果只显示统计，详细合成证据留本地`data/evaluations/`。

区分：正确当前事实、允许当前否定、长期历史、错误当前事实、缺失条件、改变条件、信息不存在和无法判断。来源条件与输出条件逐项比较；不以“含关键词”或整体感觉代替。来源支持一个弱化陈述，不代表该陈述保留了关键条件。审阅由Codex及独立代理完成，不冒称人类标注或用户确认。

两窗口fixture含“只在周末喝无糖茶”“除非下雨，否则骑车通勤（不说明雨天交通）”“尚未决定养猫”“每周恰好两次游泳”。后续新增不互斥的吉他爱好，并以同义表达重新说明通勤条件；检查未纠正事实、否定范围与频率保留。再使用已有paraphrase偏好链验证停用/戒掉等表述，并要求饮料排他条件；群聊/寒暄使用现有可审阅案例。

## 调用预算、验证与退出

本轮真实HTTP总上限 **9次LLM，0次Embedding**：v3条件基线2次；根据证据保留或升级提示词后，条件2次＋群聊/寒暄2次＋不同措辞偏好链3次。每次运行仍不超过现有8次硬上限，每个任务尝试1次、SDK重试0、抽取截止60秒。逐次汇总实际调用，不因语义未通过无限重试；网络失败导致未覆盖范围必须在结果中明确。

离线检查覆盖新审阅合同的遗漏/重复/失配、条件失败不能被case通过掩盖、旧报告兼容、不同窗口来源和依赖链、质量模式Embedding硬禁、提示词升级对未提交候选与已提交凭据的区别。真实模型验证后再运行全量和静态检查，按独立功能提交。

退出以完整证据、可解释结果、按证据的改进和必要工程验证为准，不承诺9次调用消除所有自然语言歧义；发现的新问题需要记录和告知，不把未测多模型/真实用户会话包装成准确率提升。
