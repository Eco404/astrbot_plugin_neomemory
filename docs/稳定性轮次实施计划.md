## 实施边界

S1 使用临时目录、测试配置和本地监听地址，不加载生产聊天或实际 Provider。尽量复用宿主原有路由、鉴权和资源服务；如使用最小父窗口代替完整 Vue Dashboard，必须在报告中说明覆盖到桥/API而非全部登录界面。网络代理的路径场景以隔离前缀部署检查，不能推断所有真实反向代理配置都已验证。

S2 优先消除重复计算和多次往返，不增加数据库事实、不将正确性凭据放缓存。测量工具可临时包装阶段函数，不默认增加生产每轮诊断。候选排序、召回强化、人工保护及 generation 语义不变；涉及这些语义的变化必须先补 ADR。低配硬件无法直接验证时报告当前硬件，不用人为延迟冒充低配实测。

S3 只发送脚本内合成输入，使用已提供 API；不上传角色卡、真实聊天或配置。安排五个 LLM 窗口：低价值 1、群聊 1、私聊连续变化 3。整体最多 8 次实际 HTTP，其中 LLM 最多 6、Embedding 最多 2；任务一次尝试、SDK 自动重试关闭，宿主内部请求也计入预算。生产默认截止不为评估而放宽，网络失败保留结果，依赖窗口标为未评估。每个独立案例可以继续执行，失败依赖不伪造数据继续。

回放降低消息门限以减少测试调用，验证语义和生产任务通路，不据此声称默认群聊抽取频率经过调优。报告只保留断言、计数、模型名、耗时和安全错误码，不提交凭据、原文或模型回复。一次有限样本不能得出总体准确率或改变默认参数。

执行调整：首轮消耗4次LLM请求，寒暄/群聊通过，首次偏好修正被“旧词完全不出现”的规则拒绝；未保留正文，无法区分正确的当前否定与旧事实残留。保留此结果，将指标改为逐次旧词检查，仅允许明确当前否定，不允许历史画像。剩余额度调整为最多3次LLM与1次Embedding，使用 `--only preference --http-budget 4` 补验。该补验实际使用2次LLM后同类有限规则仍未通过，不再重复偏好链。

为避免独立的向量验证一直依赖语义质量检查通过，将最后2次额度交给 `--only recall --http-budget 2`：1次LLM独立生成记忆，1次Embedding合批节点正文与查询，验证节点键及热召回复用；不会把这个独立样本算作连续两次修正通过。本轮总上限始终为8次，分项累计为LLM最多7、Embedding最多1。不存在成功即无限追加或换模型尝试。

宿主联调边界细化：已确认固定宿主桥SDK注入根 `/api/...` 路径，本轮验证官方带token的深层资源前缀；任意额外反向代理根前缀和完整Vue登录流程未纳入已通过结果，不对宿主部署方式作未经验证的兼容承诺。
