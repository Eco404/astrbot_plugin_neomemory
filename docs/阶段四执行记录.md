- 被动召回使用当前消息与有限历史向量检索，当前命中优先，user/agent权重0.45/0.40；最近7200秒最多10条，作用域为同流、同人格，并在已知时严格匹配宿主conversation ID。
- 有界余弦匹配、一层关系/事件时间邻居、完整正文预算、双版本full覆盖去重、注入前终审。被动链路不调用生成模型重新组织文本。
- 节点缺向量时后台分批补建，在线只使用可用缓存。索引每空间最多一个、全局最多四个，有限冷却和可再入缓存检查点；不占住整个空间的向量化锁等待所有批次。
- AstrBot请求使用临时TextPart注入，同请求重复hook只替换自身对象；宿主序列化永久历史会过滤该块。真正返回的节点才异步强化，重复轮次、短时冷却、单轮总量和累计增益均受限。
- 主动回忆可查historical节点，笔记支持创建、字面检索、修改、归档/恢复；作用域只能由当前事件决定。笔记编辑在事务中核验所属空间，来源尽可能直接引用稳定source_id，无消息ID时保存必要流/轮次定位。
- 接入可用配置、健康信息、模型列表和连通性测试API。缓存故障不停止原始采集；插件关闭会取消自己的前台子操作和后台索引，不取消宿主整个聊天任务。

## 完成前复核与修正

| 发现 | 修正 |
| --- | --- |
| 整库索引可能长时间占用向量服务锁 | 按batch分段、跳过缓存命中、传递剩余总预算并让出调度；前台query可在批次间进入 |
| 节点向量全缺仍额外请求查询Embedding | 冷索引直接返回缺失诊断，后台补建 |
| 缓存读取失败在降级捕获之外 | 记录错误类型并返回空结果，取消继续传播；不把Provider正文写进诊断 |
| 同一召回中切换为同维模型可能混算 | 在缓存操作及评分前检查一致的fingerprint |
| 先取topK再过滤低强度会漏掉后续有效节点 | 先过滤资格再计算候选条数，同节点强度本轮复用 |
| 状态单独变更后注入仍显示快照旧标签 | 终审后用最新节点字段重新组织并再次检查预算 |
| 配置表单允许值超过实际服务范围 | 配置/schema/RecallPolicy边界对齐，极小极大配置均可初始化；节点缓存容量至少1 |
| 同一UMO切换conversation时混入旧历史查询 | 来源metadata保留宿主conversation ID；提供ID时严格匹配，旧未知记录不猜 |
| `_trace_persona_id=None`是宿主解析中间态 | 非空trace才直接采用，None回宿主resolver；明确`[%None]`仍无记忆人格 |
| 退出后未管理的前台召回仍可能注入 | 为每个插件前台操作创建可跟踪子任务；退出取消/等待子任务，宿主请求正常继续；真正宿主取消仍传播 |
| 可清理缓存关闭失败可能跳过权威库释放 | runtime、memory、source按嵌套finally收束 |
| 笔记source_ref使用了不可反查的turn摘要 | 有消息ID时生成与原始库一致的source_id；补充必要来源定位 |
| 大批量JSON处理和归一化阻塞事件循环 | 纯数据计算放到worker线程，数据库/网络保持异步；取消后不继续写缓存 |

2000节点×1024维合成向量的本机测量：缓存读取总耗时0.5154→0.5065秒、5ms ticker最大间隔69.9→13.3ms；完整缓存向量处理总耗时0.9562→0.9189秒、最大间隔432.1→20.9ms。改善主要是避免事件循环长阻塞，总CPU工作量仍存在。线程取消不强行终止纯计算，但不会继续数据库写入；本结果不是多用户并发容量保证。

这些是实现正确性与可靠性修正，没有新增需要用户重新选择的产品分歧。按用户要求，对目标交付和实施过程均做了检查，修复后再完成目标。

## 限制与后续边界

1. 自动持续抽取仍未上线。当前具备显式ExtractionService/Provider回调和已有节点召回，持久任务、窗口调度、失败重试及维护治理在阶段五接通。不能把本阶段视为已经完整自动记住每轮聊天。
2. 首版每空间最多2000节点参与快照，以重要性/更新时间确定范围并返回truncated。接近上限时，向量读取本身已有约0.9秒成本；1.5秒被动截止并不保证另加网络仍完成。真实Embedding冷批次约2.2–2.9秒，首次未缓存查询可能降级；应依据模型、消息量和响应预算调优，而非未经测量一味增加超时。
3. 后台索引是有限内存任务，并以可再生缓存保留已完成批次；重启后按缺失项重做。错误只在健康诊断中显示类型，完整持久错误记录、重试按钮和进度任务在阶段五。
4. 节点缓存命中同文消息向量时可能沿用消息TTL；它失效后会补建。容量按类别全库计算，过小容量或许多空间会频繁淘汰；后续规模测试再决定是否采用二进制向量、常驻快照或ANN。
5. 终审是时点检查。被选事件在终审前失效时安全丢弃，本轮不再回填此前被其full覆盖抑制的原子；下一轮按最新状态重选。没有为这一极小竞态增加长事务或额外网络操作。
6. 强化是实际注入后的可选后台写入，退出或过载时允许少记一次强化，不影响记忆正文与来源。未来需要更强的强化交付保证时可纳入持久任务，不能使用可清理缓存承载凭据。
7. 画像、人格关系和短期记忆的现有存储没有在本阶段扩展成完整独立注入编排；短期滚动摘要、完整治理流程和五栏WebUI仍需后续阶段实施，不能只凭长期节点召回宣称这些功能全部可用。
8. v4.29.3标准配置表单只有LLM选择器，Embedding暂填Provider ID，模型API可列出现有向量Provider；完整模型页面在阶段六。
9. 导入导出、原始库自动清理继续延期。source.db原文保留，memory.db迁移不自动降级；回退代码须使用匹配版本的数据副本。没有更改宿主仓库版本或用户提供的凭据、角色卡。
