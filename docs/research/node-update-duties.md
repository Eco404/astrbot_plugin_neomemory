# 节点操作与画像职责分离

## 问题与约束

画像应建立而长期节点已经存在时，模型可能同时润色旧节点。正文改变会推进内容版本、重置强度基准并影响已有覆盖声明，不能将反复改写仅视为显示差异。另一方面，禁止一切相近文本更新会漏掉真实进展、纠正和情绪变化。

本项只增加联合抽取时的操作判断提示，不增加调用、字段、事实表或提交过滤器。人格文风、完整正文、关系自主表达、来源校验及版本语义保持；不以向量相似度自动拦截更新或合并，不以节点少作为目标。用户允许少量概括瑕疵，应依据实际净收益和错误影响判断采用，不要求单次生成绝对无误。

## 候选设计

`core/node_update_prompt.py`在v27画像职责模板中仅增加独立“节点操作判断”段：

- 新独立经历或尚未记录的有意义信息采用create。
- 同一经历的进展、纠正、必要补充及有意义情绪变化采用update。
- 重复确认、重述和纯润色不提交对应节点操作。
- 画像、关系和节点分别决定是否变化；只有画像等更新时仍可提交changes和空node_changes，不错误提升为整窗no_change。

历史v27逐字保持，新候选采用独立版本身份；其余风格、schema、输入、身份与事务路径相同。工程测试只验证组合边界，不能证明模型必然遵守操作规则。

## 验证与采用

以独立合成连续链经过真实后台候选准备、生成、最多3次自动纠正、索引和事务，逐窗使用该分支真实前态。分别记录首次成功、自动纠正、最终失败，以及重复新建、无增量更新、实际更新遗漏、事件误合并和画像覆盖。不为成功补理想前态，不通过人工重新生成替代后台恢复。

允许少量语义概括损失和偶发冗余，但持续漏建、明显错误主体/完成状态、频繁错误事件合并与人工介入优先处理。采用应看总体现实收益，不为一个低影响瑕疵否决，也不以工程通过宣称质量通过。私人会话不参与规则、材料或参数设计；不按已见结果增加专用例外。
