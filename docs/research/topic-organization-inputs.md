# 主题组织的结构输入与独立评估

## 目标和边界

主题组织跨事件的持续关联，事件仍保持一次经历的粒度；主题数量和节点压缩率不作为质量目标。普通抽取和独立主题整理遵守同一成员合同，专门整理不修改事件、原子、画像或人格关系。优先使模型看见已经存在的层次关系，不提高整理频率、不扩大候选数量，也不增加摘要模型调用。

私人会话、人格和私人产物不用于本研究材料或规则设计。下面的固定图完全手写，仅用于隔离主题判断；它不能证明真实抽取能生成同样的图。

## 输入设计与成本

候选图已有 event→atomic 的 contains 时，应与可见 topic→member 关系一并输入；只暴露两个端点都在本批的边，不递归扩大事件子树。它帮助模型识别同一次经历的不同层次，但不证明事件正文完整覆盖原子，也不要求删除任何层次。

同一事件和其原子不能仅因 node_id 不同被当成两次独立经历。共享原始来源可以帮助解释层次，来源不同则不证明经历独立：当前来源摘录有数量与长度限额，而且一次经历可能跨多条消息。故不引入“来源ID必须互斥”的硬判断。未知的同一经历关系仍需根据正文判断，不制造全库的 occurrence_id 推断流程。

已有事件时间与来源发送时间职责分开。来源时间只锚定“当时说了什么”；节点中的计划日期不因较新的观察时间自动变成完成日期。沿用已有有界证据和身份输入，不为每个主题节点额外生成抽象事实表或重新抽取原文。

结构输入应属于固定请求快照、预算和版本依赖。事务提交需检测实际依赖的关系变化；旧已准备请求按原协议恢复，不把新字段缺失误判为旧任务损坏。关系补充无需新模型调用；数据库查询和序列化增加随可见候选边数增长，实际开销需记录，不能预先宣称为零。

`fixed_cases[].input` 的 `nodes/edges/evidence/related_topics` 可直接交给主题提示词构造器；顶层提供合成人格和身份集合。`review` 和 `chain_review` 仅供离线审阅，禁止发送给模型。运行前再冻结生产/候选代码摘要、实际系统提示词、配置、模型和调用上限。

| 固定图案例 | 要检验的行为 |
| --- | --- |
| sustained_association | 明确持续目标下的访谈与排练形成有用主题，同时保留独立事件 |
| same_occurrence_two_layers | 单次排练的 event + atomic 不构成两项独立经历 |
| irrelevant_member | 共同关键词和同一天不把私人出游纳入试点 |
| separate_similar_occurrences | 两次相似排练可归入共同主题，但不得混同成一次或推出无限频率结论 |
| member_only_update | 新成员不改变概况时仅改成员集合，保留正文等字段 |
| repeated_no_new_information | 已覆盖当前信息时无变化 |
| real_update_actor_and_time | 更新原主题，保留跨成员含义，区分用户交付完成、第三方未来测试和人格文字参与 |

固定图对照先比较相同规则下“可见topic边”与“完整可见层次边”，单独观察结构输入影响。没有层次边差异的案例提供兼容性而非改进证据。若同时修改提示词，必须另列条件；不能把不同条件混成同一次A/B结论。

顶层 `windows` 为4窗独立对话。实链从空库开始，分别使用自身真正提交的前序状态，不把固定图节点当成理想前态。抽取和低频主题整理按冻结计划执行并分别记录；普通抽取自行产生主题时照实统计。真实候选可见性、边、输入预算裁剪和失败任务均保存。

## 判据、边界与停止条件

逐项审阅所有返回成员与摘要：主题关联是否成立；是否保留不同经历；无关成员；同义主题重复；无新增意义的重写；主体、时间、计划/完成、范围限定；人格语气；实际调用与token。少量不改变事实的措辞瑕疵可接受，不要求完美逐字一致。成员增加而摘要无需变化的案例按明确合同核对精确保留，不把无意义改写算改进。

建议首轮两模型、两种结构输入、7固定案例，共28次初始生成；并发最多2。重试沿用固定策略但全轮HTTP调用最多40次，耗尽停止并保留失败，不手工补成功。四窗实链为独立后续验证；开始前单独冻结调度与预算，不在固定图结果不利时临时添加有利分支。出现新增主体翻转、错误完成状态或事件身份混同则保留失败，不凭主题数量增加决定采用。

若基线未出现错误，结果只说明兼容，不宣称修复；若输入补充未有净收益，不继续累加提示词来追逐此夹具。小图且候选完整的实验不覆盖真实向量候选召回、大库闭包、长期演变或多人泛化。最终实机完整数据只用于整体验收，不能反向改写这些独立材料或挑选成功结果。
