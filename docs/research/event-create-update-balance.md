# 新建与更新的平衡

## 目标与现有路径

目标是保持具体经历的身份、减少重复片段，同时不把不同场次压成一件事。节点数量不能单独作为优化指标：选择性记忆可以丢弃没有持续意义的内容，同一件事可以多次补充，不同事件即使相似也应独立保存。

当前后台抽取分两步：

1. `core/extraction_context.py` 从本批最多10条均匀取样的消息构造查询，复用向量并扫描本空间有效节点。默认最多给模型30个旧节点，其中10个近期节点优先；context.v2先纳入去重后的逐查询最佳代表，再从全空间语义排序补足；不按被动召回强度排除旧节点。
2. `core/persona_memory_prompt.py` 要求同一经历新进展更新原ID，另一时间相似经历新建，偏好变化优先更新同一原子。模型与本批节点、边、画像、关系一起输出决定，程序不会在提交后自动按相似度合并正文。

因此条目增多至少有四种不同成因：旧节点没有进入候选；候选已进入但同一性判断失误；一次互动被拆成多个粒度过细的事件；将原本可以不存的普通内容保留。不能只加一句“更多合并”，也不能将向量相似度直接当作同一事件证明。

默认候选数30不是只查最近30条，更不是只查当前窗口；提高候选数最多增加模型可见范围，不保证模型正确决定，并会增加上下文。全局最大相似度排序可能让单一高分话题占满语义名额，独立材料已复现候选遗漏和重复新建。当前context.v2以有界逐查询代表缓解，仍不能保证所有问题都相关或所有话题都被覆盖，采用依据见[ADR-0039](../adr/0039-query-balanced-extraction-context.md)。这不是私人样本全部碎片的根因证明。

## 建议的决策顺序

仍由现有后台抽取一次完成，不增加被动召回生成调用，也不新增事件本体或常驻合并模型：

1. 判断是否存在新的、有持续意义的信息。换一种说法、重复确认可以不操作；不是每个窗口必须产生新事件。
2. 对照候选寻找相同主体、具体对象及可连续的过程。补充原因、阶段进展、结果、纠正可以沿用原节点；不要求原文逐字声明“就是上次那件事”，也不因跨天就否定延续。
3. 同一经历在当前窗口的多个新细节合并成一次更新，正文重组并保留仍有效的时间、条件和情绪。不为每个细节额外新建事件，也不默认复制一份原子。
4. 不同场次、不同具体对象或实际再次发生的活动独立新建；不能把一天、一类活动或某个人的所有经历扩大成一个事件。主题只组织关联，不吞并独立经历。
5. 仅有相似语义、缺乏足够同一性依据时保持不确定，不硬选一个旧ID。来源或节点保护约束继续有效。

这套顺序表达的是原有身份合同，不等于强制新建/更新比例。相似度用于准备候选，不决定事实归属；重要性用于选择有价值内容，不用于强迫合并。

## 验证与采用门槛

冻结独立案例与判据后比较基线和候选，分别报告同一事件误新建、不同事件误合并、重复不操作、旧事实/情绪保留、人物与时序、结构通过及调用开销。固定候选探针与真实候选检索、短引用回译、事务提交分开解释。当前有限对照见[新建与更新评估](../evaluations/event-balance-20261117.md)。

若候选准备确实漏掉目标，再比较逐查询有界候选合并与当前全局最大排序，沿用现有消息向量，不额外调用生成模型。分配名额不能被证明只是在提高噪声或挤掉近期必要节点；不先扩大整体上下文再观察运气。

提示词候选须在多候选干扰、更多模型及连续窗口下同时降低重复与误合并，再考虑替换默认。已有碎片的人工治理与自动抽取是不同任务，不能以新规则为由未经请求全库自动合并。私人单会话只用于受限评估，不用于产生例外、专用夹具或调参。
