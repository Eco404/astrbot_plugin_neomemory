# 正式版模型协议 v1

NeoMemory 使用 AstrBot 的 Provider 调用模型。抽取输入由程序冻结，模型返回结构化候选，程序校验并事务提交。格式、引用和范围通过后仍需按来源评估内容质量。

| 链路 | 协议 | 职责 |
| --- | --- | --- |
| 长期窗口 | `extraction-prompt.v1`、`extraction.v1` | 一次提出原子、事件、关联、画像和私聊人格关系变化 |
| 已有记忆候选及引用 | `extraction-context.v1`、`reference.v1` | 为多话题窗口提供有限候选，映射窗口内短引用 |
| 主题整理 | `topic-prompt.v1`、`topic-consolidation.v1` | 基于有效原子、事件、完整主题成员和有限来源证据维护主题 |
| 短期摘要 | `short-term.v1` | 为指定人格和具体会话滚动更新摘要 |
| 候选纠正 | `candidate-regeneration.v1`、`topic-regeneration.v1`、`short-term-regeneration.v1` | 依据同一固定输入与目标 schema 反馈错误并重新生成 |

## 输入与引用

每条消息附发言者、来源和观察时间。群聊的发言者与被提及成员使用同一套身份依据。转发者及其附言与转发内容的原作者分别呈现。人格约束只影响记忆的取舍和叙述。观察时间、事件发生时间和从来源知道的相对时间分别处理。

请求使用窗口内的短引用。程序将模型返回的引用还原为固定输入中的用户、来源和已有节点，并验证归属及版本。用户昵称在展示和注入时渲染，明确约定的称呼可以保留原文。

## 长期候选

- 整个窗口允许返回 `no_change`。模型按对话中的持久价值选择独立事实、同一经历或跨事件主题。更新已有节点须依据确定的身份和版本，并生成可独立理解的完整正文。
- 每项变化使用本批实际来源。新节点吸收既有内容时声明 `base_node_ids`，程序保存对应版本。原文、同窗上下文、继承基线及累计来源在版本查阅中分别呈现。
- 长期正文用人格视角直接描述经历。属于用户、第三方或转发作者的动作保持实际主体。情绪可为空，非空时各标签独立保存强度。已保护或失效的节点按治理规则限制自动修改。
- 画像针对逻辑用户保存当前、可复用的特征，并保留条件和后续修正。人格关系表达私聊人格对对方的感受，长期理解与近期余韵分别使用 `keep`、`replace`、`clear`；替换提供完整正文，其余两种操作使用空正文。新生成的两段分别最多 500 和 150 个可读字符。
- 标题最多 60 个可读字符。原子、事件、主题正文分别最多 800、3000、2000 个可读字符。合法完整的用户引用按一个可读字符计，额外的编码容量限制独立检查。短期摘要在窗口短代号仍未还原时计量。

## 调用、校验与恢复

抽取默认使用 JSON Schema。宿主 Provider 或上游模型不支持该模式时，支持的回退路径会使用同一模型和提示生成文本，再按相同格式与语义规则校验。调用期限、输入预算和模型设置在准备窗口时确定。

程序核对 JSON、字段、数量和长度、枚举、引用、版本、来源与提交时状态。首次请求与候选纠正按同一标准生成约束和反馈。可纠正的失败默认在首次生成之外最多自动尝试 3 次，并共享该窗口剩余期限。失败任务保留候选、据以生成的输入和错误详情，操作方法见[维护指南](维护与故障处理.md)。

主题按独立任务维护成员与版本依据。短期摘要按会话推进。按板块重构画像和关系时，同一窗口内合并所选内容调用，主题可独立并行。来源顺序、水位与每个分支的提交凭据由程序维护。
