# ADR-0001：使用人格、逻辑用户和场景作用域隔离记忆

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 3](../开发计划.md#3-身份与记忆空间)

## 背景

同一个人可能通过多个平台账户与 Agent 交互。同一人格在不同用户、群组和平台实例中也可能拥有不同的关系和经历。若直接使用平台账户或会话 ID 作为长期记忆主键，会造成跨账户记忆割裂，或者把一个群的内容泄漏到另一个场景。

## 决策

1. 长期记忆、画像和人格关系的基本归属使用 `persona_id × logical_user_id`。
2. `logical_user_id` 由明确的账户绑定得到。系统不根据昵称、头像、文本相似度或模型猜测自动合并账户。
3. 群聊长期记忆使用 `persona_id × platform_instance_id × group_id`。
4. 群成员画像使用群作用域再加 `logical_user_id`，只保存轻量标签和短描述。
5. 短期补偿额外绑定 `conversation_id`，不把会话 ID 当作长期记忆唯一归属。
6. 原始记录保留平台账户、平台实例、会话、群参与者和人格解析结果；派生节点通过引用关联这些身份。
7. 跨空间读取必须显式配置，并在召回结果中保留来源空间。跨空间内容不能被重新表述为当前空间发生的事实。

## 后果

- 用户可以把同一人的多个社交账户绑定到统一的逻辑用户，长期记忆和画像能够连续。
- 绑定错误会影响多个账户，故账户绑定必须可查看、修改和审计。
- 群聊需要同时维护群空间和成员身份，但能避免不同群之间的记忆污染。
- 人格切换会产生不同的人格视角；不能用全局用户画像直接替代人格相关的关系状态。

## 实现约束

- 所有写入和召回入口在进入业务逻辑前必须解析出 `memory_space_id`。
- 数据库外键和服务层校验都要阻止跨空间写入。
- 未解析出逻辑用户时，可以保存原始记录，但不能静默写入私聊长期记忆；应进入待处理状态。
