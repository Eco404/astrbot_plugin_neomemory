# ADR-0018：保守处理事件对原子的覆盖（提案）

- 状态：Proposed；不替代当前Accepted ADR-0013，不改变生产默认
- 日期：2026-11-02
- 关联：ADR-0005、ADR-0013、ADR-0014；[本轮计划](../覆盖与输入完整性轮次实施计划.md)

## 背景

ADR-0013要求full同时绑定事件与原子的正文版本，并由模型声明语义完整。1A独立合成评估已出现：版本正确，但必要条件被事件改写为本次安排，原子在最终上下文中被省略。版本校验只能保证声明指向确定的正文，不能证明事件独立表达了原子的全部必要信息。

本提案讨论跨节点省略；不改变存储层覆盖记录、选择性抽取、节点级衰减或事件正文可以保留失活细节的既定语义。

## 候选与决策依据

| 选项 | 行为 | 代价与边界 |
| --- | --- | --- |
| 现有策略 | 版本匹配的full允许事件替代原子，并按现有算法提升已匹配事件 | 节省重复文本，但模型误报full可以隐藏必要信息 |
| 保留双方 | 选块时不使用跨节点覆盖省略，节点仍按既有排序和完整文本预算选择 | 不再因full声明本身丢原子；重复文本、节点数量和预算竞争增加，并不保证原子一定入选 |
| full加字面包含 | 只有full且原子全文逐字出现在事件中才允许替代 | 可挡住部分改写，但引用、否定或主语变化仍会改变含义；不构成可靠语义证明 |

建议优先评估“保留双方”作为默认修正的候选，并保留当前策略的对照证据。是否采纳应依据[覆盖研究](../覆盖保守处理研究.md)中默认/受限预算的事实保留与挤出代价确定。实验不等于生产实施，也不因为一个候选减少错误省略就认定整体召回更好。

## 如果采用的实施边界

1. 继续持久化和展示原有full/partial声明及两端版本，不重写历史数据或迁移数据库。
2. 仅改变召回组装时对该声明的信任：关闭coverage驱动的原子省略、事件提升和替换。不增加被动LLM调用，不重新生成事件正文。
3. 状态、作用域、版本复核、节点数和总预算限制仍生效；主动工具与被动召回共用规则时一并回归。
4. 不能为了容纳重复文本偷偷增加默认预算。若后续需要预算或排序调优，应单独报告上下文开销及事实保留代价。
5. 仍可对同一个node_id去重；这不同于判断两个节点是否语义等价。
6. 不基于逐字包含、相似度、共同来源或contains边自动认定语义等价。更强覆盖证据需独立设计和验证。

## 尚待确定

是否接受更多重复内容和预算竞争，将“保留双方”用于生产默认；或暂保留现状，继续研究可审计的覆盖证明。采用时应更新本ADR状态、注明对ADR-0013第8项的替代范围，并同步用户说明。当前仅交付离线证据和具体方案。
