# ADR-0026：正文版本、直接引文与更新基线分别记录

- 状态：Accepted
- 日期：2026-11-11
- 补充：ADR-0003、ADR-0008、ADR-0012、ADR-0023

## 决策

节点、用户画像、人格关系保留已经存在的正文版本，并记录每次提交的直接引文和更新基线。来源记录用于追溯一次生成或人工治理操作，不能替代事实支持程度的语义验证。

节点沿用 `memory_node_versions`；画像和人格关系使用独立版本表保存标签、正文或情绪结构。当前态表继续服务查询和抽取。版本号仍遵循既有写入口的版本判断：自动抽取以正文或结构变化推进，画像/关系的公共 CRUD 同时保留其状态变化版本行为。

每次派生操作引用一个确切的目标版本，保存操作类型、编辑方式、批次或治理凭据、更新基线版本引用和直接来源 ID。直接来源来自已经通过校验的本批 `source_ids`，或人工拆分时明确选择的来源，不复制原文。自动抽取正文不变但提供新引文时，追加 `confirm` 操作，不制造新的正文版本。幂等重试沿用已经提交的凭据，不追加操作。

更新基线说明生成时继承的同一实体旧版本。人工拆分指向被拆版本，人工合并指向所选旧版本。目标正文未变时不建立指向目标自身同版本的基线，避免形成自环。人工编辑或合并没有显式选择原始引文时，仅保存旧版本引用和人工操作，不把历史累计来源冒充本次直接引文。

`node_sources` 继续表示节点累计关联来源。新增或移除累计关联不会追溯修改已经保存的直接引文。WebUI 应区分“本次直接引用”“更新基线”“累计关联来源”；`recorded` 仅表示存在操作记录，不表示自然语言中的每项事实均已验证。

派生记录与正文、画像、关系和完成凭据在同一个 `memory.db` 事务中提交。事务内没有来源库、网络或模型访问。重构继续从原始库在新 generation 中构建，生成新身份和来源链，不迁移旧治理结果；不新增单独的重构抽取路径。

## 迁移与边界

memory.db v9 只为旧画像/关系保存实际仍存在的当前版本，不创造已经丢失的早期正文。旧节点版本继续保留。没有逐次派生记录的版本显示 `unrecorded`，不按时间、相似度或整个窗口来源推测引文。

直接引文不是整段完整正文的独立充分证据。画像更新可能继承旧爱好而只修正一项新偏好，因此应结合旧版本查阅。现有输出协议没有声明新节点对其他 `known_nodes` 的精确推导依赖，本机制不猜测这种关系，也不提供逐句引用或自动事实证明。

原始记录以后被清理时，来源 ID 与版本仍可保留，但原文可能不可读取。版本来源不是可清空缓存；它不改变当前原始库清理策略。

本决策不改提示词或抽取 schema，不增加模型调用，不把历史正文重新放入被动召回，不改变宿主输入截断问题的处理状态。

## 参考与验证依据

- Graphiti，`5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`，Apache-2.0：[`EntityEdge`](https://github.com/getzep/graphiti/blob/5c27edfa8d3e0f49b2571bcebb4261bcc89ee037/graphiti_core/edges.py#L263) 将 episode 引用与事实有效时间分开。其 episode 集合不能直接代替本插件正文版本的逐次引文。
- Mem0，`26cdefb46600c0fa5953c4b5ee5003c125539fc4`，Apache-2.0：[`add_history`](https://github.com/mem0ai/mem0/blob/26cdefb46600c0fa5953c4b5ee5003c125539fc4/mem0/memory/storage.py#L150) 保存修改前后正文、操作与角色。借鉴独立历史记录，不复制其缺少逐条来源引用的表结构。
- 两者均为本地固定参考版本，不据此宣称最新维护状态；未复制第三方代码或增加依赖。

工程验证使用独立合成输入，覆盖连续更新、同正文新引文、失败回滚、幂等、人工拆合、迁移未知来源、公共写入口和重构中断恢复。实际模型引用是否充分仍需独立审阅，不能以数据库外键或测试通过代替。
