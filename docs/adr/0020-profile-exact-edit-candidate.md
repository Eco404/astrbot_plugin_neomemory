# ADR-0020：画像采用精确片段更新的协议候选

- 状态：Proposed；尚未接入生产或通过真实模型评估
- 日期：2026-11-02
- 关联：ADR-0003、ADR-0004、ADR-0011、ADR-0012

## 背景与目标

现有画像保存tags和一段description，模型每次提交完整新正文。合成对照显示，修正一个属性时可能遗漏未被修正的旧限定。希望由程序保留未涉及的文字，而不是每次要求模型完整重写。相关实现和差异见[画像方案研究](../画像轻量更新方案研究.md)。

本提案只处理画像变更的表达和应用，不解决模型漏选画像、选择了错误修改范围、片段内部遗漏或事实不真实。当前轻量存储、选择性记忆和群成员资源边界保持。

## 建议候选

在下一次独立版本化协议实验中，让模型在原有抽取调用内产生画像创建、追加和精确旧片段替换操作；程序对准备快照执行操作，形成最终tags+description。画像数据库无需拆成事实表；版本、来源、作用域、提交凭据和事务边界继续由程序控制。

精确替换必须提供原文中唯一匹配的非空旧片段。零匹配、多匹配、版本不符或冲突操作拒绝，不做模糊搜索或选“最像”的片段。新增画像与无修改仍是合法路径，不要求每窗或每个节点都有画像。

## 必须保持的约束

1. 操作统一定位准备时的旧正文；同批多个替换的范围不能重叠，先验证全部再一次应用，不能依赖模型猜测逐步变更后的中间文本。
2. 未被定位的原文由程序逐字保留。追加不删除旧文字；删除必须显式给出非空旧片段和空new_text，字段缺席不能视作删除。
3. 标签采用精确增删或带旧值约束的操作，去重与长度限制由程序检查；不因正文变化自动删除未提及标签。
4. 最终正文/标签超限即拒绝，不静默截断或自动另调LLM压缩。片段删除或压缩仍需明确证据与评估，不等于允许全量保留。
5. 任一操作无效时，整个抽取候选按原有事务规则失败，不部分消费来源或只提交其中一个画像。
6. 旧schema和已完成凭据保持可读；新协议进入准备/输入摘要、提示词版本和任务签名。保留画像状态拒写及人工修改后的快照失效；画像当前没有节点的manual_protected字段，本候选不暗中增加永久画像锁定。
7. 仍是一轮模型调用，不在每轮被动召回做生成，也不把更新冲突改为无限自动修复循环。

## 验证与取舍

先验证确定性保障，再冻结独立材料对比当前整段替换：新建、无修改、只修一个属性、跨句限定、重复旧片段、同时更新正文和标签、群聊与多人、超长及恢复。比较操作合法率、未修改文本保留、片段内部事实完整、画像选择、输出长度和调用开销。

精确片段会增加协议复杂度，也可能增加因模型定位不准而失败的窗口；它只把一部分全文重写风险换成可检查的定位风险。可先推进隔离候选，不需要提前决定默认；实验通过前不能升级默认。正式采用时，应对比局部修改收益与定位失败/超长造成的维护频率，另一选择是继续保留整段替换。

本轮仅提出候选，默认extraction.v2与v3提示词均不变。不会以测试中机械保留旧字符的成功宣称用户画像问题已经解决。
