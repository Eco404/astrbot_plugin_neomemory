# ADR-0013：事件覆盖显式声明，并绑定两端正文版本

- 状态：Accepted（ADR-0003 与 ADR-0012 的阶段四实现细则）
- 日期：2026-10-29
- 补充：ADR-0003、ADR-0007、ADR-0011、ADR-0012

## 背景

事件正文和原子正文可以同时参与召回。若事件已经完整表达某个原子，重复注入会占用预算；但结构 contains 只说明关联，不能证明事件包含原子的时间、条件、否定等全部必要信息。原有覆盖记录只绑定原子版本，无法独立证明所对应的事件正文仍然相同。阶段三因此没有让模型自动写入覆盖。

## 决策

1. 新增 `extraction.v2`，增加必填 `coverage_changes` 列表。每项使用 `event_ref`、`atomic_ref`、`expected_event_version`、`expected_atomic_version`、`coverage_kind` 和本批 `source_ids`。模型提供语义声明，程序负责引用、作用域和版本检查。
2. v1 字段和解析语义保持不变，不接受覆盖字段也不推断覆盖。解析器只接受明确支持的 v1/v2；提示词默认升级为 `extraction-prompt.v2`，构建器允许显式选择 v1 以回放旧协议。新提示词版本进入新批次输入摘要，旧完成凭据不改写。
3. 覆盖字段的版本表示**本批提交后的最终正文版本**：新增为 1；更新且正文改变时旧版本 + 1；同正文和未更新节点保持版本。节点变化项原有 `expected_version` 仍表示提交前版本，提示词分别说明。应用层在任何节点写入前计算并验证所有覆盖端点的最终版本。
4. 只有事件最终正文完整表达原子必要事实、主体、时间、条件、否定与不确定性时才允许 `full`；`partial` 表示部分表达。无法确认时留空，不能从 contains、相似度或共同来源猜测 full。覆盖不向主题或其他祖先传递。
5. 两端必须是同空间、同 generation 的 event/atomic，来自可信输入或本批创建；已有端点必须保持快照一致且允许自动修改。人工保护或非 active 节点不允许自动追加覆盖。来源必须属于固定窗口，重复解析别名指向同一对节点也拒绝。
6. 覆盖与节点、关系、画像、完成凭据和活动轮次在同一数据库事务中提交。coverage-only 是合法 changes；no_change 必须保持覆盖列表为空。版本错误不自动纠正，任何失败均不推进轮次或消费来源。
7. `node_coverage` 增加 `event_content_version`。原有记录迁移为 0，作为不能用于去重的旧覆盖；不凭当前事件版本补填旧声明。事件正文变化清除旧覆盖，原子正文变化通过版本不匹配失效。明确重报可以 upsert 当前两端版本与 full/partial 类型。
8. 只有事件和原子都通过可召回状态检查、实际处于最终候选中、覆盖为 full 且两端版本各自匹配时，才能省略重复原子正文。partial 和失效覆盖都保留独立原子。最终注入仍要在预算内选择完整文本，不因为 coverage 自动展开整棵节点图。

## 后果与边界

- 不增加被动召回的 LLM 调用，语义判断与正文生成共同发生在抽取阶段。
- 版本校验保证声明对应明确的正文，但不能证明模型语义正确；真实回放与人工抽查需要覆盖条件遗漏、否定反转、模糊时间和不确定性等情况。没有可靠覆盖时允许少量重复。
- 手动修改、事件延续和原子更新不会继续利用过期覆盖隐藏新内容。
- 这是一项注入去重规则，不是事实级遗忘。用户已接受节点级衰减：原子失活后，事件正文可能仍然表达该细节。
- 来源字段用于本批证据校验，完成批次保留来源范围；覆盖表引用两个节点及版本，不复制节点正文或来源原文。完整候选审计与人工覆盖治理随维护阶段推进。
