# ADR-0053：人格关系使用长期理解与近期余韵

状态：采用，按用户明确要求进行实机试用。

## 决策

人格关系保持人格第一人称的自主心理表达，分为long_term（长期理解）与aftereffect（近期余韵）。两段独立keep、replace或clear，普通抽取仍与节点和画像合并调用，不增加关系专用LLM请求。不要求逐项心理清单、最低字数或积极结论；主观判断可以坚定、负面或存在误解，但不改变实际行动者，不将人格感受当作用户已承诺的事实。

参考LivingMemory提交1198a12的双段、独立更新和原互动时间设计。该仓库为AGPL-3.0；NeoMemory独立实现状态与提示词，仅借鉴设计，不复制其代码或提示词。既有小样本实验没有证明双段普遍更好；本决策来自用户试用要求，不将它改写成已验证的质量优势。

extraction.v8 / extraction-prompt.v34的关系变化包含logical_user_id、expected_version、共享source_ids及两段op/body。来源只填写一次，避免要求模型重复抄写；replace段取这组引用的最新原始观察时间，共享来源不代表逐句时间归因。keep、读取、双keep不续期；clear只清空该段，允许两段都为空。相同文字显式replace仍代表本次互动重新形成该状态，绑定新来源；模型没有实质变化时应keep或整体null。

近期余韵默认从原互动时间起86400秒后停止注入，期限可在WebUI配置，0表示不自动到期。到期不删除正文/版本、不影响长期理解、不证明感受消失或双方和解。未知观察时间不凭写入时间推断到期。重构使用原观察时间，因此历史样本的余韵可能构建完成时已不注入，但WebUI仍可查看。

长期理解上限1600、近期余韵上限600可读字符，分别计量，不要求填满。关系注入单条上限默认2400字符，整个请求仍受已有共享字节预算约束；两段完整、独立选入，不截断正文。真实长度对照仅支持实际测试范围，不宣称这些上限是普遍最优。

## 存储与兼容

relationship_states.state_json和版本快照保存format=relationship.slots.v1及两个{body,observed_at}；state_text保留可搜索拼接，不作为第二份独立语义来源。旧单段兼容为长期理解，余韵为空，无法确定的观察时间保持未知。无需新增关系表或单独缓存。

旧抽取协议继续按固定版本读取/重放，新默认不能接受旧schema冒充新结果。昵称呈现及短引用协议覆盖两段body；WebUI列表和历史按两段展示。完整重构成功后清理旧代派生内容，新实体版本从v1开始；原始会话和人格保留。

相关采用背景见[简约内心表达](0049-relationship-inner-voice.md)。本决策明确新存储及输出结构，不撤销人格自主表达、事实归属和不针对私人样本调优的要求。
