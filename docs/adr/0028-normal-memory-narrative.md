# ADR-0028：记忆正文使用正常叙述，元信息承担记忆管理语义

状态：Accepted。生产使用 `extraction-prompt.v16` / `extraction.v5`，统一采用正常叙述、身份占位符和明确约定称呼保留规则；v16 补充人格显示名不得作为普通叙述主语，并要求已有节点只作为事实基线，不作为文风示例。

## 决策

长期节点、画像和召回文本不加入“我记得”“我提过”“我们之前说过”“我知道”等记忆管理话语。正文直接表达事实、经历、资料或人格关系状态。

元信息和来源链承担以下职责：

- 节点类型、空间、人格、逻辑用户、generation、版本和状态；
- 事件时间、重要性、记忆强度和人工治理状态；
- 来源消息、派生操作、继承版本、直接来源和上下文来源；
- 画像/关系的作用域以及召回时的渲染和预算处理。

正文仍必须在单独注入时能够读懂，不能依赖未注入的元信息来猜测主体或状态。正文应保留必要的主体、当前状态、条件、否定和不确定性，但不重复描述“这是一条记忆”或“来源于某次聊天”。

叙述规则如下：

- 用户的动作、经历和偏好使用逻辑用户占位符或当前上下文明确的简洁主体；用户原文中的“我”不自动变成人格的“我”。
- 人格确实做过或说过的事情使用“我”。人格关系的 `state_text` 继续使用人格第一人称表达主观感受、期待和犹豫。
- 未映射的第三方保留独立称谓，不绑定到逻辑用户。
- 画像可以利用当前页面已经提供的用户作用域省略重复主体，但不能写成人格资料。
- 明确约定的昵称、专属称呼和引用原话按原文保留；正常身份指代使用占位符并由程序渲染昵称。
- “可能”“暂时”“计划”“尚未完成”“后来改为”等有事实意义的限定必须保留，不能当作叙述包装删除。

同一事件发生更新时，正文必须清理已被新来源替代的当前状态。仍有记忆价值的旧状态写成明确的变化历程，不能将冲突的新旧状态并列为两个当前事实。建议、询问、接受和完成保持区分；沉默、追问或人格自己的期待不能证明对方已经接受或执行。

## 影响

这种正文可以直接用于向量化和召回，减少无信息的模板词，并使注入内容更像正常记忆。来源和版本仍可在管理页、调试信息和审计记录中查阅，不需要塞进正文。

自动抽取、新建抽取任务和重构统一使用当前生产提示词，旧模板只用于显式历史回放和隔离对照，不作为生产默认或回退。提示词版本参与任务签名，旧未提交候选需重新准备；已提交正文通过正常更新、人工治理或显式重构改变，不自动改写。

质量验收持续检查独立合成输入的主体、状态、限定、引用充分性、文本风格和召回；采用当前提示词不代表未覆盖的语义质量已经通过。

## 不采用的做法

- 不用正则批量删除现有正文中的“我记得”等词；这些词可能位于引用原话或真实事实中，盲删会破坏语义。
- 不把来源 ID、版本号和“记忆类型”等审计信息写进长期正文。
- 不因为正文不再出现第一人称记忆动词，就删除人格关系的第一人称主观表达。
- 不把元信息存在当成正文可以省略主体、状态或限定的理由。

## 验收边界

候选评估必须分别报告：非必要记忆管理话语比例、主体正确率、事件状态正确率、条件/否定/不确定性保留率、直接来源充分率、召回相关性、注入预算和模型成本。合法 JSON、有效来源 ID或元信息字段存在不能单独证明正文语义正确。
