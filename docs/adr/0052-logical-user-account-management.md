# ADR-0052 逻辑用户命名与账号归属管理

状态：接受。

## 决定

平台通用账号使用该平台的身份范围与账号 ID 识别，多个机器人入口可以对应同一社交账号。实例或应用专属的账号标识按其已知范围识别。一个社交账号只归属一个逻辑用户，一个逻辑用户可关联多个社交账号。首次从另一个实例出现时沿用该账号当前归属，包括人工设置的归属。逻辑用户名称可人工修改，人工名称优先于平台昵称，后续采集不覆盖人工名称。

账号变更在维护页先展示预览，再二次确认；确认内容包括新旧归属、原用户是否删除及私聊数据删除数量。规则如下：

| 操作 | 原归属与记忆处理 |
| --- | --- |
| 将尚无归属的账号加入A | 建立账号到A的唯一关联 |
| 将B唯一账号b加入A | 删除B跨人格的私聊空间与派生记忆、版本、画像、关系、短期摘要、笔记、任务及向量，再将b绑定A，并删除B的可管理身份 |
| 将多账号B中的b加入A | 仅将b的归属转为A，B及其既有共享记忆保留 |
| 从A移除b | A须至少关联两个账号；b获得新的独立逻辑用户，A既有记忆保留，不重构、不迁移 |

以上账号数按不同社交账号计数，归属操作覆盖该社交账号在原归属下的全部入口。升级遇到已有多个归属时，旧入口继续沿用各自身份，由管理员预览涉及的用户、人格空间与内容，再显式确认转移。

共享群聊空间不属于某个账号的私聊记忆，账号转移不删除群聊共享记忆。旧原始记录保持采集时的身份，不改写成新的归属，也不将旧记忆合并到目标用户。移除账号后重新加入原用户，同样执行上述添加规则。

## 持久化与恢复

source.db v2增加人工命名来源和身份操作回执。被删除的B使用`deleted`身份墓碑保留原始记录外键，常规用户列表不再显示；原始记录不删除。私聊空间发现及回放排除已删除身份，memory.db中的持久停用标记阻止在途旧发现结果重新创建B的空间。

账号操作使用全局互斥后台任务，与重构、抽取、治理等任务互斥。提交检查确认预览，执行时再次检查归属与待删除数量；名称变化不影响已提交任务的归属判断。

原始库与派生库不是一个原子提交。清理派生记忆时在同一事务保存检查点，之后提交账号映射和来源库回执；中断后从检查点继续，已经提交的账号变更不重复执行。失败时应查看任务并从断点恢复；已完成的删除不会因后续失败或取消自动还原。删除任务后清理其来源库恢复回执，身份停用标记不作为临时缓存清理。

近期补充查询按采集身份过滤；在途召回在返回前复核账号归属。新采集的用户消息使用新绑定；Agent回复仍按原触发消息确定归属，不把旧轮次回复挪入新用户。

## 接口

用户管理的四个接口均要求所选空间的 `space_id`。私聊可管理该空间的逻辑用户，群聊可管理该人格在该群记录的发言者。`GET identities` 在该范围内搜索和分页。`POST identities/rename` 更新所选用户的全局名称。

允许手工指定其他空间账号的平台实例和账号 ID。`POST identities/preview` 展示账号原归属、目标用户、原用户在各人格下的私聊空间以及删除或保留的范围。`POST identities/apply` 按原空间中的确认令牌和幂等标识提交。切换空间后需重新预览。
