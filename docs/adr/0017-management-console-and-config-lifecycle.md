# ADR-0017：管理界面写入与配置生效边界

- 状态：Partially superseded；配置保存后重载的生命周期决策由 [ADR-0022](0022-live-settings.md) 替代，其余管理界面与任务决策仍有效
- 日期：2026-10-29
- 补充：ADR-0007、0008、0010、0015

## 决策

1. 页面按记忆、笔记、模型、设置、维护组织，拆为本地原生ES模块，复用AstrBot视图桥和相对静态资源。记忆查阅使用当前代一致快照，文本过滤先于分页；原文读取必须验证空间归属。
2. WebUI人工笔记变更使用持久note任务、同空间互斥及乐观更新时间检查；写入和receipt同事务。笔记继续独立于记忆代，重构不清除笔记。Agent即时工具保留返回语义，但在写事务内检查相同作用域的任务锁。
3. 模型探针是持久model_test任务，作用域独立于用户记忆，同一Provider测试互斥；生成与向量请求使用宿主适配层及共用并发。自动最多尝试一次，人工可重试。仅保存安全连通性统计，不保存模型输出、不修改记忆或活动轮次。
4. 插件保存宿主提供的配置对象，设置接口使用公开持久化方法。编辑携带revision，严格拒绝未知字段、类型、范围与非法门限关系，不静默纠正用户输入。保留宿主其他字段，不复制Provider凭据。
5. 已保存配置与运行配置分开显示。设置保存后需从AstrBot重载插件，当前任务继续使用启动时的不可变配置；不在处理Web请求时重启自身、不在任务中途修改并发器/模型/门限。功能关闭时设置仍可访问，方便重新启用。
6. 短期允许单独选择LLM，空Provider ID继承长期默认。仍使用同一适配层并发和超时规则，恢复摘要包含实际选择模型的指纹。

## 同阶段实施补充

- 配置服务记录宿主配置文件的磁盘指纹，检测到其他配置对象改写时返回 `external_change=true`、`can_save=false` 和 `reload_required=true`，拒绝陈旧保存。需要从宿主重载配置对象，单纯刷新插件页面不能消除外部变更。插件停止前等待已接纳的持久化完成，避免重载实例读到保存前的值。
- 正在运行的模型测试持有启动时的适配器、任务库及不可变配置，关闭时解除插件公共引用不会把成功调用误报为Provider失败。新任务接纳与重试仍检查插件可用性；模型指纹在请求前后重新读取。已保存结果的检查点可直接恢复，模型请求完成而检查点尚未落盘的崩溃窗口仍可能重复请求。
- 旧 `models/test` 路径与 `models/probe` 使用同一后台协议，必须携带幂等键，返回任务引用；不继续提供阻塞式同步探针。人工笔记失败可审查候选正文，但不得通过“重新准备”绕过陈旧版本，需刷新后重新编辑。
- 原文查看按捕获时空间验证，不依赖当前代中的抽取引用，保证失败或尚未消费的窗口仍可审查。正文只在显式请求时传输。

## 取舍和边界

增加笔记receipt表和少量管理接口，避免前端绕过原有事务治理。浏览器只负责提交与展示，关闭页面不会拥有或终止任务。

重载生效比即时动态切换更容易保证断点恢复和模型一致性；页面须明确提示保存尚未生效。配置revision防止本页面的陈旧覆盖，宿主其他配置入口有独立保存机制，应检测可见外部变化，但不声称跨进程配置编辑具备数据库式串行事务。

可视化治理最终仍生成原服务支持的带版本操作，不放宽来源、跨代、人工保护和关系约束。既有默认人格跳过、顺序失败保障和墓碑删除语义不变。
