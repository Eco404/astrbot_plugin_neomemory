# ADR-0009：群聊旁听采用低资源、低结构复杂度策略

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 10](../开发计划.md#10-群聊旁听)

## 背景

群聊中大量消息不会触发 Agent 回复，但旁听对理解群体事件和成员画像有价值。若按私聊频率和结构抽取，会增加模型和向量成本，也会放大群聊噪声。

## 决策

1. 旁听消息仍进入 `source.db`，但以低频批次提交后台整理，不逐条生成向量或长期节点。
2. 默认阈值为 `group_a=40`、`group_b=100`、`group_c=200`，空闲时间为 1800 秒；这些值只是调优起点。
3. 普通旁听只保留重要群事件、简短主题概述和成员画像变化；直接与 Agent 交互的群消息可以进入更细致的处理队列。
4. 群成员画像最多 12 个标签，描述最多 300 个中文字符；不启用私聊人格主观关系。
5. 第一版记录能到达插件处理阶段的旁听消息，不承诺覆盖宿主过滤或预处理前被丢弃的消息。

## 后果

- 群聊能够提供背景记忆，同时控制 LLM、Embedding 和数据库写入成本。
- 群成员画像信息密度较低，不适合替代私聊画像。
- 批次和空闲策略可能延迟群聊记忆可用时间，后续应依据真实群聊回放调优。
- 群聊中的隐私、成员撤回和原始记录清理需要与总体数据生命周期策略一起处理。

## 实现约束

- 群聊批次不能混入其他群或私聊空间。
- 低资源策略只能减少派生计算，不能改变原始记录的来源和参与者信息。
- 成员标签必须来自可追溯消息，模型推测不得直接成为稳定事实。
