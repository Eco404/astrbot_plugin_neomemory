# ADR-0032：可读长度与编码容量分离

- 状态：Accepted
- 决策依据：用户同意通用长度优化方案并授权执行；私人会话只作评估，不用于制定阈值。

## 决策

抽取 `extraction.v6` 对正文、画像、标签、人格关系、标题、情绪描述和事件时间说明采用可读字符计量。一个语法合法且完整的 `{{user:ID}}` 引用计一个字符；其他Unicode字符逐个计数，不按UTF-8字节计数。ID最长200字符；语法校验不代替作用域与身份归属校验。

上限保持 atomic 800、event 3000、topic 2000、画像600、标签24、关系1000、标题60、情绪160、时间说明120；群画像描述240。字段编码容量单独限定为可读上限×209，完整候选仍受120000编码字符总上限约束。字段可读长度不受稳定ID长短影响，但极端输入仍可能触及独立整体容量限制。

新协议提供 `x-readable-maxLength` 元信息，节点正文另提供分类型可读上限。程序继续负责这些JSON Schema扩展无法自行保证的语义；不把Provider支持原生schema当成替代校验的理由。

存储与人工治理复用相同计量方式，维持各自既有内容上限，不将抽取节点粒度上限额外施加到人工内容。无需数据库迁移，不修改已有正文及版本。

## 兼容与恢复

v1–v5保留旧协议规则；新请求不允许静默返回旧schema。固定窗口、提示词版本及候选仍用于重建原请求；历史模板不重标为新模板。显式历史回放按原协议解释；升级后的任务签名不匹配时停止并要求重新准备，保留已提交工作与拒绝候选，不能把旧候选改标为新协议。

纠错反馈 `candidate-regeneration.v3` 从候选声明的schema提取字段路径、枚举、格式、数量及长度限制，最多反馈12项；既有v1/v2恢复请求保持原格式。失败候选不原地修改，重新生成仍是显式维护操作。整体编码容量拒绝单独记录raw或canonical阶段、实际字符数与上限，不误报来源或上下文错误。

## 验证与边界

独立验证应覆盖短引用与200字符ID的相同可读边界、解码与持久化、群画像、治理编辑/拆合、旧协议及固定候选恢复。总输出容量、单字段可读上限、最终昵称渲染字节预算分别测试。

本决策不增加每轮被动LLM调用、不增加自动纠正循环、不改变长文本整项注入策略。真实模型纠正探针只证明指定合成错误可纠正，不代表自然错误率或无人值守成功率。
