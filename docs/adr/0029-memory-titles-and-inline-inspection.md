# ADR-0029：记忆标题与条目内版本来源查阅

- 状态：Accepted（标题/UI已工程接入；独立模型样例已审阅，扩大语义覆盖与实机部署仍待验收）
- 范围：长期节点展示字段与记忆页面查阅交互。
- 相关：[节点模型](0003-memory-node-model.md)、[版本来源](0026-version-provenance.md)、[正常叙述](0028-normal-memory-narrative.md)。

## 需求边界

长期记忆节点增加持久 `title` 字段，帮助浏览原子、事件和主题。版本、来源及点击后的原文直接在当前条目内展开；查看继承基线仍留在当前条目的查阅区域，不跳到列表底部。

范围为长期节点持久标题；画像、人格关系、短期卡片沿用类型及用户/会话作为展示标题，不额外要求模型为这些单一状态生成标题。所有已有版本/来源入口都采用条目内展开，不能只修改长期列表。短期继续展示实际已有覆盖信息，不虚构尚不存在的版本链。

## 标题语义与生成

标题是简短、具体的展示摘要，正文仍须独立完整。标题不添加正文没有的事实、不升级计划为完成、不使用“我记得”等包装，不将不同时间事件只因同名而合并。标题不要求唯一，节点身份仍由ID维护。

新建与更新标题合并到既有抽取调用，人工编辑、拆合和重构使用同一字段约束；不增加单独标题模型调用。优先省略不必要的用户指名，必须指名时沿用稳定逻辑用户占位符，约定称呼保留。

标题长度为1～60个语义字符：一个完整且合法的用户占位符按一个字符计，普通Unicode码点逐个计；每个引用ID最多200个码点，编码文本硬限为12540个码点；昵称渲染后的文本原样展示，超出窄屏宽度时换行。短引用和稳定引用使用相同计量规则，独立长ID和多成员工程样例验证这一边界，不能直接把内部ID长度当成用户可读标题长度。存储不按CSS省略结果截断。

标题不进入Embedding或默认召回正文，不替代事实检索，也不占用现有模型注入预算。若以后要让标题参与匹配或注入，应单独验证输入指纹和预算；本需求不隐式改变召回排序。

## 版本、治理与兼容

当前标题作为节点展示元数据持久保存，正文新版本生成时一并保存当时的标题快照。仅修改标题不推进 `content_version` 或 `updated_at`，不重评重要性、不重置强度、不清除强化，不失效覆盖或节点向量。标题修改作为 `title_update` 派生操作挂在当前正文版本下，记录前后标题和操作时间，不冒充一次正文更新，也不改变正文最近性排序。

历史正文版本显示其实际保存的标题快照；旧版本没有标题时显示“未记录标题”，不拿今天的标题填成过去的事实。标题单独修改的记录可在条目操作记录中查看，不为其建立第二套完整记忆版本系统。只有标题操作而缺少正文来源凭据的旧版本仍显示来源未记录，不能因补标题把provenance_status改为recorded。

标题编辑复用后台治理互斥，核对正文版本、generation、updated_at和 `expected_titles` 中调用方读取的原始title（可为null），避免正文版本未变时覆盖另一份标题修改。仅改标题不默认冻结后续正文更新；正常正文编辑/拆合继续遵循既有人工保护规则。若需要单独长期锁定标题，应另行明确，不在此引入额外保护字段。

旧库迁移允许标题为空，界面用“事件 · 短ID”等中性展示名；不批量调用模型、不改写原正文、不伪造历史标题。后续正常更新或人工编辑补标题，重构自然生成。

新增抽取字段必须使用新协议版本，与已有证据候选 `extraction.v3` 区分。旧schema仍可解析历史输出，旧未提交任务按照签名规则重新准备，不能在生产默认缺标题时静默回退旧协议。当前生产默认为 `extraction-prompt.v16` / `extraction.v5`，memory.db为v12；v5在v4结构上增加可空但必填emotion，并继续要求必填title，不包含v3证据声明。提示词正常叙述要求继续采用ADR-0028，标题协议见[当前schema](../archive/schema/extraction-v4-and-memory-v11.md)。

## 条目内查阅

卡片持有自己的版本、来源和原文容器，按需请求现有API；首次列表请求不加载所有原文。折叠再展开可复用当前页面内结果，离开空间、切换分类、分页或刷新后清除对应状态。

每个条目的加载、错误和重试互不干扰，迟到响应不得写入新的卡片或另一个空间。继承版本在同一区域提供可返回的导航，避免无界嵌套。多个条目可以各自展开，不共享会互相覆盖的全局内容容器。

保留“本次直接引用”“同窗上下文”“继承基线”“累计关联”区分；未知凭据明确标示。原文读取后展示在其来源按钮所在的条目内。使用文本渲染，保留现有来源作用域检查和默认不预取原文的行为。

## 验收

验证新旧库、仅标题/仅正文/同时编辑、拆合、旧候选恢复、昵称变化、标题搜索及历史快照。仅标题变化时正文版本、强度、coverage和向量结果应保持既有语义。

浏览器验证长列表、多个展开条目、版本基线跳转和返回、原文读取、折叠、错误重试、快速切换空间和移动端；焦点与阅读位置保持在发起操作的条目。

针对性工程与真实Chromium检查已覆盖迁移、标题治理、来源查阅、基线返回及迟到请求；真实AstrBot路由与临时数据库验证了仅标题任务和历史快照。真实模型用独立合成材料检验标题忠实性、主体、状态与限定，不能依据私人固定样本调优；两组独立真实模型调用中三条标题与正文一致，但更新标题、计划与完成、复杂条件和实机部署效果尚未覆盖，且私聊正文仍有第三人称表述。详见[验证报告](../evaluations/memory-titles-inline-20261113.md)。通过工程检查不等于标题语义或关系连续性已解决。
