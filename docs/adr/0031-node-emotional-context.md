# ADR-0031：长期节点保留轻量的当时情绪

- 状态：Accepted
- 范围：原子、事件和主题的可空情绪内容、版本、治理与召回展示。
- 相关：[节点模型](0003-memory-node-model.md)、[人格表达](0024-persona-voice-and-user-references.md)、[标题](0029-memory-titles-and-inline-inspection.md)、[强度](0030-strength-decay-reinforcement-and-awakening.md)。

## 语义

节点情绪用于保留原始经历中的情感背景。它与人格关系的当前主观感受分开保存；不能直接复制关系情绪到各节点，也不能把当时情绪解释成当下的关系状态或用户永久特征。

`emotion` 为 `null`，或包含三个字段的对象：

- `tags`：1～3 个互不重复的标签，使用 `joy`、`sadness`、`anger`、`fear`、`surprise`、`trust`、`concern`、`affection`、`neutral`；`neutral` 不与其他标签并用。标签集合没有先后优先级，存储使用固定枚举顺序。
- `intensity`：0～1 的强弱值，不作为诊断或精确心理测量。
- `description`：不超过 160 个可读字符的简短说明，交代情绪归属和必要情境；支持稳定逻辑用户引用，约定称呼照原文保留。

`null` 表示未记录或没有显著情绪，不能自动补成 `neutral`。原子、事件和主题都允许为空，不要求每个节点生成情绪。描述的完整 `{{user:...}}` 引用按一个可读字符计，引用ID最多200个字符，编码文本另有硬上限。

## 内容版本与更新

情绪属于节点语义内容。正文或情绪实际变化时推进 `content_version`，保存正文、标题和情绪快照；重要性按同次抽取重新评估，按现有内容更新规则重置强度基准与累计普通强化。情绪未变、仅标签顺序变化或单改展示标题，不造成情绪内容版本变化。

标题单改继续采用独立标题操作，不因已有情绪而误触发内容更新或人工保护。历史版本保留当时实际保存的情绪，不能用今天的值填补历史。旧 `coverage` 绑定两端内容版本，情绪变化后旧覆盖证据失效；重新声明覆盖需覆盖该版本的完整语义，不能把情绪描述当成无关展示字段。

## 抽取与人工治理

抽取协议 `extraction.v5` 为每条 `node_change` 增加必填但可空的 `emotion`，与正文及标题同次调用生成，不增加额外模型请求。显式回放旧协议时，新节点留空；更新节点时保留旧情绪，旧协议缺字段不代表要求清空。生产默认由提示词协议页管理，支持新schema不等于已经切换默认。

人工编辑可提交 `patch.emotion`，显式 `null` 清空；省略字段保留原值。情绪修改遵循已有后台互斥、内容版本/更新时间校验、人工保护和派生来源记录。拆分后的每部分单独确定情绪，省略时为空；合并后的情绪也单独确定，省略时为空，不继承其中某一节点的情绪来代表全部内容。重构按原始来源重新抽取。

## 展示与召回

WebUI 当前卡片和条目内历史版本展示标签、强弱及说明。编辑、拆分和合并提供表单，不要求用户填写 JSON。旧记录显示未记录，不伪造中性情绪。

召回仍使用节点正文向量与已有排序；情绪不独立向量化，也不自动作为强度加分。实际返回的节点在 JSON 中附带非空 `emotion`，说明中的用户引用渲染为当前昵称。渲染后的完整情绪结构参与同一 UTF-8 字节预算，不能在预算裁剪后追加，也不能截断结构后冒充完整记忆。空情绪不增加注入字段。

## 存储与验收

`memory.db v12` 在节点和版本表分别增加可空 `emotion_json`。旧库升级不回放模型、不改正文和强度、不补造旧情绪。字段结构、API语义和验证范围见 [schema](../archive/schema/memory-v12-and-node-emotion.md)。

验收覆盖旧库迁移、三个节点层级、情绪单改/清空/相同内容重交、人工保护、拆合归属、旧协议更新、历史快照、稳定引用与长ID、实际注入预算和浏览器编辑。工程验证只证明字段和流程行为；情绪标签是否准确、强弱是否恰当，仍需独立真实模型样例审阅。
