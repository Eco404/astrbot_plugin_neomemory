# ADR-0030：重要性减速、递减强化与独立主动唤醒

- 状态：Accepted
- 范围：节点强度计算、召回交付后的持久更新及热配置。
- 相关：[强度基本决策](0006-memory-strength-decay-and-reinforcement.md)、[召回运行时](0014-lightweight-recall-runtime.md)、[配置热应用](0022-live-settings.md)。

## 约束

重要性控制记忆衰减速度；普通召回强化的收益随当前强度增加而降低。时间累计损失最多 0.15，活动累计损失最多 0.6，单轮普通强化最多 0.12，节点累计普通强化最多 0.2。高级设置允许降低这些上限，不提高契约上限。

主动回忆应使有效但低于被动强度门限的节点恢复被动召回资格。该恢复与普通强化额度独立：即使普通强化已经用满，也能唤醒；唤醒不能清空已耗额度，也不能把历史事实恢复为当前事实。

## 当前强度

`importance` 是节点内容的重要性，`strength` 是最近重置后的强度基准。二者独立：正文或重要性实际变化时，基准重置为新重要性并清空普通强化；主动唤醒只设置恢复资格所需的最小基准。标题修改和相同内容重复提交均不触发正文重置。

令 `I` 为重要性、`B` 为基准、`t` 为距基准重置的秒数、`a` 为同空间同代成功抽取的轮次差、`R` 为已记账普通强化总量：

```text
速度系数 = 1 / (1 + 重要性减速系数 × I)
时间损失 = min(时间损失上限, 时间速率 × log1p(t / 时间尺度) × 速度系数)
活动损失 = min(活动损失上限, a × 每轮活动速率 × 速度系数)
有效强化 = min(节点强化上限, R)
当前强度 = clamp(B - 时间损失 - 活动损失 + 有效强化, 0, 1)
```

高重要性延缓两类损失到达上限；足够久或足够多轮后，损失上限仍相同。只读查询懒计算，不更新基准、时间或计数，不引入全库定时扫描。

## 普通强化

只为最终注入或主动工具实际返回的节点记账；候选、被预算舍弃的节点和被完整事件覆盖而省略的原子不获得强化。

```text
请求增益 = 基础增益 × 命中类型倍率 × 主动模式倍率 × (1 - 当前强度)^递减指数
实际增益 = min(请求增益, 本轮剩余额度, 节点累计剩余额度)
```

默认被动直接基础增益为 0.02，邻居倍率 0.25，主动倍率 2，递减指数 1。当前强度为 0.5 时，被动直接增益为 0.01；相同状态的主动直接增益为 0.02。持续被召回的节点每次增益逐渐减小，且仍受总额度限制。

强度使用同一次写事务中读取的最新节点基准、重要性、轮次和累计强化量计算，不采用召回开始时的旧快照。排序和强化使用同一个不可变策略对象。

节点/正文版本/轮次凭据保留 24 小时；同轮只裁决一次，零增益也记账。不同调用共享同代同轮额度，直接命中先于附带邻居。普通冷却仅从该正文版本上次**正增益**起算，默认 300 秒；内容更新使用新版本凭据。

## 主动唤醒

须同时满足：主动工具实际返回、当前代和正文版本仍有效、节点存储状态为 `active`、当前强度低于当前被动门限、同轮尚无该节点/正文版本凭据。`historical` 可以作为历史回忆返回并获得普通强化，但不会唤醒或改变事实状态；`disabled`、`superseded`、`deleted` 不参与。

```text
目标强度 = min(1, 被动门限 + 唤醒余量)
新基准 = max(0, 目标强度 - 有效普通强化)
基准时间 = 当前时间
基准轮次 = 当前代活动轮次
```

默认余量为 0.01。不恢复到原重要性；保留原重要性供后续减速使用，保留原累计普通强化量和已用额度。本次唤醒不叠加普通增益，不占普通单轮额度，也不受普通冷却阻挡。零增益唤醒不延长或重置普通冷却。

唤醒复用 `recall_reinforcements.increment=0` 的同轮凭据；存储返回项包含 `awakened=true`。基准重置与凭据原子提交，失败全部回滚。无需增加持久唤醒标记或数据库迁移。正文、标题、内容版本、更新时间、重要性、人工保护和节点事实状态均保持原语义；同轮重放不能再次重置基准。

若有效既有强化本身大于目标，合法最小基准为 0，此时实际恢复强度略高于目标。余量为 0 时，后续少量衰减即可再次低于门限；门限为 1 时，只保证重置瞬间达到 1，不提供永久豁免。已用满额度的节点仍可能在日后再次衰减失活，后续主动实际返回可以再次唤醒。

## 配置与数据兼容

WebUI 高级设置开放两类衰减、重要性减速、普通强化权重/冷却/额度和唤醒余量，支持单项恢复默认；AstrBot 基础配置表不增加这些参数。保存后新工作使用新策略，正在处理的请求保留原策略快照。

参数变化作用于随后懒计算和写入，不回写全库、修改既有正文或重新抽取。降低普通强化上限时，原始累计值保留，计算时限制有效值，后续额度按已用总量判断；再次调高不会凭空获得已经消耗的额度。更改衰减参数会重新解释自上次基准重置以来的损失，可能改变下一次召回资格；系统不保存每个时刻的策略历史。

具体字段、默认值及验收边界见[强度验证说明](../evaluations/strength-policy-and-awakening.md)。
