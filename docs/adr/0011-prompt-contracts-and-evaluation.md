# ADR-0011：提示词、JSON schema 和真实模型回放独立版本化

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 11](../开发计划.md#11-llmembedding-与提示词)、[开发计划 15](../开发计划.md#15-测试计划)

## 背景

不同 LLM 和 Embedding Provider 的遵循能力、上下文限制、延迟和成本不同。仅凭自然语言提示词很难保证事件延续、画像更新和来源引用的一致性；仅测试 JSON 是否可解析也无法发现语义错误。

## 决策

1. 提示词模板、输出 JSON schema 和业务应用规则分别版本化，并在任务记录中保存版本号。
2. schema 必须明确字段类型、枚举、长度、必填条件、来源 ID、已有节点 ID、操作类型和无变化表达。
3. 测试分为三层：纯函数/数据库单元测试、固定 source 数据和假模型响应的回放测试、真实 Provider 多模型回放测试。
4. 真实模型测试记录结构化成功率、来源引用准确率、事件延续与误合并、画像误写、延迟、token 和向量成本，并保留人工抽样审查。
5. 用户提供的真实 LLM 和 Embedding API 用于建立基线和调优；单一模型的偶然输出不得写成硬编码业务规则。
6. schema 不兼容时创建新的版本和迁移适配器；旧任务必须能按其记录的版本重试或明确标记不可恢复。

## 后果

- 提示词和模型行为可以独立演进，出现质量回退时能定位到具体版本。
- 测试成本高于只做单元测试，但长期记忆的语义错误需要回放样本才能发现。
- 真实 API 的网络波动、限流和额度会影响测试，应记录失败原因并区分基础设施失败与模型质量失败。

## 实现约束

- 每个回放样本包含原始输入、期望事实、允许的等价表达和禁止的错误推断。
- 评估结果不得直接覆盖生产记忆；模型比较运行在隔离 generation 或临时数据库。
- 提示词修改必须至少通过 schema 校验、固定回放和一组真实模型样本后才能进入默认版本。
