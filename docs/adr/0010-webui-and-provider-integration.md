# ADR-0010：使用五栏 WebUI 和 AstrBot Provider 作为模型入口

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 14](../开发计划.md#14-webui-规划)

## 背景

记忆系统既需要普通用户能理解的开关，也需要维护者调整门限、并发和模型。插件不应复制 AstrBot 的 API Key 或另起一套 Provider 管理；重构和导入类操作还必须在浏览器关闭后继续执行。

## 决策

WebUI 提供五个侧边栏入口：

1. **记忆**：选择人格和场景作用域，查看长期记忆、用户画像、人格关系和短期记忆四段内容。
2. **笔记**：查看、编辑、搜索、归档和恢复 Agent 自主笔记。
3. **模型**：从 AstrBot Provider 获取 LLM 和 Embedding 列表，选择默认模型和任务覆盖模型，设置并发、Embedding batch size，并测试连通性。
4. **设置**：分为功能设置和高级参数。每项显示默认值、单位、说明和独立恢复默认按钮，保存时校验参数关系。
5. **维护**：查看任务阶段、错误和检查点，执行重试、向量重建、重构和人工治理。

模型配置保存 Provider ID、模型 ID 和插件参数，不复制密钥。任务进度由后端保存，通过 AstrBot 插件视图的 Web API 配合 SSE 或轮询展示。

## 后果

- 用户可以主动查阅和治理记忆，维护页面能处理失败任务。
- 页面关闭不会取消后台任务，但需要任务日志和权限校验。
- 依赖 AstrBot Provider 的接口稳定性，必须在适配层隔离版本差异。
- 高级设置数量较多，必须提供合理默认值和恢复单项默认功能，避免用户只能修改配置文件。

## 实现约束

- WebUI 任何写操作都必须调用与后台任务相同的锁和事务逻辑，不能绕过服务层直接写表。
- 进度中的“总量未知”只能显示阶段和计数，不生成虚假的百分比。
- 模型连通性测试使用独立短任务，不改变记忆、活动轮次或缓存的权威状态。
