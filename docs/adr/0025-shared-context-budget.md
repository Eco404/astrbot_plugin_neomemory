# ADR-0025：共享注入字节预算与完整条目优先级

- 状态：Accepted
- 范围：被动召回的最终上下文装配；补充ADR-0005、0014、0016、0024

## 决策

最终临时上下文使用一个UTF-8字节上限，涵盖完整长期记忆、短期摘要、画像、人格关系及笔记工具提示。兼容键 `recall_budget_tokens` 保留，默认2048，既有保存值不迁移；WebUI明确显示“记忆注入字节上限”。该计量不是模型精确token数。

所有条目先按昵称渲染，再包含标签、JSON转义、包络与分隔符进行计量。正文不按剩余额度截断；不能完整容纳的条目跳过，继续尝试后续条目。单项字符上限及功能开关仍独立生效。辅助资料与长期记忆不设固定配额，避免有空余却无法使用。

配置 `context_budget_priority` 决定装配顺序：

| 值 | 选择顺序 |
| --- | --- |
| `recall_first`（默认） | 召回结果中排序最前且能单独完整容纳的一条 → 短期摘要 → 画像 → 关系 → 其余长期命中 → 笔记工具提示 |
| `context_first` | 短期摘要 → 画像 → 关系 → 长期命中 → 笔记工具提示 |

“排序最前”指当前有效排名与覆盖选择后的候选顺序，不承诺语义上最相关。第一条超限时继续寻找后续可容纳项。被动路径临时保留有界排名候选，在最终校验事务重新检查节点与覆盖关系，按共享预算重新选择；先前仅因预算、节点数或覆盖被省略的候选仍可参与。未进入索引或匹配候选的节点不因此被展开。

选择优先级与展示顺序分开：输出仍为辅助资料块和长期记忆块，各正文保持内部完整。未放入最终上下文的长期节点不获得召回强化。诊断包含单位、上限、优先级、实际注入字节及逐类省略原因。

WebUI保存后，新请求立即使用新优先级；已经开始的请求沿用其配置快照。主动回忆沿用同一字节上限，但不插入本地辅助资料，因此不应用这两个装配优先级。

## 理由与代价

统一字节计量能在无额外模型调用、无在线分词依赖的情况下严格限制最终文本大小。跨模型精确token成本需要可信的模型分词信息，不能把某个项目的经验估算当成通用精确计数。字节计量偏保守，中文尤其明显；本决策不声称解决模型上下文利用率。

紧预算下不存在所有条目同时保留的保证。默认优先保留一个长期命中，会排除一部分辅助资料；辅助资料优先可能省略该长期命中。用户可以切换优先级或调整上限，程序不隐式扩大配置值，也不通过截断条件、否定或称呼来填满预算。

实现复用同一次装配内已经渲染的节点字符串及字节长度，调用结束后释放，不写入数据库或长期缓存。不改变排序、覆盖、强度、空间、generation或来源校验。

## 验证与未覆盖边界

独立合成矩阵、实际插件请求路径、设置即时应用及浏览器验证见[预算评估](../evaluations/context-budget-20261111.md)。这类证据证明预算和选择合同，不证明自然问题的召回准确率、实际LLM质量或全量记忆重构质量。

覆盖去重须满足ADR-0014的有效要求：只有实际选中且放得下的事件才能抑制原子。最终选择使用同一事务校验的候选和当前覆盖声明；事件放不下、失效或full声明改变时，原子仍按完整文本和剩余预算参与选择。回补不增加网络调用、不持久化临时候选，也不绕过空间、代、版本、状态或节点数限制。

仍需独立处理：保守计量的token利用率、错误full语义声明的信任策略、抽取事实质量及实机持续聊天效果。宿主抽取输入截断问题不属于本决策。
