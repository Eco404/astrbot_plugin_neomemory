# 人格叙述视角与逻辑用户文本引用

状态：Accepted，依据用户明确的视角、称呼与人格关系要求。

## 决策

长期原子、事件和主题正文是人格自己的回忆。第一人称“我”指所属人格，不将对方经历写成人格亲历，也不使用旁观者报告或面对对方的第二人称讲述。不要求每句话以“我”开头。当前画像仍描述对方的资料，不能将对方偏好归到人格身上。

人格关系正文完全表达人格自己的第一人称内心想法。允许由实际互动触发的期待、犹豫、主观感受与联想，不要求对方确认这些感受，不限定情绪方向或叙事模板。事实归属、对方承诺与对方态度仍须有依据；主观表达的自由不改变来源引用、私聊作用域、版本和事务契约。

需要指名已知逻辑用户时，派生正文使用 `{{user:<logical_user_id>}}`。明确约定的昵称、专属称呼与引用原话保留原文。程序只解析保留语法，不对普通“用户”“你”或昵称做全文替换，也不据昵称判断身份。没有已知身份的第三方使用来源中可独立理解的称谓，不编造逻辑用户引用。

模型传输采用 `reference.v2`：结构化标识符继续使用窗口内 `s1/n1/u1`；派生正文中的用户引用也映射到本窗口的短引用。落库前精确解回稳定 ID。输入中已有记忆引用的旧成员也参与本窗口映射，即使该成员没有在新来源中发言；原始来源和人格文本不参与替换。未知引用拒绝，正式候选继续经过完整 schema、范围和来源验证。这替代 ADR-0023 中“只转换结构化标识符字段、不修改记忆正文”的范围，其他恢复和检查点规则继续适用。

渲染在程序内完成，不增加生成式模型或向量调用：

- 聊天中，当前发言人的当前账号昵称优先，其余身份使用来源库记录的最新逻辑用户显示名。
- WebUI 使用来源库中的最新显示名。名称缺失时显示“未命名成员（逻辑 ID）”，不猜身份或混为同一人。
- 注入与主动工具按渲染后的完整文本计算预算。昵称变化只改变展示，不改正文版本、向量输入或覆盖声明。
- 管理 API 同时保留 canonical 字段和 `display_*` 展示字段；治理和版本检查使用 canonical 内容。原始来源与笔记不会自动替换。
- 记忆页搜索保留存储正文匹配，并支持最新显示名的字面片段。先按已有身份表找匹配 ID，再在当前空间和代中查找引用；同名不合并身份，不改变来源归属。

生产提示词为 `extraction-prompt.v16`，按本决策和 ADR-0028 直接叙述事实、保留主体和明确约定称呼；v16 进一步规定人格显示名不得作为普通叙述主语，已知节点只作事实基线。输出 schema 为 `extraction.v5`。提示词和引用协议均参与输入签名。旧未完成候选需要重新准备，已提交记忆不会自动改写；历史正文须经正常更新、人工治理或显式重构改变。v15 仍可显式用于历史回放和对照。

## 短期范围

长期重构不生成短期摘要。短期由实际会话请求触发滚动后台任务，绑定来源流、宿主会话与当前代；不能将全部历史直接写成当前待办，也不能将旧代摘要复制成新代。短期生成/称谓协议仍独立，本决策不宣称它已经通过新叙述规则的真实验证。

## 验收与限制

工程验收包括跨窗口短引用重排、旧成员引用、未知引用拒绝、昵称变化、约定称呼保留、多成员身份、原文不变、展开后预算、临时注入及治理版本保留。真实模型验收使用事先固定的独立合成输入，分别审阅长期视角、画像主体与主观内心表达；有限样本通过不代表风格始终稳定。

已有引用机制参考及许可证依据继续见[引用协议研究](../research/extraction-reference-protocol.md)。这是基于现有短引用、身份库和确定性渲染的扩展，不引入另一套人格或关系本体。嵌入仍使用稳定正文；昵称相关自然语言向量查询质量及旧内容的自然更新效果需要独立评估。WebUI 支持存储正文或名字片段搜索，不对“昵称加正文”的跨边界拼接短语进行全库渲染搜索。
