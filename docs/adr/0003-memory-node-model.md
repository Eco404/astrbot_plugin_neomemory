# ADR-0003：采用可独立理解的记忆节点和有限关系

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 6](../开发计划.md#6-记忆节点模型)

## 背景

陪伴型记忆既需要保存具体细节，也需要表达一段经历的过程和跨经历的主题。如果强制所有内容都套入严格的三层树，简单偏好会被过度包装，且同一事件可能同时属于多个主题。

## 决策

1. 统一使用“记忆节点”作为存储概念，节点类型为 `atomic`、`event`、`topic`。
2. 每个节点保留可独立理解的自然语言正文；结构化字段保存类型、空间、来源、参与者、事件时间、重要性、强度、状态和版本。
3. 不强制每个原子都拥有事件父节点，也不强制每个事件都属于主题。
4. 关系图允许多重归属，第一版只实现有限且有明确语义的关系，例如 `contains`、`related`、`follows`、`supersedes`。
5. 同一经历的补充继续更新原节点；另一时间发生的相似经历创建新事件，再通过关系组织。
6. 事件正文可以完整概括过程，主题保存稳定概况和入口。召回时默认注入事件正文，而不是无条件拼接所有子节点。
7. 节点正文变化生成新内容版本；人工保护、禁用、删除和替代状态独立于内容版本。

## 后果

- 简单偏好可以直接作为节点，减少无意义的层级。
- 事件和主题可以在后台抽取阶段生成较连贯的文本，降低召回时生成模型调用需求。
- 节点正文可能包含已经不活跃的细节；第一版接受“细节淡化后事件概括仍可能被记住”的语义。
- 关系和版本需要严格约束，否则节点图会变成无法解释的重复数据。

## 实现约束

- 每个节点必须能追溯到至少一个 `source_id`，人工创建节点要标记来源类型。
- 事件、主题正文不能通过简单标题列表拼接生成；抽取 schema 必须要求可读的限长正文。
- 关系端点、关系类型和版本必须通过 schema 校验，向量只作为候选证据，不能单独决定合并。
