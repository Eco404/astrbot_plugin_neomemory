# ADR-0002：原始库、派生库和可清空缓存分离

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 5](../开发计划.md#5-数据库规划)

## 背景

长期记忆是模型从原始聊天中抽取的结果，可能因提示词、模型、人格配置或人工治理而改变。若只保存派生结果，无法可靠重构；若把所有中间结果混进权威数据库，又会增加迁移、清理和一致性负担。

## 决策

使用三个职责明确的数据库文件：

| 数据库 | 角色 | 可否清空 |
| --- | --- | --- |
| `source.db` | 原始 `conversation` 和未来 `source_event`，重构的事实输入 | 第一版不自动清理 |
| `memory.db` | 记忆节点、画像、关系、笔记、任务状态和检查点等权威派生数据 | 只能通过受控任务操作 |
| `cache.db` | Embedding 等可重算结果的有界缓存 | 可以清空并重建 |

临时数据只有在后续阶段确定会复用、且复用收益足以抵消存储复杂度时才进入 `cache.db`。当前检索候选、排序结果、聚类中心和最终注入文本默认保存在内存中，流程结束即释放。任务检查点属于可靠性数据，必须写入 `memory.db`，不能只放缓存。

缓存项必须包含文本哈希、Provider、模型、维度、编码配置和缓存 schema 版本。缓存按类型设置 TTL、条数或体积上限，批量清理；清空缓存不得改变记忆语义。

## 后果

- 可以从原始库按当前配置重新生成派生代。
- 缓存命中能减少重复 Embedding，但不会把缓存误认为事实来源。
- 三个文件需要独立迁移、备份和故障处理；写入必须避免跨数据库事务假设。
- 原始库在第一版可能持续增长，清理策略留到核心抽取、召回和重构稳定后再制定。

## 实现约束

- `source.db` 的稳定来源 ID 和顺序信息必须不可变；纠错使用版本或编辑记录。
- 派生表只保存来源引用，不复制原文作为权威副本。
- 缓存写入失败不能阻塞主流程；缓存读取异常按未命中处理。
