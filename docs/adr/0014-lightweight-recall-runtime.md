# ADR-0014：在线召回使用有界缓存索引和临时内容块

- 状态：Accepted（ADR-0005/0006/0010的阶段四实施细则）
- 日期：2026-10-29

## 决策

1. Provider通过AstrBot公开Context取得，不另存API密钥。LLM与Embedding并发独立，batch size独立于并发；直接使用get_embeddings，避免get_embeddings_batch额外重试与插件重试叠加。单个任务有包含排队的截止时间，模型内部重试仍属于Provider。
2. cache.db只存内容摘要和可再生向量。消息与节点分类型容量/TTL，节点身份包含正文版本；同空间同文本可在消息之间复用，不跨空间共享原文。动态维度必须在同指纹内一致；模型同名替换时用户可更新revision。
3. 首版为有界空间内精确余弦检索，最多2000节点，截断信息可诊断。查询路径只读已有节点向量；缺失向量后台补建，首轮空召回可以降级，不在线等待整个库向量化。缓存重建不改变权威记忆。
4. 当前消息与近7200秒内最多10条同conversation/人格历史共同查询；用户/Agent补充权重0.45/0.40，当前命中优先。当前向量已缓存时，即使历史补充超时仍可继续本地检索。
5. 不调用额外生成模型组织注入。按完整自然语言节点选择和分段，事件优先只在确实fit预算且当前coverage明确完整时去重原子。只展开一层邻居，区分相关与同期，无因果推断。
6. 注入前对活动generation和节点版本/状态终审；注入通过宿主temporary content parts，避免永久历史残留和模型把自己的旧注入当作新的用户事实。重复hook只替换自身内容对象。
7. 仅实际交给主链的节点产生强化。节点/version/turn去重保存24小时、短时冷却默认300秒；单轮总增益0.12，累计0.2。跨被动/主动调用共享限额，旧轮标识超过24小时不保证永久去重，超过窗口不应作为同一聊天轮复用。
8. 工具作用域由当前事件解析，LLM不控制space_id；历史召回可以返回historical但不能恢复其当前事实状态。笔记工具只操作当前空间。

## 后果

冷索引或首次Embedding超时可能使本轮不注入；必须显示诊断并保留聊天可用性。该选择符合被动流程低延迟要求，真实延迟和规模仍需调优。异步索引任务先用有限内存任务集合，缓存可重复构建；持久失败任务和人工维护仍归阶段五。

自动抽取上线需要窗口调度与持久重试，因此本阶段仅提供真实Provider适配和隔离抽取验证。向量召回可在已存在的合法记忆上使用，不伪造自动记忆已接通。
