# ADR-0004：选择性抽取、受约束提示词和分级 LLM 调用

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 8](../开发计划.md#8-抽取管线)、[开发计划 11](../开发计划.md#11-llmembedding-与提示词)

## 背景

长期记忆不应归档每条消息。抽取任务还同时涉及节点、画像和关系，盲目拆成多个模型调用会增加成本和不一致，盲目合并又会使上下文过大、任务边界混乱。模型输出必须能够稳定地应用到数据库。

## 决策

1. 抽取提示词明确允许整个批次不产生长期记忆。寒暄、重复、没有持续意义的琐碎内容可以丢弃。
2. 人格参与“什么值得记”和叙述视角判断，但不能改变消息归属，也不能把模型推测写成用户事实。
3. 在输入和判断依据相近、上下文规模可控时，一次调用同时输出原子、事件、主题、画像和关系变化；前后依赖不明确或上下文过大时拆分为阶段。
4. 每类任务使用版本化提示词和严格 JSON schema，固定列出身份、时间、来源、已有节点、无变化、矛盾和反例规则，并限制字段长度。
5. 程序负责校验空间、节点 ID、来源 ID、枚举、关系端点和版本；模型不直接写数据库。
6. 可并行任务使用独立的 LLM 和 Embedding 信号量，并发上限可配置。流程中可异步的模型调用和后台任务采用异步实现，但数据库事务中不等待网络请求。
7. AstrBot Provider 的内部重试由 Provider 负责；插件只管理任务级重试、截止时间和断点，避免对同一失败进行无边界双重重试。

## 后果

- 相关信息可以共享上下文并减少调用次数，但复杂批次仍可拆分，避免“一次调用包办所有事情”。
- 结构化成功率和可审计性提高，但提示词/schema 需要随模型行为持续测试。
- 模型失败只影响当前阶段或空间，其他空间和主聊天功能可以继续运行。
- 真实 Provider 差异会影响输出质量，不能只依赖静态 schema 校验。

## 实现约束

- 抽取输出必须先落入待应用对象，再执行业务规则和事务提交。
- 未知枚举、越界长度、伪造来源 ID、跨空间节点 ID 和无法解析的 JSON 必须进入可重试失败状态。
- 每次抽取保存提示词版本、模型标识、输入范围和输出校验结果，便于回放和维护。
