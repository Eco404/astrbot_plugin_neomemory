# ADR-0039：后台抽取逐查询候选覆盖

状态：Accepted。

## 决策

后台抽取的旧节点选择默认使用`extraction-context.v2`。保持最多10条查询、默认30个旧节点及`ceil(limit/3)`近期优先份额；每查询保留一个相似度达到0.35的最佳节点，去重后按得分及ID稳定排序，再以全局最大相似度排名补足剩余名额。总limit、分页扫描和向量复用保持，不新增生成或Embedding请求。

0.35为现有策略门限，不能保证语义相关。多个查询可能共享最佳节点，小预算也无法保证每个话题都保留代表；无关短句可能占用名额。接受有限噪声与概括瑕疵，以实际目标覆盖、重复条目减少及错误影响评估，不要求零噪声。

相似度只决定提供给模型的候选，不直接合并记忆。模型仍须区分同一经历进展、独立再次发生和无信息增量；更新、新建、来源与版本按既有合同提交。已有库不自动批量合并，旧节点不会因排名变化被删除。

任务签名使用新context版本，升级前尚未提交的旧上下文须重新准备；已完成窗口按回执恢复，不重复抽取、消费来源或推进活动轮次。显式v1保留用于独立对照；主动与被动召回算法不随这项后台策略改变。

## 依据与取舍

[独立向量比较](../evaluations/context-fusion-20261117.md)在默认30/近期10下，6类主要场景的目标位置从6/10提升为10/10；重复控制另列，所有场景共享节点，不能称为普遍召回率。[真实抽取利用](../evaluations/context-fusion-apply-20261117.md)中，v1因候选不可见而发生的3个重复新建操作，在v2对应分支改为正确旧ID更新，另一独立新经历保持新建。

旧[覆盖实验](../evaluations/context-coverage-20261117.md)中的一例弱相关噪声仍有效；新抽取也有次要细节概括损失。按用户接受少量瑕疵的要求，减少话题遗漏与重复新建的收益支持进入使用验证，不据此宣布多模型、冷缓存大空间或完整事件同一性已解决。

参考Graphiti固定版本的多路排名融合。独立RRF探针虽补回同样目标，却增加2—6个无关语义项且无额外目标收益，因此不新增RRF生产路径；沿用已实现并通过边界检查的v2。参考版本、许可证、冻结参数与局限见独立报告。
