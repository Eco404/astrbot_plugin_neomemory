# ADR-0008：派生记忆允许人工治理，原始事实与派生数据分离处理

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 13](../开发计划.md#13-人工治理)、[开发计划 17](../开发计划.md#17-后续计划)

## 背景

模型抽取必然会出现错误合并、错误拆分、过度推断和过时画像。用户需要能修正结果，但人工治理不能破坏原始记录，也不能让重构把旧治理状态误当作模型事实。

## 决策

- **修改**：正文、时间、参与者、重要性和关系可人工编辑；正文修改生成新版本并使旧向量失效。
- **拆分**：创建多个节点，重新分配来源和关系；原节点标记为 `superseded`。
- **合并**：指定保留节点，迁移可合并的来源和关系；被合并节点标记为 `superseded`。
- **禁用**：保留节点但停止召回和自动更新，可恢复。
- **删除**：删除派生节点、向量和关系；原始来源不删除。
- **人工保护**：保护正文不被自动抽取覆盖；新进展进入待审核候选。保护默认持续到人工解除。

第一版不自动清理 `source.db`。导入导出、备份恢复、原始记录合并和跨库派生记忆合并暂不实现，待核心功能稳定后另行设计。

重构可以清空当前 generation 的治理记录，页面必须明确提示“删除派生记忆不等于删除原始输入”，以及“重构会以当前规则重新生成结果”。

## 后果

- 维护页面成为纠正记忆的主要入口，不需要直接修改数据库。
- 原始库持续保留使重构可靠，但会带来存储增长和隐私治理问题，后续必须单独设计清理和导出策略。
- 人工修改会产生版本、向量失效和父摘要 stale 状态，需要维护任务补齐派生索引。
- 重构后的结果不自动继承人工治理，避免旧治理记录绑定到语义已变化的新节点。

## 实现约束

- 所有治理动作记录操作者、时间、原因、前后节点和影响范围。
- 禁用和删除必须在召回、自动更新和主动工具中保持一致。
- 受保护正文与新候选的关系必须可见，不能静默丢弃新进展。

## 阶段三实施补充

人工保护独立于生命周期状态，旧状态迁移、保护对自动更新的约束及重构新代语义见 [ADR-0012](0012-extraction-commit-and-protection.md)。
