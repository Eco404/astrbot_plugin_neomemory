# ADR-0037：有界候选纠正与后台索引等待

状态：Accepted。自动纠正范围、默认额度及反馈协议替代ADR-0035对应部分；其结构化输出、任务删除及不跳过窗口的决策继续有效。

## 决策

长期抽取和重构固定窗口默认允许首次生成之外最多3次自动候选纠正。`extraction_auto_regeneration`控制启用，`extraction_max_regenerations`为WebUI高级参数，范围1—10，默认3。窗口准备时持久保存额度，调用纠正模型前持久增加已用次数；网络重试、进程重启、显式重新生成不补回额度。已准备窗口保持保存值，没有额度字段的兼容检查点继续按原1次上限执行；新配置用于新准备窗口。

可纠正范围为明确可定位的候选错误：JSON语法/重复键、枚举/模式/缺字段/额外字段，以及未知时间空值、时间区间、create/update字段组合、未声明局部引用、引用种类与固定上下文范围、候选声明的版本、画像/关系引用的用户证据、边类型/层次及循环。纠正只重新生成完整候选，不由程序猜测ID、替换来源、修改版本或静默改变正文。所有候选仍经过相同schema、引用、来源、作用域及事务校验。

真实输入或配置变化、过期租约、人工保护、整体容量超限、输出不完整、未分类异常及语义合同冲突不据此自动放行。旧节点内容真的变化与模型填写错误版本是不同问题：前者需要重新准备，后者可在不变输入上重新生成。纠正不能自动跳过窗口、放弃来源或把失败标为无变化。

所有纠正与原请求共用一次窗口执行的剩余期限，默认120秒；达到期限可能少于3次即停止。后台任务临时故障重试和宿主网络重试保持各自职责，恢复使用持久的剩余额度，不加第三层网络重试循环。

`candidate-regeneration.v5`提供明确跨字段错误码、来源/用户/节点引用区别、当前输入版本及来源角色说明；重复返回同一拒绝候选时明确反馈。只带最近一份拒绝候选及当前字段诊断，避免随尝试累积上下文。旧协议检查点继续按保存版本构造反馈。

后台必须持久化的节点向量写入使用所在步骤剩余总期限，索引步骤默认300秒；写入后核对节点ID、内容版本和模型指纹对应的缓存项。在线可再生缓存仍采用短写等待，慢写不扣留已经算出的召回向量。后台读取、生成、写入和读回共用已有期限，不无限等待、不把未保存向量报告成完成索引。

## 依据与边界

用户明确要求减少人工处理并将默认抽取重试设为3次。现有固定输入、任务回执和严格提交已提供自动候选纠正所需边界，不需要放宽来源合同或另建恢复数据库。

参考Graphiti `5c27edfa8d3e0f49b2571bcebb4261bcc89ee037`（Apache-2.0）`openai_base_client.py`的应用输出纠正与网络错误分层。其内存重试计数和广泛异常文本回传不适合直接移植；本项目保留持久预算、固定错误代码和输入一致性。参考为本地快照，不声称代表最新上游状态。

独立验证见[候选恢复评估](../evaluations/candidate-recovery-20261117.md)。人工注入错误的修复不等于自然故障率下降已经量化，schema成功不等于语义正确。当前文本/结构化模式默认规则不变，宿主输入截断不在此项范围内。
