# ADR-0007：后台任务使用作用域锁、检查点和 generation 切换

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 12](../开发计划.md#12-任务重试与断点恢复)

## 背景

重构、向量重建、批量治理和抽取可能持续很久。浏览器关闭、网络波动或重复点击不能导致数据库半更新；不同任务若同时写入同一空间，会产生覆盖、重复活动轮次或索引不一致。

## 决策

1. 所有耗时操作由后端后台任务执行，任务状态、阶段、进度、错误和检查点持久化。
2. 同一记忆空间的抽取、人工治理、向量重建和重构互斥；不同空间可在全局并发上限内并行。
3. 配置迁移、数据库迁移和全量重构使用全局锁。WebUI 显示可用性，后端创建任务时再次校验。
4. 任务阶段分为固定输入范围、模型输出和校验、Embedding、派生数据事务、索引或 generation 切换。每个成功阶段保存最小检查点，失败后从最近阶段继续。
5. 重构固定一个原始记录范围，在新 generation 中按当前配置和人格回放；新消息继续进入原始库，待当前任务完成后按顺序处理。
6. 新 generation 完整成功后原子切换；失败时继续使用旧 generation。重构不读取旧派生记忆，人工治理记录不迁移并可随旧代清理。
7. 同一操作重复提交返回已有任务或明确冲突，不创建重复任务。无法确认状态的运行中任务在进程恢复后转为可恢复状态。

## 后果

- 任务中断不会要求从头重复所有模型调用。
- 作用域锁会暂时延迟同一空间的新派生写入，但原始消息收集保持可用。
- generation 会增加存储和切换管理复杂度，却能避免重构半成品污染线上召回。
- 页面需要展示阶段和真实计数；总量未知时不能伪造百分比。

## 实现约束

- 锁必须设置持有者、租期和恢复策略，进程崩溃后不能永久锁死空间。
- 检查点必须能验证输入范围、配置版本、模型版本和目标 generation，防止错误续跑。
- 任何阶段重复执行都必须幂等，尤其是来源引用、活动轮次和向量索引写入。
