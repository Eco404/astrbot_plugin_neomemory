# ADR-0006：重要性、时间衰减、活动衰减和有限强化共同决定强度

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 9](../开发计划.md#9-衰减强化和活动轮次)

## 背景

长期记忆需要区分重要性和近期活跃度。只按时间衰减会让长期未使用但仍有价值的记忆消失；只按召回强化又会造成“越容易召回越强”的循环。抽取批次不断产生新内容时，还需要表达旧内容退到背景的效果。

## 决策

记忆强度按以下概念计算：

```text
当前强度 = 基准重要性 - 有上限的时间损失 - 活动轮次损失 + 有上限的召回强化
```

- 重要性在节点新增或正文更新时评估；节点内容更新必须重新评估重要性并重置强度参数。
- 时间衰减采用缓慢增长的非线性损失，并设置累计上限，避免长时间未使用后全部记忆失活。
- 活动轮次只在同一记忆空间的一次成功抽取批次完成后推进；重试同一批次不重复推进。
- 召回强化只作用于最终注入或主动工具实际返回的内容；直接命中强于邻居命中，主动回忆强于被动注入，短时间重复命中有增量限制。
- 查询时懒计算强度，不需要每天扫描全库；强度计算不能重置最后使用时间。
- 新偏好替代旧偏好时，使用 `supersedes` 或 `historical` 表示历史关系，不能靠强化把旧偏好恢复为当前事实。

## 后果

- “重要性”和“活跃度”成为不同维度，能保留长期背景记忆。
- 更新节点会重新获得合理的活跃度，避免内容已变化但强度仍沿用旧状态。
- 查询路径需要携带上次抽取轮次和召回时间，但不需要定时全库更新。
- 衰减参数会影响召回排序，必须通过回放样本调优并暴露高级设置。

## 实现约束

- 所有损失和强化都必须设置上下限，避免单次任务造成异常跳变。
- 关系邻居不能因为被附带返回而获得与直接命中相同的强化。
- 重要性更新、强度重置和正文版本变更必须在同一事务内提交。
