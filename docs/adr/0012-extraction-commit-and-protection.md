# ADR-0012：人工保护独立，抽取按固定范围原子提交

- 状态：Accepted（用户确认保护独立与 memory.db 装配；其余为 ADR-0004/0006/0007 的阶段三实施细则）
- 日期：2026-10-29
- 补充：ADR-0003、ADR-0004、ADR-0006、ADR-0007、ADR-0008、ADR-0011

## 背景

阶段二把人工保护同时作为状态和布尔字段，无法自然表达“禁用且保护”。抽取多种派生数据时，如果沿用多个独立 CRUD 事务，失败会留下部分节点，重试也可能重复推进活动轮次。离线应用接口同样需要防范乱序、过期上下文和来源伪造。

## 决策

1. 节点状态只取 active/historical/disabled/superseded/deleted。manual_protected 是独立布尔属性，可选原因单独保存。修改状态不隐式解除保护；保护持续到人工解除。旧库通过 v2 将旧保护状态归一化为 active + protected，并用触发器禁止继续写旧状态，保留 v1 DDL和全部关联记录。
2. 主插件先开 source.db，再将其 has_source 注入 MemoryStore；抽取入口没有校验器时直接拒绝。来源存在性在事务外检查，空间/人格/说话者归属由 ExtractionService 从真实原始记录判定，模型不能创建作用域。
3. 模型调用在事务外完成；严格解析后，节点、边、画像、人格关系、来源引用、批次完成凭据和活动轮次在 memory.db 单一事务内提交。候选不直接调用分散 CRUD，事务中不访问 Provider 或 source.db。
4. batch_id 由空间、generation 和有序 source_ids 生成。同一范围完成后只返回已有凭据，不再次创建记忆/调用模型/衰减。复用原 PreparedExtraction 的重试校验完整输入摘要；重新准备后上下文发生变化，不能把它当成原任务重试，调用方应读取成功凭据。来源不可在同一 generation 被两个窗口重复消费。
5. generation 保存 activity_round，隔离未来重构与当前线上轮次。成功的 no_change 同样推进一轮；失败和幂等重试不推进。每个 stream 的已完成 sequence 上限也保存在来源凭据中，较早窗口不得晚于较新窗口应用，防止旧画像覆盖新画像。调用方必须顺序提供窗口；乱序旧数据需要新 generation 回放。
6. 更新检查模型拿到的 content_version、updated_at、活动代及轮次；受保护、历史、禁用、已替代、已删除节点不能自动改写或追加关系。阶段三整批拒绝需审核的候选，阶段五再引入持久化待审队列。治理修改和重构不能绕过保护：重构生成新节点，不继承旧保护记录。
7. supersedes 是显式的替代语义：相同类型节点的新→旧关系把旧目标标为 historical，并禁止环。偏好变化优先更新同一原子的完整历程；不为了建立关系强行拆成多个节点。人工拆合产生的 superseded 状态仍由阶段五治理负责。
8. 自动画像/关系变化至少包含对应逻辑用户的本人发言，所有被引用的用户发言须来自同一人；Agent 发言只能作补充。程序只能验证身份和引用，语义是否有直接证据仍由提示词、真实回放和人工抽查验证。
9. 新 Agent 来源记录原请求 trigger_message_id；抽取时按同流、同人格、同请求用户记录确定私聊归属。这样用户消息写入重试晚于回复时仍可解析。旧记录缺少该字段时保守使用前序用户；找不到明确归属则保留原文并拒绝抽取，不能猜身份。

## 后果与阶段边界

- v3 增加 generation 活动轮次、节点强度重置基准和完成批次表。完成凭据是幂等正确性数据，不能放入可清理缓存。
- schema 中没有事件 coverage 的推断字段。阶段三不凭 contains 自动宣称 full coverage；事件正文更新清理其旧 coverage，原子版本改变后旧 coverage 只能对应旧版。阶段四实现注入去重前要显式完成覆盖协议。
- 本阶段通过显式服务和假模型验证，没有自动 Provider 调度。输出协议是离线候选，进入默认在线抽取前仍需真实模型测试。
- 当前不持久化失败模型输出；原始记录不消费，仍可重试。失败任务、进度、检查点、待审候选由阶段五统一实现。
- SQLite 事务取消须完成排队回滚再释放锁；提交成功后才收到取消时，以持久化凭据识别结果，不能假设取消就代表未提交。
