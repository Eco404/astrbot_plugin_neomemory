# ADR-0042：显式旧节点依据与主题成员版本一致性

状态：Accepted。协议为extraction.v7；当前采用情况以文档入口和模型评估为准。

## 决策

新建或改写节点吸收已有节点内容时，模型在必填列表`base_node_ids`中声明实际采用的已有节点。只相似、同主题或进入上下文不构成依据。程序按固定输入快照保存其精确内容版本；不由模型猜版本，不在提交时替换成更新后的版本。自身旧版本在正文更新时继续自动继承。

`source_ids`保持本批直接来源的职责，`base_versions`保持版本继承职责，不把递归来源展开复制成当前直接证据。依据只能来自本次提供的已有节点，不允许本次局部新节点，避免把尚未生成的结果当作原始输入。只读或人工保护节点可作为依据，不能据此修改它。范围与快照检查复用现有抽取事务，不添加网络调用。

仅标题变更及普通不变内容确认不追加新的正文继承依据；这些操作不重新生成原正文版本。专用主题的显式成员重新确认保留现有确认语义，逐次操作与创建/更新区分。确认关系可能存在版本引用回路；读取按已访问版本去重，不能将循环引用本身视为事实成立的证明。

普通抽取与专用主题提交共用成员版本依赖写入。普通路径只更新明确关联或明确用于主题新正文的成员依据；未触及成员保留已有依据，不用所有成员的最新版本冒充实际生成依据。专用完整成员提交替换完整成员集合及对应依据。

只有组织关系改变而正文不变时，记录独立`membership`操作及评估过的成员版本，不把它算成正文重新生成。累计来源与人物索引继续用于主题浏览，精确依据仍由逐次操作和版本保存。

专用任务`changes=[]`可能表示无变化或材料不足，不表示确认全部现有主题，因此不写入新依据、不回填缺口。旧记录缺失且没有可靠依据时保持缺失，可通过显式重新确认或重新构建建立新的依据；不得伪造历史。

## 兼容与验证

新任务默认采用extraction-prompt.v30 / extraction.v7，正文独立可读，依据引用不代替正文必要信息。原schema、prompt及已有明确版本的PreparedExtraction保留显式版本执行，不为旧输出补填或猜测`base_node_ids`。旧未提交后台窗口在执行签名变化时暂停并要求重新准备；缺少显式prompt字段的旧检查点不从raw推断版本。已有完成凭据继续优先恢复，不重复模型调用。新协议使用现有版本依据表，不需要新增数据库结构。

验证包括跨窗口新节点引用、同批依据节点被更新时仍引用输入旧版、只读依据、范围错误回滚、短引用还原、幂等提交，以及普通/专用主题新增、成员变更、显式确认和空变化路径。结构验证只能证明记录准确，不能证明模型引用内容充分。
