# 空间共享与抽取模型

## 同人格的跨空间召回

共享按人格开启，默认关闭。来源空间可以单独禁止被检索，同时继续按权限读取其他空间。群聊读取同人格私聊需要在人格设置中单独开启。被动注入、主动查询和维护页的召回测试使用相同的来源授权范围。

当前空间先使用预算。其他空间只补充已有向量索引的原子、事件和主题。默认合计最多两条，并且最多使用总 UTF-8 字节预算的 20%，来源说明计入其中。画像、关系、笔记和短期摘要属于原空间。外部节点在返回前再次检查授权和版本，读取时不会强化该节点。

提供给模型的辅助资料列出原场景与参与者。同一人格可讲述自己的往事，只有当下的发言可以证明当前对象参与了什么。抽取使用当前空间的原文与候选，保留转述中原本的参与者和场景，把当下作出的回应、决定或约定归于当前互动。

## 模型来自哪里

- 人格回复被采集时，记录可确认的请求 Provider。事件指定的 Provider 标记为请求选择，按宿主会话配置查出的 Provider 标记为会话配置。若响应包含实际报告的模型名，单独保存。AstrBot 在图像路由或故障回退中可以换用其他 Provider，仅凭响应模型名无法还原该 Provider。窗口中明确指定的模型覆盖参数会随请求 Provider 一起复用。
- 自动长期抽取按来源会话流组窗。空间可指定固定 Provider、跟随窗口或继承插件设置。继承时优先使用全局记忆模型，留空则读取本窗口最近一条有 Provider 记录的人格回复。同一逻辑用户从多个账号聊天时，账号的原始流分别提供窗口依据。
- 空间的主题和短期摘要分别默认继承插件对应的专用模型。插件专用模型留空时按插件主模型设置选取。两项也可分别选择跟随本空间主模型，或指定固定 Provider。当主题跟随会话时，需要能从成员来源确定一致的模型。管理员可以在空间配置中明确指定，或在任务确认框中只覆盖主题步骤。
- 手动抽取和重构可为本次任务选模型，也可以保留各窗口原有选择，只补齐缺少模型的窗口。断点重试复用已确定的模型。需要切换模型时使用重新准备。选择只对本任务生效。

## 验证依据

路由采集依据 AstrBot v4.29.3 的会话选择、请求模型覆盖和响应字段。合成测试分别验证稳定的 Provider 标识、响应模型名、多个账号流的窗口、人工任务选择、共享的授权和预算。两种真实模型在同一合成私聊情境下各产生一条回复，两条回复分别由两种模型抽取，四组结果均通过输出协议校验，正文均保留当前用户的天气条件及经历归属。一组标题把“不下雨”收窄成“晴天”，另有一组产生部分重复内容。该规模只能验证调用和观察归因，风格收益仍需多场景评估。
