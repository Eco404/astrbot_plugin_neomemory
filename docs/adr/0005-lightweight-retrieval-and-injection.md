# ADR-0005：被动召回使用轻量向量流程，注入采用预生成记忆文本

- 状态：Accepted
- 日期：2026-10-28
- 相关章节：[开发计划 7](../开发计划.md#7-被动召回)

## 背景

被动召回参与每轮对话，额外调用生成模型会直接增加延迟和失败面。当前消息常有指代，单独向量化当前消息又可能漏掉最近上下文；但把整个历史交给模型重写也不符合轻量要求。

## 决策

1. 当前消息作为主查询，并默认从最近 7200 秒内最多 10 条消息中补充查询。
2. 补充查询使用可配置权重，首版默认用户消息 `0.45`、Agent 消息 `0.40`；当前消息的主查询优先级不被历史权重抵消。
3. 当前消息和未命中的历史消息使用一次批量 Embedding 请求；已存在且指纹一致的向量从 `cache.db` 复用。
4. 各查询向量只取得少量候选，在本地合并、去重、预算裁剪，再扩展一层关系或事件时间邻居。
5. 默认不增加生成模型调用。节点正文和事件叙述在抽取阶段生成，召回阶段只负责选择、分组、排序、格式化和注入。
6. 注入优先使用连贯的事件段落；原子命中时直接使用原子，主题命中时使用主题概况和少量事件。关系邻居和时间邻居必须标识其语义，不能暗示因果。
7. 只强化最终注入或主动工具实际返回的节点，同一轮重复命中只计一次；超时或向量服务失败时可降级到当前消息结果或不注入。

## 后果

- 被动路径不依赖额外生成模型，延迟和费用更可控。
- 召回文本的连贯性主要由抽取质量决定；抽取正文需要有长度和语义标准。
- 混合当前消息和有限历史可以缓解指代，但不能解决所有复杂指代；真正需要推理时应由主链模型处理。
- 缓存和批量 Embedding 能减少重复计算，但必须维护模型指纹和预算截止时间。

## 实现约束

- 召回截止时间内未完成的补充查询不得阻塞主链。
- 注入总 token 预算、候选数量和邻居层数必须有硬上限。
- 节点级衰减允许事件概括继续被召回，即使某个细节节点已经不活跃；第一版不动态重写事件正文以过滤细节。
