# 开发版与正式版的版本规则

日常开发在 `dev` 分支进行，插件开发版号使用 `1.1.0-dev.1` 这样的预发布格式。`metadata.yaml` 提供 AstrBot 读取的插件版本，也是安装包文件名的版本来源。`main` 对应正式版。

## 开发期间

每个自有协议和每个数据库格式独立计版。某项格式在正式 `v1` 基础上第一次发生变更，使用 `v2-dev.1`，再次修订使用 `v2-dev.2`。例如修改抽取输出协议时可以产生 `extraction.v2-dev.1`，仍使用原格式的主题协议继续使用 `topic-consolidation.v1`。内部开发序号按各自的格式修订递增，可以与插件的开发序号不同。

开发数据库须能在重开时识别其具体开发修订，开发版之间需要的数据转换放在开发分支。SQLite 的 `PRAGMA user_version` 是整数。首次更改某个库的格式时，应单独持久记录其开发修订，使同一正式基线上的不同开发布局可区分。节点正文版本、任务次数等业务计数按实际操作递增。

## 正式发布

逐项对照上一个正式版与待发布格式。最终有变化的组件统一落到各自的下一个正式版本，例如 `v2-dev.1`、`v2-dev.2` 的最终成果发布为 `v2`。最终格式与上一正式版相同的组件沿用原号，包括开发中尝试后又撤回的改动。

对每个有变化的库，将本周期的开发迁移合并为从上一正式格式直接到新正式格式的迁移。保留更早正式版本仍需的升级路径，移除开发修订间的迁移步骤及仅供这些步骤使用的代码。发布前分别验证空库初始化和上一正式库携带已有数据升级，核对最终结构、版本及已有数据。
