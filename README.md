# NeoMemory 1.2.2

NeoMemory 为 AstrBot 的人格提供长期记忆。它先保存聊天原文，再从有持续意义的对话中提取事件、细节和主题。在后续聊天中，人格可以回忆这些经历，结合用户画像、对彼此关系的理解和近期会话作答。私聊按人格和逻辑用户划分空间，群聊有独立的群空间。

## 1.2.2 更新

在「维护 → 人工维护」可搜索并治理长期记忆，编辑或删除用户画像、私聊人格关系和会话摘要。「维护 → 插件日志」可查看操作和后台任务的处理记录，默认按日保存 7 天。重新准备失败任务会沿用原任务编号，可在同一处查看历次尝试。

各正式版的变更见[更新日志](CHANGELOG.md)。

## 安装与首次使用

1. 在 AstrBot 4.29.3 或更高版本的插件管理页面上传 `astrbot_plugin_neomemory-v1.2.2.zip` 并启用插件。首次启动会在插件数据目录创建所需的四个 SQLite 数据库。
2. 打开插件 WebUI 的「模型」，选择向量模型。主模型用于长期记忆、画像和人格关系抽取，留空时跟随原对话窗口。主题抽取模型和短期摘要模型可以分别指定，默认跟随主模型。模型凭据由 AstrBot 管理。
3. 在「设置 → 功能设置」选择要启用的功能。宿主原生配置也提供模型与功能开关。WebUI 设置保存后对后续工作生效，正在执行的任务沿用自己的配置。
4. 使用指定人格聊天。在「维护 → 后台任务」查看待抽取来源和任务进度。私聊默认至少积累 5 条消息，5～19 条时等待空闲 2 小时；群聊有独立的触发门限。成功处理一个窗口后，“记忆”页可查看生成的内容及其来源。普通寒暄也可能仅保留原文。

## 记忆与召回

- **长期记忆**分为原子、事件和主题。原子保存具体事实，事件叙述一次经历，主题组织多项有关联的经历。长期正文以人格视角叙述，保存标题、时间、重要性以及有依据的情绪。每个情绪标签有独立强度。
- **用户画像**保存有辨识度、与本人直接相关的特征。**人格关系**记录私聊人格的长期理解及近期余韵。近期余韵默认自对应互动起注入 24 小时，期限可调。群聊可形成成员画像。
- **短期记忆**按具体会话维护滚动摘要。它由短期功能单独调度。执行长期全量重构时，只重放长期抽取链路。
- **被动召回**默认使用自适应召回。它结合正文向量与词面匹配，承接追问时补入相关上文，多事件回顾可由记忆模型挑选证据。WebUI「设置 → 高级参数 → 召回策略」也可选择向量排序或相关性筛选，保存后立即生效。默认截止 15 秒，完整条目在昵称展开后共享 15000 字节的注入预算。人格还可通过 `neomemory_recall` 主动查询，并通过 `neomemory_notes` 管理独立笔记。
- **私聊图片**按消息顺序辅助文字抽取，每个窗口默认最多处理 10 张普通图片，平台明确标记的表情会跳过。可在高级参数中将上限设为 0。成功抽取后清除临时图片，重构复用已保存的文字依据。

## WebUI

| 页面 | 常用操作 |
| --- | --- |
| 记忆 | 选择记忆空间，搜索、筛选、排序，在当前条目下展开历史版本和原文 |
| 笔记 | 查阅和编辑人格创建的笔记，归档、恢复或删除 |
| 模型 | 选择 Provider，测试连通性，设置模型并发和向量批量大小 |
| 设置 | 配置功能、高级参数、记忆空间、文本清理和外观。文本清理支持可编辑的分组、正则、替换和拖动排序 |
| 维护 | 管理任务与账号，治理记忆，重构所选空间或板块，模拟召回、查询插件日志和查看存储占用 |

在「设置 → 记忆空间」可为当前人格开启跨空间召回，或将所选空间排除在共享来源之外。默认只查询当前空间。开启共享后，只从同人格的其他空间补充原子、事件、主题，群聊读取私聊还需单独开启。空间的主模型默认继承插件设置。空间的主题抽取模型和短期摘要模型默认各自继承插件对应的配置，可单独选择“跟随主模型”使用本空间的主模型，也可直接指定模型。手动重构仅列出所选流程涉及的模型，短期摘要由会话单独触发。

重构以当前人格、配置和保存的来源为依据。全量重构成功后替换该空间的派生记忆，新实体从正文版本 1 起计。按板块重构可单独选择主题、画像和私聊关系。独立笔记和原始记录分别管理。原始记录没有自动清理期限。

在「设置 → 文本清理」可以编辑默认的「陪伴插件文本清理」规则。启用的规则依次处理新采集的人格输出，用户原话与被转发作者的文字按来源保存。最近召回记录默认关闭，开启后跨重载保存最近 50 次实际结果，关闭时清空记录。

## 数据与验证

插件通过 AstrBot 的 `StarTools.get_data_dir("astrbot_plugin_neomemory")` 定位数据。待写队列、原始会话、派生记忆与向量缓存分别保存在 `ingress.db`、`source.db`、`memory.db` 和 `cache.db`。从 1.0.0、1.1.0、1.2.0 或 1.2.1 正式版升级时，首次加载会按需将 memory.db 升至 v4、source.db 升至 v2。ingress.db 和 cache.db 使用 v1。插件审计日志按日存放在数据目录的 `logs/` 下。抽取输出沿用 v1，长期和主题候选的纠正反馈使用 v2。各实体的正文修订独立计数。

抽取质量受模型影响。主题可能继承事件中的主体错误，画像可能遗漏限定，召回也可能遗漏相关记忆。维护页支持按空间复查原文、模拟召回和人工修订。维护指南、存储结构、模型协议与开发路线见[文档索引](docs/README.md)。

从源码打包可在仓库根目录运行 `python scripts/build_plugin_package.py`。安装包输出到 `dist/`，包含插件代码、依赖清单和 WebUI。
